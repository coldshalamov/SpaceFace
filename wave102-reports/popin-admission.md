# Wave 102 — popin-admission audit

Audited `devin/1791064509-perf-w60` @ `230b88e42` (W101 docs commit on PR #220). Read-only audit; no code changed, no app run.

`saturated: false` — the W101 membership-scan fix still leaves two positional escape modes that drop a live row for a frame (F1), the deferred cull-freeze queue carries two drain defects that hit exactly the storm cases it was built for (F2), and two bounded residuals remain (F3, F4) — all with concrete implementation paths.

## Findings (ranked)

### F1 — fence-pack membership scan still positional: mid-scan appends escape the frozen `activeNow` bound, and stale-tail "rescue" is clobbered by retire/alloc pairs → committed snapshot drops a live row for a frame

**Evidence:**
- `src/render/snapshotFence.js:493-498` — `const activeNow = world.getDiagnostics().active | 0;` is captured once; the loop `yield`s every `every` rows (:496), parking the generator mid-scan. Rows allocated during those parks append at indices ≥ `activeNow` — never visited, never packed.
- `src/render/presentationWorld.js:315-325` — `removeActive` swap-moves the tail slot into the freed position and leaves a stale duplicate at `activeSlots[lastPosition]`; `addActive` (:308-313) appends at `activeCount++` — i.e., onto exactly the stale-tail region the oversized scan bound reads.
- Hide path for a missing row: `renderer.js:23177, 23192-23198` — `snapshotIndexOf` −1 → `posed=false` → `applyEntityMeshVisibility(mesh, false)` → the bound spawn hides for ≥1 frame (same flicker class as W101 F2).

**Mechanism:** escape mode 1 — a spawn burst lands while the membership scan is parked mid-loop: appends extend `activeCount` past the frozen `activeNow` and are visited by no sweep (the appended sweep's slice was already consumed). Escape mode 2 — the scan's stale-bound overshoot is what accidentally rescues swap-moves today: retire at a visited index moves the tail row into visited territory, but the stale duplicate still sitting at `activeSlots[lastPosition]` gets packed by the overshoot. A subsequent `addActive` in the same park writes the new slot over that stale index — the rescue copy is clobbered and the swap-moved row is genuinely lost. Both orderings are real under combat churn (alloc+retire inside one parked pack), the same trigger as W101 F2 — the positional-coverage defect, one generation deeper.

**Fix sketch:** make the final sweep membership-exact like the comment at :487-491 intends — iterate the live set instead of positions. `world.byId` (Map, entityId→slot, maintained at `presentationWorld.js:675`/`739`) is the authoritative live membership index but is not exported; expose it (or a `forEachLiveSlot`/iteration accessor) and run `for (const [entityId, slot] of world.byId) packRow(slot)` — Map iteration visits mid-iteration inserts (covers mode 1) and skips deleted keys (covers retires), position-independent (covers mode 2 and every swap-move ordering). Same O(active) order. Effort **S**. Magic-frame impact **M** (rare real pop-out — the exact class W101 F2 killed, narrower window). Risk **low** — packRow already dedupes by identity; the only behavioral change is fewer missed rows.

### F2 — `_drainHiddenFreezeQueue` ignores cleared queue-intent and pays O(n) `Array.shift()` per stale entry → post-unbind freeze mints on pooled meshes + O(n²) stale drains inside one presented pass

**Evidence:**
- `renderer.js:21025-21045` — the drain `shift()`s each entry, deletes `ud.sfHiddenFreezeQueued`, then drops only on `sfHiddenFrozen===true || matrixAutoUpdate!==true || visible===true || !mesh.parent` — it never consults the queued flag it just deleted.
- `renderer.js:21216` — `_unbindPresentationMesh` deletes `sfHiddenFreezeQueued` precisely so "a pooled reuse can't inherit it" — but the queue entry survives and still mints: post-unbind the mesh is `sfHiddenFrozen===false`, `matrixAutoUpdate===true`, still `visible===false` (a culled mesh is hidden via `applyEntityMeshVisibility` → `mesh.visible=false`, `entityMeshVisibility.js:67-72`), and pooled members stay parented → every drop check fails → the drain composes, freezes, and marks the subtree on a mesh the world no longer owns.
- `renderer.js:21029` — `pending.shift()` on a plain array is O(length); stale drops do not increment `minted`, so the `HIDDEN_FREEZE_MINT_ROOTS_PER_PASS`=6 cap (:889) bounds only successful mints — a fully-stale queue drains its entire length in one pass at O(n²) element moves.

**Mechanism:** two storm-shaped costs. (a) Mass-despawn sweeps unbind thousands of rows (`:21141-21230` per row); each leaves a live queue entry that mints a full `updateMatrix`+`freezeHiddenSubtreeMatrices` traversal on a doomed or pooled mesh — the O(subtree) cost the queue exists to defer, paid on objects leaving the world. A pooled reuse then inherits `sfHiddenFrozen`+`matrixAutoUpdate=false`+`sfMatrixFrozen` marks — it self-heals only if it returns through the world show-path restore (:23234-23238); a reuse drawn before a world re-bind presents a frozen subtree. (b) A cull-storm queue that goes stale (pan-back re-shows, or the same despawn wave) shifts every stale entry inside one `syncEntityViews` pass — thousands of O(n) shifts, the in-frame burst class this lane hunts.

**Fix sketch:** honor the intent flag first — `if (ud.sfHiddenFreezeQueued !== true) continue; delete ud.sfHiddenFreezeQueued;` (one-line; unbind's delete then actually gates the mint). And stop paying shift-per-entry: walk the array with a head index (or `pending.splice(0, consumed)` once per pass) and bound stale drops the same way mints are bounded. Effort **S**. Magic-frame impact **M** (in-frame burst + inherited freeze on exactly the storm paths). Risk **low**.

### F3 — post-append sweeps un-gatable: the pack pays an O(active) Map-get walk every commit even with zero mid-park churn

**Evidence:** `snapshotFence.js:481-499` — appended slice + membership scan run unconditionally per pack; on a quiet pack (no alloc/retire during the park) both are pure re-verification. `presentationWorld.js:134-135, 676, 743` — `diagnostics.allocations`/`diagnostics.retirements` are monotonic counters bumped by every alloc/retire.

**Mechanism:** cost only — O(active) `Map.get` + `alive` reads per commit (thousands of slots per presented pack on populated scenes). The scan exists for coverage, not throughput, so the waste is bounded — but it is free to remove: capture both counters at mint (`:397` already reads diagnostics); if `allocations` is unchanged at the appended-sweep point, skip it; if both are unchanged at the scan point, skip it — with neither counter moved, no row can have been appended, swap-moved, or recycled. Effort **S**. Magic-frame impact **L-M** (steady per-pack shaving). Risk **low** — counters already cover every structural mutation path (`addActive` is called only from `allocateRecord`; `removeActive` only from `retireSlot`/clear).

### F4 — stale-large cull-radius residual narrowed: only non-keyed `drawnCullRadiusForMesh` cache misses (interior subtree changes under unchanged top keys)

**Evidence:** `renderer.js:23242-23247` — the visible loop calls `world.refreshVisibleEntity(slot, entity, viewRadius)` with a freshly measured `entityVisualCullRadius` **every frame**, and `refreshMetadata` writes `world.radii[slot]` on any finite change (`presentationWorld.js:543-557`, including shrink) — so a `wholeShipLodActiveLevel` transition (partsLibrary.js:9215) busts the `drawnCullRadius` cache key (`visualCullRadius.js:60-93`: `{assetState, compositionId, lodLevel, childCount}`) and the shrunken radius re-stamps the same frame. The gap that survives: interior subtree mutations that move none of the four keys (a grandchild graft/split under unchanged direct-child count, same composition/assetState/lodLevel) keep the cached large measurement forever while visible.

**Mechanism:** over-admit only — `exactVisibleCompute` adds `radiusNow` to both rect tests (`presentationQueries.js:176-194`), so a stale-large row stays admitted, keeps its mesh submitted, and inflates `maxRadius`-driven collect expansion (`:348-357`) — work, never a pop (three's own frustum cull still applies at draw; the stamp self-heals at hide/:23144 or rebind/:21106). W101's F5 described a wider window than exists — the visible-path restamp already closes keyed transitions; this residual is narrower. Implementable now: key the cache on a cheap content epoch the graft paths already bump (e.g. `visualRevisions[slot]` or a `drawnCullEpoch` counter incremented where authored content is spliced), or re-measure at a fixed cadence for continuously-visible rows. Effort **S-M**. Impact **L**. Risk **low**.

## Lane residuals (a)–(e)

- **(a) `packedSlotGens` entityIds fallback:** no production exposure — `world.slotGenerations` is unconditionally allocated on every real `PresentationWorld` (`presentationWorld.js:176`, grown `:253`), so the fallback only serves foreign/test doubles. Even there, a collision needs the same entityId re-minted on the same slot mid-park (sim ids do not recycle). Verified clean.
- **(b) appended identity-scan cost:** bounded — `packRow` dedupes by (slot,generation), so each identity pays ≤1 write; a churn-heavy park adds at most churn-count extra rows to one commit (dead-row orderings are valid — equivalent to atomic pack-before-retire — and vanish next pack). No stacked allocation defect. The real residual is F1 (escapes) and F3 (ungated cost).
- **(c) deferred-freeze interplay:** packed state identical either way — the pack reads world-owned scalar columns (x/y/z, rot→quaternion, bank/pitch, flags, typeCodes, generation; `snapshotFence.js:441-463`); the freeze mutates mesh-side `userData`/`matrixAutoUpdate`/`matrix` only, and `world.radii` is not a packed column. Verified clean; the queue's own drain defects are F2.
- **(d) stale-large cull radius:** implementable now — narrowed to non-keyed `drawnCullRadiusForMesh` cache misses (F4). The visible-path restamp (:23246) already propagates keyed shrinks same-frame, including `wholeShipLodActiveLevel` transitions.
- **(e) un-budgeted walks, ranked:** **top fixable = F3** (gate the appended+membership sweeps on `diagnostics.allocations`/`retirements`). Remainder verified bounded-by-design: `presentationQueries.query` full walk is grid-bounded with retain fast paths (zero-dirty :238, pose-dirty :260-330) and `candidateSlots.sort(compareEntityId)` (:371) is the deterministic admit order — removing it trades ~O(c·log c) for unstable (grid-order) admit priority; keep. `syncAsteroidInstancePool` is dirty-gated (`canReuseStaticSubmission`, asteroidInstancePool.js:500-521). `syncJournalRebuildEscalation` is the rare by-design atomic fallback (≥3 invalidations, presentationRunner.js:743-754, :802); its O(entities) `collectedLiveIds` Set (:789-794) builds only on suppressed-destroy races. `collectSpecialSlots` is O(specialCount) trivial (:1410-1414). `syncEntityViews` visible/hidden loops are the frame's core work, bounded to retained sets.
