# Bounded creative convergence loop

This is an optional thinking aid for one production unit. It is not a sequence of required documents,
subagents, reviews, or acceptance gates.

## 1. Observe

Inspect the ordinary behavior or current owner closely enough to state one concrete deficit. Do not
survey the whole repository.

Output in working notes only:

- current player-visible behavior;
- desired player-visible change;
- live owner;
- one focused way to falsify the change.

## 2. Generate

Produce one to three materially different candidates. References are optional. Do not create a
candidate dossier or multiply ideas to satisfy a quota.

Choose the candidate with the best combination of player value, bounded implementation, and reuse of
current owners.

## 3. Build

Implement the smallest coherent production path. Finish one unit before beginning another. A focused
test may accompany the source change; standalone infrastructure is not an implementation.

## 4. Verify

Run existing owner-level checks first. Escalate only if the unit makes a broader route, visual,
performance, save, or accessibility claim.

A failed high-level harness is evidence about that claim, not an automatic new project.

## 5. Review

The implementer performs one evidence-bound self-review:

- what changed for the player;
- what could still be false;
- whether the change is distinct and reachable;
- the largest in-scope defect.

Fix verified causal defects once. Do not restart discovery after the causal re-review.

## 6. Commit and continue

Commit the production unit and record its lifecycle/verification state. Then select the next unit.

No phase requires a standalone Markdown deliverable. Learning notes are optional and should be
captured only when they prevent a concrete repeated mistake.

## Anti-loop rule

When the next action improves only the proof apparatus rather than the production result, ask:

> Is this exact support change required to establish the claim this unit actually makes?

If not, leave the broader claim unproven, terminate the unit honestly, and continue.
