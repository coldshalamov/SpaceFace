# Design Archive

Everything below this directory is historical context, superseded reasoning, or a completed task
record. It is not current policy, status, or a default implementation source.

Use archived material only when an active plan links to a specific section for background. Before
reviving an idea, reconcile it against:

1. `ARCHITECTURE.md` for technical contracts;
2. `design/GDD_2_0.md` for game design;
3. `design/program/README.md` for current done/remaining status;
4. `design/PLAN_REGISTRY.md` for the active plan family;
5. live code, checks, and player-route evidence.

Do not copy archived visual tokens, primitive-only asset guidance, performance shortcuts, stale
backend paths, or completion claims into active work. If an archived idea is deliberately revived,
move its maintained version into the appropriate active suite and add it to the plan registry.

## Contents

- `specs-1.x/` — original subsystem specs superseded by spec2/spec3 and live code.
- Task and review records — completed or abandoned packet context retained for archaeology.
- Older graphics/HUD plans — may contain ideas, but cannot override current graphics, UX, or
  performance policy.
