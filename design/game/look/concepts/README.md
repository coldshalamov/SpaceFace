Existing named moods can override base fields, and explicit profile light colours override rig hex colours; applying the eventual choice must account for those existing overlays. Global grade cannot introduce teal/amber into an absent sky plate or restore black pixels: retain the authored sky and adjust its existing background intensity/painted-sky contribution separately if needed. No sky geometry, assets, code or runtime values were changed here.

Generation prompt set: all three calls used the original screenshot as the sole edit target and requested only lighting, colour, value and glow changes, preserving the camera, objects, full framing and HUD layout; no new objects, harbour scenery, fog, labels or broad neon wash. A requested golden key light, cool blue-violet shadow fill, readable midtones and teal/amber nebula; B requested brighter near-white key light, saturated paint and lighter blue space; C requested deep blue-violet space, warm reflected rim light on every hull and restrained engines/lamps. The built-in tool returned 1672×941 images; ImageMagick Lanczos resampling normalized them to 1280×720 without cropping. These are generative paintovers: fine rock texture, tiny stars and some HUD glyphs/numerals can differ from the untouched reference; they are visual direction, not pixel-exact screenshots or evidence of runtime behaviour.
