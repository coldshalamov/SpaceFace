# The controls people see

**Verdict.** Preserve the instrument-panel art direction. Its best elements work like instruments. A tether under load can tell a pilot when to cut. A credit counter inside three nested rings cannot tell them whether buying a part sacrifices their next repair. The first UI pass should buy legibility and decision speed at the two moments players are most likely to quit, the first throw and the first Armory visit.

## A screen can be handsome and still ask the wrong question

The public browser build I examined displayed the “First light” card. A dark plate, a conspicuous gold Play key, calm typography and generous negative space made the default easy to find. The alternative button said “Use first light.” The preceding paragraph had to explain what the alternative actually did. Keep the visual treatment. Label the action “Use calmer settings” and reserve “First light” for the title if it earns its place. A keyboard user pressing Escape needs the same disposition as the button language implies. On current master the code distinguishes the calm choice, Play and dismissal. Verify the printed key hint against what Escape actually applies. The public build displayed a big gold-hand dial, Continue and Swarm, then New Game, Load, Crucible, Settings and five smaller destinations. Naming both Swarm and Crucible asked a player to know the project's vocabulary. The current master implements a desktop Adventure door, a Swarm door, a subordinate setup route and a More disclosure. The repo already contains the response to much of the public title's clutter. Test the new title on the intended release artifact before assigning a redesign. Treat the public-vs-master mismatch as a distribution problem while it persists. | Surface | Player question | Build and judge it this way |
|---|---|---|
| Flight HUD, aim, radar, map | Which thing can I grab, where will it go, and what will hit me first? | Keep a distinct lock outline on the actual target and a separate danger shape. At maximum text size the pilot, target, incoming vector and release affordance must remain visible in the same encounter. Delay lore notices through that moment. |
| Armory, Shipworks, research and fitting | What changes about my *next move*? Can I still afford a repair? | Use available round-one items to offer a specific change in play, such as a longer swing radius, a closer heavy shove or a repair reserve. Print the equipped baseline, outcome, full cost and balance after purchase. A missed button opens no spend. Launch stays available without a purchase. |
| Manifest, Base, markets | Which cargo is mine to sell? Which line is losing money? | Use identical terms for aboard, reserved, entrusted and free quantity. Put operating cost beside gross receipts. Hide aggregate charts until the player can act on one named route. Test with a contract and personal stock of the same commodity. |
| Hail, notices, popups and results | Who needs me, how urgent is it, and can I dismiss it safely? | Draw one priority notice at the action edge. Queue flavor and coalesce duplicates. Restore focus to the still-valid opener, including on cancellation and after a purchase removes a card. A result should name cause, one possible counter and a ready retry. |
| Star chart, journal, Codex, Archive, Help | How do I resume the thing I was doing? | Carry the selected job or destination across chart → journal → back. Show a route the player can pay for. Put unknown names and lore one step behind the current physical instruction. Return from Help to the same selection and camera. |
| Settings, pause, save/load | Will this apply, and can I go back? | Change one value mid-flight, resume, save and relaunch. Show whether an action changes the run, profile or device. Test a restored save with remapped controls, an interrupted load and a controller disconnect. |

The shared Stage dialog seat and opener restoration are worth keeping. So are the existing device-aware prompt resolver, HUD attention logic, and accessibility settings. Building bespoke modal code for every artistic treatment makes Escape behavior, captions and focus progressively harder to trust. ## Three packets for the current owners

1. **One action vocabulary.** Walk the first latch, release, mining and dock with mouse, a rebound key and a pad. The README describes Space/F for the line and holding RMB to mine. The current first-hour brief explicitly calls for RMB latch/throw. Both may coexist as contextual bindings. Resolve that on each actual route and record the action/device/context matrix. Feed hints, help and README from the resolved bindings where feasible. Fail if the game teaches an unavailable input, an alternate cannot perform the action, or a held mining input accidentally starts a throw. Include an existing profile. [Public controls table](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/README.md) · [First-hour strip](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/design/game/20_THE_FIRST_HOUR.md) · [Binding owner](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/src/systems/input.js)
2. **One intermission decision.** Start Swarm from the title, earn the first intermission, enter with just enough for one purchase, inspect two choices, cancel one and buy the other. Repeat with zero spend. On both paths require exact credit delta, a single effect, usable Back/Launch and round two under control. Have an unfamiliar player say what they gave up. Compare the current art to the revised screen at 1280×620 and at larger text. Reconcile with PRI-12 / PRI-14b before assigning. 3. **Equivalent information in different bodies.** A deaf player must locate the incoming hazard from shape, text or direction. A motion-sensitive player must read tension and release with camera shake and flash reduced. A one-handed or remapped player must be able to return to the berth. Repeat on a physical handset before claiming phone parity. Use portrait for editing menus and the supported flight orientation for combat. Preserve per-device settings, separate motion from flash, and prevent touch UI from covering the latch target. Existing phone policy provides a 25% HUD budget and a flick-to-throw vocabulary. Test aiming accuracy as well as area. **Localization decision.** The checked-in readiness table reports 17,798 reviewed English entries and 219 each in Spanish, French, German and Brazilian Portuguese, with all four marked preview. That is 1.23% of this inventory per preview locale. It says little about what fraction of one session is comprehensible. Prioritize title, controls, first job, Armory, death, save recovery and text expansion as a contiguous translation unit. Run one journey end to end with a fluent reader, including fallback text after missing audio. Publish a language promise only at the scope tested. ## What the public Armory actually did

On the retry I reached the public Armory at round one with 1,017 run credits. Its three offers were a Pulse Laser M at 28, an EMP Disruptor M at 48 and a Shield Booster S at 18. The highlighted laser named hardpoint 3 and showed the balance it would leave. Choosing it fitted the laser and produced the predicted 989 credits. Launch round 2 carried that balance into combat. Preserve the transaction language, the explicit campaign/run distinction and the persistent primary Launch button. They make the screen function even on a first visit.

At this desktop viewport the narrow cards wrapped their names across lines and their descriptions extended below the visible card area. The selected weapon's cream glyph repeated, larger, in the middle schematic. The upper-right credit total used a high-contrast serif style beside condensed navigation and sans-serif item text. One icon occupied two of the most prominent spots while the mounting point remained abstract. Use the center to show the actual mount on the hull or the changed firing pattern. Shorten the unselected cards to silhouette, one move, cost and fit. Keep the larger detail pane for the selected item. Let the same price numeral style carry from card to receipt. Recheck the current master layout before implementing against the public-build observation.
