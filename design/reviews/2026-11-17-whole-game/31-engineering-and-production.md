# Repository, code ownership and production confidence

**Judgment.** SpaceFace has built sophisticated tools for a small game. The dangerous production habit is allowing several individually true statements to add up to a false release decision. A feature can have a simulation test, an attractive lab image and a marked-complete work packet, yet still fail to appear in the installed game. The next production milestone should make precisely that discrepancy cheap to find.

## What is actually in the tree

At the reviewed revision, `git ls-tree -r --name-only HEAD` returns **30,024 tracked paths**. They include 8,852 under `assets/`, 7,475 under `design/`, 6,531 under `test/`, 3,501 under `src/` and 1,432 under `scripts/`. Within the test subtree, 5,888 paths end in `.test.mjs`. The package defines 786 npm scripts. These counts describe the size of the maintained tree and its declared commands. New agents can follow the current design in `design/game/`, and the fleet queue supplies available work. Treat any proposals here as candidates for that queue. The code has real architectural seams. A dedicated sim lane, presentation snapshots, a public input path, asset residency, deterministic checks and isolated software-rendered routes are professional affordances. Their value is clearest where responsibility is concentrated. `renderer.js` has 36,228 newline-terminated lines and owns initialization, teardown, entity-view sync, opaque batching, shadow policy and projection. `saveSystem.js` has 10,505 and imports individual story and economic domains as well as storage and recovery. Line count alone would be a poor reason to split anything. Two concurrent workers changing enemy rendering and shader admission already have a common file and an explicit scheduling conflict. Save/restore changes in an individual storyline can similarly reach a high-consequence shared owner. ## Repair the path from commit to evidence

1. **Restore confidence in master.** Extend the existing KNOWN-REDS work with the exact failing test, build SHA, failing route, observable consequence, owning system and oldest verified failure. Assign one owner per independent failure cluster. Classify infrastructure interruptions, known stale expectations and player-affecting regressions separately. When behavior deliberately changed, require the new behavior or an authorized design decision before updating the assertion. During recovery, surface *new* failures on each change and display the outstanding baseline. Close this recovery milestone on a passing aggregate and all expected shards running. A cancelled shard still leaves unknown behavior. [Existing queue rows](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/design/program/fleet/QUEUE.md#L151-L155) · [CI aggregation](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/.github/workflows/check.yml#L278-L305)
2. **Fix compact onboarding without deleting game history.** Run the current packet selector on a blobless tree, group included paths by byte contribution and category, and cut regenerable evidence or retired design copies from the packet. Preserve runtime source, schema, canonical queue, package lock and the narrow fixtures needed for the chosen task. Offer the existing omitted-path manifest for the rest. Acceptance is a usable engineering packet below the existing limit, with a clean extraction, three representative import paths resolving, and omissions distinguishable from genuinely absent files. Stream heavy playable assets separately only when a route requires them. The repo's retention rules already classify source, reference and evidence. [Selector](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/scripts/lib/agent_code_packet_selection.py#L28-L111) · [Current ceiling and manifest](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/.github/workflows/agent-code-packet.yml#L58-L118) · [Retention classes](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/docs/ARTIFACT_RETENTION.md#L7-L28)
3. **Give each expensive regression the right execution frequency.** Retain pure invariants per applicable change, a public-route smoke check per integrated batch, the full suites at candidate milestones, and the long hardware soak for a named release artifact. Reuse the current script registry and report groups. The fleet's Swarm gate deliberately samples ten simulation seconds and validates seven boot-critical rows. Its proof extends through that entrance. Keep this fast, and reserve a separate durable receipt for an ordinary round transition, boss, loss and immediate retry. The current ACCEPT-07 packet itself records that prior acceptance runs ended early. [Gate implementation](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/scripts/fleet/gate.mjs#L36-L73) · [Late-content evidence gap](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/design/program/fleet/packets/ACCEPT-07-later-content.md#L1-L14)
4. **Extract on the path of actual work.** At the next approved repeated-hull optimization, give the draw-resource owner explicit attach, reuse and dispose responsibilities, keep the renderer's existing public calls, and measure context loss, replacement and sector exit before merging. At the next domain save change, move that domain's normalization and compatibility fixtures together, preserving canonical envelope shape and byte identity wherever promised. Stop if the diff touches unrelated story owners. This reduces concurrent edit collisions one boundary at a time. [Existing renderer cleanup](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/src/render/renderer.js#L8639-L8661) · [Save migration contract](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/src/save/AGENTS.md#L3-L11)
5. **Budget the assets that actually ship.** A source .blend, a historical acceptance image and a packaged playable hull have different lifetimes. Use the existing staged bundle, release manifest, receipt and asset provenance to track download bytes, initial decoded bytes and repeat GPU residency for specific playable routes. Flag top regressors per asset and route. Review the same hull at tactical distance, chase distance and in the preview before accepting a cheaper variant. Keep the authored source and attribution when derivatives change. The retail builder deliberately selects release content, validates its receipt and publishes the candidate directory after verification.
