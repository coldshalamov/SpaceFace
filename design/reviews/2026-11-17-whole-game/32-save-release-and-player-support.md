# Save trust, distribution and player support

**Production decision.** A player willing to come back tomorrow has already supplied the game with its hardest-to-earn resource. Continue has to return their ship, possessions, commitments and practical ability to act. The release build, the save format and the store channel jointly own that promise.

## Existing capabilities worth protecting

The save system has a versioned envelope, checksums, a migration chain through version 23 and separate recovery copies. It bounds input size and structure. The local browser/server and Electron routes have a loopback player store with per-key generation checks, conflict handling and a write queue. The hosted static web route has a different storage environment. Publicly document where a pilot's save lives and how to export it before promising transfer between devices. In this review the focused Node cases for corrupt primaries, fallback, concurrent writers, deleted slots and older fixture migration passed. The hardest integrity check is semantic. Suppose the player attaches a damaged workpiece, saves, returns, delivers it and gets paid. Position and inventory may both look plausible when the body has silently been replaced or the money can be collected twice. The campaign promises physical continuity, so preserve identity, attachment, damage, provenance, ownership, objective and once-only settlement as one story. The current sim CI includes failing assertions about a scavenger's finite hold and a mid-cut Continue. Those point to scenarios worth reproducing in the public game. Scope each finding to the failing scenario and then verify its ordinary route. [Current sim job](https://github.com/coldshalamov/SpaceFace/actions/runs/44051579471/job/133930451946) · [STAB-05 through STAB-11](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/design/program/fleet/QUEUE.md#L124-L135)

One failure leads to a specific engineering investigation. `finalizeLoadedGame` waits for `ensureLocaleReady` before applying accessibility and proceeding. English returns immediately. A non-default locale can await English and translated bark catalogs. Both request paths wait for fetch and JSON parsing. The pinned source declares no local deadline on these fetches. The local and CI regression assertions both failed on this wait. A public-route slow-network reproduction remains open. Handle the slow path with bounded waiting, stale-transition handling and a visible retry or source-language recovery. Keep the player's chosen language and save intact. ### Save trust work packages

| Proposed packet | Start at | Acceptance |
|---|---|---|
| Restore a mid-task save with a real player action | Use one existing industrial route with a physical workpiece, one owned upgrade and one active consequence. Record ordinary UI steps to reach the checkpoint. | In the retail build quit, reopen, Continue, finish the job, inspect settlement, quit and Continue again. Compare the original body ID, damage and remaining resource quantity, selected target, money and objective. Destroying or delivering that original object must prevent a second settlement. Preserve a prior-version fixture and record its schema. |
| Recover from slow or conflicting restore | `finalizeLoadedGame`, locale readiness, restore generation and shared store. Pair the existing STAB packets with the browser shard's failing contract. | Using a controlled catalog stall on a non-English save, an interrupted download, a late completion after Back and a second Continue, the player gets one usable result or a named recovery choice within the defined loading budget. Late completion cannot change the accepted world or language. Preserve both valid generations during a two-writer conflict. Choose the supported conflict behavior explicitly. |
| Make recovery understandable | Existing slot card and recovery metadata, settings export, Continue and quit route. | With a corrupt latest primary, the UI identifies the recovered save and its age and returns control. A future-version save offers a readable explanation and keeps its bytes. Full storage leaves the old playable save or a visible failure. Give testers a real older save and ask them to resume unaided. Record recovery success, time to control and duplicate rewards separately. |

Use tests of actual repair and re-entry to protect this work. A test that scans source for the name of an awaited helper can catch drift, as it did here, but accepting the helper's name in an allowlist would prove nothing about late responses or return to control.

## The package the customer opens

Development serves raw ES modules with an import map. Production builds minified chunks, copies selected assets, bundles workers, writes a release receipt and stages publication. Electron includes the built web tree, a local server, preload and shell components. The retail smoke workflow exercises a headless Chromium title menu on software GL, separately from the broad CI workflow. That separation saves time and catches broken chunk URLs. Commercial qualification still requires the *same installed artifact* to proceed through an encounter, save, relaunch and accept input. The retail workflow triggers on pull requests to master and manual dispatch. Its declared triggers cover pull requests to master and manual dispatch. ## Support and release acceptance

First, make one support packet intelligible to a teammate who has never seen the machine. The desktop shell already writes a local JSON crash report and identifies version/build. Frame truth has a structured trace and the session report has first-flight, swing, shove, dock and economy milestones. Connect the existing evidence through a user-initiated export. The default support view should show build, channel, host, graphics mode, last named transition and a copyable error, with a short recent frame/worker window when relevant. Make save attachments an explicit choice. Retain elapsed time, route and event identity while scrubbing local paths and usernames. Test that a second developer can distinguish a missing asset, a stalled catalog request and an old pose from three anonymized reports. [Crash reporting](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/electron/main.cjs#L731-L776) · [Frame export](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/src/core/frameTruth.js#L601-L626) · [Session milestones](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/src/observability/sessionReport.js#L1-L45)

Second, publish a candidate receipt tied to the exact asset digest, executable version and SHA. Attach installation and upgrade outcomes, route completion for the two front doors, retained evidence for a loss/retry and a later boss, and the save fixture pack. The minimum-spec file specifies two-hour soaks and at least 200 save/load cycles for browser and Electron. Run those on the target hardware for a release-candidate decision and label skipped hosts. A saved game that comes back with the correct credit count but an unusable camera fails the return-to-play case. [Build receipt validation](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/scripts/build-bundle.mjs#L178-L209) · [Soak specification](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/build/min-spec.json#L26-L47) · [Hardware evidence checker](https://github.com/coldshalamov/SpaceFace/blob/4bbe545d550a4c43e720df18c254b1c8d190d8a1/scripts/check-min-spec-floors.mjs#L89-L106)

Third, prepare rollback before external testing by pointing web players to the previous immutable artifact, offering the previous direct installer or private depot, and preserving original saves before version migration. An older build may legitimately reject a newer envelope. Prove recovery using an untouched prior generation, without silently downgrading or erasing an advanced save. The commercial metrics are resumed sessions that regain control, successful upgrades, interrupted saves recovered, and actionable support reports per incident. Each is observable before a review or refund supplies the same information too late.
