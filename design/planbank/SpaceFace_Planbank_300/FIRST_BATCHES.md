# Suggested first batches — conditional starting choices, not a second queue

These are my proposed starting priorities from the inspected snapshot. Current reproduction, owner direction and exact-path availability can change the order. Do not implement a stale repair simply because it is listed first. Admit selected work through the existing workflow.

## Batch A — repair causality where it is currently least credible

**[SF-136 — Put a real crusher into the yard tow-out](plans/10-missions/SF-136-put-a-real-crusher-into-the-yard-tow-out.md)**: the selected yard script resolves a private moving radius/timeout as 'crushed'. Give the encounter a real machine law and a recoverable result. Read its deep dive before handing it to a weaker executor.

**[SF-076 — Restore the real Ceres miner-to-hauler cycle](plans/06-jobs/SF-076-restore-the-real-ceres-miner-to-hauler-cycle.md)**: the repository reports an upstream Ceres miner→handoff→loaded-approach failure. Locate the first missing real transition; do not spawn a loaded hauler to satisfy the test. This is cause-adjudication work first, then a bounded fix.

**[SF-106 — Make competent hauling viable through real terms](plans/08-economy/SF-106-make-competent-hauling-viable-through-real-terms.md)**: resolve the reported hauling-economy problem using executable quantities and full trip costs. The earlier model arithmetic fix is already described as landed; do not repeat it or lower the target just to pass.

These three touch shared world/economy seams. They are not automatically parallel. Finish one useful repair and use its actual route before broadening.

## Expansion stays optional

SF-181–SF-195 deepen the already planned Vethari/Charon Bloom ecology. They are intentionally conditional expansion candidates. ## Selection test

Before admitting a packet, answer: **What ordinary action becomes better, what source owner supplies it, what evidence says the gap remains, and what exact files can be changed safely now?** If those answers are absent, resolve the uncertainty rather than delegating another open brainstorm. A useful first batch ends with a more coherent playable route, not 25 new task statuses.
