# Strong batch review prompt

Review the completed selected SpaceFace packets as a connected game change, using the actual current diff and ordinary-route observations supplied with them. Do not approve from the implementer's narrative alone, and do not assume the plans are right merely because they are detailed.

First verify the current owner, default route and changed files. Identify whether any packet duplicates an existing feature, follows stale diagnosis or revives retired direction. Then inspect the implemented causal chain: entry, choice, physical action, authority, feedback, settlement, interruption and aftermath.

Prioritize errors that make the game false or unplayable: fake physical outcomes, missing normal entry, duplicated/lost custody or rewards, stale-generation publication, stuck control/pause, unreadable counterplay, silent fallback and performance wins obtained by deleting quality. Inspect the packet's contrary case, not only its happy path.

Where you can run/observe the game, compare the actual sequence with the intended result. Where you cannot, state the evidence limitation and review source/test semantics without claiming feel, visuals, audio or frame pacing are accepted. A second textual review is not independent gameplay evidence.

Return the highest-impact concrete defects with source path, reproducing scenario, why the consequence matters and the smallest owner-preserving repair. Separate must-fix, optional improvement and unproven. Do not inflate the result with a score, generic advice or a new reporting institution. Fix clear owned defects within the authorized workflow when implementation is part of your task.

Conclude with which outcomes are implemented, accepted, already satisfied, cut or require a narrowly defined replan. Explain any rejected mechanism through the actual failure, not model preference. Keep useful work and current foreign edits intact.
