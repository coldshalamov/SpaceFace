# Model, VFX, audio and UI production contract

## Start at the actual camera

Forge's documentation gives its current reference chase/close setup, but workers must inspect the present runtime camera rather than freezing those numbers into a new law. A top-down silhouette, readable load path, actual contact point and useful negative space matter more than unseen underside detail. Render new work beside the best existing content under production lighting, materials and postprocessing. [S22]

Every model brief in `assets/` is a **family/outcome brief**, not a claim that its mesh is missing. Reuse current Forge outputs and supported props when they already work. Existing texture/material classifications and manifests outrank prose counts in any old asset inventory.

## Human, biological and machine language

Human: manufactured, attached, occupational, colorful within current family discipline. Useful mass and fittings remain visible. No runtime floating parts to rescue a bad source mesh.

Biological: the conserved fungus morphology links different hosts; tissue follows actual seams, heat or load paths. A body is not defined by noise. Thick membranes, trunks, cavities and active margins read at normal camera distance.

Machine: exact, sparse, functionally articulate, deliberately silent or still when waiting. Minimalism is not permission to ship default primitives without design. A Courier has a token socket; a Mason frames its workpiece; a Custodian can make a contact the player sees. Oppose fungal entanglement without turning every robot into a chrome halo.

## Assets and interaction

Each gameplay asset declares source file, stable asset ID, supported states, pivots/orientation, collision policy, attachment/work sockets, material ownership, LOD/residency and publication route. The current Forge coordinate convention is +X nose, +Y port, +Z up in Blender, with runtime normalization. Check the actual exporter mapping into XZ gameplay. [S22]

Only named dynamic workpieces require physical bodies. Cosmetic microfilaments do not. Collider count and detail follow gameplay need. A clearly open gap must be passable when the rules promise it; decorative antenna tips should not become invisible snag traps. Do not switch to mesh colliders by default to cure a poor proxy.

Forge-integrated hardpoints mean the renderer does not indiscriminately bolt extra guns to the hull. New fitted visuals need the supported authored state/hook route. A model visible only in Blender or a debug gallery is not delivered content.

## Effects describe authoritative events and state

The current VFX standards ask for substantial evolving forms, moving dark/light internal structure, unequal arrival, actual contact and an aftermath that does not reverse birth. One universal grow-spin-shrink animation fails that bar even if its shader is sophisticated. [S21]

Effect briefs reference **semantic signal requirements**. Where a precise bus event is not verified, the worker must bind to the current owner or add one narrowly named receipt there. Do not invent events in the renderer and claim the gameplay is wired. Continuous effects may read a state owner; one-shot events require deduplication. Use stable cosmetic variation separate from simulation RNG.

Macro-parcels or bodies own collision, force and damage. A larger cosmetic ribbon or splash may enrich the material but cannot imply a larger dangerous area than the actual law. Bloom-off readability is necessary but not a license to make bright material opaque; bloom-on must preserve internal form too.

## Lifecycle review

For each retained family inspect: preparation/onset; sustained action beside a moving hull; source-off while matter remains; final cooling/disposal. Also pause, rebase, camera zoom, target death, pool reuse, save/load and reduced motion/flash. A screenshot of peak brightness is not an animation review.

The audio component is part of each effect brief. Listen to its place in the full mix. Weight, threat and source-off are mechanical information. Support spatial/source cues where the current audio engine can do so, but never invent precise direction in captions when the source data is not available.

## Interface

ORRERY is the shared instrument. New research, cargo, machine protocol or mission information uses its existing library and tokens. Minimal task-required changes are permitted under current root policy; broad redesign work stays with the current redesign lane. No new blue-line box system, font stack, dashboard cards or visor framing. Keep heavy blur/filter work off live flight as the direction requires. [S01, S19]

## Validation and publication

Use the existing asset and UI tools as documented in the current checkout. Typical verified Forge commands are listed in `audit/COMMANDS.md`; substitute real IDs, don't run the examples literally. Publish source, runtime mapping and required derived outputs together. Review through cold production load and normal play. Test disposal and shared-material ownership under multiple instances.

Do not share or duplicate bundled font files in this handoff. This pack contains no generated art/audio/models; it specifies what agents must build and how they must judge it.
