# Finish and release gates

## Development gates

A selected feature passes only when ordinary acquisition/encounter, usable input, actual behavior, model/VFX/audio/UI, meaningful failure and persistence are complete. This can be reviewed and integrated incrementally. Do not wait for every possible machine, organism or weapon to exist.

Current source contracts—especially Feel, architecture, asset readiness and ORRERY—remain authoritative. New numeric performance or difficulty thresholds require actual baselines and current owner acceptance. This pack does not supply invented benchmark results.

## Scope freeze

Before final convergence, adopt a finite retained feature/route manifest in the current project system. Every chosen mission, region, build and scene has an ordinary reachability path and complete production dependencies. Optional research features leave the critical path. Existing essential story chapters remain part of the scope unless deliberately revised for a coherent product reason.

## Candidate finish checklist

| Gate | Required evidence |
|---|---|
| No current reproducible critical blocker | No unresolved ordinary-route crash, save corruption, stuck control, essential dead action or campaign softlock in the existing ledger |
| Control and physical trust | Current Feel Contract, correct authority/capability behavior and full input sequences |
| Modes complete | Full supported Crucible arc and existing Adventure campaign route, not just showcase starts |
| Distinct content | Retained missions/builds/regions pose different useful decisions; redundant content merged |
| Presentation complete | No obvious placeholder on retained routes; force/material identity visible in motion; sound mix finished |
| Whole-loop economy | Fair acquisition/recovery with canonical quotes, custody and one-time settlement |
| Persistence | Old supported fixtures and interruption seams round-trip without loss or duplication |
| Access | Essential input alternatives, truthful options, readable non-color and reduced-motion/flash states |
| Smoothness | Current performance policy met on declared tested hardware/settings; no unsupported universal hardware claim |
| Independent review | Another agent/reviewer can reproduce the claimed ordinary experience; external playtest gaps named honestly |

“A-list” is not a final checkbox. It is a judgment about the coherent whole, including things not fully captured by metrics. The point of gates is to make obvious failure hard to hide, not to certify taste mathematically.

## Release preparation is separately activated

When the owner starts preparing a release, re-check current requirements for the actual platforms. Use the existing build identity, distribution, store asset and achievement tooling. Verify asset/audio/font rights, installer/update behavior, offline requirements, save migration, crash/support information and uninstall behavior. Do not add a mandatory online account or analytics backend to justify a finishing milestone.

Marketing must show real play from the released route. A cinematic mockup is not proof of the product. Store language and system requirements must match tested capabilities. This pack neither publishes the game nor certifies platform compliance.

## Post-finish reservoir

Retain optional machine jurisdictions, nonlocal vector physics, large membrane ecosystems, extensive succession, expanded species and cultural texture as later experiments. Finish the core before choosing the next expansion. The correct result may contain fewer proposed features and much better play.
