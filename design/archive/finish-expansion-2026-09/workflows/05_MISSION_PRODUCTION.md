# Mission production: from a premise to a place the player can break

Select one `missions/Mxx` brief only after checking the current mission/encounter catalog for the same physical question. Current types already include physical recovery, rescue, demolition, authored set pieces and breakaway operations. Do not invent a new type merely because the title is new. [S16]

## Paper pass

Draw the action in the XZ plane using current hull, velocity, camera and turn-radius references. Identify entry, readable threat, useful masses, workpiece, reward destination and escape. Think in seconds-to-contact, relative speed and visible screen depths, not arbitrary decorative spacing.

Describe what the player does with each hand. Specify which object is selected, what a press/hold means, how to cancel and how to recover a miss. Use current actions/rebinding; the pack does not allocate keys.

Write two viable approaches that produce different costs or aftermath. An alternate approach is not merely “shoot from the other side.” Keep a conventional route when a mission teaches a new physical tool; fail-forward should preserve consequences rather than pretending every mistake succeeded.

## Runtime pass

Use actual entities and stable IDs. Objective markers follow moved objects. The mission listens to successful operations from canonical owners; it does not infer success from VFX, a dialogue line or an arbitrary proximity when the task is physical. Transaction/escrow rules come from current quote/cargo/economy owners.

Write transition semantics for offered, accepted, active, partial, failed/recoverable and settled. Define late arrival, abandonment, premature action, destroyed target, full hold, lost specimen, contested custody and save/resume. Rewards and penalties settle once.

## Production pass

Use the linked asset and F-series effect/audio briefs. Stage the real workpiece, not a cube placeholder beside a final ship. Show each important phase. Bind needed information to ORRERY and current comms arbitration. A scene with no sound or feedback is not complete simply because its state machine works.

## Review pass

Play normal solution A, alternate B, an unintended plausible manipulation and a failure. Use a different hull/build when appropriate. Leave and return. Save halfway. Never use a special acceptance-only world to make the scene look correct. The result passes only when an independent player can understand what mattered without the design document.
