# Build-worker workflow

Read the current root and nearest nested `AGENTS.md`, live build map, native task and matching supporting packet. Inspect current status/ownership and the exact live selection path. Supporting source pins are orientation, not permission to overwrite later work.

## Before editing

Name the ordinary player route, the current owner and one difference the change should make. Check whether it already works. Resolve relevant prerequisites by existing implementation evidence. Confirm exact paths you can write. Don't spend a session inventing a new ownership system.

## Build sequence

Implement in the existing owner. Add/repair the actual acquisition, target admission, operation, feedback and persistence links required by the task. Keep core business rules out of UI/render code. Use current data IDs and exact API contracts from source, not prose event strings in old mission documentation.

Add focused tests for the actual invariant and its likely regression. A changed feel behavior needs player-unit evidence and current authority context; a transaction needs idempotence and cancellation; an effect needs lifecycle and attachment checks; a scene needs alternate solutions and failure.

Play the ordinary route. A hidden flag, forced scenario completion, console-granted equipment or mock backend does not establish public reachability. Fix obvious nearby defects that hurt the assigned experience within current ownership policy; unrelated genuine defects go to the existing ledger with a reproducible case.

## Review and commit

Ask the independent reviewer to reproduce the changed behavior. Iterate until the selected unit is genuinely complete. Commit exact owned paths using current repo practice, then update only the relevant native status. Don't alter unrelated dirty files or claim an entire program finished.

Report: player outcome; paths/native identity; tests and route actually run; evidence boundary; remaining concrete risk; next safe step. Keep it useful, not ceremonial.
