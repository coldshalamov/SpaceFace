# Persistent identities, work orders and bounded offscreen change

## The important state is the consequence

Save a wreck identity, a delivered token, a repaired component, a severed relay, a known observation or an unresolved obligation. Do not save cosmetic particle positions, renderer object references or every per-frame motion sample. The current save owner and canonical snapshot conventions determine serialization. A new subsystem cannot silently acquire its own independent persistence authority.

## Actor-to-cargo is a transaction

A physical specimen, workpiece or token sometimes becomes cargo and later a physical actor again. Define one stable item/lot identity and exactly one current custody representation. A successful conversion performs an atomic logical handoff through existing owners. Repeated collision/receipt processing must be idempotent. A full hold refuses before destroying the actor or charging the player. A lost source or stale target reference aborts or recovers through a specified state.

Minimal proposed transition vocabulary—adapt to the current schema, do not copy as a second engine:

`available → reserved → attached/carried → receiver-validating → accepted → settled`

Alternate terminals: `released`, `damaged`, `destroyed`, `returned`, `expired`. “Settled” contains the successful operation identity so save/resume cannot pay twice. A reservation is not ownership. A displayed transfer beam is not proof of transfer.

## Machine work orders

Start local. One Courier route, one recipient, one token and one dependent repair are enough to prove machine logistics. A work order identifies its subject, required condition/material, current phase, current owner and terminal result. Movement/repair is carried out by existing physics, cargo and site-operation owners. Its visual layer reads phases; it never advances work because an animation ended.

A stalled order should show the actual missing requirement. On return, a robot resumes or re-evaluates it, rather than replaying its first greeting and minting another artifact. Do not make an all-purpose autonomous planning framework before several selected scenes need it.

## World-site mutation

A moved asteroid or changed gate component needs a stable override in the current world/site state. Initial seeded placement must not overwrite a consequential later pose when rematerializing. At the same time, don't persist every decorative pebble. Authoritative workpieces and meaningful destroyed/repaired states get records; decorative placement can rederive from the stable seed and stage.

If a mission object is promoted from noncolliding dressing to dynamic matter, remove/supersede the previous representation. Otherwise the player may see a real object plus its ghost decoration, or collide with a second invisible copy.

## Offscreen ecology

Use a small state graph at coarse event/visit intervals, with bounded catch-up work. A carcass might become scavenger habitat, then an inert resource. Each transition needs a cause, a time condition, a visual/interaction consequence and a termination. Do not iterate every missed simulation tick across a long absence or generate an unbounded backlog of news and rewards.

Physical contamination can change after actual events or admitted succession. Knowledge can change after observation. Learning that a site is contaminated does not retroactively grow tissue there. Suppression does not automatically decrease biomass. A machine quarantine can protect one species while excluding another; treat those as authored relationships, not omniscient ecological truth.

## Irreversibility and route safety

Before admitting a route closure, verify a low-resource player retains a refuge, service or repair/appeal path. Optional succession cannot destroy the only campaign prerequisite or force a new save. If a major irreversible choice is part of the story, it needs explicit anticipation, a reachable alternative and clear scope. “The world is alive” is not a defense for random save destruction.

## Migration cases

Old saves lack new fields; apply additive defaults. Unknown optional content IDs need explicit treatment rather than crashes. Restored transient fields or attachments must resolve valid current actors or expire safely. Reference-frame and sector-coordinate migrations need concrete tests. Never “fix” an old save by reinitializing all story, inventory or reputation.

Run interruption tests before mass-producing content on this foundation. The most convincing world is also the one that remembers only what it can remember correctly.
