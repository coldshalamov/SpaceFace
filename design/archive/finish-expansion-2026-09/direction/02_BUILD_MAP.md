Presentation is not the final coat of paint. Art, VFX and sound run beside each playable slice; the scene cannot pass a satisfaction gate before its feedback exists. Conversely, do not build every final asset before the mechanic proves its value.

## Practical critical path

Current branch and route → trustworthy input/physics → readable physical fight → repeated combat and first adventure earn-fit-use → complete mission/consequence loop → authored ordinary regions → one finished ecology site and machine work cycle → selected unique interactions → complete campaign/modes → lifecycle, full-quality performance and final convergence.

The selected alien path specifically is: PR/branch reconciliation → target/capability audit → one fauna and one machine workpiece under correct authority → visible contact/work → mission acquisition/reward → state persistence → only then more organisms, machine kinds or weapons.

Do not build the speculative membrane, global succession or momentum router before the above. They are optional branches, not prerequisites to proving the core game.

## Dependency interpretation

A task's catalog dependencies are **preflight prerequisites**, not a declaration that all prerequisite code is absent. If the named outcome already holds on the current route, reuse it and record the existing native owner; do not rebuild it. Within a program, detailed dependencies are expressed in the task and current activated native packet. A phase label is not permission to run every same-phase file edit concurrently.

Cross-program branch prerequisites matter: `src/data/alienEcology.js` and machine modules are branch-dependent at this audit pin. A human UI, flight, mission or audio task can proceed while another agent integrates that branch. Missing alien code is not a reason to stop all work.

## One complete slice at a time

The atomic release-worthy unit is not “add data row.” It is:

> Player acquires or encounters something → can act with the current controls → the authoritative simulation changes → model/VFX/audio/UI expose the consequence → the world/economy records it correctly → save/load and failure paths preserve it.

A slice may contain several path-partitioned tasks. Keep one captain accountable for the whole result. Agents may finish individually, but the content family remains incomplete until the chain works through ordinary inputs.

## Review without a bureaucratic deadlock

An independent agent can review the actual route and code. Genuine new-player feedback is valuable and often catches design failures, but its absence is not permission to stop implementation. Continue with bounded improvements, state what audience evidence is missing, and do not claim a human quality verdict that did not occur.

A reviewed result may be integrated, iterated or cut. “Needs another report” is not a default outcome. Prefer one concrete reproduction and one fix over another ledger.
