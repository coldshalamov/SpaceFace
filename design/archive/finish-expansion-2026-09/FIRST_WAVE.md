# First wave: useful work immediately

This is a starting slate for an orchestrating implementation agent. It is not a claim that the current checkout is unchanged, or that all tasks below remain necessary. Spend only enough integration effort to find actual ownership and prerequisites, then produce a visible improvement.

## Captain's first action

Run current repository orientation, status and dispatch inspection. Verify the chosen build boots through its ordinary route. Compare the pinned audit with current code. Select one actual weakness affecting that route. Register/adopt only the corresponding narrow unit in the existing control plane. If already solved, move to the next outcome rather than invent a harder rewrite.

## Disjoint candidate lanes

| Lane | Opening work | Stop condition for this unit |
|---|---|---|
| Hand | `SFQ-B011` / `SFQ-B012`: test current G stick and hand conflicts | One reproduced usability issue improved, or current behavior verified and a more useful hand issue selected |
| Physical interaction | `SFQ-B021` / `SFQ-B025`: attachment capability and fresh-wreck use | A real body that should be usable can be latched and manipulated without violating opt-outs |
| Fight | `SFQ-B031` / `SFQ-B033`: starter differentiation and composable state response | A normal fight exposes distinct useful verbs without a new combat engine |
| World job | `SFQ-B071` / `SFQ-B079`: object-bound mission and failure edges | One existing mission works end to end when the object moves, fails and reloads |
| Art/VFX | `SFQ-B172` or `SFQ-B181`: attached parts or nozzle/history continuity | An actual visible defect is corrected in the production asset/effect owner |
| Machine integration | `SFQ-B003` then `SFQ-B141`: branch reality and one physical Courier token | Selected machine site supports a real custody transaction; no blind merge |
| Runtime quality | `SFQ-B211` / `SFQ-B217`: current hitch or leak diagnosis | One demonstrated causal issue improves without altering scene quality |
| Reliability | `SFQ-B221` / `SFQ-B223`: save boundaries or async route ownership | One adversarial ordinary transition survives without lost progress or stale world |

These are candidate lane outcomes, not eight compulsory concurrent agents. Inspect exact paths. Art publication and world-site changes may collide with the same manifest. A system worker and an INFERENCE worker may also collide even when their titles look unrelated. Partition by actual files and keep feature-required frontend changes aligned with the ORRERY lane.

## What the first report should contain

Build identity, player-visible outcome, exact changed paths/native unit, checks actually run, ordinary route actually exercised, remaining concrete risk, and the next safe unit. Do not report a whole program complete because its first packet landed. Do not submit a plan-only update when the implementation assignment is to build.
