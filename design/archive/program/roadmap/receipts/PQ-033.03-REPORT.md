## The achievements and what unlocks each

| Steam API name | Achievement | Unlocks when | Real signal |
|---|---|---|---|
| `SF_BERTH_ASSIGNED` | Berth Assigned | dock at a station | `dock:docked` (src/ui/input.js) |
| `SF_ROCK_HAS_A_PRICE` | Rock Has a Price | the player's first ore or salvage | `mining:yield`, other miners excluded (src/systems/mining.js) |
| `SF_PAPER_TRAIL` | Paper Trail | buy or sell at a market | `economy:tradeCompleted` (src/systems/economy.js) |
| `SF_SIGNED_AND_DELIVERED` | Signed and Delivered | complete a contract | `mission:completed` (src/systems/missions.js) |
| `SF_OUT_OF_THE_POCKET` | Out of the Pocket | jump to another system | `jump:arrive` (src/systems/world.js) |
| `SF_MADE_CONTACT` | Made Contact | latch the Massline | `tether:latched` (src/systems/tetherGameplay.js) |
| `SF_LIGHT_SHIPS_ARE_AMMUNITION` | Light Ships Are Ammunition | a Massline throw | `massline:throw` (src/systems/masslineThrow.js) |
| `SF_RAZOR_RELEASE` | Razor Release | a razor-rated release | `tether:releaseRated` classification razor |
| `SF_KEEP_THE_SPEED` | Keep the Speed | a crushing whip impact | `tether:whipImpact` rating crushing (src/systems/masslineImpacts.js) |
| `SF_INTO_THE_CRUCIBLE` | Into the Crucible | one settled Crucible run | survivalRecords `records.lifetime.runs` |
| `SF_TENTH_WAVE` | Tenth Wave | reach wave 10 | survivalRecords `records.lifetime.deepestWave` |
| `SF_BETTER_THAN_LAST_TIME` | Better Than Last Time | beat your own best in a challenge | `run:resultsReady` score vs the pre-run best |
| `SF_SAME_SEED_SAME_DAY` | Same Seed, Same Day | finish a daily run | survivalRecords `daily.byDate` |
| `SF_WALKED_OUT` | Walked Out | extract from a swarm | `run:resultsReady` outcome extracted |
| `SF_PAPERWORK_FILED` (hidden) | Paperwork Filed | get declared WANTED | `heat:changed` wanted + wantedCrossed (src/systems/heat.js) |
| `SF_SIX_FIGURES` | Six Figures | 100,000 credits earned in total | `credits:changed` positive deltas (src/systems/economy.js) |

The default Crucible door runs the swarm ruleset, which never ends in victory, so the Crucible
set rewards depth, bests, the daily board and extraction rather than a win screen it cannot reach.
Existing Crucible history and telemetry career totals unlock retroactively and silently on first boot.

## Honesty gaps

- **Owner step (external).** The Steamworks partner account work above. Nothing here creates an
  app, uploads, or sets anything live.
- **Achievement icons are drawn from kit glyphs, not illustrated.** Each is its achievement's Field
  Hardware glyph on a chamfered plate: lit amber when achieved, dim grey when not, at Steam's 64×64.
  They read at that size on Steam's dark blue; bespoke illustrations would be a later art pass.
- **steamworks.js is not installed** (by instruction). The adapter is proven against a fake SDK and
  as a no-op without one; a real activation against a running Steam client is unproven.
- **The depot folder was a pipeline proof, not an upload.** It was packed from the existing
  11 September bundle because a fresh bundle is blocked by the foreign ship-manifest mismatch above,
  inspected, then deleted to reclaim 1.1 GB. Run `npm run dist:steam` on a clean bundle before uploading.
- **Screenshots are stand-ins, not launch shots.** One is the photo-mode still; four are captures
  from earlier evidence runs, copied with provenance. All are real frames of the game, but the outpost
  still carries the flight HUD and a flat purple slab across its planet, and the Massline swing and
  photo-mode stills leave the hull small in a mostly black frame. Retake all five through Pause →
  Photo → Capture before the page goes public and list them in `assets/store/page/screenshots.json`;
  the builder and `--check` take new stills unchanged.
- **Library hero decal.** The hull carries its painted "DIE LAUGHING" marking. Steam's no-text rule
  targets overlaid text, but a reviewer could still ask.
- **Proof boundaries.** The session proof runs the real missions, runSession and survivalResults
  systems; the dock intent, the ore release and the extraction request are emitted with the exact
  payloads their live emitters use. The screen was photographed from the title, not from Pause
  (Pause entry proven by mount and the pause-shell test).
- **English only.** Achievement copy has stable keys and the extractor already picks it up, but the
  generated catalog is stale for everyone (540 added / 248 removed / 1,989 changed keys, mostly other
  lanes' screens), so its regeneration and the four translations belong to the localization owner.
- **No Steam progress stats** (community progress bars) are configured.
- **No Steam leaderboard.** The Crucible daily board stays local. `src/systems/survivalRecords.js`
  still names PQ-033 for a Steam board in its header; this unit did not build one.
- **The runtime witness is not a matched before/after.** Run 2026-09-15 00:54 after this commit
  (headed Electron, Intel iGPU): verdict presenting, top bucket still presentation, the same bucket
  order as the 2026-09-14 08:37 run, and no achievements work anywhere in the report. Its p95s are
  higher (presentation 21.1 vs 11.9 ms, render 17.5 vs 8.0 ms) with the window occluded, other agents'
  browser work on the machine and 16 hours of other commits in between (GPU geometries 348 vs 210), so
  the two runs do not isolate this unit. What this unit adds to the running game is bus listeners
  only: no registry system, no per-frame work, and no allocation on an event that counts nothing.
- **The Steam overlay changes how the GPU process runs on Steam builds, and nothing here measured
  it.** With steamworks.js installed, a Steam build appends Chromium's `in-process-gpu` and
  `disable-direct-composition` switches and repaints each window at 60 Hz so the overlay keeps drawing
  (read from steamworks.js's own source). The runtime witness cannot see this: it launches the
  development shell as an isolated evidence run, where Steam stays off. `build/steam/README.md` §4
  has the owner compare the Steam build with and without `--no-steam-overlay`, a launch argument added
  for this because Windows Steam launch options cannot set environment variables. The adapter test
  proves both opt-outs keep the switches off while achievements still unlock. Direct builds never take
  these switches.
