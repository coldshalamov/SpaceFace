## Review addendum — 2026-09-09 (honesty pass)

Traced the fixture inputs against the live route rather than the assertions. Verdict: **STATUS
DONE holds.** A combat-only run can file an ending on the default route and a builder run can,
and both stakes have real production writers. Four things the first pass did not say:

1. **The combat stake is live, but it rests on a receipt-copy string parse.** There is no emitter
   of `namedAce:defeated` anywhere in `src/` — it has two listeners (`aceMemory.js:69`,
   `provenanceLedger.js:685`) and zero publishers. The only live writer of `defeated` is
   `aceMemory._receipt` ← `encounter:receipt`, emitted by `encounterDirector.js:1312` when
   `encounterScripts.js:2411` resolves the `named_hunter` boss kill as `'killed'`. That payload
   carries **no aceId**, so the ace is recovered by scanning the player-facing receipt text
   (`HUNTER DOWN — Yara No-Cut removed from the lanes.`) for a roster name via `aceFromText`.
   The name reaches the text only because `encounterScripts.js:2309` sets `live.vars.name`.
   Three renames each kill the stake silently, and the stamped fixtures would stay green:
   the outcome word (`killed`; the sibling bounty-hunter script wipes with `cleared`, which
   `_receipt` rejects), the `{name}` var / receipt copy, and the payload key (`shape` at the
   emit site vs `shapeId` at every request site). The named test now pins all three.
2. **Killing an ace is not enough — it has to be the encounter.** `aceMemory._playerKill`
   (`entity:killed` / `combat:kill`) records player *style* only; it never sets `defeated`.
   "Beat a named ace" means live: kill the boss of a director-run `named_hunter` encounter.
   That is reachable — rare/major in ambush and outlaw zones at sector tier ≥ 2, plus the
   authored spawns aceMemory forces for culture intros and planet challenges (`ace_yara_no_cut`
   is on the Yara planet-challenge route, `planetStates.js:91`), plus the beat-5 captain binding.
3. **Tow class and one field are not walls at all.** `readTowClass` grants `medium` at
   `beatIndex >= 3` and `readFieldCount` grants a field at `beatIndex >= 2`, unconditionally.
   `flags.endgame` is only set when the spine advances off its last beat (`missions.js:6144`),
   so every run that can open the endgame already clears both bars regardless of fittings.
   The leaf's "heavy-verb tier" headline is inert on the live route; the discriminating walls
   are money, standing, the stake, and the offer flags.
4. **The fixtures never touch the offer.** They stamp `endgameOffered = true`. Live, A and B are
   board contracts posted only from `story.js:_maybeOfferEndgame` → `postEndgameDispositionOffers`,
   which additionally requires `flags.deep_reach_operation_complete` **and** one of
   `ashfall_visited` / `deep_reach_ashfall_docked` / `kurtz_desk_opened`. Those have live writers
   (`missions.js:6095`, `story.js:471/1343/1440`), so this is reachable and not a status-flipper —
   but the test proves eligibility, not that the row appears.

Confirmed live, not assumed: `evaluateEndingEligibility` is the real filing law — `_onEndgameChoose`,
the C and D routes, and the Ash Cache courier all run it, and `_endgameGateMet` is only net worth
plus standing, so the widened stake is not bypassed by a second gate. Builder stake writers:
`claims.js:228`/`1506` push `claims.bodies`; `automation.js:2133` pushes `automation.outposts`.
Standing clamps to ±1000 (`factions.js:82`), so 50 is not a ceiling problem. The B7 spine gate
(`missions.js:6111-6114`) uses the same 100k / 50 pair and the same "branch faction, else best
faction" fallback as the shared gate, so no run reaches the offer without already clearing both.

Not flipped on the missing 25 h telemetry: the owner peeled that clause. No hours are claimed here.
