DONE  PQ-033.01 — A crashed game now leaves a readable report that names the exact build, the
desktop shell can update itself from GitHub releases, and the title and pause screens show the
version together with the build it was cut from.

WHAT I FOUND     The Electron shell already wrote Crashpad dumps under userData/crashes and the
title/pause already painted a version, but nothing identified the build — a dump or a bug report
could not be tied to the code that produced it — and there was no updater at all. The leaf test
pinned the absence of updater wiring.

WHAT I CHANGED   One release identity is resolved at boot — the release receipt's bundle digest
when packaged, the git HEAD in dev, an env pin for evidence runs — and it feeds everything:
crash extras, readable crash reports, and the player-facing label. Renderer, GPU/utility-child,
and main-process faults each write a plain-JSON report next to the dumps (latest.json always
points at the newest); ordinary teardown — clean exits, routine Chromium child kills, app quit —
writes nothing. electron-updater runs on the packaged route only: it checks once, downloads
quietly, and offers a Restart prompt parented to the game window; "Later" still applies on the
next normal exit. Isolated evidence launches never touch the feed. The renderer learns the build
through the allowlisted preload bridge, or — on a statically served bundle — reads the release
receipt at the web root. electron-updater is pinned at 6.2.1, the exact release-train sibling of
the repo's electron-builder 24.13.3 (6.2.0 ships a critical mac-updater bug), and the mac target
now emits dmg+zip so the updater's required zip artifact exists.

WHAT YOU WILL FEEL   Nothing changes in play. The title and pause fine print now read
"SpaceFace v0.1.0 · <build>"; after a crash, a readable report under the game's data folder names
the build it happened on; when a new release is published, the desktop app fetches it and offers
to restart into it.
