### What the test does, step by step

1. **Session 1** — `game:started` on seed `16304` stages the leftover rescue/first-hour rail. The
   test drives the full flight drill into the three rescue verbs (swing a rock through the derelict,
   put the scout into the asteroid, run the pod to the beacon), then the missing three (boost,
   draw-to-fly stroke, well). It then settles the real 47-A contract through the live `missions`
   system: sample the marked rock, dock Helios, story beat 0 → 1.
2. **Session 2** — a Continue on the same save: the serialized `state.story` is restored and
   `save:loaded` fires (never `game:started`), so the tutorial rail cannot stage a second time. The
   test posts the live Helios board and reads the beat-1 offer.
3. **Classification** — `classifyBeatOne(offer)` returns `set_piece` only when the live board offer
   carries a physical type, a physical headline verb whose title leads with it, an authored PQ-152
   set piece, and two completion methods. A synthetic single-solution `cargo_delivery` is denied
   first, so the classifier is not a rubber stamp.
4. **Retention proxy** — the session-2 player accepts the contract, then a bare generic
   `mission:completed` is fired at it. A physical set piece cannot be settled by that fetch-shaped
   shortcut (B1–B3 only advance through the authored physical contract,
   `src/systems/missions.js _advanceEmbodiedStoryMission`), so the player is still in beat 1 at
   T+180s with no `game:exitToMenu`. Reported over the seeded cohort `16304..16308`: `100.0% (5/5)`.
