## Honesty gaps

- **The new guard is bypassed on the live route.** `_leftoverSlotRefillsDisruptedApproach` is
  only consulted on the `wasFresh` branch at `traffic.js:1772`. Two earlier `continue`
  statements — `terminalWorldRecord(record)` at 1730 and `if (record && !entity)` at 1735 —
  take that decision first in every live case: after a player kill (record destroyed) and
  after any hard exit (record active, body cleaned). Verified by booting `world` alongside
  `traffic` on one bus: killing the authored `ceres_refinery_hauler` set its record to
  `alive:false / outcome:"destroyed"`, and a hard re-enter with `disruptedStationIds`
  manually emptied still produced no hauler.
- **The test harness supplies the one state the live route does not.** `makeWorld()` builds
  `state.world = { currentSectorId, sectors: {} }` — no `records` bag — and never registers
  `world`, so `records = {}` and `wasFresh` is always true. That is why the guard appears
  decisive. The added record-branch test pins the live shape.
- **Save/load of the leftover bag is now on the leftover traffic blob.** Leftover iterate after
  this review added leftover `disruptedStationIds` to leftover `traffic.serialize()` /
  leftover `deserialize()` / leftover `newGame()`. Continue keeps the leftover bag for leftover
  recommission and leftover first-visit refill. It still does not decide leftover live
  rematerialize after leftover a leftover destroyed leftover convoy leftover record.
- **The latch never lifts.** `disruptedStationIds` is only ever pushed to. There is no decay,
  timer, patrol, or delivery that removes a station — a grep across `src/` and `test/` finds the
  identifier only inside `traffic.js`. It also gates `_recommissionCeresRefineryHauler` at
  `traffic.js:1539`, so a disrupted station blocks recommission of an existing body too.
- **The thinning is one hull of eight.** The Ceres cast materializes eight actors; only
  `ceres_refinery_hauler` is withheld. `ceres_seam_miner` carries a `dest:station_ceres` route
  mark and still spawns, because `leftoverHaulerSlot` keys on
  `presentationRole === 'hauler' || jobKind === 'hauler'` and that slot is `ore_carrier` /
  `miner`. `ceres_ambush_loaded_hauler` is a hauler but its marks are `activity:throughline-*`,
  so it is untouched.
- **The generic ambient top-up claim has no coverage.** `_leftoverStationOpenForTopUp` lives on
  the non-Ceres branch of `_onSectorEnter`; the Ceres branch returns before reaching it. Every
  test in this file enters `sector_ceres_belt`, so that reader is exercised zero times. The
  earlier claim that "generic ambient top-up will not pick a disrupted station" was a code read,
  not a proven behavior.
- **What the input trace did confirm.** The station id the guard needs is produced by the live
  path, not only by the plant. Killing the authored `ceres_refinery_hauler` — which materialize
  gives `targetId = null` and no `data.stationId` — still resolves `station_ceres` through
  `_leftoverKillStationId`'s `_nearestStationId` fallback. The refinery pocket anchor is
  `station_ceres`'s own position and the only other station in the sector, `station_beltout`,
  sits roughly 2000 WU away, so that fallback is not fragile.
- **The kill is injected.** Same `entity:killed` shape as `combat.js:585`. No gun, physics, AI,
  or law system runs.
- **The witness is planted.** `_markRouteDisrupted` needs a second hauler bound for
  `station_ceres`. The live cast does not guarantee one.
- **The 8 s is decorative.** All writes land inside the two emits.
- **The rumor is in-session.** `pirateRumor` does not serialize `lastHeadline` /
  `ui.pirateRumor`. A save/load can drop the card until another surface event.
- **The route copy is presentation.** `routeDisrupted` is a boolean; the sentence is
  `dockArrival` copy over a hull count.
- No shipping-camera strip. The campaign forbade headed capture.

`_materializeCeresActivityCast` — so it decides on the path the live route actually takes — and
prove it with `world` booted on the same bus, or drop the claim and state plainly that a
destroyed durable record is what keeps the Ceres approach thin. If the persist is meant to
survive Continue, add `disruptedStationIds` to `traffic.serialize()` / `deserialize()`, and give
it a way to lift.
