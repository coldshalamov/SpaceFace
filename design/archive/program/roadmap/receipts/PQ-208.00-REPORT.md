## What the guard enforces

`scripts/check-progression-verb-audit.mjs` (run by `npm run check:progression:verbs`) keeps its
existing scalar/verb/intel classification and its vocabulary drift guard (a module `mods` key the
vocabulary does not know fails the run). Leaf .00 adds the second, previously missing failure mode —
**consumer drift**:

- Every registered verb key in `VERB_MOD_KEYS` now carries consumer **evidence**, verified against
  live source on every run: `{ file, symbol }` requires `symbol` to occur in the named file.
  16 keys verify this way, including the four formerly "landing lane" keys (`swingDrive`,
  `lootMagnetRange`, `towFlail`, `pointDefense`) whose consumers have now landed and are pinned
  mechanically (`flightV3.js`, `lootShards.js`, `collisionConsequences.js`, `countermeasures.js`).
- A verb key with no direct key consumer may only be registered as
  `{ declaredOnly: '<packet leaf>' }` — an honest, loud label printed in the generated report on
  every run. The two packet-named keys carry `declaredOnly: 'PQ-208.01'` with a note stating the
  precise current truth: their behaviour ships by module id (pale-coil dash blink /
  choir-bell missile knockback in `src/systems/uniqueLootAbilities.js`); no system reads the mods
  keys themselves. Resolving them (wire or reclassify) is leaf .01's decision.
- Fail-closed: a verb key with a missing evidence block, malformed evidence, a `declaredOnly`
  label without a tracking leaf, a deleted consumer file, or a vanished consumer symbol is fatal —
  the audit exits nonzero with a `DECLARED VERB '<key>' names no implemented behaviour` FAIL line.

The pure guard pieces (`keyClass`, `classifyModule`, `classifyWeapon`, `auditModules`,
`verifyVerbKeyConsumers`, `runAudit`) are exported; the CLI behaviour (report on stdout, `--write=`,
exit codes) is unchanged and only runs when the script is the entry point.
