## Status: DONE — the per-refresh ledger page is gone; the line still reads the same

`leftoverRapLine` answered "does this hull's file hold a fact?" by building a whole
`buildShipLedger` page and scanning page 0's 24 entries. The berth refresh runs every 18 frames
(`src/ui/uiRoot.js` — `this._rt % 18 === 0` → `def.refresh(ctx, {periodic:true})` →
`stationApp.refresh()` → `renderStatus()` → `buildDockArrival` → `leftoverMechanicCard`), so a
scarred hull paid the full projection — every source family walked, a candidate object per admitted
row, template prose, `toLocaleString`, `deepFreeze` — roughly 3.3 times a second while docked, to
produce one boolean.

The line now asks `shipLedgerHasFactOutside(state, HULL_HISTORY_TYPES)`: the same walk, the same
admission rules, stopping at the first admitted row outside hull history, building no candidate
objects and no page. The ledger's own projection paths are untouched; `buildShipLedger` output is
byte-identical against `492bb4a9d^` (old vs new compared over a six-state corpus including
duplicate-heavy, 900-row and cap-overflow trades, plus per-family states).

Two commits: `492bb4a9d` (the probe) and `9f5af58aa` (the verification pass — per-iteration guards
in the loss/scar/renown families, the session sink answering on the row, comment accuracy).

## The one deliberate delta

Presence, not a window. The old check read page 0 (the newest 24 rows), which was an artifact of
asking for a page; the copy says *already has a fact*. Two same-direction edges follow: a fact the
newest 24 rows had pushed out, and a fact beyond `SHIP_LEDGER_MAX_ENTRIES` (240) that no page shows
at all. In both the ledger does hold the fact, so the line is truthful; the old code stayed silent.
The delta is pinned in the new test (`scratch-pq207-delta.mjs` isolates it). Nothing else differs:
page output is byte-identical for every state compared.

## Independent verification

Three read-only agents reviewed the change (two static, one with a shell on the final revision):

- **Adversarial pass** enumerated all 14 source families and confirmed every one can stop in probe
  mode; confirmed `probe.hit` cannot be set by an excluded type, that probe mode never calls
  `makeCandidate` and never pushes a candidate, and that `observed` counting is unchanged for the
  non-probe path. It found no correctness defect, and its two cost findings (the loss family
  walking past a hit, and the session-sink row building its receipt before asking) became `9f5af58aa`.
- **Quality pass** endorsed the seam (a check in `mechanicVoice.js` would duplicate the family list;
  an option on `buildShipLedger` would return a misleading page; a cache would add invalidation to a
  deliberately stateless projection), found the same two cost misses plus an inaccurate trade
  comment, and confirmed the delta is documented where a future reader looks.
- **Dynamic pass** re-ran the benchmark, the old-vs-new page comparison and the family corpus on the
  final revision: card 13.3 us / arrival 11.9 us against a 2463 us page on the 240-row state (~185x);
  its own timing showed the card flat across ledger size (7.9 us at 240 rows, 6.6 us at 900) while
  the page scales 1689 us → 5420 us (815x). Its own 13-state adversarial corpus (no loss ledger,
  empty arrays, duplicate rows, repeated receipt ids, 600 titles, scars+patches+renown only, >512
  observed rows, null/NaN shapes, negative times, evidence receipts) produced **zero page diffs**,
  **zero probe misses** and **zero probe false positives**; 15 family-isolation states all probed
  true with a scars-only control false. It also measured the revert: putting `buildShipLedger` back
  fails three tests (the source pin, the delta case, and the budget assertion at 3.269 ms).
