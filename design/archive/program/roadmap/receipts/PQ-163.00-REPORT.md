## What is still NOT proven, and cannot be from here

- **The crossing.** Both in-play tests set `scout.pos = asteroid.pos + 40` by hand. What the file
  proves is packet admission plus the speed the gun raises; the ~118 wu the scout must travel, and
  the 5 wu/s random-bearing drift pulling it off the wall line during that travel, are unsimulated.
  Arithmetic says it fits (≈5.6 s at 4 hits, ≈28 wu of lateral drift against a 64 wu contact ring)
  — arithmetic is not a run.
- **`physics_rejected`.** `impulseApplied: true` in the LIVE GATE is guaranteed by the test's own
  port. Production routes to SG-02's `applyImpulse`, which returns `false` without a live dynamic
  record. No node test can observe that failure mode; only a live route can.

- **Any picture.** GPU/browser ban observed. No headed capture, no live walk.

## Two leftovers this iterate created or exposed

1. **The scout is now killable, and the restage moves the target off the wall line.**
   `_onRescueKilled` has no scout branch, so a destroyed scout is caught one 0.2 s resolve tick
   later by `_resolveRescueDone` → `_rescueFail('shove', 'scout lost')` → `_respawnRescueSlot`.
   That is a retry, not a wall — newly pinned by a test. But `_respawnRescueSlot` re-rolls a whole
   tableau bearing from the *current* player position and spawns the scout slot only, so the
   standing asteroid keeps its old position while the fresh scout is placed relative to a bearing
   that no longer relates to it. The first attempt is a clean "push it along this line"; the retry
   is not. Before this iterate the scout could not be destroyed, so this path was reachable only by
   the 1500 wu escape.
2. **500 hull invites the wrong verb.** The marker says "Scout" one beat after the game teaches
   shooting. 96 landed starter hits to destroy an unarmed, non-firing drone is a long time to spend
   confirming that killing it is not the lesson. The hull raise is defensible (the body must survive
   the burst); the number chosen is ~5x what the code comment says it is for.
