# PQ-138.01 — Spilled cargo is noticed

## WHAT I FOUND

When a freight hauler was gutted and its cargo pods went tumbling into space, **nothing in the world
noticed**. Not the two salvage ships already flying around that same sector with nothing to do. Not
the station whose lane it happened in. The pods just sat there until they timed out and vanished.

The game already announces the spill — it fires an event called `freight:cargoSpilled` the moment
the cargo comes loose. That event had **zero listeners anywhere in the game**. It was a radio call
into a dead channel.

Worse, the bench claimed this bar was passing: it reported "a salvor arrives 3.75 seconds after the
spill". That number was arithmetic — a made-up distance divided by a made-up speed, from a scenario
that spawned nothing and ran no game at all.

## WHAT I CHANGED

Somebody is listening now. When cargo spills, the salvage yards hear it:

- The pods from that spill are flagged as work worth doing.
- The usual 18-to-45-second "somebody eventually notices a hulk out there" delay is **skipped for an
  announced spill** — this one came over the distress channel, so nobody has to stumble across it.
- The existing salvage dispatch is asked to look again, and it prefers an idle salvage ship that is
  already in the sector over spawning a new one.

No new ship was added to the game to make this work. No spawn count was raised. The salvor that
comes is one that was already out there doing nothing.

## WHAT YOU WILL FEEL

You blow open a hauler, its cargo scatters — and inside half a minute a salvage cutter is on its way
in to pick over what you left. The wreckage you make is now somebody else's opportunity, and if you
want that cargo you are now in a race for it.

### Engineering appendix

- **Hypothesis line.** `freight:cargoSpilled` (emitted at `encounterScripts.js:1314` and `:1533`) has
  zero `.on()` subscribers in `src/`, so spilled freight is inert, which breaks the vision sentence
  "a scavenger appears after something goes wrong"; one listener in `traffic.js` that flags the pods
  as salvageable and re-runs the existing dispatch should move bar B10b from NEVER to ≤ 30 s.
- **Files:** `src/systems/traffic.js` only.
- **Mechanism (connection, not construction):**
  - `_onFreightCargoSpilled` collects the spill's pods (by `encounterId`, else within 240 WU of the
    named carrier), sets `data.spillNoticed = true` and `data.salvorNoticeAt = simTime + 2`, clears
    the salvage-target cache and calls the **existing** `_dispatchGeneralSalvors(sectorId)`.
  - `_isSalvageableBody` additionally accepts a `pickup` that carries a `freightCustodyPod`, has a
    positive `amount`, and has been flagged `spillNoticed`.
  - Verified the delay skip actually works: `_salvorNoticeReady` only invents its
    `18 + hash32(...) % 27` stumble delay when `data.salvorNoticeAt` is **not** already finite, so
    pre-setting the field is the supported way to shortcut it. Without this the 18–45 s stumble alone
    would blow the 30 s bar.
  - Verified the sector salvor cap is not a blocker: `_dispatchGeneralSalvors` **prefers an existing
    idle salvor hull** (`for (const rec of state.traffic.freighters) … if (ent.data.jobId) continue`)
    and only calls `_spawnGeneralSalvorNear` when none is free. With `MAX_GENERAL_SALVORS_PER_SECTOR`
    at 2 and two salvors already alive, the arrival measured is a re-tasking, not a spawn — which is
    exactly what "connection, not construction" requires. The instrument confirms it:
    `arriverRole: 'salvor'`, `arriverHadJob: true`, `salvorsInSector: 2` unchanged.
- **Determinism:** no `Math.random`, no `Date.now`, no host branching. All timing derives from
  `state.simTime`; the pre-existing stumble roll uses `hash32(seed, …)` off `state.meta.seed`.
- **Cohort guard:** the handler returns early if the carrier or any pod carries
  `data.runCohort === 'survival'` — per entity, per the recorded ruling (there is no
  `state.runCohort`). A Crucible run cannot dispatch campaign salvors.
- **Golden safety:** the handler cannot fire unless `freight:cargoSpilled` fires, and that event is
  emitted only from the two freight-encounter paths in `encounterScripts.js` (carrier destroyed /
  disabled, and a raider re-spill). `grep -rln 'cargoSpilled\|freightCustodyPod' src/story/
  test/*.expected.json test/fixtures/` is **empty** — no replay tape and no fixture carries the
  trigger. `_isSalvageableBody`'s new branch requires `spillNoticed`, which only this handler sets,
  so a tape containing ordinary cargo pickups is unaffected. `_dispatchGeneralSalvors` already
  carried the golden guard (`typeof assign !== 'function' → return 0`); the shipped test "golden-style
  sessions without npcJobs never spawn general salvors" still passes.
- **Single writers:** the handler writes only pod `data` flags, clears its own cache and calls the
  existing dispatch. No credits, no reputation, no heat, no `npcJobs.js`.
- **`traffic:spillNoticed`** is emitted as a receipt. Nothing consumes it today — it is a debugging
  and test hook, not a contract. Noted rather than hidden.
- **Scenario / seeds:** `world.reaction_trio` clause B10b, seeds 4242 and 8008. Probe:
  `node .devshots/fun-loop/lanes/WORLD/probe/run-trio2.mjs --seed=4242`.
- **Checks run (raw):** `node --test` over `salvor-occupation`, `traffic-freight-role-agreement`,
  `traffic-role-mix-reads-contents`, `pq048-salvage-cutter-loop`, `salvage-station-intake`,
  `depth-program-authored-salvage`, `npc-jobs-runtime-wiring` — 46 pass, 1 fail. The single failure
  is `npc-jobs-runtime-wiring`'s "envelope stamped v12" case: it pins the save envelope at v12 while
  the game is at v14, and this lane touches no file under `src/save/`
  (`git diff HEAD --stat -- src/save/` is empty). Pre-existing, not this leaf.
