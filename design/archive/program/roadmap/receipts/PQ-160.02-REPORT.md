# PQ-160.02 — Seeds and ghosts (receipt)

DONE PQ-160.02 — Two machines reproduce the same Crucible run from a paste-able code at seed
16002. The run travels as an `SFC1-` seed/build code; the recorded hull travels as an `SFG1-`
ghost block. A shared ghost renders as a translucent hull (opacity 0.32), never a combatant.

WHAT I FOUND — Crucible already remembered a launch (`lastCrucibleSetup`), recorded a local ghost
pose tape (`survivalRecords` / `survivalRun`), and drew a translucent clone when a ghost was
armed (`crucibleGhost.js`). Nothing turned that run into a code another machine could paste, and
nothing turned the tape into a file another machine could import.

WHAT I CHANGED — Added a checksummed share envelope (`SFC1` run codes, `SFG1` ghost blocks) that
fails closed on tamper, truncation, or a starter this build does not ship. The Crucible door
gained paste fields for both. The results plate gained a Share band with selectable text and
download links. A clean-room child process receives only the code string and the ghost file,
reruns the production swarm, and matches the exporter's run hash.

WHAT YOU WILL FEEL — Finish a Crucible run and the results plate offers a code. Paste that code
on another machine's Crucible door and it loads the same seed, the same starter, the same rules.
Paste the ghost block and a translucent hull races you. A bad paste says why instead of launching
a different run.
