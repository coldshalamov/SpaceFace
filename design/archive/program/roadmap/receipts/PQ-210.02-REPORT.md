## Measurement honesty

The packet's formal bar is frames over 33 ms **≤ 5 %**. Two settled references on this host
bracket the honest read:

- Settled (30 s settle) at 75 % host CPU: **18.2 %** over 33 ms — and the best opening run
  (17.5 % at 42 % CPU) meets that mark.
- Settled (30 s settle) at 38 % host CPU: **1.9 %** over 33 ms (p50 16.7 ms, worst 50 ms,
  sim at 100 % real-time, zero hitch callbacks). At comparable host load the opening still
  carries a ~15-point residual over settled.

That residual is attributed, not unexplained: it is the scripted opening tableau spawning
*live* — `game:started` plus beat-cadence `spawnEntity` calls (drone hauler, payloads, beacons,
wreck, raider/convoy hulls, instance-pool chunk promotions). Each spawn pays sim-side spawn
cost (22–36 ms sim spikes visible in the worst-frame table), the exempt-path mesh build, and
first-draw buffer uploads — the same work a wave arrival pays inside any later 20 s window.
It is not leftover loading work: the queue that used to drain one-compile-per-presented-frame
now reads `admissions queued at flight: pipelines 0`, and draw-time links fell from ~25 to 2.

The leaf's own named check makes the same point on the same host: `probe:smooth-flight:crucible`
(no settle, 42 % CPU, seed 4242) read **29.8 %** over 33 ms — and its worst frames are the same
signature: a scripted wreck/asteroid swarm arriving at +23–29 s in-window paid 27 mesh builds,
~60 draw-time links and dozens of buffer uploads mid-flight. Live content arriving is expensive
in every regime; the opening's residual is one instance of that, not an opening-specific defect.

The only machinery that could remove instance-level spawn cost — exemplar/roster prewarm — is
deliberately unwired after PQ-210.00 measured it as a regression on this exact host
(launch 63 s → 205 s with the catalog; more in-round links without it). Reordering the tableau
earlier into loading would touch rng-adjacent sim ordering, which this leaf must not do.

## Considered and rejected

- **Roster/type prewarm for the opening cast** (spawnable-hull exemplars mounted hidden behind
  the shell): the PQ-210.00 receipt measured both wirings as regressions on this host
  (launch 63 s → 205 s; without the catalog, MORE in-round links than unwired). The mechanism
  stays deliberately unwired.
- **Widening `prepareLiveSectorAfterJump`'s collect set** the same way: rejected — the jump
  path already drains its whole mesh-build queue behind the jump shell
  (`_drainMeshBuildQueue(Infinity)` at ~7472); the opening's defect was the 20 s residency hold
  parking builds *in flight*, which does not exist on jumps.
- **Moving the tableau spawns into loading**: rejected — spawn order is rng-adjacent sim
  work; reordering risks determinism for a render-layer goal.
