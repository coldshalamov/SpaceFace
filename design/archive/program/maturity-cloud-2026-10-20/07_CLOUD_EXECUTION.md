# 07 · Cloud execution and delivery workflow

## One-shot contract

One packet produces one coherent runtime/data/presentation improvement, its focused regressions,
and one draft PR. It does not mean the entire parent campaign is finished. A documentation-only
PR, an unused helper or a test with no changed player outcome does not count as production.
The ten packets are source-oriented and do not require new assets or a quiet GPU to begin.

## Preflight before editing

1. Read root and nearest `AGENTS.md`, `build_map.md`, the packet and its parent row. Read current
   `NOW.md` and open PR changed paths; old lane names are not permanent reservations.
2. Fetch public master and record the exact SHA. This pack's baseline is evidence, not a pin that
   future work must remain on. Create an isolated `cloud/maturity-<packet>-<date>` branch from the
   agreed public base. Never switch or reset a shared dirty checkout.
3. Trace the ordinary public route and real producer/consumer for the packet. Search for an existing
   implementation by both symbol and player outcome. If already complete, return the evidence and
   choose another unowned packet only under the controller's assignment; do not invent a near-copy.
4. Compare overlapping open PR hunks. Do not merge, cherry-pick, alter or absorb another agent's
   branch. A real same-hunk dependency is integration order; useful disjoint work may continue.
5. Name the small exact write set. A newly necessary preload/check registration is permitted only
   with a concrete dependency; no lockfile updates, CI redesign, broad formatting or architecture reset.

## Build loop

Reproduce the named gap at the cheapest truthful layer. Define input/output and negative cases.
Implement through existing writers. Run the focused regression, adjacent owner checks, then one
ordinary public-route or screen-bench check appropriate to the change. Fix attributable failures.
Preserve and label unrelated failures; unchanged source alone is not proof that a failure is baseline.

Keep simulation deterministic using existing seeded RNG and simulation time. Projections do not
write gameplay. No per-frame full-world scans, unbounded histories or persistent UI caches. Retire
listeners and pending callbacks at their owner lifecycle. Repeated input must not double-settle.

Use production functions in tests. Mocks may represent external boundaries, not replace the owner
whose behavior is claimed. A success test needs an adversarial counterpart that would catch the
original lie, invalid identity, hidden knowledge or repeated settlement.

## Evidence ladder

- **Source verified:** owner and call path read at a named revision.
- **Focused green:** listed real-owner tests pass on the exact proposed tree.
- **Route demonstrated:** ordinary UI/command route exercised, with setup shortcuts disclosed.
- **Visual/feel assessed:** actual supported presentation inspected, not inferred from DOM or mocks.
- **Integrated:** owner merged into the named public branch; distinct from every acceptance level.

Use current repo test selection and UI benches. Do not invent CLI options or claim a command was
run because it appears in this plan. Discover exact bench IDs via the current script/help. Physical
phone, quiet-host performance and whole-game acceptance are never inferred from headless success.
If the required host is absent, deliver the verified source slice and a precise unaccepted boundary,
not a fake screenshot or weaker gate. Keep existing global status open where that boundary matters.

## PR handoff

The PR body names parent row and packet, baseline/head, player result, exact write set, ordinary
entry, tests actually run, baseline-versus-new failures, current collision/dependency status and
remaining visual/device evidence. Attach a short capture only when actually produced. Use exact-path
commits, no force push, no blanket staging. Update only the controller-authorized existing program
surface at integration. This pack does not create a second completion ledger or perpetual monitor.
