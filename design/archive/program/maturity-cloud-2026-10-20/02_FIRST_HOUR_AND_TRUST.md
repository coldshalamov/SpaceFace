## Implementation workflow

Choose one broken transition, record its exact base and public steps, and trace input → command →
canonical owner → read model → visible response. Repair the first incorrect edge. Prefer the
smallest production fix with a behavioral regression; a new observer is justified only when the
existing evidence cannot distinguish two plausible causes.

Recheck the next transition, not every subsystem. A corrected BUY button still needs one real
trade and the resulting cargo/credits readout. A corrected departure still needs flight with the
same course. Additions to default import/preload/check registries are part of wiring, not optional
cleanup, but modify only the actual required entry.

## Interruption matrix

For the touched workflow test double input, pause/modal focus, target retirement, scene departure,
failed asynchronous completion, cancellation, save/load and a legitimate retry as applicable.
A stale callback must not re-open a screen, grant a reward, overwrite a new target or mutate the
next run. Use the real command handler; a fake owner that simply returns success proves nothing.

Functional acceptance and presentation acceptance are different. DOM rectangles can prove no
measured overlap; they cannot prove that an enemy reads against the backdrop. Native/headed captures
on the prescribed host establish visual claims. Software rendering does not certify phone GPU or
minimum-spec frame time. No test budget or quality setting is weakened merely to turn a result green.

candidate, with truthful remaining evidence. Row 454 closes only after the integrated route meets

entire 25-hour progression. Reuse the fixes before adding another tutorial system.
