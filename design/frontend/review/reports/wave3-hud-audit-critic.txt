   Interaction clarity 1.0 / — : no control, verb, or reading is reachable on screen.
3. PREVIOUS LIST: none (first audit). Nothing to carry.
4. MOUNT DIAGNOSIS (read-only inspection; nothing edited):
   The bench DID mount the preview (DOM text with real rects is what the audit measured), but the
   whole stage paints into a ~0x0 box, so every child is clipped and the still shows only backdrop.
   Chain, all verified in source:
   a) flightPreview.js:14 stages `.orr-flightpreview { position:fixed; inset:0; overflow:hidden; ... }`.
   b) tools/ui-bench.js goto() mounts EVERY screen inside a root div `.screen.sf-screen--visible`.
   c) styles/ui.css:143-154 puts `transform: translateY(0)` on `.screen` (push/pop transition).
      A non-none transform makes the root the containing block for fixed descendants, so the
      stage's inset:0 resolves to the ROOT's box, not the viewport.
   d) The root is a centered flex item of #screens (ui-bench.html: flex, center/center) whose only
      child is the out-of-flow stage, so it collapses to ~0x0 at viewport center; the stage's
      overflow:hidden then clips all paint. Layout rects survive (hence CUT OFF/OFF FRAME findings
      on "Helios Prime", "Contract", Charge/Blast/Line/Fieldwork/Rig/Bay), paint does not.
   e) Bench-only failure. flightPreview.js is imported ONLY by tools/ui-bench.js (sole match in
      src/tools/scripts besides a generated localization catalog). The live game never mounts
      orreryFlightScreen — Phase 1 mounts the Cluster via hudAdapter.mountOrreryCluster into #hud
      as an in-flow absolute host (hudAdapter.js:140-147,154-178): no fixed positioning, no
      transformed ancestor on that path. The live flight stills in this same batch SHOW the
      ORRERY cluster working, which corroborates that only the bench staging of the preview fails.
   SMALLEST STAGING STEP THAT MAKES IT SCOREABLE (one rule, bench side, no component change):
     .screen[data-screen="orreryFlight"] { transform: none; }
   added to the <style> in tools/ui-bench.html. With transform:none the fixed stage resolves to
   the viewport again; the bench never runs push/pop transitions so nothing is lost. (Component-side
   hardening for later: position:absolute + the screen stretching its own root — see O5.)
5. RANKED FIXES (unblock + acceptance; HUD craft cannot be ranked until paint exists):
   O1. Bench root transform (tools/ui-bench.html <style>, staging only). The .screen root's
     translateY(0) collapses the fixed preview stage to ~0x0 (see §4). Add the one rule above.
     PERF: n/a (bench staging; zero runtime cost).
   O2. Re-shoot acceptance: cluster. After O1 the Cluster must occupy (18,516)-(778,1056) with
     hull art + ring stack + 104px speed numeral visible. PERF: n/a.
   O3. Re-shoot acceptance: tape + place. Objective tape 640px wide top-center (640..1280, 26..110)
     and place block at (40,34) must be on-frame; quoted CUT OFF findings must clear. PERF: n/a.
   O4. Re-shoot acceptance: verbs. All nine verb keys + four group nodes must sit x<700 (crescent
     radius 262 from pivot); quoted OFF FRAME findings must clear. PERF: n/a.
   O5. Harden flightPreview.js (follow-up, not the unblock): replace position:fixed with
     position:absolute AND stretch the mount root (flex:1; align-self:stretch; position:relative)
     so no transformed ancestor in any host (bench or game uiRoot) can re-collapse it. PERF: n/a.
6. MEMORABLE LINE: A flight HUD that powers up like an orrery waking — rings drawing themselves
   round your own hull. Currently it never wakes at all.
7. OWNER CRITERIA: (a) FAIL by absence — no instrument is visible, so none can carry weight; the
   quoted CUT OFF/OFF FRAME text proves layout without paint. (b) FAIL by absence — no signature
   interaction can be seen. Screen NOT PASSED.
