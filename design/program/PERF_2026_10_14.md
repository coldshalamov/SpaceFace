## Executable method

`node scripts/performance-campaign.mjs --label=<unique-name>` runs sequential isolated Electron
cells for Adventure opening/settled flight, Swarm opening/settled flight, Gauntlet opening and
the public Circuits → Orbital Gallery racing route.
Two further cells hold thrust for 90 seconds before sampling: `adventure-travel` and
`racing-travel`. A settled cell waits stationary; a travel cell pays real streaming and residency.
Each holds W for 20 seconds at default settings. These are targeted performance workloads,
not gameplay acceptance or a claim to cover every sector or long-session state.

`--cells=adventure-early,swarm-early` selects a narrower cycle. Repeat after a runtime fix with
`--baseline=<before-name>`. Raw rows and reports live under `.devshots/performance-campaign/`;
source digest, commit, settings, GPU, runtime, viewport, CPU, host load and observer identity
travel with each cell. Unique names protect baseline files. Each child has a five-minute bound
and the runner terminates its own child process tree on Windows if it overruns.

`--diagnose` follows the largest measured p99 with main/worker CPU profiles, CDP timeline,
GPU pass queries and worker work/packing/domain-diff costs. That observer has its own identity;
its timings are diagnostic, never compared with the cadence-only baseline. GPU queries pause
and drain before their report, preserving invalid/disjoint/time-out verdicts. It also runs Perfetto
slice SQL when the installed wrapper is present; `--trace-processor=<executable>` supports an
external installation. Import-health warnings are retained and overlapping inclusive slice
durations are not additive wall time. `--spector` records a separate actual-draw GL diagnostic.
`--frame-solid`
runs the existing fly-away/return/loiter admission check; `--soak` runs four isolated Electron
lifecycle cycles; `--verify` runs the four headed player-truth gates sequentially. Each writes
its own log and workflow exit; one failed branch does not suppress the independent branches.
The runner measures the Electron window's display frequency and requires >=95% of it for
the full target. Missing hardware/route identity cannot pass a comparison.

Compare world-submit FPS, submission p95, callback p99, >50/100 ms gaps, sim/wall progress and
world/simulation staleness. Repeated successful draws of an unchanged simulation snapshot
are counted separately from a renderer that stops submitting. A 3x claim requires the specified hitch-rate gain and lower p99, no cadence regression, no hidden world
freeze, and separate picture/behavior acceptance. Report vsync saturation honestly: reaching
60 Hz from 40 Hz is 1.5x FPS, even when a measured internal cost falls 3x.

Select the largest measured cost; implement one causal runtime change; run the real-function
regression and matching route; keep a measured improvement or revert the owned hunk. Continue
to the next remaining measured cost. Do not make an unrelated port to satisfy an option count.

## Diagnostic branches and open-source tools

| Measured condition | Existing workflow | Runtime intervention |
|---|---|---|
| Game CPU busy, unknown native cost | `probe-main-thread-profile --sampling-us=4000 --trace`; Perfetto SQL on `trace.json` | Remove identified scans, redundant writes, allocations, driver round trips or serialize/clone work |
| GPU submission/fill dominates | `--gpu-timers`; `perf:spector` on a separate diagnostic session | Shared programs, retained batching, conservative caster sets, exact post-pass fusion |
| Early flight or first encounter hitch | `probe-frame-solid --cpu-profile`, opening cook ledger, shader timeline | Cheaper asset composition, same-key preparation, bounded uploads, predictive residency |
| Retained memory or repeated GC | Launch `--heap-sampling`, witness `--alloc-probe` / `--gc-probe`, isolated `perf:memlab` cycle | Fix retainers, dispose owners, reuse buffers; preserve context recovery |
| Sector, dock, save or fast traversal hitch | Witness production-route matrix | Fix the named transition owner, then rerun that route |
| Simulation/worker transport dominates | Worker diagnostics + authoritative fixed-seed comparison | Incremental mirrors, dense snapshots, reduced duplicate work; no clock or event-order changes |
| Structural options exhausted | PERF_OPTION_SPACE platform spike matrix | Bounded Worker/WASM/WebGPU/native experiment with measured transport cost and rollback |

CDP/V8, Playwright, Spector.js, stats-gl, MemLab, glTF Transform, meshoptimizer and KTX2/Basis
already exist; extend them rather than adding twins. Perfetto v58.2 Trace Processor was installed
under ignored `.devshots/tools/perfetto/` from the official wrapper; Apache-2.0, offline diagnostic
only, no game runtime/bundle/save/determinism cost. Its Windows binary is cached by the wrapper.
Use `python .devshots/tools/perfetto/trace_processor query <trace.json> '<SQL>'`.
Official references: [Trace Processor](https://perfetto.dev/docs/analysis/trace-processor),
[CDP Profiler](https://chromedevtools.github.io/devtools-protocol/tot/Profiler/),
