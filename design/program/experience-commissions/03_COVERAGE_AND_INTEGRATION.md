# Coverage and integration — own the whole without colliding

## Two kinds of ownership

A **place owner** owns the coherent player result in a bounded geography. A **shared owner** owns one canonical mechanism or cross-area experience. A place owner can require a working contact interaction, but cannot quietly introduce its own contact system. A shared owner must prove the mechanism in an actual place instead of delivering an abstract framework and leaving content agents to invent its integration.

One accountable lead integrates each commission. Specialists receive exact production deliverables and write sets, not broad uncontrolled mandates. Existing native claims and current branches determine available paths. The EC labels organize these documents only.

Agreements should be concise and live with existing work. They do not require a committee or a new universal API. Agree a narrow shape, integrate one real consumer, then extend proven seams. Keep one writer for each state authority and one current writer per exact path.

## Parallel sequence without an all-or-nothing dependency trap

Begin with the Helios and Foundry fronts plus the existing camera/presentation/engine owners. Prove reusable people/work/custody integration there. Expand to Ceres and Tethys while fitting and ordinary work mature. Expand to Charon for visible consequence, Dione/Io for institutions and influence, and other sectors according to free paths and existing campaign priorities. Art production for later places can happen concurrently against agreed asset contracts.

The `coordination` arrays in `manifest.json` deliberately include mutual relationships. **They are not a DAG of prerequisites.** A tool must not topologically sort them and declare a deadlock. A camera owner can investigate a real large-object defect while the interior owner authors geometry; neither waits for the other's entire commission. Only the acceptance claim depending on the missing boundary remains open.

Do not hold a finished local PR hostage to the entire galaxy. Do not close the whole galaxy because one local PR is finished. The native integrator records which outcomes are implemented, which are accepted, which need a shared fix and which remain unverified.

## PR and merge discipline

Choose an exact area/shared boundary and current base. Coordinate any common manifest or owner integration hunk instead of scattering repeated edits across all branches. Keep linked dependency stacks understandable; rebase/reset/force-push and broad staging are not permitted where current repository instructions prohibit them. A patch to an unrelated UI PR is not an acceptable shortcut around permissions.

An area-level PR can contain many coherent files. Its logical unit is the playable outcome, not an arbitrary line count. When it must be split, every child points to the parent experience and leaves the remaining obligation explicit. Merge/deploy remains separately authorized. After integration, repeat the affected ordinary routes on the actual candidate: branch-local success does not prove the combined game.

## Release scope and future expansion

The library is a finite specification for the whole named experience. It leaves design variables to capable agents but does not grant permission to add unrelated mechanics indefinitely. Optional later expansion belongs in native planning after this commissioned promise works. The user should not have to keep explaining that a town requires useful people or that a boss death needs an outcome.
