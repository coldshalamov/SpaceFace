## Diagnosis and decision

The existing dock catalog already had stable contact IDs, authored voices, appearance gates,
persistent conversation/deed counters, and working mission acceptance/settlement owners.
Lantern Ward already had a real working Nessa launch, lamp repair, causal history, and optional
ship hail. The scanner's common hail rejected station bodies; the named dock contacts had no
shared flight address. Dock mission attention knew cargo/clauses/readiness, but flight contacts
did not consume that result. This was a missing connection between working native systems.

Three remedies were considered:

| Remedy | Player benefit | Cost and risk | Decision |
| --- | --- | --- | --- |
| Add station-tab instructions and larger markers | Makes existing menus easier to find | Leaves the physical hail/identity connection absent | Rejected |
| Spawn another named ship for every dock character | Individual moving silhouettes | Duplicates lives, needs actor/culling/save budgets, risks conflicting world records | Rejected |
| Make actual station berths answer through the existing hail, using the existing catalog and owners | A repeatable physical address, optional conversation, truthful work and memory | One bounded read model and existing scanner/UI route; no new actor population or quest store | Implemented |

The address is the berth itself for its stationed residents. Nessa remains at her original working
launch; the dock card explicitly says **field radio** and can mark that real launch. The code does
not claim she is physically in the bar, revive a lost launch, or create an offscreen duplicate.

## What the player can now do

1. Select a real nearby station in flight and use **HAIL**, including the existing Alt comms fan.
   The same person and stable contact ID appear in flight and at the dock. A selected target is the
   only signal surface; there is no icon on every background actor.
2. Ask for work, a local word, or the next eligible resident. The contact name, authored role,
   current purpose and actionable sentence use the existing two-line/three-action hail contract.
   Resident text wraps; a named **Close resident conversation** button revokes its live actions.
3. Read three distinct signals: **! Work available**, **◇ Work in progress**, and
   **✓ Ready to settle**. Accessible labels include words, not just a shape or color. Scanner reads
   these at its existing 5 Hz cadence and retires stale actions when cargo, posting, eligibility,
   completion, failure, or identity changes.
4. Accept an ordinary remote-safe contract through the mission owner. Cargo-loading, clause-bearing,
   story-choice and special physical work instead provide **Approach for work**. The player still
   docks for those terms and for settlement; hail cannot teleport sealed freight into the hold.
5. Ask for directions without automatically engaging autopilot, docking, pausing, moving the camera,
   or changing flight input. Navigation binds the real current body through its normal owner.
6. Return to acknowledgment based on committed mission receipts and existing deed counters.
   Reading or replaying a conversation cannot grant the mission reward again. Depth contacts keep
   their authored counter-driven voice; Nessa reads the actual lamp/work history.

## Ownership and implementation

The station catalog was moved without changing its existing IDs or authored content. The mission
attention implementation was moved from UI into the native missions helper and re-exported at its
old UI address. This removes a UI dependency from simulation without duplicating settlement logic.

`missions.contactOfferReadiness` reads current offers, expiry, clause-gambit reconstruction, causal
lead/disposition validity, captain gates, standing/rank/berth/capacity rules, active limits and fees.
Acceptance still goes through `missions.acceptMission`; cargo, economy, navigation and lamp repair
retain their existing writers. Flight dialogue records only the existing contact memory event.

Resident choices consume the exact request before any synchronous owner callback. They capture
the player/mission objects, lifecycle epoch, body generation and station identity, and validate
again before durable speech and after its callbacks. Nessa's physical repair obeys the same rule.
User cancellation also crosses the worker boundary. There is no new saved social database.

The event surface was regenerated with its required census script. In addition to the new
`contactHail:cancel`, the current-tree generation reconciled existing `title:arrivalGreeted`
forwarding and `swarm:bossMilestoneAck` / `swarm:scoreboardToggle` main-only classifications.
