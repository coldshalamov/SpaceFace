# EC-G05 — owned facility operation loop

## Diagnosis

The ordinary Automation → Outposts route can buy a fuel-synthesis facility, but its owned card
only offers Decommission. The actual recipe needs hydrogen, iron and silicate; there is no pilot
input supply, output collection, buyer selection, expansion or immediate upkeep recovery control.
The existing producer already conserves recipe inputs and materializes an authored outpost.

The output path breaks the same contract: `_outpostAutosell` removes the entire store before
calling a capped credit funnel. It ignores market receiving room and stock, and may discard output
even when the cap pays zero. Offline catch-up repeats the same deletion and assumed sale.

Replacing automation/economy would duplicate mature ownership, cadence, save and presence code.
A UI-only repair would expose an operation whose outputs still vanish. The chosen implementation
extends the current facility record and owners: bounded input storage, nearby pilot cargo transfers,
canonical market intake, retained unsold output, a bounded latest receipt, destination and recovery
controls, and paid capacity/throughput expansion. No new simulator or parallel economy is needed.

### Player route and resulting behavior

Adventure → Operations → Outposts → research Outpost Charter → build Fuel Synth (45,000 cr).
The card describes its hydrogen/iron/silicate recipe and upkeep. Locate opens the physical site,
including its actual position. Within 450 m, Supply inputs transfers available, unreserved pilot
cargo into bounded recipe-shaped input bins. The existing producer consumes that stock and local
legacy feeder stock, with the existing deterministic production and offscreen cadence.

Collect output moves only whole units that fit the real hold. Settle output and minute autosales
now quote the existing local station market. The receiving target is the same finite stock rule
used by programmed miners; the current price curve, faction pricing, existing 80% automation
payout and shared passive allowance all apply to the quantity actually accepted. The old path
deleted every unit and then discovered how little could be paid. The new path retains everything
that demand, the shared allowance or the wallet cannot accept. Refused sales do not move stock or
credits. Market intake does not impersonate a manual player trade or complete a cargo mission.

A bounded last receipt records the stable facility identity, sequence, good, buyer, quantity,
gross quote and realized proceeds. The panel distinguishes stored output from paid income and
labels proceeds before upkeep/feedstock costs. It exposes local buyer changes, paused autosales,
input recovery, paid expansion, arrears recovery and protected decommissioning. Expansion to
levels 2/3 increases the existing capacity/throughput/defense rules and upkeep, and adds at most
two existing authored outpost annexes through the dressing owner. No additional physics workers
or per-crate simulation were introduced.

Acquisition, expansion and resumption use economy's exact-payment commit contract. The owner
record and credit movement settle before reentrant observers see them; absent/refused payment
cannot build a free facility. Routine shortage no longer repossesses a fixed facility. Its input,
output and ownership remain recoverable. Unpaid offline upkeep becomes real arrears.

Offline production uses the same receiving and custody settlement, with the existing 60%
offline efficiency. Already-paid facility receipts are excluded from the aggregate worker grant.
Unaccepted output remains inventory rather than fictional earnings or dropped overflow. Continue
normalizes the additive fields and retains inputs, output, buyer, level and receipt. Runtime
presence/annex IDs are omitted; facility save snapshots no longer alias the live input store.

### Canonical contracts and exact production paths

- `src/systems/automation.js`: input/output custody, order handling, deterministic live/offline

- `src/systems/outpostOperations.js`: pure shared readers, capacity/level/cost rules, transfer range,

  ordinary `openGalaxyMap` intent with the saved physical position.
