# EC-G12 — persistence and recovery implementation evidence

**Status: AREA INCOMPLETE.** The connected save/load lifecycle repairs below are implemented and behaviorally checked. The entire commission is not accepted; public-route rendering and several existing native persistence gates remain open.

## Diagnosis and selected remedy

Baseline: master `0ca4e55e70e1e384b3589b24b5068a5dc64a5134`, integrated with the existing EC-G12 draft. The save owner already supplies versioned campaign envelopes, bounded imports, recovery copies, rollback, physical-reference restoration and temporary-session save protection. Replacing it would discard working contracts.

Three connected failures were found at the load boundary. The public `game:load` handler aborted an active scored run before checking that the requested save was readable. Async load/import fences compared restore sequence but not the run epoch advanced by New Game, so a slow older request could replace a newer game or publish its stale error. FileReader success also started a fresh import without checking whether the route changed during the read. A successful envelope parse merged profile records before knowing whether the world could actually be restored.

Alternatives considered:

1. Disable loads during temporary flights. Rejected because loading a campaign is an existing useful exit.
2. Add another temporary-run persistence engine. Rejected because it duplicates owners and cannot reconstruct active runtime resources from a run label.
3. Extend the existing transaction at its authority boundary. Selected: keep valid exits, reject stale/invalid transitions before departure, and publish profile acceptance after actual world commit.

## Production changes

- `src/save/saveSystem.js`: `game:load` no longer settles a run merely because a load was requested. The canonical restore start emits one `run:endRequested` immediately before `save:restoring`, after validation and rollback capture. The receipt contains the actual simulation tick. Direct imports and direct envelope restores now take the same path; rollback never re-settles the departed run.
- Async slot selection, primary/recovery preparation, import preparation, rollback capture, locale preparation and FileReader completion now honor both the existing restore sequence and the existing run epoch. New Game and temporary launches therefore invalidate pending old loads, as newer committed loads already did.
- Imported achievement and Crucible sidebags commit through their existing additive merge owners only after a successful, nonsuperseded world restore, including native reconciliation. Successful restore results explicitly identify a queued successor. A successor that runs before an async continuation resumes also fences the profile write. Failed native adoption, rollback and queued replacement cannot publish the candidate's medals.
- `importString`/`importFile` resolve success only after their own world commits. A queued import waits for its deferred restore; a replaced or destroyed queue resolves false. Slot/direct-envelope requests retain their existing handled-result contract, so the import screen cannot mistake queue acceptance or supersession for an imported world.
- `src/ui/saveFeedback.js`: refused rollback capture explains that the current flight is unchanged; failed rollback admits that the prior flight could not be restored; temporary-world failures name the protected Adventure saves and ordinary Save-screen/main-menu recovery routes. Temporary save rejection now explains the mode boundary.

**State and ownership:** no new persisted facts, envelope format, schema version or migration. `CURRENT_VERSION` remains 23. SaveSystem owns the transaction stamps/quarantine; runSession owns run termination; achievements and survivalRecords own profile merge. Native economy/cargo/world/identity owners remain authoritative. This work does not change costs, grant items, fabricate successful settlements or turn an arena into a campaign save.

A failure after destructive restore begins can still end a temporary run. Active temporary simulation is deliberately absent from campaign envelopes. The existing rollback restores the available world snapshot, while the temporary-state quarantine continues to block campaign writes. The player can retry another load or return to the menu. This is not a claim that rollback can resume an in-progress Swarm round.

### Existing blockers established separately

- Three cases in `test/sg02-scalar-contact-episode.test.mjs` have stale zero-clock expectations. The current native owner deliberately sets the rebuilt clock to `max(previous native tick, canonical restore tick)` (101 or 19218 in these cases), so recent impulse provenance is not read as future time. The retained contact budgets themselves pass. Rewinding production time to satisfy those expectations would violate the current owner contract.
- Fourteen existing v15–v22 free/tethered native Continue cases fail at `test/save-old-version-continue-matrix.test.mjs:159`: restored contact-episode lastTick is undefined, expected 120. A narrow read-only instrumented v15 free restore establishes why: the player is correctly remapped, with identical identity, pose and velocity, but the current ship owner recomputes the Kestrel from saved physics revision 1 / inertia 34.120879 to revision 2 / inertia 1635.803810 (mass remains 40.5). The contact-budget donor correctly refuses a changed physical contract; the old matrix assumes unchanged contracts. This is not evidence of erased player identity. The current-version matrix also references absent `continue-v23-free.json` and `continue-v23-tether.json` fixtures.

The same 19 SG02/matrix failures were reproduced with the exact master SaveSystem blob substituted through a read-only Node `registerHooks` loader. No branch, index or shared worktree files were reset for the comparison. These are not regressions introduced by the lifecycle changes. The gates need expectations reviewed against canonical provenance/physical-contract semantics and genuine current captures; their present failures do not justify bypassing those authority checks. Full native Continue acceptance remains open. No expected values were weakened and no fixtures were fabricated to hide them.

The initial asset import blockers were resolved by hydrating exact master bytes for the radar glyphs, wreck-court variants and achievement manifest. The seven affected cases then passed. No replacement assets or test substitutes were introduced.
