# Production quality through compounding improvements

Planning baseline: `adc71448e95c0cd488b0ba195ff5187b799e1488`, 2026-09-30.
Scope: a source-grounded second opinion and executable first wave. This PR changes documentation only.
No runtime, audiovisual, performance, or subjective-fun verdict was produced by this analysis.

## Decision

SpaceFace's production work should strengthen a fast physical playground with RPG targeting,
powers and build depth. Piloting must create opportunities as well as avoid damage or change location.
World activity, progression, presentation and reliability must support that experience.

The owner wants professional analysis that finds gaps between prompts and investments whose
benefit compounds. Entirely agentic development is required. This is not a new vision manifesto,
queue, mandatory capture pipeline, engine rewrite or promise of commercial success.
[FINISH_LANES](FINISH_LANES.md), [INFERENCE_LANES](INFERENCE_LANES.md) and the
[build map](../../build_map.md) retain their roles.

**Start with the finite first wave in [FIRST_WAVE](PRODUCTION_QUALITY_FIRST_WAVE.md).**
Its first assignment joins physical results to useful terrain; its second resolves terrain-assisted
piloting; its third carries one completed experience through acquisition, play, reward and return.
Architecture decisions are in [ARCHITECTURE](PRODUCTION_QUALITY_ARCHITECTURE.md).

## 2. Investments with compounding value

These are selected work priorities, not assumed defects in every subsystem.

### A. One physical result stays true through the whole interaction

A selected target is eligible; the applied force reaches the real body; that body's motion hits
terrain; the impact has an attributed result; the result creates an appropriate remnant or reward;
the picture and sound describe the same event.

Fixing this chain improves bumpers, tethers, guns, machinery, missions and future props together.
Start with thrown hostile hulls and two existing terrain interactions. Do not invent a universal
object engine before a specific inconsistency is reproduced.

### B. Places are reusable gameplay constructions

A useful route combines readable entry, a physical opportunity, commitment, alternate path,
consequence and recovery space. Build it once and use it for travel, pursuit and a job.
The first-wave Ceres route deliberately reuses the Sluice, rocks and an existing receiver.
Later Pallas debris and Tethys freight routes must differ in decisions, not just decoration.

This is the actionable answer to asset shortage: prioritize missing *roles and shapes*.
A broad convex contact face, movable bank plate, detachable plug or readable catch bay can enable
many encounters. Another cosmetic hull variant does not automatically do so.
Prefer repurposing existing assets; new authored media still follows Forge, manifests and collision truth.

### C. Player-facing feedback shares a causal language

Choose contact, denied contact, held body, release, secondary impact and result as one worked sequence.
Repair actual missing listeners, misleading labels and competing voices along that sequence.
Include reduced-motion/flash equivalents in the same change. Reuse ORRERY and existing audio/VFX owners.

This gives INFERENCE many useful small jobs: one missing denial reason, wrong material cue, stale
target marker or omitted result entry. They are leaves of a real experience, not new scoring systems.

### D. Builds create reusable problem/solution differences

Compare one light mobility build, one heavy impulse build and one existing tow/control build using
accepted fittings and loaded mass. Each must have an advantage and cost in a shared route and job.
NXB-030/031 own the comparison and truthful explanation. Do not guarantee a winner by adding hidden
handling bonuses or forced hull gates.

Progression should expose these differences through ordinary earning and fitting. Swarm can offer
rapid experimentation while Adventure retains meaningful acquisition; the underlying toy behaves
consistently in both.

### E. A completed activity includes its edges

Acquisition, explanation, action, refusal, failure, partial success, settlement and return are one
delivery. Fixing an interrupted cargo transfer or save boundary benefits many missions.
This is where professional polish accumulates without more features.

Small usability changes are valuable when they remove a concrete broken step. A test, receipt,
renamed queue entry or new checklist alone does not count as gameplay production.

## 4. Verification that earns its cost

Follow root AGENTS and the existing validation workflow. The default is current-owner inspection
plus a focused test or fixed-seed number. No mandatory human verdict, screenshot archive, multi-hour
battery, new grading service or review ceremony per tiny change.

- Per meaningful code change: affected fast checks and the counterexample that can falsify its claim.
- Per integrated slice: union the relevant checks once; reuse the same scenario for motion,
  attribution, outcome and lifecycle assertions when it genuinely observes all four.
- Only a session-shape claim calls for a targeted ordinary-route run. Select the affected window,
  not a universal campaign battery. Prepared scenarios cannot prove earning/reachability.
- Visual claims need actual visual inspection where possible; numerical force evidence does not
  prove legibility. Keep any capture scoped and ephemeral under repository rules.
- Independent agent review examines the changed behavior and evidence, then actionable defects are fixed.
  A missing GPU must not convert implementation work into endless harness repair.
- Record evidence identity compactly: candidate revision, relevant configuration/seed/loadout,
  command and result. No committed dump is required. Rerun when relevant physics, geometry,
  input, camera or lifecycle owners change; unrelated prose does not invalidate a gameplay result.
- Existing playable/performance checks keep their repository scope. Never weaken a golden,
  alter a fixture simply to pass, silently lower visuals, or present a historical report as a new run.

## 5. How INFERENCE compounds instead of making work

For the current bundle, direct INFERENCE to the existing OPEN children that improve the actual
route. A useful nomination contains the object/control, the observed gap, the current owner,
the player-visible correction and one cheapest falsifying check.

Examples after the first-wave capability exists:
- The rebound surface gets the same visible eligibility treatment as its real contact rule.
- A Grip release denial names excessive mass instead of appearing to ignore the input.
- A receiver explains the accepted quantity and leaves rejected cargo physically recoverable.
- A secondary impact stays associated with its real body after the selected target dies.
- The next-round description names the new pressure without prescribing the solution.

These examples are selection shapes, not new IDs or claims of observed bugs. Already-correct
behavior earns no implementation task. Do not spend a batch only adding synonyms, manifests,
telemetry or tests unless that is the requested deliverable.
