## Outcome

The four screens the player reads rather than operates — the missions log, the codex, help and the
tech tree — migrate onto the kit from `PQ-187.02` to the pictures in
[`DIRECTION_SHEET.md`](../../../frontend/direction/DIRECTION_SHEET.md) §2 "The reading screens",
keeping what each does (mission tracking, codex plates and tabs, the controls table read from
`input.js`, the tech lanes and unlocks) and shedding their old CSS as they move.

## How agents get this wrong

Read this before touching code. The integrator rejects a unit that matches any line.

- Restyling before the kit and the title exist; these screens migrate onto the kit, they do not
  invent one.
- Keeping the old style block "for safety" beside the new rules. It is deleted in the same commit.
- Boxing the codex text or the mission list into a panel; grouping is by distance and hairlines.
- Writing a literal key name into help copy (the screen-imports check rejects it); keys come from
  `input.js`.
- Calling a leaf done on a green check without the visual review against the sheet.

## Performance

These are DOM screens over a paused or live scene; stay inside the UI floor (≤ 2 ms UI frame cost,
≤ 1,500 DOM nodes per screen). The codex's long measure is one column of text, not a virtualised
list; the tech tree's lanes are drawn once per open, not per frame. Never reduce content to meet a
budget.
