## Security domains

### Actor

Uses visible UI, accessibility roles/names, keyboard/pointer/controller, pixels, and public seed entry. It cannot read hidden state, internal IDs, owner events, diagnostics, future outcomes, or held-out answers when choosing actions. A deterministic actor policy is allowed only when it is a plausible public-surface player and cannot consult the observer.

### Observer

Read-only collection of approved owner events/projections, save receipts, errors, focus/visibility/timeScale, process/GPU health, performance, and media. It cannot emit gameplay events, call mutating owner methods, change timeScale, expose hidden telemetry to the actor, or manufacture a semantic success.

### Judge

Validates schemas, immutability, matrix completeness, native duration, deterministic hashes, owner evidence, parity, save, accessibility, performance, media, and human forms. It cannot delete an inconvenient attempt, relabel a scenario after observation, choose profile class from measured FPS, average away a failed hard cell, or convert unknown to pass.

Keep these domains as separate modules/process interfaces with tests that reject information-flow violations.

## Failure taxonomy and rerun policy

| Class | Treatment |
|---|---|
| `QUALIFICATION` | wrong/dirty revision, dependency/seed/scenario/profile/native-time/timeScale/GPU/source/capture mismatch; retain invalid attempt |
| `ENVIRONMENT` | independently evidenced external fault; one predeclared replacement; retain both |
| `HARNESS` | actor/observer/judge/stream/cleanup defect; block affected cells; repair harness; new harness hash; rerun affected cells only |
| `PRODUCT_ONBOARDING/NAV/ECONOMY/PROGRESSION/COMBAT/MASSLINE/SAVE/A11Y/PERF/PARITY` | product failure; route to exact owner with focused regression; new game candidate required |
| `HUMAN_JUDGMENT` | critical discoverability/fairness/readability/coherence failure; acceptance fail |
| `UNKNOWN` | evidence cannot attribute or prove required fact; hard fail |

No best-of-N. No deleting red attempts. No unchanged candidate rerun. A product fix changes the candidate commit and invalidates qualification cells. A harness fix changes harness hash and invalidates only cells whose evidence path was affected, as proven by contract tests.

## Performance profile contract

Profile class is assigned before the run and never inferred from measured cadence.

- **Target:** p95 <=16.7 ms and target-specific hitch policy; cannot pass at floor threshold.
- **Floor:** p95 <=33.3 ms with floor-aware delivery/hitch classification; raw >32 ms remains reported but is not blindly zero-gated.
- **Diagnostic:** never acceptance-eligible.

Every attempt records p50/p95/p99/max, raw threshold counts, missed-vsync, multi-step/backlog, phase costs, entity/draw/triangle/particle/light counts, residency baseline/peak/end, save blocking, process/GPU health, and capture overhead as available. Default quality/settings remain fixed.

Long-session qualification rejects monotonic growth in entities, listeners, timers, observers, resources, save payload, queues, or retained evidence buffers beyond declared bounded high-water behavior.

## Accessibility and human judgment

Automation checks roles/names, focus, contrast, reduced motion/flash, non-color/non-audio cues, text scale, input reachability, and semantic checkpoints. Human player and independent reviewer decide discoverability, role identity, fairness, cue clarity, recovery comprehensibility, perceived continuity, and whether the route feels coherent rather than merely executable.

Critical rubric questions and failure thresholds are frozen before held-out runs. Human judgment cannot waive hard technical failures; hard automation cannot certify fun.
