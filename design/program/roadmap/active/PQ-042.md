Neither D subcase permits any corrective product/runtime mutation inside PQ-042 beyond retaining or removing the frozen, disabled-by-default Phase-0 diagnostic diff, and a changed source candidate cannot be recaptured to manufacture a replacement D closure.

## Diagnostic approach

This packet attributes the dominant GPU cost to one of four buckets and fixes that bucket. The
diagnostic *idea* is frozen; the exact statistical method is not — whoever runs the capture against
the real machine chooses sample sizes, thresholds, and the block design that will actually be
trustworthy there. See the four-bucket diagnostic matrix and branch guidance in
[`design/PERFORMANCE_MODERNIZATION_EXECUTION_PLAN.md` §15](../../../PERFORMANCE_MODERNIZATION_EXECUTION_PLAN.md).

The earlier revision of this packet pinned FNV-1a hash recipes, exact query counts, Type-7 quantile
formulas, and an irrevocable "packet-terminal" verdict into prose ahead of capture. That machinery
made the result impossible to re-validate and would freeze the packet forever on a single misread
number. It has been retired in favor of: run a clean capture, attribute honestly, pick the branch the
evidence supports, and say so plainly when the evidence is ambiguous. A clean interpretable result
beats a frozen contract no one can re-check.

The four buckets (mirroring §15):

- **A — pixel/overdraw:** scene GPU time scales with output pixels when draw/state counts are held.
- **B — material/ordering:** cost scales with draw calls / state changes / pipeline switches when
  pixels are held.
- **C — post-pass:** cost concentrates in full-screen passes (bloom composite, copies, post).
- **D — not a GPU problem:** GPU timing is healthy but callbacks are still late → investigate the
  non-GPU owner; don't mutate GPU code.

Branches are mutually exclusive by attribution (C > B > A > D in priority of ownership), but if the
evidence is ambiguous or Browser/Electron disagree, report `BLOCKED` rather than forcing a branch.

### Selecting render path notes

- Selecting captures use `renderGraph: false`; the live `bloom` or `straight` path is what's measured.
  The default `bloom` path's post cost is `bloomDownsample + bloomComposite` (the fused composite owns
  sampling, tone map, grade, grain, vignette, sRGB, and final presentation — no separate upsample/grade/
  vignette/grain/copy query). On `straight`, post cost is zero.
- Diagnostic perturbations (lower pixel scales, post-bypass) are non-promoting: they restore defaults
  after each block and never become accepted quality controls.
- Attribute owner work in callback `k` to the callback interval *ending* at `k+1`, not to its execution
  duration. Record external scheduling as a non-owner residual.

### Post-correction acceptance (A/B/C)

When a branch is selected and corrected, prove the win is real with a matched before/after comparison
on the same seed/route/content: the selected scope's cost should fall, the aggregate domain it lives in
shouldn't grow to eat the savings, and no unselected owner should regress enough to matter. Semantic,
image, temporal, and default-quality equivalence must hold. A local scope win that quietly grows the
cumulative domain cost is not a win.

Keep this proportionate: a clear, interpretable before/after on the real route is the goal, not a
fixed seven-block bootstrap. If the chosen correction is clearly right and the equivalence holds, move
on; if it's marginal, gather more evidence or defer — don't loop.

## Stop conditions

Return `BLOCKED` if: a prerequisite packet is unaccepted; the capture environment is contended or the
no-op control is invalid; required discriminators can't be produced through bounded diagnostic paths;
the evidence is genuinely ambiguous and won't resolve to a single branch; or Browser and Electron
disagree in a way you can't explain. For A/B/C, also block on missing/unmapped lineage or an
unresolved dominant owner.

Return `FAIL` if: semantic/image/temporal equivalence drifts; default quality is reduced to claim a
win; a context/shader regression appears; or the selected scope doesn't actually improve once the
aggregate guards are applied.

If a correction cures the original pathology and the GPU ends up healthy (D), that's a reported
outcome, not a failure. A *different* actionable A/B/C branch surfacing post-fix goes to a separately
admitted follow-up rather than getting reopened here.
