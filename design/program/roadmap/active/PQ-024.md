## Outcome

In Asteroid Ops, Survey progressively reveals one deterministic connected interior formation before a Core is installed. That knowledge is explicitly volatile. Installing the Core atomically commits the exact target/revealed cells into the integrated World Site owner. The site becomes `producing` only after an existing producer performs real positive output and emits one authoritative receipt. Exactly one exterior relay/collar then appears in flight and survives Continue.

The player should feel a physical chain:

```text
probe geology -> choose whether to commit -> build -> produce something real -> see industry alter space
```

No colony-management or second production game is required for this corridor slice.

## Deterministic survey contract

On the first qualifying Survey pulse in `cold` state:

1. use the live drill session's exact effective field seed;
2. derive candidate cells from current field material/type and bounded dimensions;
3. build same-material connected components in a stable neighbor order;
4. filter by declared minimum/maximum area and reachable/valid cells;
5. select by deterministic score and stable cell key tie-break;
6. freeze `targetId`, seed, ordered target cell list, and revealed set in transient session state;
7. each effective Survey pulse reveals a deterministic bounded frontier subset; ineffective/duplicate pulses do not advance.

No RNG calls outside the established seeded path, wall time, DOM order, object iteration order, or player camera decide target/reveal.

Before Core, save/Continue may discard this state. UI must say so clearly before the player commits.

## Atomic Core adoption

Core installation is one owner transaction:

```text
validate Core placement and World Site preconditions
validate transient target seed/cells/reveal against current drill field
create/commit the authoritative site record
adopt exact target/revealed set
or reconstruct byte-identically from the recorded seed if the owner contract requires it
record one commitment receipt
publish committed state
```

No partial site without survey, no durable survey without site, no reroll between Survey and Core. Invalid/stale adoption aborts visibly; it does not silently choose another formation.

## Producing receipt

`committed` is not `producing`. Do not infer production from installed machines, projected rates, selected mode, timers, capability, or stored input.

At the exact mutation where a non-Core producer commits positive output, the existing production owner emits a stable unique receipt:

```js
{
  receiptId,
  siteRecordId,
  producerId,
  recipeId,
  outputId,
  positiveQuantity,
  committedTick,
  sourceMutationId
}
```

The World Site owner validates the receipt belongs to the site, is positive, owner-authentic, not duplicate/stale, and then monotonically records `producing`. Replays are idempotent. Negative/zero/capability-only signals cannot advance lifecycle.

## Exterior consequence

Exterior count by lifecycle:

```text
cold: 0
committed: 0
producing: 1
producing after Continue/reentry: 1
```

The relay/collar uses one stable entity/place ID derived from site record ID and one exact accepted asset identity. It is a read-only projection of producing state; destruction/reload behavior follows the current place/World Site recovery contract rather than spawning another truth record.
