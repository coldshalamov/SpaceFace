## Outcome

SpaceFace renders from a disposable, generation-safe, dense `PresentationWorld` whose work scales with changes, visibility candidates, and visible handles rather than every registered object root. The ordinary route runs identical seeded quiet flight, five-times population, dense combat, travel/rebase, damage/effects, authored asset admission, save/Continue, churn, and context recovery through legacy and shadow paths until transform, visibility, LOD, attachment, pool, and diagnostic semantics match; the accepted path then supports five times the current render population at no greater entity-publication cost than the legacy current-population path on the same machine.

`GameState` remains authoritative. No simulation system reads `PresentationWorld`; it can be destroyed and rebuilt from current state and journals.

## Data and authority contract

Dense numeric arrays contain generation, alive, stable entity ID, render slot, previous/current X/Z/rotation/bank/pitch/scale/bounds, type/team/relation flags, transform/visual/attachment/residency revisions, LOD/visibility state, dirty masks, and active-list positions. Compact side tables hold only JS/Three references that cannot live in typed arrays. A handle is valid only when both slot and generation match.

Publication rules:

- spawn publishes a complete record;
- destroy retires handle and every pool membership before reuse;
- transform and visual owners publish revisions through PQ-036 journals;
- static records skip transform work until version change;
- newly visible records receive full pose/attachment sync;
- already visible records publish only changed fields;
- visibility/LOD decisions shadow legacy behavior before authority changes.

## Mutexes

- `renderer` — primary migration surface.
- `registry`/`loop` only for the journal adapter already owned by PQ-036.
- `vfx` and `browser-gpu` serialize affected consumer work and headed acceptance.
- `asset-manifest` is not required; stable authored identity is consumed, not rewritten.

## Non-goals

- General ECS conversion or simulation access to `PresentationWorld`.
- WebGPU, GPU-driven visibility, OffscreenCanvas, Worker, or backend replacement.
- Changing camera, cull distances, LOD thresholds, authored roots, materials, effects, or default quality.
- Hiding entities or reducing the 5x workload to pass.
- Permanent legacy and dense render authorities.
- Rebuilding asset packages; PQ-037 owns compiled inputs.

## Performance and quality budget

- Steady-state publication allocates no per-frame records/diagnostics after capacity is established.
- Work grows as `O(changes + visibility candidates + visible handles)`, not all registered roots.
- Static/far-culled records do not receive transform writes until version/visibility changes.
- Memory capacity, growth, free-list, and generation reuse are bounded and reported; teardown/rebuild returns high-water resources to expected baseline.
- At 5x current entity population, entity-view publication is no slower than legacy current-population publication on the same route/machine.
- Exact visible set, pose, LOD, stable root, attachment, pool slot, and visual semantics remain equivalent.
