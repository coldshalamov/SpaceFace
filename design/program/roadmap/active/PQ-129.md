## Outcome

Ordinary Continue and combat flight on the owner's Intel iGPU no longer drop 40–500+ ms bricks
that spin the sim into catch-up. The picture keeps updating, the ship keeps the helm, and first
sight of an authored hull or shader key is not one display callback. Default bloom, shadows,
particles, scale, and on-glass population stay on. Crowded 60 fps is a later wave after hitch
count is halved — not the first leaf.

## Player route and state machine

1. Title → New Game or Continue → loading shell → flight canvas changing.
2. Ordinary thrust in the starting pocket, then first hostile / traffic on the glass.
3. Keep flying 20+ seconds. Sim clock, renderer frames, and canvas hashes must all move.
4. Failure class is a hitch (frame >32 ms or a named brick), not a frozen 3D picture behind a live HUD (`PQ-051`).
5. Saves stay deterministic. Cadence changes require `PQ-066` before they ship.

## Performance and quality budget

Target: desktop p95 ≤16.7 ms **after** hitch bricks die; hitch frames >32 ms ≤ half the
2026-08-20 witness tail on a matched headed fly. Floor: 33.3 ms must not be the steady
combat feel.

Do not buy the target with content, population, effects, draw distance, or default visual
quality cuts. Compose slicing, admission, exact-key prewarm, and off-glass-already-retired
submit are the legal tools.

Expected IMPL growth: zero extra entities, colliders, or draw families. Admission work moves
off the present beat; on-glass submit should fall or hold, never rise.
