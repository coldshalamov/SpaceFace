## Outcome

A visible surface launcher fires one physical cargo capsule toward a lawful catcher. The player can intercept it with existing flight/Massline/boost physics, trigger witness-validated theft and pursuit by existing job-origin patrols, escape without magically clearing heat, and physically deliver the same capsule to a fence for exactly one settlement. Lawful arrival, destruction, confiscation, expiry, absence, abandonment, and retry are deterministic, save-safe outcomes—not script gaps.

The fun is the geometry and mass: predict a launch, meet a moving body, alter its trajectory, manage attachment/load/boost, improvise escape, and choose when a risky physical handoff is worth committing.

## State and arbitration contract

Separate nonterminal progress from immutable terminal outcome.

```text
scheduled -> launched -> possessed -> pursued -> escaped -> receiver_pending
     \          \           \          \             \
      \----------> resolution_pending -----------------> terminal
```

Terminal outcomes:

```text
lawful_arrival_observed
payload_destroyed
lawful_confiscation
fenced_success
expired
unresolved_absent
abandoned
```

Every report becomes plain deterministic candidate data:

```js
{
  candidateId, // hash(missionId, payloadStableId, kind, causalTick, sourceStableId)
  missionId,
  payloadStableId,
  kind,
  causalTick,
  sourceStableId,
  proof
}
```

The mission owner buffers same-step candidates and decides no earlier than `causalTick + 1`. Selection never uses callback/insertion order, wall time, live entity ID, or random choice.

Pin explicit tie rules in pure tests. Recommended terminal precedence at one tick:

```text
destroyed > confiscated > fenced > lawful_arrival > expired > unresolved_absent
```

Nonterminal possession applies only when no terminal candidate wins. Remaining ties use stable `candidateId`.

Exactly one prepared terminal receipt is compare-and-set, then owner effects commit idempotently:

```js
{
  receiptId,
  missionId,
  payloadStableId,
  outcome,
  causalTick,
  winnerCandidateId,
  status: 'prepared' | 'committed',
  effectKeys: {}
}
```

A crash after prepare resumes the same receipt. Receiver/economy/faction/mission effects never select a new winner during replay.

## Required owner invariants

For every route and reload:

```text
terminalReceiptCount == 1
capsuleProjectionCount <= 1
receiverCommitCount <= 1
missionSettlementCount == 1
economyRewardCount == (outcome == fenced_success ? 1 : 0)
factionOutcomeCount <= 1
heatApplicationCount == (validatedWitnessedTheft ? 1 : 0)
playerCargoMutationCountForCapsule == 0
sectorOwnershipMutationCount == 0
activeJobControlClaimsAfterTerminal == 0
```

Pursuit uses existing job-origin patrols. No available patrol is a valid, visible outcome recorded by law; it is not permission to spawn a fake job-origin responder.
