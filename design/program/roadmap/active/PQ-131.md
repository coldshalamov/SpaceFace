## Outcome

Every object in the mine — rover, Massline Core, extractor, refinery, surface derrick, conduit kit, gas
tap, fabricator, cargo port + crates + courier pod, and the ore/gas/exotic/ice inclusions — is an
**authored, reviewed, wired PBR asset** at the flight ships' bar, loaded through the game's release
pipeline, seen through the works camera. The procedural builders for those objects are deleted. The owner,
looking at the live mine beside the flight game, does not see a different game.

Owner verdict that created this packet (2026-08-21, live build): "the rover is like this 8-bit NES model
inside this 3d world … you're intentionally cutting corners … I'd rather you at least made plans for the
future development to actually get the game that we want." `PQ-130`'s presentation work stands; its
acceptance is blocked on this packet.

## Performance and quality budget

Authored assets replace procedural meshes of similar or higher triangle counts; budgets per asset are in
the campaign inventory (LOD0 / LOD1, KTX2 textures). LOD1 at the site register keeps the whole-body view
cheaper than today's instanced procedural clusters. Bloom, shadows and the shared grade stay on. Never buy
a pass by removing an asset, a lamp, or a shadow; never ship a studio-quality LOD0 without its LOD1.

## Verification budget

- Per asset: works-camera stills (`works_top` 120 px/cell, `works_site` 19 px/cell) beside a flight
  still; three independent reviews listing every defect at play size; revise until KEEP; `npm run
  check:asteroid-theater` and `npm run check:playable` green; no quality cuts; release build hashes in the
  manifest; the replaced procedural builder deleted.
- `.00`: a release part loads and renders in the works context with correct colour space and LOD by
  register; disposal on exit leaks nothing (`renderer.info` before/after).

## Review questions

- Beside a flight still of a ship near an asteroid, does the mine's object read as the same game?
- Is the still a works-camera frame at play size (120 px / 19 px per cell), not a studio crop?
- Did three independent reviews list defects at play size, and were they revised, not argued with?
- Is the procedural builder for this object deleted, and does the runtime state (hopper stages, bit
  heat, lamps, progress, flow, lid, scar) still drive the authored hooks?
- Does the asset load through the release pipeline (KTX2 + manifest hash), with LOD by register and
  clean disposal on exit?
- Can the diff be honestly described by campaign §6 (vanilla collapse)? If yes, fail.

## Stop conditions

- A unit's diff can be described by campaign §6 (vanilla collapse) — not done.
- A still that is a studio crop, or no flight still beside it — not proof.
- Blender unavailable — do `.00`'s loader half, record the blocker, stop.
