## Outcome

Dynamic sprite, trail, authored-instance, and ship-auxiliary pools upload only the component span changed since the last acknowledged GPU upload while preserving the exact visible instances, matrices, colors, opacity, draw count, ordering, lifetime, growth, wrap, and teardown behavior. The ordinary proof route runs sparse and dense combat, trail churn, spawn/destroy, capacity growth, context recovery, and five-times population with identical presentation semantics; upload telemetry follows the dirty active span instead of allocated capacity and demonstrates a repeatable CPU/driver benefit or the abstraction is removed.

This packet starts with unleased pools. It does not seize `src/render/vfx.js` or any active VFX owner merely to make the migration list complete.

## Dirty-range contract

For each changed attribute, the owner records the lowest and highest changed **component** index in an unpublished pending span. Logical commits never call `addUpdateRange()` or set `needsUpdate` directly. Publication must occur before Three.js first processes that object's attributes. Three.js 0.184.0 calls `WebGLObjects.update()` during `projectObject`, before an `Object3D.onBeforeRender` callback, so object hooks are explicitly forbidden as this packet's publication seam. The initial stage instead adds a renderer-owned coordinator at `src/render/renderer.js#drawPreparedFrame`: it arms a chained `Scene.onBeforeRender` only around the ordinary gameplay render path and publishes before `projectObject` / `WebGLObjects.update()` after ordinary writes, slot allocation, capacity growth, and attribute replacement have settled:

1. union every logical write with the unpublished pending span; a context-lost/loading/skipped frame, a render path that never reaches the armed scene hook, or a processing-ineligible owner allocates no public range, increments no attribute version, and never retires dirty state;
2. register each initial combat-sprite or trail-streak owner before its mesh is attached or can reach a renderer traversal, and require exclusive ownership of every tracked attribute. After the preserved scene callback runs, an owner is **processing-eligible** only when its mesh is still attached below the rendered scene, every ancestor and the mesh are visible, `mesh.layers.test(camera.layers)` is true, no ancestor is an auto-updating `LOD`, and `frustumCulled === false`. It is **ordinary-draw-eligible** only when processing-eligible, its single material is visible, and active draw/instance count is positive. Cullable meshes, shared tracked attributes, material arrays, and auto-updating LOD ancestors are `BLOCKED` until a later packet revision defines and tests a public predicate matching their live traversal;
3. arm one renderer-frame epoch immediately before the selected renderGraph/bloom/straight path and disarm it in `finally`. Save the exact prior `scene.onBeforeRender`, install one exact coordinator wrapper, reject wrapper re-entry, and invoke the prior callback first with the original receiver and arguments. Propagate a prior-callback exception with pending state intact. After it returns, require the wrapper still to own `scene.onBeforeRender`; replacement or recursive rendering aborts the route before `projectObject`. On success, no-render, or throw, restore the prior hook in `finally` only when the wrapper still owns the slot; never overwrite a foreign replacement, and invalidate any route that loses hook ownership;
4. recompute processing/draw eligibility and resolve the owner's **current** attributes after the prior callback. An ineligible scene invocation does not consume that owner's epoch opportunity. Publish exactly once at the first invocation where a force-full generation is processing-eligible or an ordinary pending span is ordinary-draw-eligible; later scene renders in the same epoch do not republish that owner;
5. to publish, rebuild only this owner's public range metadata, call `addUpdateRange(start, count)` once per changed attribute, retain the exact appended record, set `needsUpdate = true` once, record the resulting version, move the span into an immutable published snapshot, and reopen an empty pending span. Never widen or republish an in-flight record;
6. at registration, require every tracked attribute to have only Three.js's default no-op `onUploadCallback`. A non-default/pre-existing callback blocks that pool; revision 7 does not chain arbitrary callbacks. Install the adapter's sole acknowledgement callback and verify its identity again before every publication. At callback entry, require the current attribute and version to match an immutable snapshot; an unsolicited callback without that snapshot is a hard failure. Ordinary `bufferSubData` has already cleared the public list; initial `bufferData` removes only the published snapshot's exact stale record by identity. The callback may update adapter bookkeeping only and must not set `needsUpdate`, replace an attribute, or change unrelated public range metadata;
7. hold a coordinator-wide upload-callback guard for the entire acknowledgement and an owner-specific published-epoch guard until `drawPreparedFrame` disarms. Every selected owner writer checks both guards **before touching any tracked typed array or replacing a tracked attribute**. Callback-time writes and writes after that owner has published in the same renderer epoch fail closed without changing matrix/color/opacity bytes. Callback replacement and direct version/range mutation also invalidate the route. Supporting such writes later requires a new packet revision with preallocated staging or a pool-wide completion barrier; it is not admitted here;
8. registration/first creation, capacity growth or attribute replacement before publication, and context restoration mark the final current attribute force-full. Three.js processes and can initialize attributes before material visibility or instance count suppresses an actual draw, so a force-full generation publishes at the first **processing-eligible** traversal even when material is hidden or count is zero; ordinary pending spans wait for ordinary draw eligibility. If context loss or an interrupted renderer call leaves a published generation without a callback, record an explicit terminal `superseded-reset`, remove only its exact owner record, carry the complete initialized union to the replacement attribute, and force a new full generation. Superseded records are reported separately and cannot satisfy the steady-state allocation budget;
9. update active draw/instance count independently of capacity and publish logical/requested bytes, pending/published/acknowledged/superseded generations, force-full reason, range identity, attribute version, scene-hook/epoch/callback-guard violations, eligibility skips, and cumulative `addUpdateRange()` counters without owner-created per-frame objects;
10. use a measured dense full-upload fallback only when its threshold is declared before capture and the complete initialized live range is published.

Three.js 0.184.0 updates scene/camera matrices, calls `Scene.onBeforeRender`, and only then traverses `projectObject` and invokes `WebGLObjects.update()`. Auto-updating `LOD` ancestors may change child visibility during that traversal, so revision 7 excludes them. `WebGLObjects.update()` runs before material visibility is checked and regardless of an `InstancedMesh` count of zero; an uncached/replaced attribute therefore executes initial `bufferData` and its callback even when no primitive will draw. Force-full publication uses processing eligibility to install its immutable snapshot before that path. Three.js allocates one `{ start, count }` record inside each `addUpdateRange()` call, clears ordinary partial-update ranges after `bufferSubData`, invokes `onUploadCallback`, and only then snapshots `attribute.version`; initial `bufferData` invokes the callback before the version snapshot and does not clear queued range metadata. Revision 7 deliberately rejects arbitrary upload callbacks, same-epoch post-publication writes, and callback-time owner writes so an early attribute callback or a later scene pass cannot produce sibling or cross-pass tearing. Tests and telemetry count cumulative `addUpdateRange()` calls/record allocations, not only final `updateRanges.length`. Do not publish from `Object3D.onBeforeRender`, patch private Three.js internals, or bypass the public range API without a separately reviewed version-pinned contract.

A zero-change initialized draw performs no upload request or range-record allocation. A skipped-render `R1` followed by disjoint `R2` keeps only the owner-side union pending and publishes `union(R1, R2)` once at the next ordinary-draw-eligible armed scene traversal. A newly registered, grown, restored, or replaced attribute instead force-publishes at its first processing-eligible traversal so Three.js can never issue an untracked initial `bufferData` callback. Growth anywhere in the 18-spawn-plus-one-integration pre-draw fanout settles before that traversal so the replacement matrix/color/opacity attributes still allocate exactly three records total. Release via `ZERO_MATRIX`, immediate slot reuse, wrap, growth, LOD exclusion, rejected hook/callback mutation, interrupted upload, and context recovery must never expose stale or cross-generation GPU data.

## Performance and quality budget

- No per-frame allocation occurs in the pending-span utility or owner telemetry. The initial combat-plus-trail-streak stage permits only Three.js 0.184.0 range records: at most 23 cumulative `addUpdateRange()` calls/record allocations per ordinary draw-eligible or force-full processing-eligible transfer generation (four combat buckets × five dynamic attributes plus three trail-streak attributes), zero on initialized unchanged, skipped, or processing-ineligible frames, at most 1,380 records/second at 60 acknowledged uploads/second, and at most 82,800 records in a 60-second target-profile window. A required initial/grow/restore force-full transfer is counted even when material is hidden or count is zero because Three.js still processes that uncached attribute.
- The 23-record ceiling is independent of logical commit fanout and ordinary growth before publication. In the capital-debris regression, 18 spawn commits plus one integration commit and a capacity replacement before one draw still allocate exactly three trail records on the final matrix/color/opacity attributes; one-times and five-times population must not turn those writes into 57 records or the replacement into six.
- A context-loss/interrupted-render `superseded-reset` record is terminal recovery evidence, not an acknowledgement or an ordinary-budget success. Its old exact record and new forced-full publication are both counted and reported; any supersession in an uncontended ordinary target-profile window invalidates that window.
- Against the matched full-upload baseline, the initial stage adds no major GC, no more than one minor collection per 60 seconds, no more than 1.0 ms additional total GC pause per 60 seconds, and no more than 0.25 ms p95 GC-pause regression. Crossing any ceiling removes the range abstraction from that stage.
- Requested bytes follow the complete owner-side pending union published by the armed `Scene.onBeforeRender` coordinator before `WebGLObjects.update`, not total capacity, except explicit registration/create/grow/restore force-full cases. Ordinary spans wait for draw eligibility; force-full spans publish on processing eligibility so initial `bufferData` is always tracked.
- Range metadata remains one public record and one attribute-version increment per changed attribute per qualifying transfer. Ordinary pending state survives skipped/material-hidden/zero-count renders after initialization. Non-default callbacks, auto-updating LOD ancestors, scene-hook ownership loss/re-entry, callback-time writes, and same-epoch post-publication owner writes are unsupported in revision 7 and fail before traversal, publication, or tracked typed-array mutation as applicable; later write support requires staged backing storage or a pool-wide completion barrier.
- The initial stage is retained only when sparse-route requested bytes fall by at least 25% and paired owner-plus-driver median time improves by at least 2% with a 95% paired interval excluding zero; otherwise it is removed even if correctness passes.
- Ribbon, authored-chunk, ship-auxiliary, and later VFX stages remain inadmissible until their packet revision declares numeric one-times/five-times aggregate records/upload-generation and records/second, the same or stricter GC limits, a population-scaled keep/remove threshold, and rollback behavior.
- Active count, capacity, high-water growth, wrap, release, acknowledgement, and reallocation remain explicit and deterministic.
- No stale matrix/attribute data may appear after skipped render, shrink, `ZERO_MATRIX` release, slot reuse, growth, or context recovery.
- Presentation output and default quality remain unchanged.
