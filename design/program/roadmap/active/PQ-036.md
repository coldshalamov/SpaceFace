## Outcome

SpaceFace retains one authoritative 60 Hz simulation and one ordinary Browser/Electron route, but fixed-tick advancement and presentation scheduling have explicit owners. The ordinary route runs the same seeded input tape through normal flight, render-disabled, render-stalled, UI-stalled, lifecycle restore, and backlog/shedding cases; every tick, ordered event, RNG result, input action, interpolation result, and save continuation remains equivalent while callback attribution identifies simulation, presentation, admission, or external scheduling as the delay source.

The first implementation remains on the main thread. This packet creates a semantic seam and change journal; it does not move simulation to a Worker.

## State and publication contract

```text
InputCommandSnapshot
  sequence, targetTick, raw axes/actions, lifecycle generation

CompletedTick
  tick, simTime, stateDigestMarker, inputSequence, journalStart, journalEnd

PresentationJournal record
  tick, sequence, kind(spawn|destroy|transform|visual), entityId, generation, revision
```

Stable ordering is tick then sequence. The journal is derived publication, not gameplay authority, and can be discarded/rebuilt. The renderer may skip obsolete presentation snapshots but may not reorder or invent simulation ticks.

## Mutexes

- `loop` — fixed-timestep and rAF ownership.
- `registry` — step/render order and authoritative manifest compatibility.
- `input` — raw axis/action semantics and tick-boundary publication.
- `lifecycle` — shared restore/suspend behavior inherited from PQ-035.
- `renderer` only for the narrow completed-tick adapter, not a presentation rewrite.

## Non-goals

- Simulation Worker, OffscreenCanvas, SharedArrayBuffer, or parallel system execution.
- Generic ECS conversion or a new authoritative entity store.
- Changing fixed dt, catch-up cap, discarded-time policy, system order, RNG, input grammar, or timeScale ownership.
- Making simulation faster by skipping systems or reducing cadence without evidence.
- Replacing the renderer or implementing dense `PresentationWorld`; PQ-038 owns that migration.
- Permanent dual loop implementations.

## Performance and quality budget

- No per-tick allocation for snapshots, completed-tick records, or common journal records after steady capacity is established.
- Input and completed-tick queues are bounded; overflow fails closed with diagnostics and cannot silently drop authoritative commands.
- Journal work grows with changes, not total entity count, and carries only stable IDs/scalars/revisions—not object graphs.
- Extracted runner overhead is below PQ-034 run noise on the current-population route.
- Stalled presentation must not amplify work beyond the existing explicit catch-up/shedding policy; hidden time remains excluded by PQ-035.
- Foreground visuals, interpolation, HUD, audio, input response, and deterministic outcomes remain equivalent.
