## Upstream contract

Exactly five literal page IDs are read by direct property lookup:

```text
wreck_cathedral.missing_convoy
wreck_cathedral.capital_hull_located
wreck_cathedral.clock_stopped_first
wreck_cathedral.released_from_inside
wreck_cathedral.what_was_carried
```

The receipt contains causal IDs/state/ticks and catalog revision, not title/body/image URL. The catalog contains immutable presentation and provenance, not earned state. The Ledger reads both; it writes neither.

Preferred bounded record:

```js
siteRecord.evidenceReceiptsByPageId[pageId] = receipt;
```

If the upstream owner exposes only an unbounded append-only array or requires scanning a general evidence object to find the five pages, stop and request a direct-keyed owner adapter. Do not disguise unbounded traversal behind the existing legacy admission cap.

## Deterministic projection

Stable row identity depends only on page ID, never revision, host, copy, image path, or arrival order. A higher accepted revision updates the same row.

Defensive selection per literal page:

```text
direct-read page value
normalize to one candidate or <=4 revisions
validate identity, finite saved tick/time, provenance and catalog revision
select highest valid revision independent of order
collapse byte-equivalent duplicate winners
if same-revision winners differ: omit page + conflict diagnostic
resolve exact catalog revision
publish one immutable row/detail keyed by pageId
```

A conflict is a hard acceptance failure. It is never resolved by last write, array order, display text, request completion, wall time, or host.
