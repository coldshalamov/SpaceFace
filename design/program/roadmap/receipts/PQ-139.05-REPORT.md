## Player-visible result

Live gravity wells now publish bounded distortion records into the existing production
`DistortionField` path. A dedicated six-slot well pool can coexist with the existing weapon-haze
producer; the render graph clears its distortion target once and accumulates every live producer.
Collapsed wells release their slots and the pass sleeps when no producer is live. Reduced-motion
turns well refraction off while reduced-flash leaves it available.

At 1280 px, the authored 190 WU / strength-240 well calibrates to an 11.20 px peak. Radius and
strength are monotone: 95/190/285 WU at strength 240 produce 5.60/11.20/16.80 px, and strengths
120/240/360 at radius 190 produce the same bounded progression. GPU strength is capped at 0.4
(about 17.92 px), preventing a whole-screen wobble.

The effect is intentionally available only through `settings.video.renderGraph === true`; the
bloom/native route does not sample the distortion texture.

## THE FRAMES

**None with refraction on: the capture harness cannot turn the flag on, and this is recorded rather
than worked around.** `settings.video.renderGraph` is `false` by default
(`src/core/gameState.js:28`), and there is exactly one seam that can change it before the renderer
exists — `bootstrapProfileSettingsBeforeRegistry(state)` at `src/main.js:97`, which reads
`sf.settings.profile.v1` out of `localStorage` **synchronously**, before `createRegistry`.
`captureFrameStrip` opens a fresh Playwright context for every run and never writes that key, and it
exposes no init-script or settings hook. Its one storage option, `playerStoreDir`, is the *server*
save store, which the save system fetches asynchronously long after the registry is built, so it
cannot decide the present path. The input tape can only press keys and move or click the mouse, and
the strip's own HUD-text-off stylesheet hides `#screens`, so a tape cannot reach the Video settings
toggle either. Nothing was photographed with refraction live and nothing is claimed about it.

**What is missing is one option on the capture, not a change to the game.** The setting is read
*live, per frame*, and the pass is built lazily: `src/render/presentPath.js:29`
(`if (video.renderGraph === true) return PRESENT_ROUTE.GRAPH;`) and `src/render/renderer.js:7654`
(`if (video.renderGraph === true && this._ensureRenderGraph() && this._renderGraph)`). So a
`page.addInitScript` in `captureFrameStrip` that seeds `sf.settings.profile.v1` with
`{ settings: { video: { renderGraph: true } } }` before the first page script runs would put the
strip on the graph route for the whole run, and the manifest should then record the route it
photographed beside `camera` and `hudText`. That edit is in `scripts/lib/bench/frameStripCapture.mjs`
outside the `STRIP_SCENARIOS` block this lane owns, so it is filed here rather than made.

**The shot itself already exists on the default route.** The `chain_reaction` tape added to
`STRIP_SCENARIOS` this session deploys a standard Well with `Digit5` into a swarm cluster and then
shoves hulls through it — craft, wrecks and debris crossing a live well at the shipping camera, which
is the picture this unit's done-when describes. Its manifest is
`design/program/roadmap/receipts/fun-loop/manifests/crucible/<sourceTag>/chain_reaction-physics_toolkit-s4242/`
(see PQ-137.09's receipt for the run this session captured). Those frames are the honest **before**:
the well pulls, and there is no refraction anywhere in them, because the flag is off. Re-running that
same tape with the init-script above is the whole remaining capture.

Whether the render graph should be the default route is the integrator's call, not this lane's; this
receipt only records that the flag is off by default and that the instrument cannot set it.

This receipt deliberately stops at `implemented`. Queue `done` requires a 1280 px normal-speed
shipping-camera capture with the render graph enabled, HUD hidden, and loose debris visibly falling
through a standard well's localized refraction without whole-screen wobble.
