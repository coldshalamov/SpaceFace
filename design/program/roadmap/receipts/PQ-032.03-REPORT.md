## Honesty gaps

### The done-when's own example id is not a live id

`title_thunderchild:0:player` cannot be written by the live game. The full input trace is under
WHAT IS NOT: `titleSeenRecord` takes its holder half from `holderKeyOf(entity)` =
`entity.data.worldRecordId`, the only hold-opener excludes `state.playerId`, and no producer in
`src/` gives the player hull a `worldRecordId`. This is the PQ-140.01 shape the protocol names — a
green assertion fed a value the live route cannot produce.

What survives the correction: the peel is not id-specific. It slices at the first colon, so it is
right for the ids the game does write. The added test proves that on
`title_thunderchild:0:wr_ship_1a2b3c4d`. The mechanism is sound; the claim about who ends up holding
the title is not.

### The carried Thunderchild is inert on the live route

Four consumers all key on `holderKey`, and on the live route all four miss: `syncTitleStamp` (no
hull stamped), `wingMorale.thunderchildHolder` (no aura), `saveLoad.isPlayerHeldTitle` (absent from
the slot card), and `_rebindSilently`'s player fallback, which skips Thunderchild by name. Only the
Ship Ledger sighting row reads the carried record, and whether it wins a slot was not traced.

### The fed byId row is not a live shape either

The fixture's held Thunderchild row omits `holder`. `ensureState` forces `status` to `vacant` for a
held row with no holder (`titles.js:112`), so a saved bag can never contain that combination. The
added live-id test supplies the holder. It does not change the outcome of the original test; it
means the original test's byId row is constructed on a second axis as well.

### The wipe explanation was right by accident

The prior receipt said the test's `titles.newGame()` stands in for a live wipe via `game:new`. The
mechanism is different: `titles` subscribes to `game:newGame`, which nothing on the New Game route
emits, and `titles` is absent from `FRESH_RUN_SYSTEMS`. The real wipe is `resetRunState` replacing
`state.story` wholesale. Ordering still holds — `prepareRun` runs before `game:started`.

### The claimed pass count was wrong

The file ran 8 tests, not 7: the byId-map-key test was appended twice, byte for byte. The duplicate
is removed and the slot now holds the live-id case.

### Carried over from the prior pass, still true

- postEnding on the new run is fresh continuity of ending E, not progress from the completed source.
- The "save migration test" still uses `CURRENT_VERSION` envelopes.
- The keepsake GRANT is still untested; `main.js` still throws `NEW_GAME_PLUS_UNAVAILABLE` when
  `grantModule` returns false.
- Headed capture is peeled.
- `program-queue.json` is not marked.
