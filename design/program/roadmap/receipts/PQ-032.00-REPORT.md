## Honesty review 2026-09-09 (inputs traced, not assertions)

Law verified live by direct probe, not by reading: at the 90 WU dest-dock pose `dock:docked` pays
`tow_in`, `massline:throw` pays `sling_in`, and a clean `tether:releaseRated` pays `sling_in`; at
434 WU — inside the leftover 700 WU berth — the release path, the loose-dock path and the latched
dock path all refuse. `STATUS DONE` stands. Three test-side repairs, no `missions.js` change:

- **The far throw was not the live event.** `masslineThrow._executeThrow`
  (`src/systems/masslineThrow.js:419-463`) emits `massline:throw` only from a live attachment it then
  cuts, and that cut produces the canonical `tether:releaseRated` next tick. The old test emitted a
  bare throw with no latch — a shape the publisher cannot produce — and never touched the release
  path at range. The refusal direction was safe (the gate is distance-only), but the coverage was
  not. The test now drives latch → throw → clean release at 1471 WU and refuses all three.
- **Beat 3's headline verb was unproven.** `towToTheDock(..., 'tow_in')` took a branch that threw the
  core and asserted `sling_in`, so the parameter named the method it did not test and the spine's
  method list ended `sling_in`. A mission settles once, so the spine now runs twice from the same
  arrival pose: cut the line → `sling_in`, keep it on the line and dock → `tow_in`.
- **1471 WU was unpinned.** The spine spawns the cargo off the sector origin; a live jump arrives
  farther out, so the harness refuses at a distance the live route beats by ~3x. A new test pins the
  live arrival (`world.entryPoint` + the 220-300 WU spawn ring) and fails if a leftover cargo could
  ever start inside the old 700 WU berth.
