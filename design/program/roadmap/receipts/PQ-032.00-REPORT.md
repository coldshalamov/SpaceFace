## Honesty gaps

- **Nothing in the game can touch the dead tower.** A `wreck` spawned without an explicit
  `collisionMask` takes `DEFAULT_MASK.wreck === 0` (`src/core/entity.js:16-25,167`), and
  `canCollide` is a mask AND (`src/core/physics.js:1055-1057`). The mission spawn sets
  `collides: true` but no mask (`src/systems/missions.js:3905-3922`). So the projectile sweep skips
  it (a projectile's mask is `SHIP|ASTEROID|STATION`, no `WRECK` bit — `physics.js:641`), and a
  thrown rock (`asteroid`: `SHIP|PROJECTILE|DRONE`) passes straight through it with no contact
  resolution.
- **Both of B1's posted solutions are therefore dead.** `wrecking_ball` hooks
  `on: ['whip', 'throw']` and `cut_down` hooks `on: ['kill']` (`src/data/missions.js:1099-1100`).
  The `whip` half cannot fire (wreck excluded from the impact victim filter). `cut_down` cannot fire
  because the tower cannot be shot. Two solutions are posted and the test asserts
  `completionMethods.length === 2`; **one** is live.
- **The one live completion settles at release.** `_onPhysicalThrow` completes the moment
  `massline:throw` fires with `aimTargetId === tower.id` (`src/systems/missions.js:4428-4434`). A
  throw that misses entirely still finishes the contract — and per the masks above, every throw
  misses.
- **The pods cannot be shot either.** They are `type: 'wreck'` on the same zero mask
  (`missions.js:3930-3947`), so the two `rescue_escort` wasps cannot destroy them. The contract
  carries a `podsLost` counter (`embodiedMissions.js`) that gunfire can never increment. The escorts
  are real and shoot the player; the pods themselves are not at risk. B3's slag core is
  `type: 'asteroid'` (`missions.js:3882`) and is a genuine physical body — that one is sound.
- **No berth proximity on the latch completions.** `_tryPhysicalDockComplete` settles `tow_in` and
  `stage_tow` on `_playerLatchedTo` alone (`src/systems/missions.js:4328-4348`). The `sling_in`
  branch immediately beside it *does* check `_entityNearDestBerth`. That asymmetry is the defect.
  `m.params.latchedTargetId` is written once (`missions.js:4362`) and never cleared, and
  `_playerLatchedTo` falls back to it when `state.player.tether.targetId` is null — so a released
  line still reads as latched. The dock turn-in does gate on `m.destStationId`
  (`missions.js:4570`), so the degenerate run is "dock at the right station without the cargo", not
  "dock anywhere".
- Leftover B1–B3 were haul / bounty / hull-buy. They did not already name the verbs.
- B2 board tag is still leftover `campaign47a:b2:elroy`. The beat id is `first_blood`. The verb is
  pull.
- Leftover Elroy identify / custody / force handlers remain, gated to `bounty_hunt`. The default B2
  offer is rescue. The weak-point graffiti test still plants a leftover bounty to fire that path.
- Leftover B3 shipyard routes (`getBiggerBoatRoute`) remain for later leftover stakes. B3 itself no

- Later beats still read `elroy_outcome` when one exists. This leaf does not set a new choice. The

- `src/systems/missions.js` was required so the spine actually advances. The packet write set named

- Auto-dispatch on undock still accepts the one story contract. That is not a choice menu.
- Continue saves sitting on the old cargo haul or hull-buy must accept the new set piece.
- Headless only. No shipping-camera strip. The job forbade headed capture.

## Shared-change requests

All three sit outside this leaf's write set (`src/data/missions.js`, `src/story/`,
`src/core/newGamePlus.js`, `src/data/postEndingReplayChains.js`) and were **not** made here.

1. **Give the tower and the pods a collision mask.** `DEFAULT_MASK.wreck === 0`
   (`src/core/entity.js:24`) makes every mission-spawned `wreck` untouchable by projectiles and by
   thrown mass. Either set an explicit `collisionMask` on those spawn specs, or give the `wreck`
   default a real mask. Owner: physics/entity + missions spawn. This is the root cause of both dead
   B1 solutions, and it also applies to the PQ-152 authored `set_piece_wrecking_ball` and
   `set_piece_pod_rescue`, which use the same `kind: 'wreck'`
   (`src/data/encounters/set-piece-authored.js:33,49`).
2. `src/systems/masslineImpacts.js` — `COLLIDABLE_TYPES` (`:48`) excludes `wreck`, so even with
   request 1 landed, no whip impact would name a wreck as victim. Admit `wreck` there so the swing
   becomes the verb the beat is named for. Owner: massline/impacts.
3. `src/systems/missions.js` `_onPhysicalThrow` — require contact (the whip impact from requests
   1+2) before `wrecking_ball` settles, rather than settling on release.
4. `src/systems/missions.js` `_tryPhysicalDockComplete` — apply `_entityNearDestBerth` to the
   `tow_in` / `stage_tow` / `latch_dock` branches, matching the `sling_in` branch beside them.
