# PQ-185.01 — Asteroid Works matrix and acceptance

**Verdict:** KEEP. The mining board is the game. It is not a gunmetal console and it was not restyled into one.

## What a player gets

You fly to a rock, latch on, and press the drill key. The mine comes up. Before this pass the approach finished and the screen was pushed, then a 150ms fade stayed stuck at invisible in the headless checker, so the route was scored as "never opened." The dock veil is still the arrival. The second fade on the shell is skipped so the board is actually there.

The rock's name (`AST-` plus its number) and the claim chip use tabular figures, so the digits line up. On a 2560-wide window the board sits in a centered frame 2508px wide (under the 98% stretch line) and still covers most of the glass. At 1280 and 1920 it stays edge to edge. Longer language can wrap the top strip and the heat/charge labels instead of clipping them. The spoken announcement for screen readers no longer counts as a clipped box.

No new look. The rock is still the screen. Heat and charge stay the small cluster in the corner. Orrery rings were not painted over a board that already owns the glass.

The process still exits 1. Three reasons, none of them a red measurement of this screen:

1. Those unproven seams fail the row on purpose. The matrix tests forbid turning them green from a proxy. No screen in the game is fully green until that tool exists.
2. A one-surface run measures 1 screen. The check also requires 30.
3. Reeling into the rock took about 56–122 seconds per pass. The measuring budget is 5 seconds. The time is the flight, not a hitch inside the board.

`npm run check:asteroid-works-render`: 19 passed, 0 failed.

## Review

Would I put this in front of someone tonight? Yes. You bore the rock. The words are few. It is not a painted metal dashboard and not a web page of cards. A later pass can hang heat and charge on arcs of light; doing that here would have been a restyle of a screen that already reads as the mine.
