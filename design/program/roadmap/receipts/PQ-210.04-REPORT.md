## What shipped

1. `src/core/graphicsProfileBootstrap.js` — `AUDIO_DEFAULT_MUTE_VERSION` 1 → 2. The v1 policy
   force-muted every older profile once because the procedural-only stack was opt-in; that era
   ended when PQ-158.06 landed the authored sound pass, but the migration was never revisited —
   so the game still shipped silent to any profile that predated the stamp, and fresh installs
   inherited the same mute through the migration path. v2 reverses the default for the same
   reason v1 existed: a pre-policy profile cannot distinguish an intentional mute from the old
   default, so it receives one unmute. Stamps at the current version keep the player's explicit
   choice; a stamp from a NEWER version is now left alone instead of being downgraded.
2. `test/hit-answer-channels.test.mjs` (new, 4/4) — the four-channel contract, pinned honestly:
   the real `feel`, `vfx`, and `audio` systems are init'd onto the same bus as the real damage
   router, so the bus subscriptions themselves are under test (deleting `bus.on('combat:damage')`
   in feel.js or audioSystem.js, or `add('projectile:hit')` in vfx.js, fails the suite). Terminal
   sinks are observed, not entry points: `timeEffects.set('feel:hit-stop')` + `feel._hsTimer`,
   `WeaponLightPool.live`, `combat:hitstunImpulse` + the physics impulse port, and `audio.play`
   requests checked against `AUDIO_RECIPE_BY_ID`. The repeater law is pinned both ways —
   autocannon punches FOV with NO hold, concussion cannon earns the real 1–2 frame dip.
3. `test/graphics-profile-bootstrap.test.mjs` — migration expectations re-pointed (10/10):
   pre-v2 profiles unmute once, post-policy choices survive, future stamps untouched, boot never
   rewrites the profile.
4. `scripts/probe-hit-answer.mjs` (new) — the live audit: real browser, real Crucible route,
   seed 4242, default kit (`ricochet_runner` = ship_hornet + `wpn_autocannon_m` +
   `wpn_concussion_cannon_m`), driven by public controls only (G target-lock + held LMB).
   Observes, never mutates.
5. `SAVE_SCHEMA.md` / `ARCHITECTURE.md` — stale `defaultMuteVersion: 1` / `muted: true` defaults
   synced to the shipped policy.

## Tradeoffs recorded

- A player who *deliberately* muted during the v1 era carries `muted:true, v1` — indistinguishable
  from a policy mute — and is unmuted exactly once. Re-muting is one click and is never touched
  again. The unit's text accepts this; there is no signal that could do better.
- `WeaponLightPool` is a strict 2-slot priority pool; in a dense exchange a low-priority hit light
  can be evicted by a heavier one. That is the authored budget, not a missing channel.
- Audio cue delivery (AudioContext running, distance culls) is browser-side and out of scope for
  the Node contract; the live audit exercises the real `play()` path and counted 215 cue calls.
