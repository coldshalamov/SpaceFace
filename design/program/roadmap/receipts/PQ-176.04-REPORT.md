IMPLEMENTED PQ-176.04 — fitted hardware is now visible on the hull: any module at 15 % or more of
the outfit budget mounts an authored part on the ship's fit sockets, the fitted drive recolors the
nacelle glow, and big guns bristle on both modular hulls and the baked whole-ship bodies.

DONE WHEN (verbatim): Stills at the shipping camera show the build; the asset reachability check
stays green.

WHAT I FOUND — The visible-fit contract was half-built. Whole-ship bodies (the Kestrel and every
roster hull) carry authored `SOCKET_*` markers — `SOCKET_Weapon_Front`, `SOCKET_Utility_Dorsal`,
`SOCKET_Cargo_Ventral`, `SOCKET_Engine_Main` — and `wrapShipWithAuthoredParts` already mounted
*runtime* weapons through them, but nothing a player fitted ever appeared: the modular mount path
was skipped for whole-ship hulls, non-weapon modules had no visual at all, and the drive swap left
the nacelle glow untouched. Hot-swap itself was already wired — `recomputeEntity` changes the
appearance fingerprint and emits `ship:appearanceChanged`, and the renderer rebuilds on that event —
so the missing piece was purely which parts the composition asked for and where it hung them.

WHAT I CHANGED — `src/render/partsLibrary.js` gains `visibleFittingsForEntity`: a fitted module is
visible when its mass is at least 15 % of the hull's `outfitSpace` (relative to the budget, not an
absolute mass cut, so a Shield L on a capital hull and a stripped thruster on a fighter both read
honestly). `fittedModuleMounts` maps each visible module onto the authored contract — cargo →
`pod_cargo_container` on the ventral socket, mining → a pod at the bow, utility/sensor → utility
pod or `greeble_antennas` dorsal, thrusters → mirrored `greeble_rcs` pairs — with per-module
`visuals.part` overrides for cases where the slot default reads wrong (Ram Plate → armor plates,
Sensor Array → antennas). Fitted weapons now mount on whole-ship bodies too via the same socket
contract (`authoredWeaponMounts` `fittedOnly` branch), so a railgun bristles at the bow. The fitted
drive does not add geometry — every hull already shows an engine — instead `visuals.glow` on the
engine module def re-tints the drive core/plume materials (clone-on-write, shared cache materials
untouched): Ion blue `#8fd4ff`, Fusion amber `#ffb154`, Warp violet `#b48cff`, Pale-Coil near-white
`#d8f4ff`. `authoredPreloadPlanForEntity` now cooks those same fit-dependent files into the plan for
both modular and whole-ship entities, so admission/preload demand exactly what the composition
mounts. Only files inside `PART_LIBRARY_CONTRACT` are ever requested — no invented asset paths.
`station-lab.html` gained `?fit=heavy` so the live Shipworks screen can exercise a big-budget build;
`scripts/capture-visible-builds.mjs` captures the shipping-camera stills.

WHAT YOU WILL FEEL — Fit a bigger drive and the engine glow changes color before you undock. Bolt
on a railgun and it shows at the bow; a cargo expander rides under the hull; a sensor array raises
antennas; vernier thrusters add RCS quads. Strip the fit and the hull goes clean again — the
silhouette tells you what the ship is carrying.
