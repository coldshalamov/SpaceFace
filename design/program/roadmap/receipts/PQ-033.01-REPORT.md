## Honesty review — 2026-09-09 (Claude opus, `.devshots/packets/HONESTY-REVIEW.md`)

Traced the test's **inputs**, not its assertions, at `0020b7907`. Three passing tests, one flipped
row. Production was not touched.

### FLIPPED — the leftover version is not live on the packaged route

`test/pq-033-01-crash-version.test.mjs` mocks `fetch` as a hardcoded `{ ok: true }` that always
returns the repo's own `package.json`:

```js
globalThis.fetch = async (url) => {
  assert.equal(String(url), '/package.json');
  return { ok: true, async json() { return leftoverPkg; } };
};
```

That input can only ever model the **source** route. The packaged route cannot produce it. Each link
verified against live code, then measured:

1. `paintLeftoverVersion` → `loadLeftoverVersionPayload` → `fetch('/package.json')`; on `!response.ok`
   it resolves `null`, and `applyLeftoverVersionText(target, null)` returns the node **unchanged**.
2. The unchanged text is the hardcoded starting string in both places — `pause.js` mounts
   `el('span', '', leftoverVersionLabel(null))` = `SpaceFace`, and `mainMenu.js:278` mounts
   `el('span', '', 'SpaceFace')`. Neither carries a version.
3. `resolveWebRoot({ packaged: true })` (`scripts/lib/electronLaunchProtocol.cjs:164`) returns
   `build/web`, not the project root.
4. `build/web/package.json` does not exist and never will: `RELEASE_COPY_MAPPINGS`
   (`scripts/lib/releasePackaging.mjs:22`) has no `package.json` entry and `scripts/build-bundle.mjs`
   never mentions the file. The electron-builder `files` entry puts `package.json` at the **asar
   root**, which is not the served web root.
5. `scripts/lib/gameServer.cjs:255` answers a missing file with `404 Not Found`.

Measured, both roots served through the real `createGameServer`:

```text
packaged=false webRoot=.          GET /package.json -> 200 ok=true  {"name":"spaceface","version":"0.1.0",...
packaged=true  webRoot=build\web  GET /package.json -> 404 ok=false 404 Not Found
```

Measured, the same packet test re-run with only the mock flipped to the packaged truth
(`{ ok: false, status: 404 }`):

```text
PQ-033.01 pause under packaged 404: "SpaceFace"
  actual:   'SpaceFace'
  expected: /SpaceFace v0\.1\.0/
```

So the done-when clause *"leftover version on title and pause"* is live on the source/dev route and
**not live in a packaged build** — the one build where an installer version and a local crash dump
actually matter. `AGENTS.md` §6 makes browser, Electron, and packaged builds one game path, so this
divergence belongs on STATUS rather than in a footnote. The title half of the hole is inherited, not
introduced here: `_loadVersion` was already the `/package.json` fetch before this packet. The pause
half is new and copies the same dependency.

### CHECKED AND DISMISSED — pause does paint itself

The test calls `paintLeftoverVersion(target)` by hand before asserting `versionNode.textContent`,
which would let a broken `mount` → `_loadVersion` path pass unnoticed. Tested by deleting the manual
call from a scratch copy and letting only `pauseScreen.mount` run: the node still painted
`SpaceFace v0.1.0`. `els` is assigned before `this._loadVersion()` in `mount`, so the live paint is
real. The manual call is redundant, not load-bearing. Not a finding.

### CHECKED AND CONFIRMED — the receipt's own admissions hold

- *"No leftover commit/build hash was already available in the Electron shell"* — true.
  `collectRuntimeIdentity()` (`electron/main.cjs:371`) carries only electron/chromium/node/v8,
  `isPackaged`, and paths. No git sha appears anywhere in `electron/*.cjs` or
  `electronLaunchProtocol.cjs`. The one build artefact the packaged route *does* serve,
  `build/web/spaceface-release-build.json`, carries no version or hash field either. Nothing was
  available to use, and nothing was invented.
- *Updater NOT DONE* — true and pinned. No `electron-updater` in the tree, and the test asserts its
  absence (`doesNotMatch(mainSrc, /\bautoUpdater\b/)`). `package.json` was not edited.
- *Forced crash dump not live-run* — true. `startLeftoverCrashReporter(electron)` is unconditional at
  module top level and correctly ordered (isolated `userData` → `setPath('crashDumps')` →
  `crashReporter.start`), so the wiring is real; only the dump itself is unproven.

### COVERAGE GAP — the crash boot assertion never sees the packaged shape

The sandbox stubs `app.isPackaged: false` and `resolveElectronLaunchConfig()` →
`isolatedEvidence: false`. So the boot-path assertion
`paths.crashDumps === join(paths.userData, 'crashes')` is measured only with the **default,
un-isolated** `userData`; the `app.setPath('userData', launchConfig.userDataDir)` branch that the
receipt names ("crashReporter.start after isolated userData") is never taken, and the packaged shape
is never exercised. Source order was verified by reading only. A gap in what the green proves, not a
false claim.
