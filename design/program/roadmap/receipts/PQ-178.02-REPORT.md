### What the packet actually proves — held up

Re-resolved from live bytes, not read off the receipt:

  `narrative.js` bytes exactly, curly apostrophe and em dash included
  (`faction_dmc.scan[0]` carries `ain't` with U+2019; `story_b8_helix_audit`
  carries an em dash). No invented example text.
- `BARKS.faction_helix` is genuinely `undefined`. Helix has **no bark table at
  all**, so its register is anchored to `COMMS.story.story_b8_helix_audit`, a
  single `once`-flagged story comm. The receipt discloses the narrative.js
  source; it does not disclose that Helix's register therefore rests on one
  non-repeating line rather than on any faction bark the game speaks.
- Free Frontier is cite-only. Its sheet carries no register keys, `faction_free`
  is absent from `REGISTER_HOUSE_IDS`, the `voice_register` block quoted in

  raises `invented_house` if register keys are added to it.

- The 7-of-8 % is genuinely uninvented, and `REGISTERS.md` says so in words. The

### The miss — the test never runs the path it names

`test/pq-178-02-registers.test.mjs` names its first case *"leftover writing-rule
keys a leftover reader can assign"*. Its only call into the reader is:

    assert.equal(assignRegister(sheet.register_example), sheet.id);

The input is the sheet's own stored `register_example`. Inside `assignRegister`,
that string-equals the same sheet's `register_example` and returns on the
**exact-match** branch at the first filter. The `register_tell` substring
branch — the only path a bark a writer *newly writes* could ever take — is never
executed by any test in the file. The green case is the answer key fed back to
itself, eight times.

`assignRegister` is not a register reader. It is a case-sensitive
`String.includes` against one hardcoded phrase per house.

### Three silent holes in the leftover validator

`validateFactionRegister` cross-checks exactly one pair of keys
(`register_example` against `register_example_cite`). The other four are
presence-only. All three of these return `[]` — the headless check passes them:

1. **The cite is never checked against its own house.** Anchoring Concord's
   register to `src/data/barks.js#faction_mts.scan[0]` — MTS bytes on the
   Concord sheet — yields zero issues.
2. **`register_tell`, `register_forbidden`, and `voice_direction` may be
   whitespace.** Only `register_rule` gets an `empty_rule` check. A sheet with a
   blank tell passes the validator, and the reader then silently loses that
   house. The *test* catches this with its own `trim()` loop, so the receipt's
   claim that the headless check fails "leftover empty leftover rule" is true
   only for the one key named.
3. **`register_forbidden` is never compared against anything.** It is prose. An
   example, or a live bark, may contain every term its own house forbids and
   nothing reports it.
