## 4. What a green check could NOT see (and how it was caught)

Two defects survived every node test and were found only by driving the real game:

1. **Six kills worth twelve credits paid eight.** Uncollected chips were credited at a phase
   boundary; two of six bodies were already destroyed by then. Then a deeper one: `pickup:collected`
   has **two publishers with different payload shapes** — `mining`'s carries a `wallet` field,
   `physics`' contact-collect does not — so a chip the player *flew into* paid differently from one
   the magnet pulled in. **No headless check can ever see this, because a headless player never
   moves.** Run chips now have exactly one payer settling from its own ledger.
2. **The route probe's own first version was too weak.** Killing through the console `entity:kill`
   seam only flips `alive`; it never reaches `combat.kill()`, so no kill receipt, no reward, no chip.
   It now kills through a lethal `projectile:hit` — the real damage route — which is why the
   shortfall became visible at all.

3. **The second draft of a run re-showed the first draft's three cards.** The draft surface was
   built once and cached. The route probe opens exactly one draft, so a repeat on the second was
   structurally invisible to it — the same class of blind spot as the two above, and found only
   because a separate lane read the screen's lifecycle rather than its output. A full ten-wave
   capture now ends with nine DISTINCT drafted verbs.

Also caught: `check:playable` stayed **green** while the Node runtime was broken, because the browser
reads `registry.js` and headless reads `nodeSystemFactoryTable.js`.

## 5a. Behaviour changed OUTSIDE this leaf

Stated plainly because these touch code a campaign player hits, not just the Crucible:

- **Combat Lab autosave suppression** (`leaf .01`). Campaign save suppression was broadened from
  `kind === 'survival'` to include `kind === 'lab'`. Correct per ruling 2 — a Lab session is the
  same ephemeral state by another name, and it previously left campaign autosaves live while an
  arena relocation fired `sector:enter`. It is still a behaviour change to `.01` made from `.02`.
- **`game:save` / `game:load` bus handlers** (`saveSystem.js`) are now wrapped. For an Adventure
  session both predicates are false and behaviour is byte-identical; verified by `check:sim`
  (47-A golden, unchanged), `check:save-schema`, `check:combat` and `check:playable`'s own
  save/Continue round trip.
- **`mining._collectCreditChip`** no longer emits `economy:grantCredits` for a chip stamped
  `wallet: 'run'`. Campaign chips take the unchanged branch. Precisely: on the run branch the
  campaign GRANT is skipped, but acceptance is still reported and `creditGranted` is still
  stamped — the body must be consumed either way, and `resolvePickupAcceptance` reads
  `acceptedAmount` to do it. For a run chip that flag now means "handled", not "paid"; a comment
  in the file says so, since nothing else in the tree depends on the older reading.
- **A recycled-entity-id guard** now sits in the wave owner, not in `core` or `spawnBudget`. The
  underlying race is theirs and pre-dates this program; the guard is local so no shared owner
  changed.
