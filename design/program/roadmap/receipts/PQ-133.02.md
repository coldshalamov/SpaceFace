## 4. What a green check could NOT see (and how it was caught)

Two defects survived every node test and were found only by driving the real game:

1. **Six kills worth twelve credits paid eight.** Uncollected chips were credited at a phase
   boundary; two of six bodies were already destroyed by then. Then a deeper one: `pickup:collected`
   has **two publishers with different payload shapes** — `mining`'s carries a `wallet` field,
   `physics`' contact-collect does not — so a chip the player *flew into* paid differently from one
   the magnet pulled in. **No headless check can ever see this, because a headless player never
   moves.** Run chips now have exactly one payer settling from its own ledger.
2. **The route probe's own first version was too weak.** Killing through the console `entity:kill`
   seam only flips `alive`; it never reaches `combat.kill()`, so no kill receipt, no reward, no chip.
   It now kills through a lethal `projectile:hit` — the real damage route — which is why the
   shortfall became visible at all.

Also caught: `check:playable` stayed **green** while the Node runtime was broken, because the browser
reads `registry.js` and headless reads `nodeSystemFactoryTable.js`.

## 5. Reviewer findings fixed

A stronger reviewer read the landed slices against the binding rules. Four fixed:

- **F5 mid-run wrote the arena over the campaign save.** Only autosave was suppressed; the pause
  brief literally instructed the blocked keypress. Manual save is now refused, loading out of a run
  ends the run, and suppression covers Combat Lab too.
- **Winning under-reported salvage** — the wave-10 sweep settled after the results froze.
- **A wave the arena could not build hung the run forever** — `run:wavePlanFailed` had no listener.
- **A recycled entity id could clear a wave with a live enemy still shooting** — core reissues a dead
  body's id immediately but queues its destroy receipt to end of tick. Fixed and mutation-verified.

## 5a. Behaviour changed OUTSIDE this leaf

Stated plainly because these touch code a campaign player hits, not just the Crucible:

- **Combat Lab autosave suppression** (`leaf .01`). Campaign save suppression was broadened from
  `kind === 'survival'` to include `kind === 'lab'`. Correct per ruling 2 — a Lab session is the
  same ephemeral state by another name, and it previously left campaign autosaves live while an
  arena relocation fired `sector:enter`. It is still a behaviour change to `.01` made from `.02`.
- **`game:save` / `game:load` bus handlers** (`saveSystem.js`) are now wrapped. For an Adventure
  session both predicates are false and behaviour is byte-identical; verified by `check:sim`
  (47-A golden, unchanged), `check:save-schema`, `check:combat` and `check:playable`'s own
  save/Continue round trip.
- **`mining._collectCreditChip`** no longer emits `economy:grantCredits` for a chip stamped
  `wallet: 'run'`. Campaign chips are untouched by construction.
- **A recycled-entity-id guard** now sits in the wave owner, not in `core` or `spawnBudget`. The
  underlying race is theirs and pre-dates this program; the guard is local so no shared owner
  changed.

## 6. Performance

## 8. Shared-change requests

1. **`pickGate` overwrites each package's authored gate with a uniform-random one ~50% of the time**
   (`survivalWavePlanner.js`). A wave authored as a three-sided squeeze is currently a coin flip.
2. **No exported canonical list of `arenaPhase` values.** The validator accepts any non-empty string;
   two files now carry the list of eight independently and will drift.
3. **The Combat Lab (leaf .01) still cannot fit its own `physics_toolkit`** — every module is
   tier-2+ and the research gate refuses them in a fresh game. Verified by probe:
   `applyCombatLabSetup` returns `notFitted` for all three. Crucible works around it by unlocking
   the tech tree at launch; the Lab does not.
4. **`spec.data.telegraph` / `counterHint` are written by `combat.js` and read by nothing.** The
   Crucible sources that copy from the enemy defs instead, because the per-entity mirror carries no
   entity id in any payload that reaches a consumer.
5. **`damageTrail` entries carry a bare numeric `attackerId`** with no label, so the results plate
   cannot aggregate by attacker — only by weapon. Wanted shape:
   `{ attackerId, attackerLabel, faction, weaponId, amount, type }`, resolved the way
   `attackerLabel(state, attackerId)` already does in `src/combat/playerDefeat.js`.
6. **The published result has no structured stop reason**, so `aborted` cannot distinguish a player
   quitting from the arena failing to build a wave. Wanted: `stopReason: 'player_exit' |
   'wave_plan_failed' | null`. Until then the results title stays neutral ("Run Ended") rather than
   accusing a player of abandoning a run the arena broke.
