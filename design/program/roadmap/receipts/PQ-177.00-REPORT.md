## Honesty review 2026-09-09 — what is live and what is not

This section replaces the original "the blockade is injectEvent" gap with the traced answer, and
adds two gaps the first pass did not name. Protocol: `.devshots/packets/HONESTY-REVIEW.md`
(trace the test's inputs; STATUS must match the live route).

### The blockade is live, not a constructed value

The first pass flagged `economy.injectEvent` as an honesty gap. Traced, it is not the PQ-140.01
pattern (a number the live route cannot produce). `injectEvent` is the production constructor:

- `economy.js:2128` — `rollSpontaneousEvent` picks from `['shortage','boom','blockade','piracy']`.
- `economy.js:2131` — that roll calls the same `this.injectEvent({type, stationId, commodityId, duration})`.
- `economy.js:2082` — `injectEvent` emits `economy:eventStarted { eventId, type, stationId, commodityId, duration }`, the exact payload `marketNews.js:323` subscribes to.
- `economy.js:832-834` — the roll fires inside `econTick` every `EVENT_INTERVAL_S = 90` sim seconds.
- `economy` is in the production `UPDATE_ORDER` (`docs/SYSTEM_REGISTRY.md:15`), so that clock runs on the default route.
- `economy.js:2256-2259` — `newGame()` warms every home-sector market, so the roll has targets from the first frame.
- The test's `duration: 120` sits inside the spontaneous 90–210 s band; the station and commodity ids are real catalog entries.

Test 2 in `test/pq-177-00-ticker.test.mjs` now proves it end to end with **no `injectEvent` call**:
it runs `newGame()`, drives `sim.step(1/60)`, and waits. On seed 17700 the very first scheduled
roll is a blockade at Ceres Refinery at **91 sim seconds**, and it lands on the ticker log citing
`economy:eventStarted`, with the cited id present on `state.economy.econEvents` as a live
`type: 'blockade'` event.

### The dock card has no renderer — this is why STATUS moved

The done-when is "capture of a blockade line and its card." The card does not exist on screen:

- `marketNews.js:332` emits `news:dockCards`. It has **zero subscribers** — `docs/EVENT_ROUTING.md:845` records 1 emitter, no consumers, and a repo-wide search finds no listener.
- `state.ui.marketNews.lastCard` has exactly one live reader: `dockArrival.js:31-32`, and it uses the card only as a **fallback string** (`card.headline`), never `badge` / `title` / `body`.
- `dockArrival.js:29` prefers a station-matching log line first, so in practice even that fallback rarely fires.
- `stationApp.js:1000` renders `buildDockArrival(...).news` — one string under the station name.

So at the berth the player gets a headline, not a card. `BLOCKADE`, `Iron Ore Blockade` and "iron
ore is frozen at Helios Station" are computed, stored, asserted by the test, and drawn by nothing.
Test 3 records that surface without forbidding a future renderer.

### There is no ticker strip either — the line ships on the alert floor

`marketNews.js:358` mounts its DOM strip only into `document.getElementById('news-ticker')`. No
file in the repo creates that host. `scripts/check-ui-identity.mjs:74-83` pins that lookup and
**forbids** falling back to `#hud` or `document.body`, so the absence is deliberate policy, not an
oversight. `renderTicker` is therefore a no-op on the live route.

This is not a defect against the leaf, which asks for the line "at the arbiter's chatter tier":
`voiceArbiter.js:303-304` installs `ctx.helpers.voice`, `uiRoot.js:394` hands that same ctx to
`createMarketNews`, and `commitHeadline` says the line on the `news` channel with a `toast` floor
underneath. The line reaches the player. It is not a rotating ticker, and the original receipt's
"the ticker names the station and the freeze" overstated the surface. The original gap line said
the host "was not opened or captured," which reads as a missed capture; the truth is that no
renderer exists to capture.

### "Traces to a sim event" is enforced, with one vocabulary caveat

`commitHeadline` (`marketNews.js:230-231`) drops any record `tickerEventRef` cannot cite. That is
live production behaviour, not a test-only rule.

`tickerEventRef` accepts `eventId` / `id` / `intentId` / `sourceRef` / `receiptId`. Economy and
freight lines cite real runtime ids; authored `news:publish` lines cite an authored constant such
as `traffic:helios-civic-liner` — honest provenance, but a token, not a sim event id.

Every live emitter carries one, so the refusal rule drops nothing the player used to see. Checked
exhaustively: **8 emit sites in 4 files** — `traffic.js:2853` and `:8171` (`sourceRef`),
`titles.js:590` and `:701` (`receiptId`, on both the succession and the vacant branch),
`world.js:537` (`id` + `source`), `uniqueWrecks.js:371`, `:1490` and the `_surfaceCanonicalRumor`
relay reached at `:772` (`sourceRef` + `receiptId`). A repo-wide search finds no other emitter on
the live route — the remaining hits are the generated `build/web` bundle, the packaged `dist`
asar, and a CI log, all copies of the same `src` sites. In particular no scenario file emits
`news:publish`, so the dirty `329-curtain-convoy.js` is unaffected.
