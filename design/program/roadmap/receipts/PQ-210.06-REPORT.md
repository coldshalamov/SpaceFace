## What landed

Every harness in `scripts/` that can run over two minutes now lowers its own OS priority at process
start, mirroring the `scripts/run-actual-game-playthrough.mjs:28` reference:

```js
try { os.setPriority(os.constants.priority.PRIORITY_LOW); } catch { /* best effort: background compute yields to the game */ }
```

The rule is written into `docs/AGENT_OPERATIONS.md` (the existing play-machine power-budget bullet,
tightened to the always-runs-at-lowest-priority rule).

## Risks / residuals

- The priority is best-effort by design; a harness run under an admin token that denies
  `setPriority` degrades silently to old behavior (no crash, no output change).
- Electron/browser child processes inherit the parent's priority on Windows; harnesses that
  re-exec themselves at a different elevation are not covered by this pass.
