## Honesty review 2026-09-09

Reviewed at commit `d2089c9a6` against `.devshots/packets/HONESTY-REVIEW.md`. Everything above

### Verdict: NOT DONE

Two beats out of three describe the live settle correctly. Beat 3 describes it backwards, and it
does so in the one clause the leaf exists to get right — what a player must physically do to be
paid. The done-when also asks for "captured (PQ-152)"; headed capture is peeled, which this
receipt already admits.

### Q1 — are the two solutions per sheet live methods?

**Yes, all six.** Each is a method `src/systems/missions.js` can actually pay, and each is
executed by a booted-sim test that asserts the settlement receipt's `completionMethod`:

| Method | Live settle site | Executed by |
|---|---|---|
| `wrecking_ball` | `_onPhysicalWhipImpact` — tower role, solid/crushing | PQ-032.00 (story spine) + PQ-152.00 |
| `cut_down` | `_onPhysicalKill` — `demolition` + `byPlayer` | PQ-152.00 (generic board route) |
| `stage_tow` | `_tryPhysicalDockComplete` — latched pod at story dest dock | PQ-032.00 (story spine) + PQ-152.00 |
| `corridor_pull` | `_onPhysicalTetherReel` — escorts clear, then reel | PQ-152.00 (generic board route) |
| `tow_in` | `_tryPhysicalDockComplete` — core on the line at story dest dock | PQ-032.00 (story spine) + PQ-152.00 |
| `sling_in` | four sites: loose dock, clean release, throw, authored `throw_berth` | PQ-032.00 (story spine) + PQ-152.00 |

The distinction worth keeping is route, not liveness: `cut_down` and `corridor_pull` are executed
on the generic board route, not on a story-tagged 47-A run. Nothing here is vapour.

**But the landed test did not prove any of this.** It read
`embodied.missionBoardContract.params.completionMethods` and deep-equalled it against
`leftoverSpineMethods(beatId)` — which is that same frozen array's own `.slice()`
(`beatStandard.js:82`). A value compared to itself cannot fail. The same declaration is also the
only input behind the `invented_solution` gate. So the assertions proved sheet-matches-sidecar and
never once touched the system that pays. The test's own title said "solutions that exist"; the
inputs could not tell an existing method from a deleted one. That is the PQ-140.01 shape: a green
law fed a number the live route never produces.

### Q2 — does `bigger_boat`'s `sling_in` still mean the 700 WU cheat?

**No. It has not meant that since `d9bef7f94` — the direct parent of this leaf's own commit.**

That commit ("Refuse a leftover long throw for the slag-core tow; pay only at the dest dock")
added `_usesStoryDestDock` and routed every story-B3 sling path through `_entityAtStoryDestDock`:

- `_onPhysicalThrow` — story branch checks the dest dock, then `continue`, so the old
  berth-or-dest-sector fallthrough is unreachable on the story tag.
- `_onPhysicalReleaseRated` — clean release gated on the dest dock.
- `_tryPhysicalDockComplete` — loose-core sling gated on the dest dock.
- `_tryCompleteAuthored` — `throw_berth` / `release_berth` gated on the dest dock, and
  `if (storyDock) return false` refuses rather than falling through.

`PHYSICAL_BERTH_WU` is still 700, but on the story route it is dead: the live gate is station hull
or dock radius + cargo radius + 24 WU slack — **112 WU** at `station_ceres` (radius 34, dock 72).
`PQ-032.00-REPORT.md`, the receipt this very sheet cites as its `liveSettle`, records the numbers:
core at 434 WU — *inside* the old 700 WU berth — **does not pay**; core thrown at the dock at
90 WU **pays `sling_in`**. 700 WU survives only for non-story `tow_recovery` and non-story
authored set pieces.

So these five claims are false as written, on a sheet whose own `storyTag` is
`campaign47a:b3:bigger_boat`:

- `setPiece.twist` — "Leftover `sling_in` still uses leftover `PHYSICAL_BERTH_WU` 700."
- `setPiece.solutions[sling_in].how` — "into leftover 700 WU berth … still use
  `PHYSICAL_BERTH_WU`. **Not dest-dock**." (the live code is dest-dock *only*)
- `canon.whoWantsWhat[slag_core].because` — "Leftover `sling_in` still uses 700 WU."
- `setPiece.provingFrame` — "Leftover `sling_in` still 700 WU."
- `honesty.leftoverSlingInStill700Wu: true`

The claim also propagates to this receipt's HONESTY GAPS ("Leftover sling_in still uses 700 WU"),
to the Files line for the B3 sheet, to the `## Honesty` bullet for B3, to the Proof block, and to
`docs/worldbuilding/BEAT-STANDARD.md:78` ("`sling_in` (700 WU leftover)"). Those are left in place
as the record of what was claimed; this section is the correction.
