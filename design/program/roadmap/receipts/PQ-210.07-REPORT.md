# PQ-210.07 — Ask once about motion, never assume — REPORT

RESULT: DONE (implemented + integrated)

## What landed

On first boot, when the OS reduced-motion hint (`prefers-reduced-motion`) is set AND the settings
profile has never been asked (`accessibility.motionAsked` false), the game shows ONE plain choice —
**Full** or **Reduce** — and stores the explicit answer (`recordMotionChoice`). Nothing follows the
OS without being asked afterward. The explicit **System** option remains in the Access settings
screen; choosing any value there also marks the profile asked.

- `src/ui/accessibility.js`: `shouldAskMotionPreference`, `firstBootScreenId`,
  `recordMotionChoice`, `MOTION_ASK_CHOICES`, `FIRST_BOOT_MOTION_ASK_ID`. Reuses the existing
  `settings.accessibility.motionPreference` field and `applyMotionPreference` — no second source of
  truth.
- `src/ui/screens/motionAsk.js` (new): locked dialog on the title hangar still, two equal buttons,
  keyboard roving focus, `aria-modal`; ESC cannot skip (the unit is to ask, not to nag later).
- `src/ui/uiRoot.js`: boot routes the first screen through `firstBootScreenId(settings)`; unset OS
  hint boots to mainMenu exactly as before (verified unchanged path).
- `src/core/gameState.js` + `SAVE_SCHEMA.md`: `motionAsked: false` default, schema row.
- `src/ui/screens/settings.js`: both Access selects mark the profile asked via the same helper.
- `styles/kit.css`: one selector line — the ask shares the menu backdrop.
- Registrations: `scripts/check-ui-screen-imports.mjs`, `tools/ui-bench.js` (the new screen is on
  the default route and the bench roster).
- Tests: `test/pq-210-07-motion-ask.test.mjs` (new, 5/5: never-asked+hint fires and stores; asked
  never re-asks; no hint never asks; dismiss/locked semantics; wiring pins) and
  `test/accessibility-settings-parity.test.mjs` (extended, green).

## Risks / residuals

- A player with the OS hint set who somehow never sees the ask screen (boot aborted before UI)
  still boots with Full and will be asked next boot — the ask condition is derived, not scheduled.
- Legacy profiles that already stored `motionPreference: 'reduce'|'system'` are treated as asked
  (an explicit stored choice); only the silent-default `full` without `motionAsked` triggers the
  one-time ask. This matches the unit brief's intent (full was the unprompted fallback).
