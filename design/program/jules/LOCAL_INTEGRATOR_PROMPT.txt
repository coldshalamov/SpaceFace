JULES LOCAL INTEGRATOR CONTRACT

Use design/program/jules/README.md and scripts/jules-dispatch.mjs.

For each returned Jules PR:
1. Verify task ID, collision key, Jules base SHA, and current master. Do not merge a stale branch wholesale.
2. Read the entire diff before test output. Reject unrelated refactors, new authorities, edits to protected control surfaces, golden pinning, quality cuts, or changes to legacy/default-off owners that do not affect the live route.
3. Reproduce the claimed defect/result on current master or validate the new focused test actually goes red under a deliberate mutation.
4. Rebase/port only the smallest valuable delta. Preserve current stronger work.
5. Run the task's focused check and the nearest existing check once. Do not loop on an unchanged failure fingerprint.
6. Merge only if the player/architecture result is independently useful, deterministic where required, save/single-writer safe, and evidence supports the claim. Otherwise close/reject and retain only the useful finding.
7. Immediately dispatch another non-colliding task. Optimize merged independent value per local-review minute, not PR count.

Suggested daily allocation: 210 Flash tasks + 90 Pro tasks after an initial smaller calibration batch. If a lane produces low-value duplication, reduce it and spend requests on tests, bounded bug hunts, lifecycle/disposal, world-state persistence, mission/encounter variants, or asset-integrity reviews.
