# SpaceFace maturity campaign — 15 October 2026

## Goal

Make ordinary play dependable, smooth, readable and complete: bodies load on time, ship and
camera motion remain coherent, controls and transactions recover correctly, and an interrupted
operation leaves a useful way forward. Preserve authored visuals and default quality. Continue
the owner's performance target: three times fewer hitches, lower worst-frame delays, and FPS
toward the display limit, measured on actual game motion rather than the HUD spinner.

This implements [build_map §1.8](../../build_map.md#18-production-maturity-debugging-and-polish)
through the existing finish lanes. It is an execution plan, not a second defect ledger or queue.
Unfixed discovered defects belong in [the existing demo ledger](DEMO_READINESS_2026-09-20.md#6-the-demo-defect-ledger--everything-a-demo-player-will-hit-live-opened-2026-09-22).

## Assumptions and constraints

  supporting systems, review/improve/merge cloud PRs, and run the complete test matrix.
- GPT-6.1-Sol at `xhigh` handles research, architecture, consequential review and integration
  decisions. Luna handles bounded implementation with exact file ownership. Four concurrent
  slots are available, including the orchestrator; rotate finished researchers into workers.
- One checkout, current master, exact-path publication, preserved foreign dirty work. No branch
  switches or extra worktrees. Fresh remote heads and exact PR SHAs determine integration.
- Browser/Electron retain one gameplay path. Keep deterministic simulation, raw input semantics,
  save compatibility, accessibility and single-writer authority. No quality cuts to pass perf.
- Root owns serial GPU work. The host currently has unrelated agent/test processes; development
  diagnostics are not quiet-host certification. Never assert quiet-host authority by setting a flag.
- The existing request to stop one foreign Claude test tree is awaiting an answer. No process
  belonging to another session is terminated without authorization.

## Analysis and decisions

Choose cause-driven repair across player workflows, followed by representative route checks
and the full existing matrix. A feature-first expansion would preserve the broken experience;
an unbounded review campaign would delay the repairs. Build additional machinery only for a
demonstrated ownership, cancellation, scheduling, loading or testability gap.

Review existing evidence when its owner has not changed. Do not repeat a completed inquiry
for confidence. A new failure, conflicting result or changed production owner reopens only the
affected check. Prior three successive clean scoped polish reviews remain bounded coverage;
the owner's newer whole-game research request expands the workflow coverage below.

### Second performance wave: complete opening admission during loading

Cloud PR #387's exact-head re-gate (`093c007` versus `6f0d42f`, eight interleaved
runs per arm) failed. It drew the world on all first frames, but clean p99 rose from
1132.5 to 1397.5 ms, median load rose by 3.2 s, and shader linking after reveal did
not improve. SwiftShader and concurrent-host interference limit hardware conclusions;
the recorded ordering still identifies work arriving after the intended loading window.

The proposed repair is to start residency as authored subjects commit, prepare their
exact first-picture submissions incrementally, and admit required streamed meshes through
loading's existing sliced cadence. Flight must not begin through a timeout while that
required work is pending. Preserve cancellation/generation checks, context ownership,
shared resource leases, quality, and actionable failure recovery. A longer hidden wait
alone does not fulfill this outcome.

Sol owns a finite architecture packet against the integrated shared GPU queue and narrowed
opening roster; Luna handles separable implementation. Reconcile the first-picture veil
with the resulting readiness owner, then run the affected startup/cancellation/queue
fixtures and one coherent frozen before/after native route. Reuse those results across
claims only when source, route, observer, settings and hardware identity actually match.
Do not duplicate the finished cloud experiment or merge its regressing candidate unchanged.
