# Copy-ready local implementation commission

Use the following with a named `LW-*` packet. Replace the task ID, then let the agent execute.

```text
Work in SpaceFace. Implement THE OPEN REACH task <LW-ID> completely as one coherent
player experience. Start with AGENTS.md and current source. Read
design/program/living-world/README.md, then run:

node scripts/living-world.mjs --validate
node scripts/living-world.mjs --task=<LW-ID>

Read the district brief(s) and only the relevant story, systems and asset sections.
The package is a source-grounded plan; its future experiences are not already implemented.
Do not confuse a validated specification with live content. Preserve stable existing IDs,
good source behavior and concurrent foreign work. Use the existing WORLD/LONG GAME/
PICTURE/HAND/EAR lanes; this is not a second queue.

Build the whole named outcome: ordinary approach, visible place and occupations, actual
player verbs, readable feedback, interruption/failure/recovery, persistent return state,
and ordinary-route reachability. Use native physics, AI, cargo, economy, law, ownership
and save writers. Take control of the exact physical hull for theft; consume the exact
finite lot for delivery; never invent success by emitting a positive event in a test.

For a district packet, complete all its explicitly owned routines and opportunity IDs,
including the smaller local stories. Its example scene is not the whole completion scope.
Honor the Dione split between LW-04's base/drill/bus and LW-05's actual tender theft.

Use current authored models where the packet names a suitable reuse asset. For a missing
model, make or commission the precise model brief and continue all independent work.
Any development blockout is labeled and cannot count as visual acceptance. Do not ship
a generic sphere, a recolored familiar station or decorative orbit as the promised place.
Every moving actor must have a legible destination, a reason to be there and a response
to interference. Authored warm/calm behavior belongs in the same slice as combat.

Keep the simulation in the XZ plane unless an explicit approved packet extends it.
Camera presentation cannot change collision or input semantics. Preserve ship/load
clearance, a retreat path, nonzero-origin correctness and safe Continue inside a passage.
Use one canonical world clock and bounded actor/residency budgets. Dense scenes share
the existing global budget; reserve inventory is not extra active bodies.

Delegate disjoint source/art/story pieces with exact write paths, integrate them, and
independently critique the resulting experience. Work from a normal reachable route,
not only a forced diagnostic spawn. Validate the behavior at the smallest layer that
can observe it, then run the applicable public-route/player-truth gate for gameplay.
Read the actual picture when claiming appearance. A focused test is not visual or
performance acceptance. Do not weaken gates or re-record goldens to hide a regression.

Do not ask the owner to playtest before proceeding. Resolve routine implementation choices
yourself. If current source already implements a promised behavior, keep it and finish
the missing connection. If the brief conflicts with source or another packet, record the
specific discrepancy, resolve it by content and update the affected specification.

Deliver source and assets through the owner's requested branch/PR workflow. Update the
existing build map and this packet's implementation status only to what evidence supports.
Report: what the player can now see and do, the actual route, tests/evidence, exact commit,
and any precise unfinished artifact. Do not report 'district complete' for a catalog,
plan, model, harness, scripted success event or technical demonstration alone.
```

## A useful review question

Give another agent the normal entry route and ask it to answer from what is visible:
“What is this place doing, what could I interfere with, what happened because I did, and what
will be different when I return?” If it needs the implementation document to answer, improve
the player experience. Do not solve that failure with more technical HUD labels.
