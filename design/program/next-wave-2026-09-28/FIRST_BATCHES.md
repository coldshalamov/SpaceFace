This is a recommended integration sequence, not another live queue or a mandate to ignore already-open work. Current canonical status, current source and exact dirty hunks win. Do not run several batches that touch the same owner simultaneously. Strong agents implement and review the cross-owner mechanisms; smaller agents take the named independent leaf or a newly opened follow-on.

## Strong review after each coherent batch

Review the complete player outcome and the most dangerous counterexample, not the number of files or tasks closed. Verify that the selected mechanism remains simpler than a competing owner or special route. Play one competent and one mistaken attempt. Read the diff for resource/accounting/ownership regressions. If only local tests were possible, preserve route-unproven status rather than holding every unrelated development task hostage to that environment.

## Avoid a 300-task waterfall

Only five internal BUILD dependencies and one external integration dependency are mandatory in this wave. The rest can use existing compatible capabilities. The 122 waiting small tasks open when their particular parent capability exists; independent leaves do not need to wait for all 60 strong tasks. Child assignment counts are not additional feature counts. Acceptance can close several related leaves from one real, well-observed landing.
