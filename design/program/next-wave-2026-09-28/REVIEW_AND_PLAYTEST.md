# Review and playtest — inspect the result, not the task count

This plan defines future implementation acceptance. **No game run described here was performed by the planning session.** Reuse the current game's route, harnesses, fixtures and evidence locations. No separate demo implementation, remote certification program or full-repository run for every small task.

## A matched route set

| Route | Setup and deliberate action | Mistake or interruption to include | Observe |
|---|---|---|---|
| Hand | Normal adventure/Crucible, seed 4242; G-stick, pad takeover, tow, boost/brake | Disconnect, resize, invalid ray, rapid press/release, UI capture | One intent owner, finite commands, one edge consumption; ship character remains physical. |
| Work and commerce | Accept preloaded freight; buy extra of the same good; tow a recoverable load; use the real receiver/market | Full hold, partial receiver, cancel, duplicate confirmation, save during handoff | Goods, reservations, credits, claims and mission progress reconcile. No hidden substitute delivery. |
| Fight | Existing enemies, field overlap, one capital/specialist opportunity | Missed throw, destroyed source, accepted surrender, simultaneous blast | Readable net force and counterplay; no legal continuation after legitimate stand-down; useful aftermath. |
| Crucible | One authored three-round act, draft, refit, restart | Unaffordable/ineligible offer, wave ending with useful wreck, stale challenge code | Changed physical questions, honest run envelope, preparation that matters. |
| Industry/claims | Drill to capacity; fill a refinery output; interrupt repair; arrive during a raid warning | Save, leave/re-enter, partial convoy loss, duplicated settlement callback | Material-backed work, one durable outcome and a recoverable interruption. |
| Story/discovery | Follow a clue, change its subject, return; reach story through trade/combat/salvage; continue an existing ending | Stale clue, destroyed subject, missing offering NPC, NG+ transition | No impossible marker or omniscient disclosure; knowledge and physical carry rules remain separate. |
| Picture/instrument/ear | Same crowded release→field→impact moment, quiet return, long-name transaction UI | Reduced motion, alternate controls, narrow viewport, entity rebind | Cause is visible/audible; selected object and amounts stay truthful; no loss of spectacle or operability. |
| Machine | Default authored boot, repeated travel/dock/fight/Continue on one host | Failed required load, stale retry, context/resource release, save during owner mutation | Correct current bodies, bounded lifetime, coherent save; collect performance evidence only for the changed path. |

Use fixed comparable settings, seed, camera and cache condition before/after when those affect the claim. Add a small different-seed sample to challenge an accidentally overfitted content result. Never compare a warm route to a cold route or quote a noisy/software-GPU result as user-hardware acceptance.

## The review questions

**Agency:** Did the player's understandable action produce the result, or did code secretly guide it? Can a mistake remain readable and recoverable?

**Causality and ownership:** Are motion, visible contact, damage, custody, money and persistence describing the same fact? Can repeating or interrupting it duplicate or erase anything?

**Comprehension and character:** At the normal camera, can a new player identify the opportunity, action and consequence without a wall of text? Does the result still belong to SpaceFace rather than a generic menu or a reskinned stat fight?

**Craft and cost:** Are timing, sound, effects, focus, labels and failure feedback complete? Did the optimization preserve the authored picture? Is lifetime/steady-state behavior measured where it actually changed?

## Disposition

Use **KEEP** when the result and its counterexample work on the claimed route with no material unresolved regression. Use **REVISE** with the single leading defect and a bounded correction when they do not. Use **already satisfied** for an existing matching result. Use **not reproducible** for a conditional premise that fails to reproduce, naming exactly what was exercised. Use **implemented / route-unproven** when source/test work exists but the visible/played result has not been verified.

This is not a numerical certification system and does not guarantee A-list quality. It is a way to prevent compile-only success and idea proliferation from substituting for a fun, coherent result. Store evidence and any residual defect in the existing program locations.
