# Agent workflow — complete outcomes, not parallel prototypes

## Director pass

Read the current build map, exact NOW claims, relevant source and open PR diffs. Select one commission and one complete player-outcome slice. Record exact base, owning paths, expected decision, observable result and strongest falsifying case. The SC index is supporting detail; it never supersedes the existing dispatcher or creates status elsewhere.

Partition by exact current files/hunks. Start disjoint content, tests and pure query work while shared owners are occupied. A broad subsystem label is not an indefinite lock. Do not reinterpret an open PR as shipped, cherry-pick another agent's unfinished branch, or take over foreign work merely because its plan resembles yours.

## Implementer loop

1. Trace the ordinary producer/consumer route and reproduce the gap at a cheap truthful layer.
2. Compare two plausible approaches; choose the one that improves the player decision with the least duplicate authority.
3. Implement the complete named outcome: input/eligibility, simulation, presentation, lifecycle and evidence as applicable.
4. Use `agent-loop` / existing focused checks while iterating. Do not repeatedly boot the whole game for a pure descriptor or screen fixture.
5. Fix the attributable failure, then test interruption, duplication, capture, sector transitions and Continue where relevant.
6. At a coherent integration boundary, run the affected ordinary route and the repo's applicable player-truth acceptance. Describe missing hardware/visual checks without turning source tests into those checks.
7. Commit/publish the owned paths and deliver a scoped draft PR; no automatic merge/deploy.

## Independent reviewer

Review evidence against the exact proposed tree, not the author's confidence. Check one meaningful alternative plan, one failure, one dishonest-success path and one lifecycle boundary. For a visual claim, inspect the picture. For a physical claim, inspect the actual force/pose/result path. For a supply or memory claim, trace the original owner through its real consumer.

Reject: a second state writer, phantom completion, unrelated events counted as a causal chain, hidden information leaked to the actor, a fixture promoted to ordinary play, weakened goldens, missing tests reported as zero failures, or gameplay complexity manufactured by increasing file size.

An independent review is useful evidence, not an invitation for endless consensus rounds. Correct material findings and move the implementation forward. Do not wait for the user to perform QA.

## Grunt-work dispatch

Every task document contains three specific follow-on assignments. Scope one to its exact producer, consumer and negative case. A complete unit changes an observable outcome or prevents a concrete false result. Expanding 25 files by a percentage, adding more enum values, or filling dialogue slots is not a player outcome.

Use this brief:

> Continue [SC label], subtask [specific item]. Inspect current master and relevant open hunks. Reproduce [gap]. Change [owned source seam] so that [player result]. Preserve [authority/lifecycle invariant]. Prove [positive case] and [negative case] using production functions. Complete the real input/readout path, not an unused helper. Deliver a scoped draft PR with exact head and limitations. Do not create a new framework or paid-agent session.

The executable `brief` command supplies the full packet. It does not launch agents, buy services or consume a separate chat allocation.

## Context packet

Keep only: exact commit and dirty-state declaration; named owner files and public entry route; current packet; relevant interface excerpts; one failing reproduction; constraints/foreign hunks; and the current hypothesis. Carry a small checkpoint stating what is implemented, what was actually measured and what remains. Do not load every design directory or confuse a historic report with live behavior.

## Integration loop

Refresh origin and inspect the branch delta. Resolve overlap by content, preserve foreign hunks and test the exact combined tree. A component pass from before a merge is not evidence for the merged graph. Use existing board/status and landed-review conventions; do not copy a second progress tracker into this package.

The definition of done is appropriate to the commission. Static authoring tools can finish with focused behavioral tests. Gameplay changes need reachable behavior and the relevant route evidence. Entire strategic depth, visual maturity and enjoyment cannot be inferred from a count of green assertions.
