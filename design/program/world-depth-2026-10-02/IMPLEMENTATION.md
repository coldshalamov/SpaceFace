# Mature-game delivery packets and acceptance

## Contract and present status

This is the finite delivery roster for [TARGET](TARGET.md), under the existing build map, FINISH_LANES, graphics program and gameplay owners. It is **not another queue, inference command or implementation framework**. Packet labels below make handoffs and coverage unambiguous. Existing owners record implementation and evidence in their existing ledger/receipts. This document does not assert that a listed feature is absent, authorize overwriting newer work, or replace current canon.

The owner requested expanded/reviewed planning, publication as a draft PR, then implementation in small commits through the full agreed feature set. The planning revision itself contains no new runtime or production asset. At its source baseline, `c488ecc10c23ad613dc35c61c04f124a3b77723a`, a generic Blender CPU model/export/render probe passed. Subsequent setup rebuilt real Forge `place_transfer_arm.py` from canonical source plus six shared textures in Blender 4.3.2: 883,104-byte preview, 5,856 LOD0 triangles, 27 meshes, 9 materials, with two canonical sockets and asset identity preserved. glTF Transform parsed source/release/preview; esbuild/Sharp are available, and launch-policy plus 23 event-bus/save-envelope tests passed. Publisher/release regeneration, full-game visual/default-route gameplay and target-device performance remain unrun. Shell Chromium currently hits a sandbox socket restriction; official CUA localhost reports `ERR_BLOCKED_BY_CLIENT`. Never propagate export/parser/focused-test success into runtime or performance status.

The six TARGET experience commitments are covered below through linked packets, including their connective work and the mature Swarm roster. The first successful district proves a production path; it does not complete the expansion. Routine art details and narrow fixes can be decided within a brief. Canon, progression economics, material target changes and new systems outside these briefs go back to their existing owner.

Per-model workers own their source and candidate artifacts, not independent rewrites of shared generated outputs. Places use the actual place release tool; ships/other entries use their appropriate release path. Rebase/refresh before composing concurrent source work; never reconstruct a stale repository tree wholesale.

## 4. Six independent evidence states

Record these statuses separately in the existing packet handoff/receipt: **not started, in progress, passed, failed or blocked**, with evidence and revision. A passed column never implies its neighbors passed.

- **Source:** authoring/behavior sources, exact IDs and tests are present, reviewable and committed; canon/current-owner duplication check done
- **Asset:** actual exported binary parses, provenance/source hash matches, materials/motion/sockets/bounds/collision contracts pass, required states and LODs exist; Blender render alone is insufficient
- **Integration:** manifest/resolver/release/package/spawn chain reaches the intended normal-route consumer and actual authored bytes; intentional procedural bodies are identified explicitly, fallback counters checked, unreachable entries not counted
- **Functional:** normal use, meaningful interference, failure/recovery and leave/Continue tests pass; finite quantities, leases/custody, navigation and persistent geometry reconcile; no fake visual-only state transition
- **Visual:** paired runtime captures at real chase/close/place framing inspected for each model and composed scene, including peak state; silhouette, material, lighting, motion, attack/interaction readability and spatial gaps satisfy the brief
- **Performance:** component and composed-scene comparisons recorded on the specified profile; load and warm frames separated; CPU/GPU p95/p99, admission spikes, draw/material/texture/residency and relevant simulation cost accepted against existing budgets. Software-renderer numbers remain labeled and do not become target-device certification

The acceptance chain is source → authored asset → release/package → loader selection → actual spawned state → player interaction → persistent aftermath. Record exact IDs, hashes and route/seed for that chain in the existing receipt. Check first-visible, leave/return and save/reload, not only a debug gallery. For renderers intentionally remaining procedural, record the actual builder and why its authored anatomy satisfies the brief rather than pretending a GLB exists.

If current numeric budgets or target-device access are unavailable, measure the available baseline, name the missing acceptance evidence and keep performance blocked. Propose a concrete profile/budget through the existing graphics owner; do not invent an FPS claim, quietly lower quality, or mark the whole packet done on a source test. Automated functional tests do not certify human enjoyment; visuals require looking, and feel/pacing require a representative playable review.

## 5. Iteration and completion boundaries

Use [ASSET_FAMILIES §6](ASSET_FAMILIES.md#6-bounded-packets-individual-models-and-real-consumers) for every model and changed system: baseline → one hypothesis → one interpretable change → identical-scene comparison → keep/reject → small commit. Preserve fidelity by addressing measured algorithmic/resource cost. A defect is closed when its declared evidence passes, not after an arbitrary number of renders. A stalled approach gets a revised concrete hypothesis; it does not turn into an endless global restyle.

At each stage, play the connected route rather than merely summing component passes. Exercise normal work, player disturbance, worst meaningful action and persistent return. At full expansion closure:

1. P01–P13 cover the Adventure-facing families and their connective progression/campaign obligations; P14–P21 cover the declared Swarm roster/biomes, arsenal, identity, modes, creator tools, construction and arcade lifecycle
2. Every named piece/state has a real receiving consumer or an explicit reviewed target change; no unconsumed GLBs, hidden galleries, cheap permanent stubs or “later” hero bodies count
3. Each packet has all six evidence states passed on the applicable profile; missing target-device evidence remains explicit and prevents that performance claim
4. Early/mid/late journeys and Swarm bank/retry/return have been played as compositions, old hull/campaign/save behavior remains intact, and generated source/release/package hashes agree
5. The existing owners/ledger identify actual completion and any approved scope revisions; these documents do not create another ongoing catalog to polish forever

The mature target remains ambitious because substantial new art and behavior are ordinary work, not exceptional rewards unlocked only after all cheap fixes are exhausted. Finite packets make that ambition deliverable without confusing a production probe, a nice thumbnail or one excellent local district with the finished game.
