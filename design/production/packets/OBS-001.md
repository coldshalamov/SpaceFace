## Player outcome

The production cell can reconstruct what the player, AI, simulation, renderer, and asset system did
at the same moment—without relying on arbitrary screenshots and without changing the game being
measured. OBS-001 proves passive, lossless, synchronized records. It does not claim media-complete
or quality-valid acceptance; OBS-002 adds real video and mixed audio.

  1. `afterInput(state)` immediately after live `input.update()` so edge verbs are captured before
     scanner/flight/charges/countermeasures consume them;

  3. `onRenderFrame(state, frameDt, alpha)` after renderer diagnostics.

## Recorder contract

`createSessionObserver(...)` returns guarded hooks, `drain()`, and `stop()`. Browser code only
buffers/drains. The Node runner owns filesystem containment, hashes, worktree/candidate/selection
fingerprints, atomic publication, and validation.

Sampling:

- applied effective input every fixed tick, including every locked action field;
- state plus selected AI intent every third tick (exactly 20 Hz);
- asset exposure at 10 Hz plus lifecycle changes;
- raw frame duration every render frame; aggregate perf reports only periodically;
- fixed-tick/final canonical state hashes after lifetime sweep;
- declared event receipts losslessly and in sequence.

Never call `state.rng`; use `state.meta.seed`, `state.tick`, and `state.simTime`. Wall offsets/frame
IDs align presentation but are excluded from deterministic receipt hashes. Observer exceptions latch
`observerFault` and invalidate evidence without entering gameplay. Periodically drain; any overflow,
drop, rate shortfall, or fault makes `validForAcceptance:false`.

Use an observatory-specific tape with per-tick effective input and ordered public UI actions keyed
primarily to route-step predicates. It cannot inject entities/state. The current golden tape alone is
insufficient because it omits live action, pointer, and paused-menu activity.

## Three matched executions

1. observer on + media pending/off (OBS-001 record);
2. observer on + media off (observer-control performance);
3. observer off + media off (authoritative performance/passivity control).

All use the exact seed, tape, candidate, selection, route, and policy. Periodic/final canonical
hashes and ordered deterministic receipts match across all. OBS-002 later reruns #1 with actual media
on; capture overhead is then measured between #1 and #2, observer overhead between #2 and #3.
The observer-off record has `inputHz/stateHz/assetExposureHz: 0`; it keeps external raw frame/perf
and canonical hash receipts and never fabricates observer samples.

OBS-001 writes `observatory-session.schema.json` lifecycle `observer_contract`, media `pending`, and
`validForAcceptance:false`. Fake media paths or a self-asserted `match:true` never validate; the
semantic checker recomputes paths, hashes, rates, arithmetic, and equality. It also rejects finding
windows whose end tick/sim-time precedes their start or lies outside the parent session.
