## Findings (ranked)

### F1 — `shouldSubmitEntityMesh`'s protected early-return defeats the doomed hide for protected roots (M)

Evidence:

- `exactVisible` deliberately fails doomed slots BEFORE the playerId and FORCE_RENDER/NEVER_CULL bypasses (presentationQueries.js:133 before 135-137) — the block comment (129-132) states the intent: "fails before every bypass — player/FORCE_RENDER/NEVER_CULL included — so the slot evicts into hiddenSlots and gets a real mesh hide."
- The eviction half works: a doomed slot lands in `hiddenSlots` and the hidden loop drives it through `applyEntityMeshVisibility(mesh, posed && shouldSubmitEntityMesh(_submitVisibilityOptions))` with `_submitVisibilityOptions.hidden = true` (renderer.js:22468, 22485-22486).
- But `shouldSubmitEntityMesh` returns `true` at entityMeshVisibility.js:21 for `isProtectedEntityMesh` — BEFORE the `options.hidden === true` deny at line 36 — so the hide never lands: a doomed player/forceRender/neverCull row keeps `mesh.visible = true` and draws its last pose for the rest of the suspension window, the exact ghost class W91 set out to remove.
- Reachability today is narrow — a doomed protected row needs a suppressed destroy or feed-skip tombstone on a flagged entity, and real destroys emit `entity:destroyed` → `_unbindPresentationMesh` → `world.unbindMesh` clears doom + drops `meshRefs` (renderer.js:16027, presentationWorld.js:787). Protected flags on journal-row entities are rare (grep finds no literal `flags.forceRender = true` writes; the packable flags come from entity data). But the only other hidden-loop entry for a protected root is `!meshRefs` — meaning for a protected root, doom is effectively the ONLY channel that ever should hide it, and it is silently defeated.

Mechanism: the two halves of the W91 contract disagree — `exactVisible` says doom beats protection; the hide channel re-grants protection. Any future path that dooms a flagged root (a forceRender entity tombstoning mid-suspension, a suppressed destroy on a protected ledger row) revives the stale-draw bug with zero diagnostics.

Fix sketch: pass `doomed: true` through `_submitVisibilityOptions` in the hidden loop (it can read `world.doomed[slot]` directly) and honor it ahead of the `protectedRoot` return — or reorder `options.hidden === true` before the protected early-return. The carve-out's stated purpose is transient pose gaps ("a render-boundary miss"), not authoritative tombstones.

Effort: S. Impact: M (highest-visibility class × whole suspension window when reachable). Risk: S (the reorder only affects rows already in hiddenSlots — protected roots can't arrive there via culls since exactVisible's flag bypass keeps them in visibleSlots).

### F2 — `bindMesh` and the apply writers never clear `doomed`; the clear set is feed-stamp-only (L)

Evidence: doom clears at exactly five sites — the two feed stamps (929, 936), `retireSlot` (705-706), `unbindMesh` (787), `allocateRecord` (631-632). `bindMesh` (765-778), `applyTransform`, `applyVisual`, and `setVisibility` (1049-1058) leave a live row's doom untouched.

Mechanism: today the window is self-healing — a mesh bound onto a doomed row during suspension (`_bindPresentationMesh` → `world.bindMesh`) stays hidden only until the next prefix feed re-stamps the entity (clears doom atomically at 936), and every suspension terminates in a complete feed (`rebuildCollectedEntities` → `updateFromEntities` unsuppressed) or `world.clear()` that retires every unstamped row. But the invariant is implicit: any future non-feed writer that binds or re-poses a live row (a direct journal-record replay path, a manual re-admission binding a kept mesh) defers first-draw with no un-hide channel — the row sits doomed until the next feed happens to stamp that id. `setVisibility` even writes `visible[slot] = 1` on a doomed row without consulting the flag (the column is bookkeeping, so this is inert, but it widens the asymmetry).

Fix sketch: clear `doomed` in `bindMesh` when the row is alive (a bound mesh is the freshest liveness evidence) — or gate it: `if (world.doomed[slot] === 1) world.doomed[slot] = 0` at bind plus a matching `markDirtyBits(VISIBILITY)` so the query re-admits it next frame. A debug-only assert `doomed === 0` at bind would also surface any latent path early.

Effort: S. Impact: L-M (latent; bounded by collect progress under today's callers). Risk: S (clearing doom on bind restores pre-doom behavior for a row that earned a tombstone — only sound because bind proves liveness; keep the doomed check in exactVisible as the authority).

### F3 — Skipped-at-collect tombstones never enter a feed → no doom possible → stale row draws through suspension (L)

Evidence: the `skippedIds` doom (presentationWorld.js:909-915) only covers entities present in the feed sample. But `pushAlive` excludes `_noMesh`/projectile-skip rows from the collect itself (presentationSources.js:109-110), so an entity whose skip predicate already held when the collect cursor passed it never enters `collectOut` → never appears in any prefix feed → `skippedIds` can't name it → its stale bound row keeps drawing through the entire suspension (prefix feeds suppress the retire sweep by construction, 975-987).

Mechanism: the doom coverage is "entities that tombstone mid-window," not "entities already tombstoned at collect." Currently nearly unreachable — `_noMesh` latches only on entities that never built a mesh (3-strike build failure, renderer.js:21915-21930) so no bound mesh exists to ghost, `projectileSkipsVisualFactoryMesh` reads spawn-static `data.weaponId` (recipes.js:755-765), and the appearanceChanged rebuild unbinds before rebuilding (22100). The gap is a coverage boundary, not a live bug: any future eligibility predicate that flips on a mesh-bound entity mid-life draws stale for the whole window.

Fix sketch: during `retireSuppressed` feeds, sweep `byId`-resident rows whose `world.entityRefs[slot]` fails the eligibility predicate and doom them — the absent-retire dense scan (982-986) is already the symmetric complete-feed operation; a cheap `entity._noMesh === true || projectileSkipsVisualFactoryMesh(entity)` check on refs keeps it O(rows) only during suspension windows.

Effort: M. Impact: L-M (latent; bounded by suspension length). Risk: M (a mis-doomed row hides wrongly until a feed re-stamps it — the predicate must mirror pushAlive exactly or live rows flicker).

### F4 — `commitAuthoredCargoCapsuleBoundary` is fully atomic, including `touchAuthoredExactTarget` + `invalidateShadowCasterPolicy` inside publish (L)

Evidence: partsLibrary.js:3326-3387 — "The whole commit is one atomic span." The leg does `detachBoundaryResolvingMarker` + `boundary.remove/add` + `invalidateShadowCasterPolicy(boundary)` (a whole-subtree dirty traverse, 3342) + registry write + ~15 userData writes + `releaseDetachedCargoCapsuleSubstrate`, then publish runs `options.touchAuthoredExactTarget(authored.root)` (3367 — a residual variant-link walk over the authored subtree) + `setPresentationAdmission`. `notePacedFrameSpend` debits the measured cost (3385), but there is no yield seam anywhere in the span — unlike the ship and place commits which pace their freeze+dispose legs (4259-4273, 9509-9541) and yield between graft and teardown.

Mechanism: consistent with the deliberately-atomic commit doctrine (a half-swapped boundary can't be presented), and cargo capsules are the smallest authored payloads — the span is real but bounded. Flagging as the last commit family with zero internal pacing: if capsule payloads grow (multi-part cargo, denser authored compositions) or the exact-target touch grows a subtree walk, the whole cost lands adjacent to a presented frame with only the ledger debit to show for it.

Fix sketch: none required today — watch `notePacedFrameSpend` deltas on capsule commits; if the span ever dominates a frame, split the pre-publish bookkeeping (marker detach, userData stamps, substrate release) from the atomic graft+publish the way the place commit already does (graft first, paced dispose after).

Effort: M (if pursued). Impact: L (bounded span, debited, small subtrees). Risk: M (splitting a graft mid-swap needs staged-visible discipline).
