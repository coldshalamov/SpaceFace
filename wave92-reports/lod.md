## Ranked findings

### 1. Denied parks have no castability-flip release trigger — kept/undrawable parks that turn castable ride the recheck backstop up to ~16 s (hunt a)

Evidence:
- `src/render/renderer.js:24769-24781` — the parked-release eval is an else-if chain keyed on exactly three terms: `dirtySeq > parkedEntry.seq`, `parkedEntry.lightSig !== this._shadowCensusForFrame()`, and ortho-cell drift (`oqX`/`oqZ`). `opts.allowCast` is recomputed live every sync at `:24750` but is never consulted as a release trigger.
- `src/render/renderer.js:24789-24807` — the keep-branch fires on `parkedRelease && parkedReleaseOnDrift && opts.allowCast === false`, re-keys `seq`/`lightSig`/`oqX`/`oqZ`, and keeps the park. After re-key the same three triggers must fire again — a verdict-relevant change that touches none of them is silent.
- `src/render/renderer.js:24821-24834` — `parkedEntry.recheck` decrements every visited sync; expiry sets `parkedRecheck`, the only non-trigger path into `collectGate` for a parked root (`collectGate` at `:24839` needs `parkedRecheck || parkedReleaseOnDrift || (band!==1 ? !queued : dirtySeq>stampedSeq)`; parked ⇒ `queued===true`, parked roots stamp castBand 0 ⇒ `band!==1` ⇒ `!queued` is false).
- `src/render/renderer.js:25242` and `:25358` — park mints arm `recheck = (96 + stamp%32) * Math.min(8, 1<<(cycles-1))`; escalation caps the multiplier at 8 ⇒ worst ~96–127×8 ≈ 768–1016 syncs ≈ 13–17 s at 60 fps.
- Mutations that deserve a re-verdict but bump none of the three terms: (i) **root-side motion** into `SHADOW_CAST_RADIUS` — `axisDistance` is recomputed live in `allowRealtimeShadowCast` but a moving entity under a kept park (player + key-light target cell static) fires no trigger; (ii) **non-family lodLevel promotions** (`lod2→lod0` on plain `THREE.LOD` members — family swaps are covered by `invalidateShadowCasterPolicy` seams at partsLibrary.js:9169/9201 etc., which bump `dirtySeq`, but a plain LOD object's level flip doesn't); (iii) **drawability-repairing writes on withheld members** (`mesh.visible`, `mesh.layers.mask`, `geometry`/`material` field writes) — the code comment at `renderer.js:24819` already names this class ("visible toggle, LOD swap, drifting inside the shadow ortho") as the reason the recheck backstop exists.

Mechanism: a root parked as undrawable-or-denied whose subtree becomes castable while the ortho cell and light census stand still keeps its casters `castShadow=false` until the (possibly ×8-escalated) recheck fires — a fully drawn ship/station inside the magic frame missing its shadow for seconds. The W91 keep-branch made this strictly more reachable: drift-outs re-key and keep instead of releasing, so a root can sit under a kept park for the whole backstop window.

Fix sketch: discriminate denial-parks from cap-parks. Stamp `denied: true` on the undrawable-verdict mint (`:25354`) and set `parkedEntry.denied = true` inside the keep-branch (`:24789`); leave the abort-mint (`:25238`, over-cap class) unstamped. Add one release branch: `else if (parkedEntry && parkedEntry.denied === true && opts.allowCast === true) parkedRelease = true;` — plain release (not `parkedReleaseOnDrift`), so the collect re-verifies drawability under the live census. Cap parks never stamp `denied` → no release/re-park churn; the ±10 WU cast-band hysteresis damps flapping; a still-undrawable re-collect simply re-parks with `cycles+1`.

Effort S · magic-frame impact M · risk L (reuses the exercised release path; worst case is extra re-collects on oscillating roots, bounded by `SHADOW_DEPTH_PASS_COLLECT_CAP`).

### 2. `syncShadowCasterPolicy` traverses carry no node budget — one fat subtree is an atomic leg on the presented sync and inside the arm's restore loop (hunt e)

Evidence:
- `src/render/shadowCasterPolicy.js:248-278` — `syncShadowCasterPolicy` is a single `root.traverse(...)`; unlike the flag collects it has no node budget.
- Presented-frame path: `src/render/renderer.js:24957-24975` — whole-subtree traverses run inside `_syncShadowCasterPolicyChecked` up to `SHADOW_ROOT_SYNC_PASS_CAP = 8` per pass, plus withhold-verdict exempts (bounded by the collect cap but each traverse unbounded per root), plus scoped graft syncs.
- Arm path: `src/render/renderer.js:25456-25481` — the restore loop checks `armNow() >= restoreDeadline` only *between* roots (`restored >= 1` then break); a single fat authored boundary's restore traverse is one atomic leg inside the `armCallbackAfterPresent` task.
- Contrast: `collectUnstagedShadowCastersFlag` walks are bounded by `SHADOW_DEPTH_PASS_NODE_CAP` (4096, ×`depthNodeScale` ≤ 8) at `renderer.js:24853/25218`.

Mechanism: flag collects abort mid-subtree and resume; the policy traverse cannot. A 10k-node authored root pays its entire flag rewrite atomically — inside the presented sync for the first 8 roots/verdicts, or inside the arm on restore. The arm's spend is ledger-debited (`notePacedFrameSpend`) so other slicers back off, but the leg itself lands whole adjacent to the present.

Fix sketch: a stepped twin `syncShadowCasterPolicySteps(root, ...)` (the codebase already has the pattern — `disposeObjectSteps`, `collectUnstagedShadowCastersSteps`), driven under the same per-root deadline rule; the apply is already per-node atomic so a mid-walk suspend is safe if detached-mid-walk nodes get the same guards `disposeObjectSteps` uses.

Effort M · magic-frame impact M (bounded by the 8-per-pass cap; each leg's size is the risk) · risk M (mid-traverse detach/remount semantics need care — keep it honest rather than clever).

### 3. Warm passes flip `keyLight.castShadow` across awaits without a census bump (hunt d)

Evidence:
- `src/render/precompile.js:861-877` (`beginDirectionalShadowWarm`) and `:880-920` (`prepareDirectionalShadowPipelineVariant`) set `keyLight.castShadow = true`, `await preparePipelines(subject)`, then restore in `finally`. `castShadow` is a per-light census signature term (`lightCensusSignature`, shadowDepthAdmission.js) — mutated twice across await boundaries with no `noteShadowCensusLightMutation()`.
- All other live-scene light writers are covered: sector rig mints once at scene setup (`renderer.js:9176-9179`); event-light and weapon pools are fixed-count boot baseline (`vfx.js:14936-14970`, `weapons/weaponLights.js:14-45`); authored parts can't carry lights (`assetLoader.js:1510` — "parts may contain only geometry and contract nodes"); teardown detection covers subtree removals (`renderer.js:26762-26846`, `disposeObject`/`disposeObjectSteps` `heldLight`); precompile staging bumps on add/remove (`precompile.js:180,198`); overhead-light dispose bumps (`flightOverheadPresentation.js:61`); pool dispose bumps (`weaponLights.js:108`). Light `.visible`/`.layers`/fog-type writes post-boot: none found.

Mechanism: inside the flip window a same-seq census memo mints the flipped sig; post-restore same-seq memos are stale until `_viewSyncSeq` advances. Consequence is safe-direction only — sig-keyed mark re-proofs and the heldSession sig compare see a transient mismatch and re-collect/re-stage rather than trusting wrong marks — but it's real churn during incremental sector warms, and it is the one remaining uncovered writer class.

Fix sketch: `noteShadowCensusLightMutation()` on flip and on restore (two lines per site). Accept that a suspended mid-window session closes and re-mints — that is the intended staleness handling, strictly better than serving the transient sig.

Effort S · magic-frame impact L · risk L.

### 4. `_deferredDepthStageRoots` is minted but never seam-deleted — a detached+remounted root inside a drive window waits out the drive (hunt b)

Evidence:
- Write sites enumerated for `pending`/`parked`/`withheld`: entity meshes delete all three in `_unbindPresentationMesh` (`renderer.js:20610-20621`); boundary owners delete all three in `_releaseDetachedBoundaryOwnersSteps` (`:20834-20843`); the arm sweep reaps detached pending+parked rows (`:25065-25085`) before the `pending.size===0` early return; `clearAllMeshes` clears everything (`:20898-20905`); slice-detached members are handled in the restore loop's `!root.parent` leg (`:25414-25420`) and the `finally` requeue (`:25484-25497`). No withheld-without-sibling leak found.
- `_deferredDepthStageRoots` (mint `:25298-25304`, consumed `:25424`, deleted only in the drive `.finally` at `:25322-25326` and `clearAllMeshes` `:20903`) is not in any seam.

Mechanism: a root marked deferred mid-drive that detaches and remounts before the drive settles keeps its deferred row → every restore-loop visit re-queues it (`pending.set(root, entry); continue`) until the drive's `.finally` deletes it. Bounded by drive duration and self-cleaning, so the cost is delayed staging of a remount, not a leak.

Fix sketch: add the deferred delete to both seams (the same three-set grammar becomes four-set).

Effort S · magic-frame impact L · risk L (a remount simply re-collects fresh — safe direction).

### 5. Nit — per-root `unstagedCache` revalidation walk is atomic per root (hunt c)

Evidence: `src/render/renderer.js:25197-25212` — on re-queue each cached mesh re-proves `casterDepthMarkCurrent` before the cache is trusted; the deadline check (`collectDeadline`, `:25178`) only separates *roots*. A single root with a very large cache walks all cached meshes atomically inside the arm; a burst of N roots is already bounded by the deadline between roots.

Fix sketch (optional): carry a cursor into the cache walk so a fat cache can yield mid-root like the collects do. Effort S · impact L · risk L.
