### Where traversals duplicate in one frame

- **T1 vs T2/T3**: `updateMatrixWorld` writes `matrixWorld`; `projectObject` only reads it to frustum-test and collect. Both derive the same per-frame verdict the game already computes elsewhere (pose writes in `syncEntityViews`, visibility verdicts in `applyEntityMeshVisibility`). The duplication is **engine-mandated** — three has no frame-persistent render list — but **structurally avoidable**: a maintained drawable set fed by the presentation world's own verdicts.
- **T2 vs T3**: pure duplicate — same scene, same camera, microseconds apart; the drawn set differs only by `overrideMaterial` and the T4 instanced masks. **Structurally avoidable** via one cached visible set.
- **T4 vs T2/T3**: the hide walk's only job is a layers-mask fixup the pool already knows the answer to (`asteroidInstancePool` registers every InstancedMesh). **Structurally avoidable** — registry-driven, zero traversal.
- **T5**: deduplicated already (Pole E) — the model for what T2/T3 could become.
- Engine-mandated floor: `projectObject`'s per-node work that can't be incrementally maintained without a vendor patch: LOD `object.update(camera)` (`:17999`), `objects.update` geometry bookkeeping, renderOrder/`groupOrder`, material-array group expansion, per-mesh `intersectsObject` for `frustumCulled` nodes.

## Findings (ranked — each with evidence label, impact, effort, risk, fix sketch)

### F1 — GRAPH+AO pays three whole-scene walks where one collected set suffices — `MECHANISM_VERIFIED` — impact H (GRAPH route only), effort S–M, risk low–medium

T3 (`projectObject` #2) and T4 (`traverseVisible`) re-derive in one frame exactly what T1's `projectObject` enumerated: the live visible drawable set. Two cheap legs:
- **(a) Kill T4**: replace `hideInactiveInstancedMeshes`'s full `scene.traverseVisible` with iteration over a maintained instanced-mesh set — `asteroidInstancePool`/`_syncAuthoredInstanceSubmission` already register every pool InstancedMesh at mint; add a `scene.add` mount-watch fallback (the unready guard's `ensureSceneMountWatch` at `bloom.js:1149-1163` is the working pattern) for foreign mounts. What breaks: nothing visible — masks are applied per-pass and restored identically; only the discovery path changes.
- **(b) Kill T3**: the normal pass differs from color only by `overrideMaterial` and the (a) masks. Bounded variants: vendor-patch `renderer.render` to accept a precomputed render list captured during pass 1 (same `_frustum`, same camera, same frame — the `WebGLRenderList` items are material-agnostic until push time, so capturing `(object, geometry, groupOrder, z, group)` tuples before material selection is exact); or patch `projectObject` to emit a reusable segment array. What breaks: nothing if the capture is inside the same `render()` — matrix worlds are already final (matrixWorldAutoUpdate=false); per-pass material swap happens at draw, which already reads the list. The unready-guard `hide`/`restore` must bracket both passes as today (it does — `_renderPostRoute` wraps the whole graph render at `:31907-31912`).

### F2 — `projectObject` re-derives the drawable set O(visible nodes) every pass — the W121 flat-registry sketch — `MECHANISM_VERIFIED` — impact H, effort L, risk M–H

The maintained-set direction, now with landed precedent: Pole E did exactly this for shadow casters (`castShadow` accessor → `_shadowCasterRegistry`, `vendor:19-75`) — the pattern "prototype setter maintains a registry; the pass re-proves membership cheaply instead of recursing" is proven in-tree. A drawable twin would register at mount (`scene.add`/`attach` hooks already patched at `vendor:148-175` for freeze-invalidation — the hook site exists) and let `projectObject` iterate a flat array, re-proving `visible`/layers/frustum per entry the way `eachShadowCaster` re-proves ancestors. What breaks: everything `projectObject` currently gets free from recursion — `visible===false` subtree prune, `isLOD` per-frame camera update (`:17999` — LOD objects must stay updated or render lists go stale; the registry must flag LOD entries or keep a small live-LOD side list), `groupOrder` from Group renderOrder, material-group expansion, XR depth mesh (inert — no XR), `frustumCulled===false` pass-through. Feasible bounded variant: registry of *drawable leaves only* (Mesh/Line/Points/Sprite/InstancedMesh/BatchedMesh — the node classes projectObject can push), preserving group/light handling by a shallow top-2-level walk or a second maintained light set (T7 already census-keys the light set). Effort L (vendor patch + mount-watch + LOD/reparent correctness). Risk M–H (vendor patch surface; presented-frame correctness — a missed register = invisible drawable = pop, the campaign's worst defect class — needs the mount-watch failsafe + a periodic cheap census assert in probe builds only).

### F3 — `updateMatrixWorld` still walks every non-frozen node + all descendants of re-posed roots — `MECHANISM_VERIFIED` — impact M, effort M, risk medium

Post-park residual: the walk skips clean `sfMatrixFrozen` subtrees but still (a) touches every mounted non-frozen node to read flags, and (b) force-descends whole subtrees under every re-posed root (a moving ship pays its full ~90–150-node subtree per frame — required for correct `matrixWorld`s, that's the work). The addressable part is (a): the dirty set per frame is exactly "roots the pose path wrote this frame" — `syncEntityViews`/`applySnapshotPoseToMesh` already enumerate it. Bounded variant: maintain a per-frame dirty-root list (pose writers push; the walk becomes "for each dirty root: updateMatrixWorld(true)-equivalent on its subtree"), with a full-walk failsafe every N frames or on mount/dirty-storm, keyed like the existing `_viewSyncSeq` epoch machinery. What breaks: any writer outside the pose path — self-animating nodes (sockets, `updateRuntimeState`/`updateDriveState`/LOD-animated nodes — already freeze-exempt by `shouldFreezeStaticChild`, `staticChildMatrices.js:17-24`, so they stay walked if the dirty-root list falls back to walking live-flagged subtrees), `traverseVisible`-only visibility flips (don't dirty matrices — safe), UI-stage/producer scenes (separate graphs — unaffected). Risk medium: a missed dirty root = stale `matrixWorld` = wrong draw position for a frame — worse than a missed projectObject entry for correctness, easier to audit (compare-vs-full-walk assert, probe-only).

### F4 — N fixed-overhead `renderer.render` calls on O(1) scenes per frame — `MECHANISM_VERIFIED` — impact L, effort S–M, risk medium

Every fullscreen/composite/blit/producer pass pays the whole `WebGLRenderer.render` prelude (renderState acquire, frustum compute, `renderList.init/finish`, `shadowMap.render` on an empty shadows array, `background.render` check, `info.reset`) for scenes of 1–2 nodes. ~4–10 calls/frame (bloom pyramid ~2–4 blits + composite + AO + distortion + optional grade). Fix sketch: a blit fast-path — `renderBufferDirect` on the quad mesh directly (the game already bypasses `traverse` for quad meshes via `frustumCulled=false` + `matrixWorldAutoUpdate=false`, `bloom.js:1650-1651`) — same pixels, ~zero engine prelude. What breaks: per-blit program/acquire bookkeeping must still happen (they do — `renderBufferDirect` runs material acquisition), and `renderer.state` bindings must be identical (they are — same call path as `renderScene`'s tail). Risk medium (vendor surface again, smaller than F2).

### F5 — Shadow pass residual: per-caster ancestor re-prove each refresh — `MECHANISM_VERIFIED` — impact L, effort S, risk low

`eachShadowCaster` walks each registered caster's ancestor chain to scene root every refresh (`vendor:60-75`). For a caster under a visible root this is O(casters × depth) — already tiny vs the old O(scene); memoizable per `(caster, viewSyncSeq, mountEpoch)` if refresh frequency proves out. Note only — the flat-registry model (F2's precedent) already landed here.

### F6 — Hidden-but-unfrozen subtrees still pay T1's compose walk — `MECHANISM_VERIFIED` — impact M, effort M, risk medium

`updateMatrixWorld` descends regardless of `visible` — only `sfMatrixFrozen`/`sfCullFrozen` marks skip. Warm roots were parked (detach) but other hidden mounted content — culled hulls not yet minted `sfCullFrozen`, off-screen interiors, stage leftovers — pays the per-frame flag-visit + any compose. Extend the W121 leg-1 pattern: either widen `freezeHiddenSubtreeMatrices` coverage (it already exists and self-heals, `staticChildMatrices.js:155-201`) to every `visible=false` mount older than K frames, or grow the park set to "hidden > K frames AND not admission-pending". What breaks: nothing that `unfreezeHiddenSubtreeMatrices` doesn't already restore on un-hide; the admission machinery's pending roots must stay exempt (`warmBuilding`/pending-subjects checks mirror `_parkBoundedWarmRoots`'s `:22936-22939`).

## Approach ranking (with what-breaks analysis)

1. **F1(a)+(b) — dedupe the GRAPH second walk + instanced-mask traversal** (S–M / low–medium). First because it's the smallest change for the largest verified duplication (2 whole-scene walks → ~0 under `high` preset). What breaks: LOD `autoUpdate` still evaluated in pass 1 (share it); the unready guard's hide/restore already wraps both passes; the masks apply identically — the only new state is "captured list valid for this frame epoch", invalidated on any mount/visible write — epoch key on `_viewSyncSeq`.
2. **F3 — dirty-root `updateMatrixWorld`** (M / medium). All-route win: converts the one walk every route pays from O(mounted) to O(dirty roots + live-flagged subtrees). What breaks: non-pose-path matrix writers (enumerated above — sockets/animated/updater nodes stay live-flagged and walked; mount/dirty-storm fallback to full walk keeps it fail-closed). Presented-frame correctness preserved because a missed dirty root is a skipped compose, not a wrong one — and assertable probe-side by diffing against the full walk.
3. **F2 — flat drawable registry (the W121 sketch, bounded variant)** (L / M–H). The end-state: `projectObject` stops walking entirely. Land after 1–2 prove the registry/mount-watch pattern. What breaks: listed above; the catastrophic direction is a missed register (invisible drawable — pop), so the probe-only census assert + mount-watch are mandatory parts of the design, not nice-to-haves. Bounded variant (leaf registry + kept shallow walk for groups/lights) cuts most of the risk for most of the win.
4. **F4 — blit fast-path** (S–M / medium). Constant small win × ~4–10 passes/frame; independent of 1–3.
5. **F6 — widen hidden-freeze/park coverage** (M / medium). Shrinks T1's flag-visit cost and T2's descend-into-hidden work; overlaps W121 leg-1 (partially landed).
6. **F5 — caster ancestor memo** (S / low). Opportunistic, smallest item.

Explicitly not recommended for this lane: **BatchedMesh consolidation of statics** (W121 leg-2) — real but it's a draw-call/node-count lever, not a traversal-shape fix; still census-gated (re-run the density census in its own unit). **Retained-mode full submission replacing `renderer.render`** — the unbounded variant of F2: L–XL effort, severs from three's pipeline; only after the bounded variant lands.
