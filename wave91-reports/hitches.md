## Findings (ranked)

### F1 — Pack clean-test reads a mask owned by the sync pass: never-visited slots hold `ALL` forever, and three byte-identical mark classes force full scalar writes

- **Evidence:** `allocateRecord` stamps `writeDirtyMask(slot, PRESENTATION_DIRTY.ALL)` at `src/render/presentationWorld.js:598`. Masks clear only inside `syncEntityViews`, and only for query-visited slots: `world.clearDirty` at `src/render/renderer.js:22427` (hidden loop over `query.hiddenSlots`) and `:22825` (visible loop over `query.visibleSlots`). The query's candidate set is `collectSpatialBounds ∪ collectSpecialSlots ∪ player` (`src/render/presentationQueries.js:300-318`) — a slot outside the cull envelope with no special flag and no bound-mesh admission is never in either output set, so its mask is never cleared: **allocated `ALL` → permanent `dirtyMasks !== 0` → `world.dirtyMasks[slot] === 0` at `src/render/snapshotFence.js:310` fails every pack → the full scalar write runs for that row on every presented frame for its whole life.** Three smaller classes share the same mechanism — marks that cannot change packed bytes still fail the `===0` test: `unbindMesh` marks `BINDING|VISIBILITY` (`presentationWorld.js:750`), `setVisibility` marks `VISIBILITY` (`:994`), the hiddenIds feed marks `VISIBILITY` (`:906`), and `applyVisual` marks `VISUAL` unconditionally (`:724`). Packed columns are only position/quaternion/scale/tint/bank/pitch/entityId/archetype/flags (`src/render/presentationSnapshot.js:24-34`) — BINDING/VISIBILITY never touch them, and a VISUAL mark only changes packed bytes when `refreshMetadata` also flipped flags/typeCodes. Same grain, fourth class: `writePoseScalars` (`:372-420`) compares 12 scalars including the six unpacked `prev*` columns, so a prev-only rebase marks TRANSFORM and produces a byte-identical write.
- **Mechanism:** the pack walks all `active` rows every presented frame; the scalar path re-reads ~10 world columns + `snapshot.write` (~16 typed writes) + `setLean`, vs `copyRow`'s 9 `subarray.set` copies. Movers legitimately dirty every frame (player/movables TRANSFORM via `recordTransformIfChanged`, `src/core/coreSystem.js:478-486`) — the residual is the *byte-identical* span: the whole spawned-but-never-visible population (far statics, ledger rows, out-of-envelope bound meshes — the majority of a dense sector's rows) plus per-frame BINDING/VISUAL/VISIBILITY-only churn.
- **Fix sketch:** a pack-owned dirty bit, not the sync-owned mask — e.g. `packDirty[slot]` set only by writers that can alter packed columns: `allocateRecord`, `writePoseScalars`' packed-6 compare (x/y/z/rot/bank/pitch — not the prev* compares), `refreshMetadata`'s flags/typeCode change sites (currently folded into the VISUAL mark), and any future tint writer. `packPresentationWorldToFence` clears it per slot after its write/copy. That collapses the never-visited class to one scalar write at allocate and lets BINDING/VISIBILITY-only rows copy verbatim. Requires enumerating every packed-column writer exactly; add a conformance test driving random dirty patterns and asserting copied rows equal the scalar-write oracle. No row-stable per-class opt-in exists today — this mechanism is the opt-in.
- **Effort:** M. **Magic-frame impact:** H (dense sectors — thousands of off-screen rows × ~2-4× per-row cost every presented frame). **Risk:** moderate — a missed packed-column writer freezes that row's pose permanently; the conformance test is the mitigation.

### F2 — `result.rebuilt` conflates `world.clear()` with the diff-apply fallback: every tick-advanced present during a suspended stepped rebuild bumps `_posePackEpoch`, killing the copy path AND interpolation for the whole window

- **Evidence:** `fallbackFromState` sets `result.rebuilt = true` on every real `updateFromEntities` apply (`src/render/presentationPublisher.js:131`), which runs on each tick-advanced present while `journal.needsRebuild()` holds across the stepped window (the `completedTickCount > 0 || !initialized || lifecycleGeneration` gate at the top of `fallbackFromState`); `_advancePosePackEpoch` bumps on `publication.rebuilt === true` or a `currentSectorId` change (`src/render/renderer.js:22226-22230`). The copy path requires `previous.poseEpoch === poseEpoch` (`src/render/snapshotFence.js:303-304`); `previousSnapshot()` — the interp blend source — requires `buffers[previous].poseEpoch === buffers[latest].poseEpoch` (`:165-168`).
- **Mechanism:** a suspended stepped journal rebuild spans multiple tick-advanced presents, and rebuilds arm during exactly the churn windows where the pack's work is largest (spawn bursts, sector transitions, kill storms). Each such present bumps the epoch → `previousIndex === null` → **every row takes the full scalar write** — and `previousSnapshot()` returns null → `poseSpanAlpha` returns the fallback alpha → movers land tick-quantized for every present of the window (the freeze-then-jump cadence the span-normalization machinery exists to prevent). `updateFromEntities` is a diff-apply — slots preserve id-keyed identity for retained ids — so neither the byId-keyed copy (`previousIndex.get(entityId)`) nor the byId-keyed interp lookup (`snapshotIndexOf`) can return a wrong-id row; the only genuinely unsafe case is an id recycled onto a different body.
- **Fix sketch:** split remap events from diff-apply — e.g. `result.remapped` set only on `world.clear()` (`:215-220`) and `journalFullRebuild`, while the epoch also bumps on sector-id change as today; diff-apply presents keep the epoch. Residual interp risk is a ~1-present stale blend on ids recycled inside the window; the precise guard is a per-id generation column in the pack (u32, alongside entityId) with copy/blend conditioned on generation equality.
- **Effort:** S-M (flag split) / M (generation column). **Magic-frame impact:** M-H — the full-scalar pack and interp loss both land inside the exact windows this wave's machinery is fighting. **Risk:** moderate — loosening the epoch accepts a bounded stale-pose blend on recycled ids; the generation column removes even that.

### F3 — The hiddenIds hide is write-only: `world.visible` has no read-side consumer, and `entity.alive === false` rows never reach the mask — the real doomed-mesh bound is the `entity:destroyed` priority drain

- **Evidence:** `world.visible` is written at `src/render/presentationWorld.js:588` (allocate), `:669` (retire), `:749` (unbind), `:905` (hiddenIds), `:993` (setVisibility), and read only inside the module (`:904`, `:992`) — a repo-wide grep finds zero external consumers. `exactVisible` (`src/render/presentationQueries.js:129`) checks `alive === 1 && meshRefs` only, so the doomed row stays in `visibleSlots`. In the visible loop, `if (!mesh || (entity && entity.alive === false)) continue;` at `src/render/renderer.js:22470` skips doomed rows *before* `dirty` is read at `:22488` — the VISIBILITY mark can never reach `_applyPresentationPose` for a dead entity. For a row whose `entityRefs` is null or stale-alive, `shouldSubmitEntityMesh` (`src/render/entityMeshVisibility.js:14-61`) has no `world.visible` input and submits via `onLiveGlass` — so on either branch the mark never produces `mesh.visible = false`. The actual hide is the `entity:destroyed` presentation handler (`renderer.js:15964-16006`: `scene.remove(m)` + `_meshes.delete` + `_unbindPresentationMesh`), which is journal-independent: `bus.queue` → end-of-step flush → `presentationPriorityQueue` (`src/core/eventBus.js:50` — `entity:destroyed` is the sole priority event) → `drainPresentationTail` every frame callback (`src/core/presentationRunner.js:1162-1174`, ungated by `skipPresentation`/`capSkip`) at `max(8, ceil(pending/4))` invocations under a `min(4ms, max(scaledFloor, tailMs))` deadline + `pacedFrameSpend` cap (`eventBus.js:379-419`).
- **Mechanism:** the presented window where a doomed mesh still draws equals its slice's position in the priority drain — ~0-1 presented frames normally, scaling to `ceil(N·listeners/drainRate)` under a mass-despawn backlog (the drain comment itself estimates "tens of frames" for a spent-frame kill clump). During it, corpses draw at their last pose. The W90 feed's `visible=0` mark is therefore dead code on live paths: kept-mesh cases can't be doomed (the ledger-row keep requires `still.alive !== false`; the recook keep is intentional), and bound meshes are always `_meshes` members that the handler scene-removes.
- **Fix sketch:** either delete the dead mark (honest dead code), or wire it: a dedicated `feedHidden` bit consulted by `exactVisible` (or the visible loop's submit gate) routes the doomed slot through the hidden path's `applyEntityMeshVisibility(mesh, hidden:true)` — a ~1-frame bound independent of the bus drain, which is what the W90 sketch intended. Do not overload `world.visible` itself — the query's own `setVisibility` writes it on set enter/leave, so it already means "query-admitted", not "feed-hidden".
- **Effort:** S-M. **Magic-frame impact:** M — the storm-backlog window is precisely when corpses linger on glass; also corrects a W90 claim that was never realized as a mesh hide. **Risk:** low-moderate — new bit must not entangle the query's admission bookkeeping; publish retire runs regardless.

### F4 — `drainDespawnDisposeQueue`'s parked `iter.next()` is unguarded — a throwing dispose hook propagates through `serviceRenderMeshResidency`, skipping that frame's `_flushMeshReleasePending`, `settleRebuildBridges`, and reconcile work

- **Evidence:** `iter.next()` at `src/render/renderer.js:1990` runs bare inside the drain loop; neither the mint (`:1981`) nor the step is wrapped. The partsLibrary twin — `retainedDisposeQueue` — wraps both mint (`src/render/partsLibrary.js:8977-8981`) and `.next()` (`:8985-8988`) in try/catch. A throw propagates out of `serviceRenderMeshResidency` (`renderer.js:2116+`) before `_flushMeshReleasePending`/`settleRebuildBridges`/the reconcile sweep run, and up into the frame loop's catch. Self-healing is partial: a completed generator answers `{done:true}` next drain, so the corpse advances, but the frame's remaining residency work is lost. The rest of the drain bounds correctly: `limit = max(8, ceil(pending/4))` (`:1955-1958`), 2ms deadline (`:1950`), paced-skip with `DESPAWN_DISPOSE_LEDGER_MAX_SKIPS=2` aging (`:1943-1948`), remount abandon at `m.parent != null` (`:1968-1973`), corpse-identity re-mint (`:1979-1983`).
- **Mechanism:** under a mass-despawn storm the queue is the pressure point; a corpse whose dispose chain throws (partially-torn subtree, a custom dispose that re-enters) costs the frame's whole residency service — exactly when `settleRebuildBridges` and the identity-release flush are most loaded.
- **Fix sketch:** mirror the partsLibrary contract — try/catch around `iter.next()`; on throw, log bounded, null `_despawnDisposeIter`, advance head. A torn-dispose corpse is already the accepted failure mode of every paced lane.
- **Effort:** S. **Magic-frame impact:** L-M. **Risk:** low — identical contract to the retainedDisposeQueue lane.

## Hunt notes (a)-(e)

**(a) Per-frame-dirty classes and residual write span:** movers (player + `isMovableEntity` set via `recordTransformIfChanged`, `coreSystem.js:478-486`) are legitimately TRANSFORM-dirty every tick — their packed bytes change, so the scalar write is paying for real work. The residual span is everything byte-identical: (1) never-visited slots holding `ALL` from allocate for life (largest class — the whole out-of-envelope population; F1); (2) `BINDING|VISIBILITY` marks from `unbindMesh`/`bindMesh` churn and `VISIBILITY` marks from `setVisibility`/hiddenIds — byte-identical by construction (mesh refs and the visible flag are not packed columns); (3) unconditional `applyVisual` VISUAL marks (`:724`) — byte-identical unless `refreshMetadata` flipped flags/typeCodes on the same record; (4) prev*-only TRANSFORM marks (rare — 12-scalar compare feeds a 6-scalar pack). No per-class row-stable opt-in exists; F1's pack-owned bit is the mechanism that would create one.

**(b) poseEpoch producers:** exactly two — `publication.rebuilt === true` and `currentSectorId` change (`renderer.js:22224-22233`). No per-frame producer exists in common flight (interp paths and rebase ticks do not bump it). The residual is the `rebuilt` conflation (F2): during suspended stepped rebuilds, every tick-advanced fallback present bumps it, so the copy path AND interp die for the whole window rather than per-remap.

**(c) hiddenIds→mesh window:** the mark cannot hide (F3). The presented window for a doomed mesh is bounded by the `entity:destroyed` priority-drain position — ~0-1 frames normally, `ceil(N·listeners/drainRate)` under backlog (tens of frames in the drain's own spent-frame estimate). Meshes surviving that drain (intentional ledger/recook keeps) draw regardless of the mark.

**(d) Post-sync re-dirtying writers:** frame order is consume → `_bindPublishedPresentationMeshes`/`_rebindPresentationMeshes` (`renderer.js:23557-23558`) → pack (`:23568-23582`) → present → `syncEntityViews` → `drainPresentationTail` (`presentationRunner.js:1162-1174`). Marks landing between a slot's `clearDirty` and the next pack: `world.unbindMesh` via `_unbindPresentationMesh` (entity:destroyed drain, mass-despawn sweeps — `BINDING|VISIBILITY`, byte-identical → unnecessary next-pack scalar write, F1 class 2) and same-path `bindMesh` re-binds (TRANSFORM — legitimate). Marks minted *inside* the sync pass (`refreshVisibleEntity` at `:22486`, query's `setVisibility` at `presentationQueries.js:247/333/346`) are consumed by the same pass's `clearDirty` (`:22427`, `:22825`) — net clean, no extension.

**(e) Despawn drain growth bound:** mint is itself paced — `entity:destroyed` corpses enter through the priority drain (`max(8, ceil(pending/4))` invocations, ≤4ms/paced cap) — so mint rate ≈ drain rate of the bus lane. Corpse drain: `max(8, ceil(pending/4))` count-wise or ~2ms of iterator steps per frame (`renderer.js:1955-1995`), one drain per frame via `serviceRenderMeshResidency` (`:23616`), paced-skip ≤2 consecutive (`:1943-1948`). Cheap corpses drain geometrically (~¼ of backlog per frame — the ~14-drain/600-corpse comment is accurate); fat corpses (1-3k-node hulls) are ms-bound at ~2ms/frame each. The queue is memory-unbounded but work-bounded — mint stops with the storm, so persistence ≈ total-node-steps/2ms frames of background GL reclaim. No unbounded growth mechanism found; the unguarded `iter.next()` (F4) is the only defect in the lane.
