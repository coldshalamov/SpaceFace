# Wave 91 audit — lod-in-frame

Lane: `lod-in-frame`. Audited `devin/1791064509-perf-w60` @ `8109eee8e` (HEAD at audit time). Read-only; no code changed, no PRs, no app runs.

## 1. Verdict

`saturated: false` — six legal contract-preserving improvements remain: the parked/withheld bookkeeping is teardown-blind, a parked boundary's authored commit mutates its tree under no park key, the retained-LOD drain's wallet aging is dead code, each arm pays a fresh whole-scene census traverse, per-arm collects are non-incremental, and an out-of-ortho drift release discards earned park bookkeeping.

## 2. Ranked findings

### F1 — Detached parked roots leak `_parkedDepthStageRoots`/`_withheldDepthCasters` rows indefinitely when pending is empty

- **Evidence:** `src/render/renderer.js:24989-24994` — the arm early-returns when `pending.size === 0` (`_killDepthStageSession()`). The pending-detach sweep (25020-25029) and the parked-detach sweep (25034-25045) run *inside* the arm callback, *after* that early return — so they only run while at least one root is still queued. No teardown path ever touches the maps: `_unbindPresentationMesh` (20555-20595) releases motion trackers / living-hull / submit lanes but not depth rows; `releaseDetachedBoundaryOwners` (20774-20800) disposes the tree leaving its rows; `releaseRebuildBridge` (2059-2065) and `clearAllMeshes` (20836+) likewise never touch `_parkedDepthStageRoots`, `_pendingDepthStageRoots`, or `_withheldDepthCasters`.
- **Mechanism:** a parked boundary detaches — despawn corpse teardown, sector rebuild, authored-bridge release, pool dispose, `clearAllMeshes` — while the depth queue happens to be empty → no arm fires → the parked record (retains `entity`, `lightSig`, ortho cell) and the withheld Set (retains every withheld Mesh object, pinning its geometry/material refs) persist until some unrelated root re-queues. Across sector churn this leak-accumulates: the maps grow unboundedly, dead roots pin partial trees, and every later arm pays the O(|parked|) sweep over dead rows. The `despawn` path does clear the *pending* row mid-flight (arm re-check at 25100-25101 drops detached roots) but parked rows survive that too.
- **Fix sketch:** run both detach sweeps before the empty-pending early return (they are already O(map size) and cheap on an empty pending), or delete the root's rows in the existing detach seams (`_unbindPresentationMesh`, `releaseDetachedBoundaryOwners`, `clearAllMeshes`), where the root is already in hand.
- **Effort:** S. **Magic-frame impact:** M. **Risk:** L — reuses existing sweep semantics; only scheduling changes.

### F2 — Authored-commit subtree swaps replace a live boundary's tree with no `invalidateShadowCasterPolicy` — stale park + dead withheld refs until the recheck backstop

- **Evidence:** `src/render/partsLibrary.js:3337-3338`, `4248-4249`, `9401-9402` — all three commit sites do `boundary.remove(fallbackRoot); boundary.add(authored.root)` with no invalidate; the file's only `invalidateShadowCasterPolicy` calls are the LOD-family seams at 9120/9152. Park-release gates (`src/render/renderer.js:24711-24729`) key exclusively on dirtySeq / lightSig / ortho-cell / recheck.
- **Mechanism:** a boundary parked as undrawable-forever (resolving-marker / fallback-substrate class — exactly the stand-in roots this lane covers) commits its authored payload in place. dirtySeq is unchanged → the withheld Set still names the torn-down fallback meshes and the parked record's keys still match → the park survives until `recheck` expiry: 96-128 syncs × up to 8× `sfDepthUndrawableCycles` backoff, i.e. ~100-1000+ syncs. Inside the window the band-1 selfDirty restamp path (renderer.js:24831-24839) rewrites `castShadow=false` onto dead meshes, and dead refs pin the fallback subtree against GC. Bounded and self-healing — but it is precisely the "mutate a parked root's tree without bumping any key" seam. On release the re-collect finds authored casters already minted at admission → empty unstaged → the park drops via the 24814-24819 release path. Same class, weaker reach: `_noteShadowMeshAdded/Removed` (renderer.js:25550-25564) updates only the receiver tally — the scene-level graft hooks (`scene.userData.shadowMeshNotes`, renderer.js:9620-9629) don't bump a host root's dirtySeq, so a chunk graft landing under a parked root has the same stale-set exposure.
- **Fix sketch:** one `invalidateShadowCasterPolicy(boundary)` at each of the three commit sites (the import already exists in the file; convention at 9120/9152). A dirty bump collapses the stale window to the next sync's release + re-collect.
- **Effort:** S. **Magic-frame impact:** M. **Risk:** L — worst case is the designed whole-root dirty re-traverse.

### F3 — `retainedDisposeQueue` wallet aging is dead code: `skips` is per-fire and `break`s on the first saturated read — a sustained saturated stretch starves reclaim forever

- **Evidence:** `src/render/partsLibrary.js:8967-8973` — `let skips = 0` is minted inside the `setTimeout` fire; `if (pacedFrameSpend() >= PACED_FRAME_BUDGET_MS && skips < 2) { skips += 1; break; }` exits the loop on the first saturated read, so `skips` never even reaches 2, and being per-fire it confers no cross-fire aging at all. The doc comment (8955-8959) promises "aging like the despawn drain so a saturated stretch can't starve reclaim forever" — the despawn twin implements it correctly via the *persistent* `owner._despawnDisposeLedgerSkips` counter (`src/render/renderer.js:1943-1948`, capped at `DESPAWN_DISPOSE_LEDGER_MAX_SKIPS=2`, reset on a passed drain). The arm's own `_depthStageLedgerSkips` (renderer.js:25002-25008) is likewise persistent.
- **Mechanism:** during sustained paced saturation — precisely when authored churn enqueues retained whole-ship LOD roots (`releaseRetainedRoot` 9058-9062, `refreshWholeShipLodFamily` 9099-9108) — every fire reads the wallet once, sees saturation, and defers the entire queue. Retained hull roots accumulate unboundedly (each carries geometry/materials awaiting `disposeDetachedObjectSteps`) and the drain re-arms a 0ms timer every fire. Reclaim latency is unbounded exactly while the frame budget is tightest: the queue exists to make demotion cheap, and instead it retains superseded LOD trees indefinitely under load.
- **Fix sketch:** hoist a persistent `retainedDisposeLedgerSkips` counter beside `retainedDisposeDrainScheduled`; skip while saturated AND `< 2`, reset to 0 whenever a drain leg actually runs — same shape as `drainDespawnDisposeQueue` / the arm ledger.
- **Effort:** S. **Magic-frame impact:** M. **Risk:** L.

### F4 — The arm mints a fresh `lightCensusSignature(scene)` — a whole-scene traverse — per arm fire; the epoch-keyed memo beside it goes unused

- **Evidence:** `src/render/renderer.js:25074` mints `lightCensusSignature(scene)` inside every `armCallbackAfterPresent` callback; the signature is a full `scene.traverse` over every node (`src/render/shadowDepthAdmission.js:374-397`). `_shadowCensusForFrame` (renderer.js:24941-24951) memoizes the identical call keyed `{seq, scene, epoch}` with `epoch = shadowCensusEpoch()` — the same validity key the session's staleness checks consume (shadowDepthAdmission.js:585-589, 635-638, 666-673, 678-683). The arm re-arms while pending holds (25363-25394), so N arm fires inside one presented-frame gap each pay the traverse.
- **Mechanism:** O(scene nodes) pointer-chase per arm fire — an un-suspendable leg inside the between-present task (debited via `notePacedFrameSpend` at 25383, but the walk itself cannot slice). The code comment's stated reason for the fresh mint (25071-25073: "the _viewSyncSeq memo can serve a sig minted before a light add/remove landed") is mistaken — the memo's `epoch` field exists precisely to defeat that case (`noteShadowCensusLightMutation` bumps it on any mid-seq light mutation, per shadowDepthAdmission.js:399-405). Caveat for the fix author: sig inputs *not* epoch-covered (fog kind, `layers.mask`) already share the same exposure in today's held-session reuse envelope, so memo reuse is no worse — it inherits, not widens, that hole.
- **Fix sketch:** serve the arm from `this._shadowCensusForFrame()`; identical freshness for every epoch-covered mutation, one traverse per census change instead of one per arm.
- **Effort:** S. **Magic-frame impact:** M. **Risk:** L-M (audit that no sig input mutates without an epoch bump — same envelope as the existing held-session checks).

### F5 — Per-arm collect is non-incremental: requeued roots re-walk the whole subtree every arm until marks land

- **Evidence:** `src/render/renderer.js:25093-25150` — each arm runs `collectUnstagedShadowCasters` per slice root under `SHADOW_DEPTH_PASS_NODE_CAP * depthNodeScale` and the 4ms `SHADOW_DEPTH_ARM_COLLECT_MS` deadline; roots requeued by mesh-cap leftovers (25178-25184 `deferredMark`; 25268-25278 `leftoverByRoot` → `pending.set`) collect again from scratch next arm. The parked-detach sweep (25034-25045) is O(|`_parkedDepthStageRoots`|) per arm fire and compounds with F1's leak.
- **Mechanism:** a fat cohort — N parked + M unmarked roots cycling the same arm — pays a fresh subtree walk per root per arm fire even though per-mesh marks are monotonic within a census epoch and the leftover audit already re-proves marks cheaply via `casterDepthMarkCurrent` (25272-25276). Each walk is bounded (node budget × scale, arm deadline), but total repeated-scan cost is O(arms × subtree), and a fat root sorted nearest-first re-spends the arm's whole collect window until the scale ladder parks it.
- **Fix sketch:** carry the collected unstaged set on the pending entry keyed by `{dirtySeq, shadowCensusEpoch()}`; on re-queue, revalidate marks per mesh (the leftover audit's own check) instead of re-traversing; fall back to a fresh collect on epoch/dirty mismatch.
- **Effort:** M. **Magic-frame impact:** M. **Risk:** M — the freshness key must cover mid-arm grafts; silent grafts are F2's class, so land F2 first.

### F6 — Drift release on an `allowCast:false` sync discards the park's earned backoff bookkeeping and still pays an exempt whole-subtree traverse

- **Evidence:** `src/render/renderer.js:24725-24729` — any `parkedRelease` deletes the record wholesale (including `sfDepthUndrawableCycles` and `recheck`) before `syncOpts` is known. `_shadowPolicyOptions` (24624-24668) derives `allowCast` from ortho distance, so a sync arriving while the root sits outside the ortho cell releases the park, clears the withheld set, then pays the cap-exempt withhold traverse — `traverseDeferred` requires `allowCast !== false` (24872-24875) so it cannot defer, and `skipTraverseOnDrift` requires `collectGate` (24871) which itself requires `allowCast === true` (24761-24764).
- **Mechanism:** an out-of-ortho drift sync (ortho-cell crossing while banded out, post-teleport re-entry ordering) throws away the parked root's escalation state and rewrites the whole subtree's cast flags in an uncapped exempt traverse; a later in-ortho dirty re-pays collect → offer → arm → the scale ladder from 1. Bounded by the existing collect-cap accounting; small.
- **Fix sketch:** when the release's follow-on verdict is non-promotable (`opts.allowCast === false`), keep the park — the withheld subtree is already cold — or at minimum carry `parkedEntry`'s `depthNodeScale`/`recheck`/`cycles` forward instead of deleting.
- **Effort:** S. **Magic-frame impact:** L-M. **Risk:** L.
