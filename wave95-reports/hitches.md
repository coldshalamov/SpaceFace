# wave95 audit — in-flight-hitches

HEAD audited: `332e07670` on `devin/1791064509-perf-w60` (wave-94 tip; carries W60–W94).

saturated: false

W94's five landings verify clean — the spent-wallet mint gate, the verdict traverse-cap join, the env-drain done-head check, the lightSig recheck piggyback, and the doom leg split all behave as designed (regression notes below). Three residuals remain on the presented-frame pacing seams: the mint gate it landed is the only paced lane without an aging floor — a fresh mint on a spent wallet does zero work per pass indefinitely under sustained churn (the headline question: no hard live-lock, but unbounded deferral); the atomic lane (withhold verdicts, scoped grafts, needsAtomicOut) is unmetered against the paced ledger and needsAtomicOut remains uncapped; and the lightSig recheck cadence leaves genuinely re-signed parks stale ~96-128 evals (~16s on escalated reparks) where an O(1) epoch compare gives every-eval latency for free.

## Findings (ranked)

### F1 — Spent-wallet mint gate has no aging floor: a fresh dirty root on a dead wallet defers forever under sustained churn — every sibling paced lane carries a ledger-skip escalator, this one doesn't

**Evidence.** `_syncShadowCasterPolicyChecked` mints the pass wallet `_policyPassDeadlineAt = now + SHADOW_POLICY_PASS_MS(4)` once per `_depthCollectPassSeq` roll (`src/render/renderer.js:24931-44`), then at :25072-77 `if (!hadParkedWalk && policyNow() >= policyDeadlineAt) { /* skip */ } else { driveShadowPolicySteps(...) }` — a fresh mint on a spent wallet runs **zero** slices: no iterator is minted, nothing is parked (the comment says "parks fresh mints unpaid" but no `_policyStepsParked` entry is written — the root simply stays dirty via the never-run `syncShadowCasterPolicy` dirty latch and re-enters next pass). Parked resumes keep the min-1 doctrine — `driveShadowPolicySteps` calls `slot.iter.next()` at :27037 **before** `deadlineFn()` at :27051 — so min-1 applies to resumes only, not to mints. No per-root skip counter, no age, no forced slice: compare `ENV_REBIND_LEDGER_MAX_SKIPS=2` (:26972-79 full-ledger forced drain), `DESPAWN_DISPOSE_LEDGER_MAX_SKIPS=2` (:1931-36), `SHADOW_DEPTH_LEDGER_MAX_SKIPS=2` (:6727-33) — all three siblings escalate after K skips; the mint gate never does.

**Mechanism.** Call order is deterministic entity-id order — `syncEntityViews` iterates `frame.query.visible` whose `candidateSlots.sort(compareEntityId)` (presentationQueries.js:325) fixes evaluation order every frame, and each call debits the shared wallet only when a stepped drive actually runs. Under bounded churn the lane self-drains: roots that finish stop spending, the 4ms window reaches further down the order each pass, so it's monotonic progress, not a live-lock — answering the headline: **a chronically-wallet-spent root is not live-locked, but has no liveness guarantee either**. The deferral is unbounded whenever invalidation churn ahead of it in id order never stops — sustained `invalidateShadowCasterPolicy` bursts (attach storms, LOD cascades, census re-signs; partsLibrary.js:3342/:4280/:9169/:9201/:9455, renderer.js:9256/:10700/:11283/:25691/:25731) keep re-dirtying early roots so the wallet dies before the tail is reached, every pass. Consequence is fail-open: the starved root's castShadow verdicts never apply — stale/missing depth casters persist with no cold link — exactly the presented-frame shadow quality the lane exists to fix late rather than never.

**Fix sketch.** Mirror the sibling ledger: per-root `_policyMintSkips` counter on the root's policy record (or on `_policyStepsParked`-adjacent bookkeeping); after `SHADOW_POLICY_MINT_MAX_SKIPS` consecutive spent-wallet skips, allow the mint + its min-1 slice — `driveShadowPolicySteps` already steps before checking, so a skipped-past-floor mint costs ≤256 visits like a resume. Cheaper variant: one "starvation slot" per pass — the first skipped mint per pass runs anyway; still bounded, preserves liveness under churn.

**Effort:** S. **Magic-frame impact:** M (per-frame cost bounded either way; the change is liveness of flag application — worst case today is indefinite shadow staleness during churn windows, not a hitch). **Risk:** L — worst case reverts toward pre-W94 behavior on a floor trip: one forced slice ≤256 visits, identical to a parked resume.

### F2 — Atomic lane is unmetered and needsAtomicOut uncapped: verdict/graft/swap traverses never hit the paced ledger and consume cap slots they can't be deferred by

**Evidence.** `notePacedFrameSpend` debits only the stepped lane — `notePacedFrameSpend(policyNow() - policyStartedAt)` at :25086 sits inside the `allowCast !== false && !needsAtomicOut` branch. The atomic else-branch (:25088-25114) — withhold verdicts (`syncOpts.allowCast===false`), scopedSync grafts, and `needsAtomicOut` (`!!(extra && extra.preCountRoot)`, :25051) — pays `syncShadowCasterPolicy(syncScope, ...)` with no timing debit: the spend is invisible to `pacedFrameSpend()`, so the env drain (:26997), despawn queue (:2027), resident-reattach (:2225-26) and reconcile (:2279+) slicers all see a ~zero wallet after an atomic burst and won't back off. Cap side: `traverseDeferred` excludes needsAtomicOut (:25052-56, deliberate — deferring a sync-out-param caller is "pure inversion" per the comment) while the counter increments on every non-deferred traverse **including** needsAtomicOut and verdicts (:25057-59). Sites: `onAuthoredAssetSwap` boundary-swap seam — walks the whole `boundary || root` subtree unscoped (:9256-77) — and `syncPackagedBodyShadowPolicy` — scoped `addedSubtree` (:11281). Withhold verdicts are now cap-joined (W94 fix verified), so they're ≤8/pass; needsAtomicOut is not.

**Mechanism.** A swap storm (boundary stand-in → authored resolves, packaged graft legs) stacks K×O(subtree≤~10k) atomic traverses in one presented pass, each unmetered, each consuming a cap slot so ordinary mints defer *and* the paced ledger underreports — the two budgets meant to bound the frame are both bypassed on the same call path. Per-frame swap frequency is already bounded by commit pacing (packaged legs yield between presents; boundary resolves are admission-gated), so the realistic rate is ~1-3/pass — but each walk is the fattest remaining presented-path subtree operation outside the census mint.

**Fix sketch.** (i) Meter the atomic leg — wrap :25103-12 in a `policyNow()` start/`notePacedFrameSpend` debit identical to :25086; trivially S, makes the ledger honest for all sibling lanes. (ii) Narrow the swap seam: per-mesh verdicts in `makeShadowPolicyWalker` are node-local (visible/noShadow/fallbackLayer/opaqueReceiver, shadowCasterPolicy.js:290-339 — nothing depends on sibling subtrees), so `onAuthoredAssetSwap` can pass `{preCountRoot: root, syncScope: root}` like the packaged site instead of re-walking the whole `boundary`; out-param semantics unchanged — the count covers the grafted subtree exactly.

**Effort:** S (i) / S–M (ii — needs the bookkeeping keyed by entity root, already the pattern at :11281). **Magic-frame impact:** M — metering alone prevents sibling slicers stacking on a false-zero wallet during verdict storms; scoping shrinks the single largest uncapped walk. **Risk:** L for (i); L–M for (ii) — a scoped swap that leaves an un-synced seat mesh would surface as stale cast flags, mitigated because verdicts are per-node local.

### F3 — lightSig release check on the recheck cadence leaves genuinely re-signed parks stale ~96-128 evals — and ~768-1024 evals (~13-17s) on escalated reparks — when an O(1) epoch compare gives every-eval latency

**Evidence.** The release chain at :24854-24906 evaluates `parkedEntry.lightSig != null && parkedEntry.lightSig !== this._shadowCensusForFrame()` (:24863-64) only inside the `parkedRecheck <= 0` tick — minted at :24834-46 as `96 + (_parkedRecheckStamp % 32)` and re-armed to the same flat range after each fire. But over-cover-max reparks mint `recheck: (96 + stamp % 32) * Math.min(8, 1 << (cycles-1))` (:25379-97) — a root parked on its 4th+ undrawable cycle waits ~768-1024 evals ≈ 13-17s at 60fps before its lightSig is ever compared, and an oqX-cell compare (:24866-72) runs every eval regardless — so the cheap check is per-eval while the expensive-then-cheap sig check rides the escalation the prompt flagged. `_shadowCensusForFrame` (:25167-78) memoizes per `{seq, scene, epoch}` — one whole-scene traverse per consult, correctly amortized.

**Mechanism.** A genuine light re-sign (noted mutation → `shadowCensusEpoch()` bump, shadowDepthAdmission.js:430-36) leaves every lightSig-carrying park withheld-stale until its next recheck tick — the consequence window the prompt asked enumerated: parked withheld casters keep `castShadow=false` (correct-side staleness — they were withheld because depth admitted them; releasing late means missing shadows persist ~1.6-2s typical, ~16s worst), and no caller needs faster release for correctness, only for shadow appearance latency. The fix is free: the recheck exists because the per-eval sig compare minted a ~16k-node traverse per frame pre-W94; the epoch counter makes the *prefilter* O(1) — `parkedEntry.lightSigEpoch !== shadowCensusEpoch()` costs a read, not a walk.

**Fix sketch.** Stamp `parkedEntry.lightSigEpoch = shadowCensusEpoch()` at park mint (:25379-97, :25507-23) and at keep-verdict re-key (:24889-99); every eval, compare epochs before — not instead of — the recheck chain: epoch-equal → skip (sig provably unchanged); epoch-bumped → run the memoized sig compare (one traverse per frame at most), re-stamp epoch + lightSig if equal. Preserves the pre-W94 release latency with zero per-eval traverse cost and shrinks the escalated window to ~1 eval. Unnoted mutations are equally uncovered either way — the epoch only tracks noted ones, same as today.

**Effort:** S. **Magic-frame impact:** L–M — bounded ~0.3-0.7ms per epoch bump (same as today) minus nothing on quiet frames; the win is release latency, not frame time. **Risk:** L — epoch bookkeeping only; the sig compare itself is unchanged.

### F4 — Parked-recheck ordering has no glass term: an on-glass withheld park waits the same recheck cadence as an off-glass one

**Evidence.** Recheck ticks fire on the root's own per-frame sync in `compareEntityId` order — no proximity or visibility term anywhere in the parked path (:24834-46 mint, :24854-56 tick). The depth arm sorts nearest-first by `shadowCastAxisDistance` (:25283-86) and slices `min(32, max(8, ceil(len/2)))` per arm (:25289) — glass proximity is a mint-time ordering the parked-recheck lane never consults.

**Mechanism.** Enumerated as the lod lane flagged: a parked root inside the live ortho/glass region and one at the far edge of the cast radius re-evaluate on identical cadence, so a glass-adjacent withheld caster whose release predicate (denied→allowCast drift or oqX cell change) fired mid-window sits withheld until its tick — same bounded staleness class as F3, lower frequency (needs both the park and the mid-window predicate flip). Fail-open, no correctness term.

**Fix sketch.** Cheap tiering only — halve `recheck` at mint for roots whose `axisDistance` sits inside the ortho extent (the arm already computes it), or tick every-eval for roots marked glass-adjacent at park time. Do not re-sort the Map — insertion order is the resume contract the cap exemption relies on.

**Effort:** S. **Magic-frame impact:** L. **Risk:** L.
