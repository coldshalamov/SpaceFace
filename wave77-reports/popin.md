## Verdict

Three contract-preserving improvements with concrete implementation paths remain. ## Ranked findings

### F1 — Partial-residency lazy-seed marks an archetype covered on ANY family-file hit

**Evidence:** `src/render/renderer.js:17364-17369` — the lazy-seed loop iterates `warmHullFilesForSpecs([spec])` (resolved primary `visual.file` PLUS every `lodFamily` sibling at `renderer.js:8164-8176`) and sets `_swarmWarmCoveredEnemyIds.set(enemyId, 1)` on the **first** `residentFiles.has(file)` hit, then `break`s.

**Mechanism:** residency is file-level, coverage is archetype-level. An archetype whose LOD family is only *partially* resident — a spawn demoted to lod1/lod2 that never drew lod0 (`installWholeShipLodFamilyController` demotes lazily), or an earlier deferred warm interrupted mid-decode by the settle deadline — seeds `covered=1`. Every later dwell's `fresh` filter (`renderer.js:17405-17407`, `covered <= reKickClaims`) then permanently skips it: its unresolved files decode at the live spawn's in-round admission — the pop-in the warm exists to pre-pay. The seed only runs when the covered Map is absent (`renderer.js:17344`, `!(this._swarmWarmCoveredEnemyIds instanceof Map)`), so the reachable trigger is exactly a mid-run restore off the cook path — the session where warm coverage matters most, since the launch warm already ran its window.

**Fix sketch:** seed covered only when the archetype's *resolved primary file* — `normalizeWarmHullFile(visual.file)`, the file its exemplar kick actually decodes — is resident, not any family sibling. (Requiring the full set via `every` is also defensible but over-strict if a sibling never resolves.) One predicate change inside the existing loop.

**Effort:** S. **Magic-frame impact:** M (restore-mid-run path only; per-archetype in-round decode at first spawn of that wave). **Risk:** trivial — the fresh filter and kick machinery are untouched; a wrong non-seed is a wasted exemplar warm, the safe direction.

### F2 — Phantom covered mark: `fresh` marks minted before spec resolution can never release

**Evidence:** `src/render/renderer.js:17411-17413` — every `fresh` enemyId gets `coveredMap.set(enemyId, +1)` *before* `swarmRosterShipExemplarSpecs('deferred-warm:ship:', { enemyIds: freshSet })` resolves specs (`partsLibrary.js:12993-13002`), which filters `swarmRosterEnemyDefs()` — i.e. ids in `SWARM_ROSTER` or `SWARM_BOSS_ROTATION` packages only (`partsLibrary.js:13026-13042`).

**Mechanism:** `eligible` unions plan-declared rows (`plan.swarm.roster`, `plan.schedule`, `plan.packages`, `plan.swarm.newcomer`, and the W76-added `capitalBossWingRosterRows(plan.swarm.bossScoreId)` at `renderer.js:17393-17395`) — a domain bounded by `SWARM_ENEMY_IDS` = **all** of `ENEMY_TYPES` (`swarmMode.js:622`), not by `swarmRosterEnemyDefs`. A declared id outside the roster/boss-package union — a non-roster wing member, a mutator or schedule row naming a non-roster enemy — mints its covered mark, resolves **no** spec, gets no kick, no settle, and therefore no release: `unmarkEnemy`/`unmark` only walk ids that made it into `pendingAttachmentEnemyIds` or `fresh`-marked throws. The mark lives until `run:ended` — coverage claimed, warm never delivered, *and* every later dwell's `fresh` filter blocks retry (covered=1 > claims=0). The first live spawn pays the in-round compose while the ledger says covered — strictly worse than a skipped row, since the lie is permanent for the run.

**Trigger status today:** latent, but by luck of content not by construction — all current wing members (`wasp_swarmer`, `warden_escort`, `choir_zealot`) are roster ids (`swarmMode.js:296-320`), and `pickSwarmArchetype` canonicalizes every roster entry through `SWARM_ROSTER.find` (`swarmMode.js:915-920`), so no current producer feeds one. The wing-row path (`capitalBossWingRosterRows`, `saveEnvelopeSectorWarm.js:82-99`) and `plan.swarm.newcomer` carry raw strings — no canonicalization gate stands between them and `eligible`.

**Fix sketch:** compute `shipSpecs` (and the hulk/ship spec lists) first; mint covered marks only for ids that resolved a spec — i.e. mark per `spec.data.lootTableId` after the filter, not per `fresh` entry before it. (Or intersect `fresh` with `swarmRosterEnemyDefs` ids and drop the unresolvable tail with a warn so a bad declaration surfaces instead of silently claiming.)

**Effort:** S. **Magic-frame impact:** M latent (in-round compose pop-in + coverage lie that suppresses all retry). **Risk:** trivial — mark-before-build ordering only needs the spec list computed first; a resolving id's mark timing is unchanged.

### F3 — `casterDepthMarkCurrent` geometry-identity check has no signature-collect twin; mark can never refresh on a sig-hit

**Evidence:** `src/render/shadowDepthAdmission.js:264` — `mark.g !== geometry` fails the mark on an in-place `mesh.geometry` swap. But `casterDepthSignatures` (`shadowDepthAdmission.js:407-432`) keys on `{material uuid, kind, morph-census, variant, layerMask, lightSig}` — **no geometry term** — because the depth program key genuinely doesn't bake geometry identity. Marks are only written inside `markCastersDepthStaged` (`shadowDepthAdmission.js:471`), which runs only for casters *offered* to a stage leg.

**Mechanism:** in-place-swap a geometry on a marked caster (keeping material, morph census, kind): flag collect reports it unstaged → withholds `castShadow` → queues the root → the arm's signature collect finds every signature already staged (`found.length === 0`) → `leftoverByRoot` has no entry → the restore path un-withholds and stamps the dirty seq (`renderer.js:22355-22400`). Net effect per occurrence: one arm cycle + a per-mesh `castShadow` withhold for the flag-collect→arm window (~1 presented frame + idle-callback latency, ≤48 ms bound). The stale `mark.g` is **never** re-written — the mesh was never re-offered — so the same mesh re-fires the same withhold→arm→restore cycle on *every* future `dirtySeq` bump on its root, forever. Real swap sites: `src/ui/asteroid/asteroidRenderer3d.js:5946` (`crateMesh.geometry = crateGeos[stage]` on a `castShadow = true` mesh, `:5941`) and the authored-inclusion LOD flips at `:1607/:1623/:1640` (`cm.geometry`/`m.geometry`/`b.mesh.geometry` on castShadow meshes, `castShadow=true` at `:4486`/`:4040`).

**Fix sketch:** the depth program key never includes geometry — so the mark check is a false positive, not a missed stage. Drop `mark.g !== geometry` (the morph terms `ma`/`mn` already cover program-relevant geometry change), or alternatively re-write marks on the restore path when a withheld root's signature collect returns fully-staged. The conservative direction is preserved either way: a *morph* change still re-stages.

**Effort:** S. **Magic-frame impact:** L-M (brief per-mesh shadow-silhouette dropout per dirty bump + wasted arm cycles on asteroid-scene LOD churn). **Risk:** low — removing a check that can never find work; a true geometry-driven variant change still re-keys via `ma`/`mn`.
