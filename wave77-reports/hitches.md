## Findings (ranked)

### 1. `compileSubjectsAcrossPresents` — the present-sliced flight compile lane — consults only its private `budgetMs` clock: no `pacedFrameSpend()` consult, no `notePacedFrameSpend` debit, so its compile issues + serial-route drains keep running on frames whose paced wallet is already spent, and siblings never see the spend

Evidence: `src/render/compilePresentSlice.js:40-65` — the loop yields only when `spent >= budgetMs` (private clock, `COMPILE_PRESENT_SLICE_MS = 4` at `:38`); no ledger consult or debit anywhere in the file. Driver: `src/render/renderer.js:9844-9882` — every non-urgent flight admission (`shouldSliceFlightAdmission` gates `mode === 'flight' && firstPlayable`) flows through it with `admissionPaceYield` (= `yieldToNextPresent({boundMs:24})`, `:9767`). Per-item work inside the private window: `compileSubjectColorAndDepth` → `_compilePostRoute` (sync compile issue, `:9742-9749`, `:9872`) plus `paceQueue()` — the linkBatch's serial-route forced GL drain — at `:9877-9879`. Contrast: every other flight slicer consults the ledger mid-walk — despawn entry `renderer.js:1817-1821`, reconcile `2133`, poll `2180`, hold-exempt `2557/2604/2623/2640/2654`, deferred-enter `sectorEnterDefer.js:154-155`, emit/tail drains `eventBus.js:349/416`, park sweep `17955`, compose driver `partsLibrary.js:10317`, gltfCompile `decodeTaskBudget.js:332`, depth arm `22103`, mesh-build drain via `usePacedLedger` `19316`, `gpuResidencyAdmissions` `9952`.

Mechanism: the yield IS present-bound, so stacking is bounded to ~one 4 ms window + one item per armed task — but (i) a frame that already spent its 4 ms paced wallet still gets this lane's whole private wallet (no consult), and (ii) nothing debits its spend, so the reconcile/poll/emit/hold drains reading the ledger later in the same frame see nothing and stack their own min-1 slices on top. On serial routes (no `KHR_parallel_shader_compile`) `paceQueue()` is a synchronous forced drain per item — the un-logged spend is real GL work, not bookkeeping. This is exactly the W76 contract hole (consult + debit), in the one lane W76's `createSlicedYield` plumbing can't reach because it predates that utility.

Fix sketch: give `compileSubjectsAcrossPresents` the same two-sided contract inline (or via `options.shouldYield`/`options.debit` to mirror `createSlicedYield`): after each `compileOne`, `notePacedFrameSpend(now() - sliceStarted)` before the yield and at loop end; yield when `spent >= budgetMs || pacedFrameSpend() >= PACED_FRAME_BUDGET_MS`. Keep the check post-item so min-1 is preserved verbatim. Effort: **S**. Magic-frame impact: **M** — every in-flight ship/station/upgrade admission rides this lane; the un-logged ~4 ms windows land precisely during the combat/contacts churn the magic-frame bar names. Risk: **L** — pacing-only; per-present cadence and ordering unchanged.

The flight-admission path still pays the ceremony whole: on a busy sector each call is several ms to tens of ms of synchronous census + double render landing in one armed task adjacent to the next present — and it pays it twice per admission (the finish call re-walks and re-renders the batch's casters to catch mounts added mid-compile; `casting.length === 0` early-outs only when the batch has zero casters, so the second pass re-pays census + reparent + renders even when nothing new links). Fix sketch: route the flight-admission depth stage through the same machinery as the arm — `createShadowDepthStagingSession` keyed on `lightCensusSignature` + the withhold contract (`_withheldDepthCasters` / `_pendingDepthStageRoots`): at admission start, withhold the batch's unstaged casters and enqueue `{lodLevel, entity}` on the pending arm (the arm's `collectUnstagedShadowCasters` per-root collect + `session.slice(leg)` + restore already does the deadline-bounded work); the finish pass folds into the same drain — genuinely-new mounts re-collect. Preserves the "no presented frame outruns the link" contract via withholding instead of inline staging. Effort: **M**. Magic-frame impact: **M** — every in-flight admission with casters pays it, potentially twice. Risk: **M–H** — the start-of-admission staging exists specifically so mounted meshes can't draw an unlinked depth variant; the chunked replacement must withhold first and must not regress the mid-compile-mount coverage the finish pass exists for (verify an async primitive instantiated mid-sliced-compile still joins the pending arm before its first presented refresh).
