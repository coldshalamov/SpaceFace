## Ranked findings

### 1. Yield-rejection skips fallback disposal at authored-swap seams — partsLibrary.js:4274-4277, 9330-9336
**mechanism.** In `commitAuthoredPlaceBoundary` (and the identical ship-commit seam at ~:9330): the authored subtree is already published/grafted, then `await waitForAuthoredAdmission(options.yieldToNextPresent(), options)` runs UNPROTECTED. `waitForAuthoredAdmission` (partsLibrary.js:8452) is `options.asyncAdmission.wait(work)` — it can reject. On rejection the exception propagates before `try { disposeDetachedPlaceFallback(fallbackRoot); }` / `disposeDetachedObject(fallbackRoot)` ever runs — the detached fallback subtree's geometries/materials/GPU residency leak, and the propagation reaches `enqueueBoundaryUpgrade`'s catch which stamps `authoredAssetState='fallback-after-error'` over an already-mounted authored root (mis-attribution that can drive spurious retry/fallback churn). Contrast: the plan loop at :9635 DOES `try { await ... } catch { assert... }`.
**fix sketch.** Wrap the yield await in try/finally (or try/catch) so the `try { disposeDetached... } catch {}` block always runs; optionally route the rejection through the same `admissionOwnerInactive` classification as the prepared-tree failure paths.
**effort S · impact M** (leak per mid-flight auth error; bounded per occurrence but repeats under rejection storms) · **risk L** — dispose is already internally catch-wrapped; no ordering contract depends on the throw propagating past the dispose.

### 2. Whole-subtree shadow-policy traverses inside presented-frame mount seams — renderer.js:21626/:21808 mounts, packaged tail renderer.js:11032-11058 → visualFactory.js:4419-4423 / visualOverrides.js:1241
