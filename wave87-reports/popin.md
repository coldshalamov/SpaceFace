## Findings (ranked)

### 1. Post-publish yield-throw leaks the detached fallback and mis-stamps a committed boundary — W86/W85 self-defect

- `src/render/partsLibrary.js:4274-4278` (`commitAuthoredPlaceBoundary`, W86) and `:9329-9334` (`commitAuthoredBoundary`, W85): the `waitForAuthoredAdmission(options.yieldToNextPresent(), options)` sits between the atomic graft+publish and `disposeDetachedPlaceFallback`/`disposeDetachedObject`, outside the `try` that guards only the dispose call itself.
- Mechanism: `asyncAdmission.wait` (`src/render/asyncAdmission.js:86-112`) rejects AbortError on stall-watchdog abort, owner-inactive abort, or the 120 s admission deadline. A throw in that one-yield window propagates through `completeAdmission`/`run()` to the job-level catch (`partsLibrary.js:7433+`). On the cancelled path the catch unconditionally runs `releaseBoundaryResidency('queued-upgrade-failed')` (:7459) and `markAuthoredBoundaryForReadmission` (:7465 → :2744-2762) — `upgradeTokensByBoundary` is set at enqueue (:5705) and never cleared at commit, so `isAdmissionBoundaryCurrent()` (:7342, token-identity) still passes. Consequences on an already-committed boundary: (i) `disposeDetachedPlaceFallback`/`disposeDetachedObject` never runs → the detached fallback subtree's non-shared geometries/materials leak; (ii) `authoredAssetState` is stamped `'awaiting-authored-admission'` over `'authored'` → a later `requestAuthoredUpgrade` path re-admits → a full decode+compose re-runs in presented-frame windows (the exact hitch class the admission pacer exists to amortize); (iii) under `deferBoundaryPublication` the mark deletes `__publishPreparedAuthoredBoundary`, so a boundary left at `'authored-prepared'` wedges — the ready verdict can never land, and the grafted authored root sits mounted-but-unpublished forever.
- Player-visible: rare trigger (abort must land inside one yield), but the failure mode is a duplicate admission storm or a permanently torn boundary verdict — both inside the magic-frame window.
- Fix sketch: move the dispose into a `finally` covering the post-publish yield (dispose is unconditional — the graft already detached the fallback), and gate the job-level catch's verdict writes on committed state (skip `markAuthoredBoundaryForReadmission`/residency release when `boundary.userData.authoredAssetState === 'authored'` or when a prepared publisher is already installed). A simpler variant: run the yield *before* publish rather than between publish and dispose, so the only unguarded span precedes observable state.
- Effort **S**. Magic-frame impact **H** (when it fires). Risk: low-M — must not double-dispose on the normal path; the finally form is sufficient.

### 2. partsLibrary commit continuations never debit the paced ledger

- `partsLibrary.js`: the only `notePacedFrameSpend` calls in the file are the policy walks (:8389), slice machinery (:10412, :10452), and one residual (:6466). All commit paths run ledger-blind.
- `commitAuthoredPlaceBoundary` (:4215-4280): the freeze leg yields per internal step via `waitForAuthoredAdmission(yieldToNextPresent(), ...)` (:4226-4231) but never debits elapsed leg time; the mount tail (:4236-4265: graft + ~10 userData writes + `publish()` → `touchAuthoredExactTarget(authored.root)` O(authored subtree) + `onSwap` + ready verdict) is one contiguous unmeasured span; `disposeDetachedPlaceFallback` (:4277) O(fallback subtree) unmeasured.
- `commitAuthoredBoundary` (ship, :9279-9336): same shape — graft + ~14 userData writes + `publish()` → `touchAuthoredExactTarget` on the largest subtree class in the game (hull + modular kit + LODs) + `packagePoolAdmissions` activation loop — all contiguous, all undebited; `disposeDetachedObject(fallbackRoot)` likewise.
- `commitAuthoredCargoCapsuleBoundary` (:3326-3380): the entire function is one atomic span — graft + `releaseDetachedCargoCapsuleSubstrate` (`root.clear()`, shared resources — cheap) + `publish()` → touch O(authored cargo subtree). Smallest authored subtree class.
- `src/render/visualOverrides.js` packaged-prop commit (~:1090-1255): mid-legs DO debit (:1146, :1157, :1169) but `instantiatePackagedPrimitives` (:1116 → :865 — O(#lod0 primitives): `new THREE.Mesh` + `applyMatrix4` per row) and the atomic mount tail (:1224-1250: `detachBoundaryResolvingMarker` + `hideProceduralPropDrawables(root)` O(fallback) + graft + `carryAdmittedOnceStamp` + `touch(packaged)` O(authored) + `packagedShadowSync` O(authored traverse) + `settleIndustrialSurfacing`) run undebited.
- Mechanism: `pacedFrameSpend()` under-reports the inter-present window, so the mesh-build drain, despawn-dispose drain, and opening-census machinery all schedule on top of a commit span inside the same presented gap → stacked spans = hitch. Ranked by subtree: ship tail > place tail > packaged-prop tail > cargo commit > `instantiatePackagedPrimitives`.
- Fix sketch: debit `notePacedFrameSpend(legNow() - legStarted)` after each uninterruptible span — the debit is retroactive measurement and does not require splitting the atomic tail; wrap `instantiatePackagedPrimitives` in the `driveLeg` pattern or give it a steps twin.
- Effort **S-M**. Magic-frame impact **H** in dense admission windows (this is precisely the work class the ledger exists to meter; W84 already established the convention — "resume legs debit notePacedFrameSpend"). Risk: low.

### 3. Reattach feed-stamp misses three feed classes — a missed sweep converts reattach into release+rebuild

- `src/render/renderer.js:2040-2048`: composite stamp = `_meshesVersion`, `entities.size`, `entityList.length`, `dressing.byId.size`, `farActors.byId.size`, `sessionEntityIdRemap.size`, `world.enterSerial`.
- Missing feeds: (i) the asteroid-field rock table — `resolveWorldPresentationEntity` (`src/world/presentationSources.js:84-99`) consults `getAsteroidFieldRock`; no field feed is stamped; (ii) same-size membership churn — the chunked collect's own comment (:130-137) documents the swap-pop-plus-spawn class that leaves `entityList.length` unchanged while membership moves; the same hole applies to every size-tracked table; (iii) every positional/verdict input to `stableIndex` — `collectMeshPresentationEntities` = journal collect + `appendNearbyLedgerRows`, which reads player pos/vel, `simTime`, camera fov/tilt/aspect, prefetch zoom, and the far/rock memo keys (`farVersionNow`/`fieldVersionNow`) — a row that enters the collect horizon between sweeps is invisible to the stamp.
- Backstop truth: the 240-frame catch-all (:2052-2053) does re-sweep eventually (~4 s at 60 fps, ~24 s at 10 fps under load). But `_meshReconcileDirty` → `reconcileMeshes({keepResidentSet:true})` (:2062) runs in the same service call and releases meshes whose id no longer resolves — so a missed reattach is converted into release + full mesh rebuild, i.e. the pop-in the keep-gpu path exists to eliminate.
- Fix sketch: stamp membership serials, not sizes — `dressing.version`-style counters already exist elsewhere (:22790 pattern); add a mutation serial to `entityList`/`entities`/far/remap tables and include `field.version`. Cheaper still: run the sweep unconditionally under keep-gpu but only when `pacedFrameSpend()` has headroom.
- Effort **M**. Magic-frame impact **M** (restore window only; bounded by the catch-all). Risk: low-M — membership serials must be maintained at every mutation site.

### 4. `fallbackFromState` re-collects + re-packs the whole presentation set on every tick-consuming present during a rebuild window

- `src/render/presentationPublisher.js:102` → `aliveEntities` (:13) → `collectJournalPresentationEntities(state)` — the SYNC whole-set collect (entityList + dressing.rows + ledger rows) — then `world.rebuildFromEntities` O(presentation world). Runs inside `registry.renderUpdate` — inside the presented frame itself.
- Mechanism: the reuse gate (:100-101) skips the drain only on zero-completed-tick presents at the same lifecycleGeneration. Under sustained write pressure — exactly the condition that keeps stepped rebuilds invalidating across multiple presents — every present pays a full collect + re-pack. W86's change halves the suppression-frame cost but leaves the tick-presented path at full price; the stepped rebuild's own completed collect set (already produced at `presentationRunner.js:783/802` via the chunked twin) is discarded instead of consumed.
- Fix sketch: hand the publisher the stepped job's *completed* collect array via `presentationFrame` (or a shared slot) when it exists — identical live-GameState sample, collected once. A partial collect is NOT consumable (a partial world = dropped entities = pop-in), so the sync collect remains the irreducible remainder whenever the rebuild's collect is still mid-flight; the win is the common case where the collect leg already finished this present.
- Effort **M**. Magic-frame impact **M-H** on dense sectors under write churn. Risk: M — plumbing crosses the runner/publisher boundary; only a completed collect may be shared.

### 5. Deferred-diagnostics latch: persisted counts + unset validation mis-attributes firstVisibleAdmissionDelta across a keep-gpu recook

- `src/render/renderer.js`: deferred path writes `openingFirstVisibleGpuCounts` at :24198 even when `pendingValidation === undefined` (:24153-24190 — mode!=='flight' during the deferred compute, e.g. a keep-gpu recook landing mid-deferral, or no receipt yet). The `finally` (:24241-24242) clears `_openingFirstDrawDiagnosticsDeferred`; validation stays unset.
- The in-place block (:24007-24045) then fires on a later flight frame — `!openingSubmissionValidation` true, latch clear, receipt kept by the recook (:17057 design comment) — and validates against the persisted census/counts minted *before* the restore. `firstVisibleAdmissionDelta` (:24017-24020) reads that stale window: (i) reattach-era mesh admissions attribute as unexplained first-visible admissions → a false `first-visible-*-delta` failure stamps the kept slot, and because `openingSubmissionValidation` is now set the gate closes forever — the new sector's real verdict never runs (exactly the slot-occupation the :24117 bail comment exists to prevent — the bail can't fire because keep-gpu preserves plan identity); (ii) a late retry pairs the stale delta with the stale `lateAdmissions` name-list → admissions landing between the stale window and the retry escape `firstVisibleAdmissionDelta` → false negative.
- A thrown exception inside the validation compute (:24157-24189) reaches the same end state via the `finally` — or, before :24198, leaves counts unset too, which the :24195 comment says is retried by re-arm; re-arm is reachable because `openingSubmissionFirstDrawSubmittedAt` is only stamped on `validation.ok` (:24086-24089, :24235-24238), but the retry re-mints the census baseline a frame later → the true first draw's admissions absorb into baseline → under-attribution either way.
- Fix sketch: carry `armedPlan` (and lifecycleGeneration) on the persisted counts object and gate the in-place path on both matching the live plan; alternatively stamp a `validationState: 'deferred-skipped'` verdict beside the counts whenever `pendingValidation` is undefined so the slot isn't left half-armed.
- Effort **S-M**. Magic-frame impact **L-M** — diagnostics-only (the verdict is informational, non-blocking, :24050-24053), but a stale verdict permanently suppresses the real one and the delta window drifts, so soak tooling can mask a true first-draw admission regression. Risk: low.

### 6. Mid-write invalidation is bounded — 3 paced strikes then one unbounded sync collect+publish inside a presented frame

- `src/core/presentationRunner.js:725-830`: `journalRebuildInvalidations` counts collect-phase dooms (:792-798) and `'invalidated'` publish results (:827-830); at ≥3, `syncJournalRebuildEscalation` (:743-754) runs the SYNC `collectJournalPresentationEntities` + `rebuildFrom` atomically inside `presentLastCompletedSnapshot` — no suspended window, so no interleaved write can invalidate it → always commits unless malformed source.
- Bound verified: no infinite same-frame loop exists. Residuals: (i) under sustained writes the escalation fires deterministically once per rebuild episode — the whole-set span the stepped machinery exists to avoid lands inside one presented frame; (ii) `journalRebuildInvalidations` resets only at `commitJournalRebuild` (:739) — after a failed sync escalation the counter stays ≥3, so subsequent episodes escalate on the first strike (fewer paced retries, more sync bricks — still bounded, but degraded under continuous pressure); (iii) the replay-capacity invalidation (`presentationJournal.js:615-617`: `count + stale*2 > size`) can also trip the sync twin — but a sync attempt has no suspended window, so `rebuildStalePublishedIds` holds only the last stepped window's suppressions; a second sync attempt sees an empty stale set → converges in ≤2 sync attempts.
- Fix sketch: none strictly required for correctness; to shave the brick, reserve replay headroom at the capacity check (reject `aliveCount*3 > size` up front instead of discovering it at the tail) or pace the retry cadence so the sync drain lands on an already-spent frame rather than a fresh one. Reset `journalRebuildInvalidations` on a *successful* sync escalation too (it already resets at commit — verify the escalation path hits `commitJournalRebuild`, it does at :753).
- Effort **M** (if pursued). Magic-frame impact **M** (rare, unbounded span; deterministic under write storms). Risk: M — the sync path's atomicity is its safety property; do not reintroduce suspension.

## Lane item (b) — dropped-write classes during suspended rebuild: all re-derivable

Every write suppressed while `rebuildRequired`/`rebuildInProgress` holds re-derives at retry collect — proof by class:

- **TRANSFORM/VISUAL, entity outside `rebuildSourceIds` or id 0** (`presentationJournal.js:407-417`): sets `rebuildInvalidatedDuringSteps` → attempt bails at the slice boundary (:604-608) → retry re-collects → the fresh spawn's `fillPose` carries live pose **and** `visualRevision` (:81-101). If the entity died meanwhile, absence from the new published set is destroy semantics under a full-swap rebuild.
- **TRANSFORM/VISUAL, entity in `rebuildPublishedIds`** (:413-414): `rebuildStalePublishedIds` → commit tail re-emits TRANSFORM+VISUAL with bumped revisions reading live state (:619-633). Capacity bail (:615) routes to invalidated → retry re-collects.
- **TRANSFORM/VISUAL, entity in `rebuildSourceIds` but not yet published**: silently dropped — but its spawn lands in a later slice of the same attempt and `fillPose` reads the entity *at that later time*, so the suppressed write's effect is captured inline. Visual state included via `presentationVisualRevision`.
- **SPAWN** (:339-345): out-of-sourceIds or id 0 → invalidates → retry collect picks the entity up (it's in `entityList`); in-sourceIds → dropped, and the rebuild publishes it anyway.
- **DESTROY** (:376-402 → :267-276): always invalidates + tracked in `suppressedDestroyIds` → retry collect excludes dead rows (`alive === false` filters at :561/:597) → absence = destroy. If the id still collects (lane-transition tombstone), the doom gate escalates to the atomic sync publish — collect is the liveness authority.
- **Collect-phase suppressions** (before `publishIter` mints): same classes — the collect snapshot is regenerated per attempt, and the doom gate (:781-799) covers the only corrupting class.

The residual hazard is not a lost write but the capacity-geometry invalidation loop — Finding 6.
