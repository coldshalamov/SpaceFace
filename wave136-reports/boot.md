## Findings (ranked)

### F1 — `loadAsync` latches `specHit` before a multi-frame window, then consumes a possibly-stale verdict
- **Evidence: MECHANISM_VERIFIED**
- `src/save/saveSystem.js:4841-4876` — `installSaveStoreWriteTracking()` + `specHit` are evaluated once on the click task (`spec.sig === 'gen:' + _saveStoreGeneration`, :4841-4843), then `primary` is consumed at `:4897` (`await primaryPromise`) after `_captureRollbackSnapshotAsync()` (`:4884`, a sliced multi-yield capture) plus the worker roundtrip. Any store write landing in that window bumps `_saveStoreGeneration`; the armed verdict — parsed from generation-N bytes — still reaches `_restorePreparedEnvelopeAsync` (`:4905`). `acceptSeq` (`:4868`) guards restore-vs-restore ordering, not store generations, and `spec.prepared` carries no generation stamp of its own.
- **Mechanism the player sees**: a same-slot write mid-window (autosave arriving between click and consume) makes the load restore generation-N bytes while generation-N+1 sits on disk — the click restores an older save than the slot currently holds. Bounded: the newer bytes are not overwritten (restore never writes the slot), the slot card showed generation-N at click, and the next load picks up the newer save. The contract "a stale verdict must never reach _restorePreparedEnvelope" is technically violated by one interleaving.
- **Fix sketch**: re-check `'gen:' + _saveStoreGeneration === spec.sig` in the `await primaryPromise` continuation before `primary.ok` is trusted; on mismatch discard `specPromise`'s verdict and fall through to `this._prepareEnvelopeStringAsync` on fresh bytes (the fallback path already exists — reuse it). Same one-line guard would cover the `save:envelopePrepared` emit at `:4903`, which otherwise warms decodes for the stale envelope's sector set.
- **Effort: S. Magic-frame impact: L (rare window, benign semantics). Risk: low** — the mismatch path is already the miss path; the guard only re-routes it.

### F2 — `fillSlotDataLazy` pays a synchronous multi-MB `JSON.parse` on a timer task while a worker lane exists
- **Evidence: MECHANISM_VERIFIED**
- `src/ui/screens/saveLoad.js:841-853` — the lazy fill runs `readSlotBlob(slot)` (`localStorage.getItem`, :847) + `JSON.parse` + `unwrapSaveData` (:850) synchronously inside the deferred-fill timer task or the `.then` microtask. This is the W132-measured 15–32 ms/parse class, still on main thread. It fires whenever the covering-spec path cannot serve: no armed spec for the slot, spec verdict non-ok, disarm/consume mid-flight, or `Worker` unavailable. Menu dwell presents frames between tasks — the parse lands inside one task and drops 1–2 menu frames on the settle of every such pick.
- **Mechanism the player sees**: pick a row whose slot isn't covered by a live spec (after a supersede, a consume, a re-open, or a non-ok verdict) → one menu-frame hitch as the card fills. The common path (armed spec → worker parse → `save:envelopeSpecPrepared` fill, :1046-1057) is already off-thread; this is the residual.
- **Fix sketch**: post the raw to the save worker instead of parsing on main — either reuse `_prepareEnvelopeStringAsync(raw)` and take `.data` (heavier: runs migrations/normalize — the portrait would then show migrated values, a behavior change for ancient saves) or add a verdict-lite worker op returning exactly the fields `buildSavePortrait` reads (player/story/aceMemory/meta projection). Keep the sync parse only under `typeof Worker !== 'function'`.
- **Effort: M (new worker op or the full-prepare reuse, plus the signature/slot binding the emit path already proves). Magic-frame impact: M (menu jank per uncovered settle — same class W132-F1 landed). Risk: M** — the full-prepare route changes what the card shows for unmigrated saves; the projection op avoids that but is a new worker surface.

### F3 — Re-opened screen does not re-arm speculation for the restored selection
- **Evidence: MECHANISM_VERIFIED**
- `src/ui/screens/saveLoad.js:1111-1115` — on (re)mount `refs.selected` is set directly (currentSlot or `latestOccupiedSlot`); `_select` is not invoked, so no `save:loadSpeculationTarget` emits for the restored row until the first focus/pick event (`:1187-1189`, `:1236-1247`). In practice the index-publish arm (`_maybeSpeculateContinuePrepare`, saveSystem.js:2501-2513, keyed on `selectLatestOccupiedSlot`) already covers the default selection — residual exposure is only a restored `currentSlot` that differs from latest-occupied, which arms on first interaction instead of mount.
- **Mechanism**: after disarm+reopen under the same generation, a non-default restored selection gets no worker warm until the player touches the strip — the click then pays the prepare the dwell could have overlapped. Narrow.
- **Fix sketch**: after `refs.selected` is restored, emit `save:loadSpeculationTarget` once on mount when it differs from the covering arm's slot (or call `_select(ctx, refs.selected, {quiet:true})` instead of assigning). Cheap; the emit path is already idempotent (`speculateLoadPrepare` early-outs on same-slot+same-sig, :2624).
- **Effort: S. Magic-frame impact: L. Risk: low.**

### F4 — Same-slot write burst re-dispatches the arm per write
- **Evidence: UNVERIFIED**
- `src/save/saveSystem.js:387-392` — the `bumpKey === LS_PREFIX + spec.slot` branch re-arms `{immediate: true}` on every same-key write: each mints a fresh spec and dispatches immediately. Two writes to the armed slot in one task (e.g. an import+save or autosave+promote coincidence) = two structured clones + two worker parses, the first superseded before resolve. Foreign-key writes are coalesced correctly (deferred `setTimeout(0)` re-arm + `speculateLoadPrepare`'s same-slot/sig early-out, :2624) — only this branch has no burst collapse.
- **Mechanism**: wasted clone+parse per extra same-slot write; no correctness issue. Whether a real same-slot burst exists is unproven (autosaves are periodic; imports are one-shot).
- **Fix sketch**: route the same-slot re-arm through the same deferred coalescing (carry `bumpValue` as the thunk result so the settle still uses the writer's bytes instead of a re-read).
- **Effort: S. Magic-frame impact: L. Risk: low.**

## Hunt-area verdicts (the brief's five questions)

- **(a) `spec.prepared` across generation bumps**: every reader is gated — `load()` consumes `spec.prepared` only under `specHit` (slot + live sig) in the same synchronous task (:4742-4757); `loadAsync` consumes the promise under `specHit` or `specByteHit` (byte-equality, :4862-4876); the emit re-checks identity + live sig + mode at resolve (:2570-2577); `coveringSpeculativePrepare` re-proves slot + live sig per call (:2644-2647). **Residual = F1** (the deferred-consume window).
- **(b) emit sig-gate vs fallback re-check agreement**: gates are {identity, ok, live-sig, mode} vs {identity, slot, live-sig} — the divergence is the mode term. Neither-fires requires a spec surviving a mode exit without consume or disarm; verified unreachable — `pause._resume` flips mode then pops in one task (onHide disarms, pause.js:1120-1123 + saveLoad.js:1690), `load`/`loadAsync` null the spec before `mode='loading'`, and every screen transition disarms at onHide/dispose (:1690, :1724). Both-fire impossible (the consult is a strict subset of the emit's gates; `entry.data` writes are idempotent, :1054). Latent asymmetry only — hardening observation, not a material finding.
- **(c) disarm + reopen**: onHide (:1690) and dispose (:1724) both disarm; `_slotDataMemo` is module-scoped (:772) and survives; a mid-flight `.then` falls to `fillSlotDataLazy` which re-resolves the live entry (:845) and fills the memo even with `refs` torn down; remount memo-hit serves the card under the same generation. Residual = F3 (restored non-default selection un-armed until first interaction).
- **(d) synchronous legs on painted tasks**: pick task pays only memo mint + card-meta stage render + `buildSavePortrait` DOM; `listSlotsIndexCards` is O(store-keys) key enumeration per render (:2343-2379); `saveImportByteLength` is band-gated (:7506-7524); import flow gates on `File.size` before reader allocation (:1603-1608) and parses once post-confirm. Residual = F2 (lazy fill's main-thread parse) and the noted Continue-arm clone (~memcpy-scale, bounded).
- **(e) gen-bump burst coalescing**: foreign-key bumps each schedule a `setTimeout(0)` but every one after the first early-outs inside `speculateLoadPrepare` before building the raw thunk (:2624) — one re-arm per storm; memo entries mint per consult, not per bump. Residual = F4 (same-slot branch has no collapse — unverified real-world burst).
