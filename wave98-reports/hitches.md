### F1 — `envBindYield` ReferenceError aborts every real-sector cook (W97 regression, self-defeating)

- **Evidence:** `src/render/renderer.js:13873-13880`, inside `state.render.cookLiveSceneGpu` (:13756). The `envBindYield` const is declared **block-scoped** at :13850 inside `if (scene.environment) { ... }`, whose block closes at :13872. The W97 drive site at :13873-13877 then calls `await envBindYield(false)` **outside** that block. The only other declaration of `envBindYield` in the file is at :12169 — inside `prepareLiveSectorBeforeFlight` (:11948), a different function. `grep -n "envBindYield" src/render/renderer.js` → 6 hits: decls at :12169/:13850, uses at :12175, :13858, :13863, :13869 (all in-scope), :13876 (out of scope).
- **Mechanism:** `syncVisiblePointLightBudgetSteps` first yields after 512 visited nodes (`src/render/precompile.js:209-250`), so every real sector scene → the `for..of` body runs → `await envBindYield(false)` → **ReferenceError**. No `try` wraps the site; `cookLiveSceneGpu` rejects. Everything after :13880 — `restoreReveal`, `armAdmissionShadows`, `_selectPostRoute`, the compile-cohort mint + compile/present drive, pool census (~:13890-~14900) — never runs. Additionally, the `for..of` close calls `iter.return()` on the abandoned walk, so a staging group found mid-walk is never released and the mint never fires.
  - Before-flight path (:12738 inside `prepareLiveSectorBeforeFlight`): `presentCook` rejects → `settleWithin` → `{ok:false}` → outcome `'error'` → `waitFor*` returns false (`src/render/pipelineReadiness.js:1364-1395`) → gate fails open/not-ready → loading releases without a cooked GPU set.
  - After-jump path (:15400 inside `prepareLiveSectorAfterJump` ← `compileSectorPipelines` :17222-17239): rejection propagates → `precompile.finally(...)` still releases `sectorShellAdmission` (:17329 arm) → `pipelinePrecompile.catch(()=>{})` swallows (:17414/:17453) → `pipelinePrecompileReady` rejection re-signals `waitForCurrentRenderPipelines` → `settleWithin` false (pipelineReadiness.js:802-805). Net: latch released as-if-cooked, error hidden, **zero compile cohort** → the sector goes live uncooked → first-draw synchronous program links mid-flight — precisely the in-flight-hitch class the cook exists to prevent.
- **Blind spots:** `compileSectorPipelines` early-returns on `gpu.software` (:17223), so the after-jump lane never executes in SwiftShader CI. The AST-eval harness (`with(env)` in `test/live-sector-cook-owner-runtime.test.mjs`) stubs only `syncVisiblePointLightBudget` (:413) — `syncVisiblePointLightBudgetSteps` is undefined in the eval env → the `typeof === 'function'` guard takes the fallback branch → the buggy line is unreachable in tests. - **Fix sketch:** hoist `const envBindYield = createSlicedYield(...)` above `if (scene.environment)` (or use the cook's own `yieldToBrowser`/`yieldLiveSectorGpu` at :13876 — consistent with sibling drives). Add a Steps-name stub to the eval-harness env so the guarded branch is exercised (see F5). Needs a real-GPU (non-SwiftShader) in-browser check to confirm the cook tail completes.
- **Effort:** S (one-line hoist + harness stub). **Impact:** H — restores the entire cook pipeline it replaced. **Risk:** M — unverifiable by CI; verification requires real GPU run.

### F2 — Paced recount is dead code: `force` flag collapses every dirty resolve to an atomic O(scene) walk

- **Evidence:** `src/render/renderer.js:26315-26317` — `_syncShadowMapEnabled` calls `tally.resolve(this.scene, { force: this._shadowReceiversDirty === true })`. In `src/render/shadowReceiverTally.js`, `markDirty` is only reachable via `_markShadowReceiversDirty`, which always pairs `tally.markDirty()` with `_shadowReceiversDirty = true` (all six `noteShadowPolicyChanged` call sites pass objects with finite `receiverDelta`, never the literal `true` → `noteDelta` path, no markDirty). So **whenever `tally.dirty === true`, `force === true`** → resolve takes the atomic `scene.traverse` branch (:98) and the ≤4ms paced path (:103-122) is unreachable — `pendingRecount` can never mint (the mint is inside the non-force branch).
- **Mechanism:** dirty is set on every mesh add/remove burst (spawn waves, seam admits, despawn drains — `_noteShadowMeshAdded/Removed` :26277-26286). Those are exactly the churn frames that can least afford an atomic ~O(scene) `scene.traverse` on the presented path — the W97 recount machinery was built for them and never runs.
- **Fix sketch:** drop `force:` so the paced path engages; pair with the conservative-on treatment in F3 so a stale `===0` window cannot flicker the map off. The recount is presentation-only (gates a refresh schedule), so stale-serve is sim-safe.
- **Effort:** S. **Impact:** H — removes the largest remaining presented-frame atomic walk from churn frames. **Risk:** L — machinery already verified (see §3, bullet 2); the only behavioral change is brief stale-serve, covered by F3's gate.

### F4 — Item (c) enumeration: suspended `_presentationRebindIter` → previously-visible meshes draw frozen across the park

- **Evidence:** `presentationWorld.js` — `rebuildFromEntities`/`clear()` (:862-897) null `meshRefs`/`boundEntityRefs` on every row; `updateFromEntities` (:906+) retains bindings. `presentationQueries.js:176-194` — `exactVisibleCompute` returns false for `!boundNow` rows → hiddenSlots. - **Consumers of `_bindPresentationMesh` side-effects read mid-rebind in the same frame** (enumerated): `socketWorldPose` memo cache (renderer.js — cache keyed per mesh; unvisited meshes serve stale sockets for the parked duration, self-heals), `stampCanonicalSurfaceProgramKeys` + texture marks (only bind-path, unaffected readers), `_meshReleasePending`/`livingHull` attach, `lanes.reserve` (idempotent re-reserve; unvisited rows keep prior lane record), `entity.mesh`/`view.root` wiring, `userData._appliedLodLevel`. - **Mechanism/when it bites:** only full-rebuild publications (`journalFullRebuild` → `world.clear()` at publisher :227-233, and `rebuildFromEntities` fallback at :137/:200) — the diff-apply fallback (:129-135) retains bindings and is near-benign. Rare but real (it is exactly the suspended-rebuild storm case the machinery handles).
- **Fix sketch:** order the rebind walk visible-first — seed the iteration from the prior frame's visible/hidden sets (or `_meshes` entries whose row had `visible===1`) so the presented leg rebinds on-screen meshes within the first 4 ms and parks only the invisible tail (invisible lag is invisible). - **Effort:** M. **Impact:** M. **Risk:** L — ordering change only, same bind call; verify against `updateFromEntities` retained-path (no-op when rows retained).

### F7 — Item (b) enumeration: `dirtySeq` supersede livelock (conditional on F2)

- **Evidence:** `shadowReceiverTally.js:103-122` — while dirty, `resolve()` mints/drives `pendingRecount` with `seq: dirtySeq`; a mid-walk `markDirty` bumps `dirtySeq`, so the `seq === dirtySeq` stamp gate (:106-119) forces re-mint instead of settle. Per-call cost is capped at ≤4 ms (RECOUNT_SLICE_MS :31), but under a perpetual markDirty storm an unlucky caller sequence pays repeated 4 ms slices without the walk ever settling — the count can stay stale for an unbounded wall time.
- **Reachability:** dead today (F2's force collapses to atomic, which always settles). Enumerated as the hazard to close **with** F2: cap supersessions — after K re-mints (or when `dirtySeq - seq > N`), finish the in-flight walk to completion regardless of the 4 ms clock (or mark it un-supersedable so it stamps the newest seq it saw). Keeps worst-case settle bounded while preserving supersede-correctness for ordinary churn. Effort S (paired with F2), impact M only once F2 lands, risk L.
