## Findings (ranked)

### 1. Suspension-window per-present re-pay chain — atomic O(prefix + hiddenIds + activeCount) diff-apply + fresh O(_meshes) rebind mint + atomic O(activeCount) fence pack on EVERY tick-advanced present [hunt (c)]

- **Impact: M** — under a suspended stepped journal rebuild, each present that consumed ≥1 sim tick (≈ every present at 60 Hz sim / 60 fps present — the gate is a *per-present delta*, not "tick ever completed") pays three compounding O(N) passes inside one presented frame, for the whole window (up to `JOURNAL_REBUILD_INVALIDATED_MAX`=3 collect attempts × multi-present collect+publish legs). The documented chunked-fallback deferral understates it: two amplifiers landed since it was written.
- **Effort: M** (cheapest half is S — see fix sketch).
- **Risk: medium** for the chunked half; low for the delta gate.
- **Evidence:**
  - `src/render/presentationPublisher.js:101-108` — gate `completedTickCount > 0`; the counter is minted per present at `src/core/presentationRunner.js:911` (`simulationRunner.consumeLatestCompletedTick` — ticks consumed *since the last present*). Only zero-tick presents hit `fallbackReusedFrames`; every tick-advanced present re-applies.
  - `src/render/presentationPublisher.js:120-135` — `sample = sharedCollect || collectPrefix || aliveEntities(state)` → atomic `world.updateFromEntities(sample, null, collectPrefix ? {retire:false, hiddenIds} : undefined)`. During publish legs `sharedCollect` is the whole completed collect (`presentationRunner.js:877-878`); during collect legs it's the accumulating prefix (`:885-888`); between attempts (invalidated, `needsRebuild` still set, nothing in flight) it's `aliveEntities(state)` — the atomic whole-GameState collect (`:12`) inside the presented consume.
  - `src/render/presentationWorld.js:925-975` push loop O(feed) + hiddenIds pass O(|hiddenIds|) (:990-1007) + skippedIds (:1010-1021) + the `retireSuppressed` resident sweep (:1024-1053) which still walks all `activeCount` slots per present — suppression gates the *free*, not the walk.
  - `src/render/presentationPublisher.js:142` — `result.rebuilt = true` unconditionally on every applied fallback, zero-delta feeds included.
  - Amplifier A: `src/render/renderer.js:23968-23974` — `publication.rebuilt` → `priorRebind.return()` + fresh `_rebindPresentationMeshesSteps()` mint. Under sustained rebuilt churn the parked walk restarts at the `_meshes` head every present: re-mint starvation — the sweep never converges and re-pays its head each frame.
  - Amplifier B: `src/render/renderer.js:24013-24024` — `snapshotNeedsPack` includes `publication.rebuilt === true` → atomic `packPresentationWorldToFence` O(activeCount) every present (snapshotFence.js:305-364; `packDirty` copyRow softens per-row cost but the full active walk + `indexByEntityId.get` per row still runs).
  - The commit present additionally pays `world.clear()` O(activeCount) + `visitRange(start, frameEnd, applyRecord)` O(committed records) (publisher :227, :255) — the already-documented rebuild tail; not re-reported as a finding.
- **Fix sketch (two independent halves):**
  - (a) **S — stop paying amplifiers on zero-delta applies.** The world already counts `diagnostics.allocations` (:661) and `diagnostics.retirements` (:728); the publisher can delta them across the `updateFromEntities` call and carry `appliedDelta` on `result`. Gate the rebind mint and the `snapshotNeedsPack` rebuilt clause on `appliedDelta > 0`. A ticking present whose feed only refreshes retained rows then costs the push loop + dirty marks — the verbatim-mirror contract, not extra work — instead of mint+pack per frame.
  - (b) **M — the deferred chunked twin:** `updateFromEntitiesSteps`. The feed array is immutable and each entity's apply is already atomic per row; park `(feedIndex, seq)` between presents, stamp `lastSeenSeq` per completed row, and defer the resident/absent whole-set sweeps to apply completion. Then the suspension window costs ≤4 ms of paced apply per present and the rebind mints once per window, not per present.
- **Note on legality:** (a) does not change *what* is mirrored — only *when* amplifier work fires; (b) preserves row-atomicity so a parked apply never leaves a half-written row. Neither touches the sim.

### 2. `_presentationRebindIter` — continue-point is sound under every enumerable `_meshes` mutation race; two residual seams remain [hunt (b)]

- **Impact: L→M** — the starvation half is covered by finding 1 (self-limiting for correctness: every mount self-binds at :22292-22299/:22474-22478 and `handleForEntityId` live-resolves at bind, so a starved walk's missing work is redundant — the burn is real, the missed-bind risk is near zero). The eligibility seam is structural, not live today.
- **Effort: S** — **Risk: low.**
- **Evidence (the sound half):** the walk `for (const [id, mesh] of this._meshes)` (:21178) rides a live `Map` iterator — JS semantics guarantee: a `delete` of an unvisited id skips it; an `add` lands at the end and is visited this same walk; a delete+re-add re-visits with the *current* mesh and entity (the walk resolves `resolveWorldPresentationEntity(this.state, id)` per visit, so an id recycled into a different entity binds the new occupant — correct). `_meshes` is assigned once (:10173) and mutated only by `set`/`delete`, so the iterator can't outlive or alias a replaced map. A mid-walk `delete` of an already-bound mesh is unbind-cleaned by `_unbindPresentationMesh` (:20855-20934), which resolves the handle by entityId at call time and is mesh-identity guarded — a stale mesh can't unbind a remount. `clearAllMeshes` (:21203-21244) never closes a parked iter but doesn't need to: it deletes every entry, so the walk self-terminates on the next leg.
- **Residual seam — eligibility gap:** the walk binds on `entity && entity.alive !== false` only (:21181-21185); it does not re-run the push-side predicates (`entity._noMesh === true` / `projectileSkipsVisualFactoryMesh` — presentationWorld.js:936-941, :1044-1051). A doomed tombstoned row that nonetheless owns a `_meshes` entry would be bound → `bindMesh` clears `doomed` (:794-798) → the feed's skip verdict silently re-admitted. Co-occurrence needs `_noMesh` + a live mesh: today unreachable (renderer tombstones latch only on 3× build failure ⇒ no mesh at :22240-22256; authored `collisionOnly`/`componentProxyPresentation === 'hidden'` rows at worldSiteRuntime.js:477 never build). It is one future mount-path writer away from a visible regression — cheap to close now.
- **Fix sketch:** inside the Steps walk, skip ids whose resolved entity fails the same two predicates the push loop applies — mirrors presentationWorld.js:936-941 verbatim — so a parked walk can never out-vote the feed's eligibility verdict.

### 3. Doomed-first reorder — no unbounded leak; the enumerated never-reach case requires perpetual suppression, which the invalidation cap makes impossible [hunt (a)]

- **Impact: L** — bounded pin, self-healing, no visible defect.
- **Effort: S** for the optional hygiene; **Risk: low.**
- **Enumeration (the asked-for proof):** a doomed row is absent-sweep-*eligible* by construction — the doom gates `lastSeenSeq[slot] !== seq` (presentationWorld.js:993/:1014) mean doomed ⇒ unpushed ⇒ stale seq, and the absent sweep's predicate `aliveCols[slot] === 1 && lastSeenSeq[slot] !== seq && byId.get(idCols[slot]) === slot` (:1064-1068) always collects it on the first non-suppressed feed. The early-out `retainedHits !== byId.size` (:1057) cannot skip it either: doomed rows are unpushed by definition, so `retainedHits < byId.size` holds while any doomed row lives. Cases:
  - **doomed + dead + unbound:** freed at the completing feed's absent sweep. Pin across the window = one `entityRefs` entry (the dead entity object) + the slot.
  - **doomed + dead + bound** (destroy emit still in the 8/frame presentation queue or dropped at the 64-cap overflow — W16 machinery): the mesh stays bound but hidden — doomed fails `exactVisible`, and the hidden loop consumes the VISIBILITY mark at renderer.js:22777-22791 (`applyEntityMeshVisibility(mesh,false)` + `clearDirty` + `matrixAutoUpdate` freeze). `boundCount` over-counts for the window; freed identically at the sweep.
  - **doomed id recycled into a live entity:** the fresh push hits the retained path — `:960-963` seq-stamps + clears doom — the row is legitimately reused. Not a leak.
  - **never-reached case:** none constructible inside bounded operation — perpetual suppression would need the collect to invalidate forever, but `journalRebuildInvalidations >= JOURNAL_REBUILD_INVALIDATED_MAX` forces `syncJournalRebuildEscalation` (runner :802-806/:840-843) → atomic non-suppressed apply → every unpushed row retires. Chained windows (commit → fresh `needsRebuild` → new collect) can extend a pin across attempts, but each window is capped and the pinned set refreshes rather than accumulates.
- **Fix sketch (optional hygiene):** count the pinned set explicitly — e.g. `doomedCount` on world diagnostics — so a future regression can't hide inside `activeCount`; or detach the mesh (`unbindMesh`-style) at doom-mint for dead residents to shrink the `boundCount` skew. Neither is required for the bar.
