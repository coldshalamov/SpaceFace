## Findings (ranked)

### 1. Re-kick-minted coverage rows survive warm discard — claimed late settle orphans `covered=1` on a dead warm

**Evidence:** `_mintWarmReKick` mints `coveredMap.set(enemyId, +1)` at `src/render/renderer.js:17077` and releases via `releaseClaim(keepCovered)` at :17104-08 with `keepCovered = swarmWarmOutcomeClaims(settled)` — unconditional on warm liveness. `_discardEarlyCrucibleWarm` (:16997-17004) skips every id in `warm.failedCoverageMarks` (:17000), which is exactly the id set a re-kick re-minted. `unmarkBeginCoverage` (:16450) has the same skip.

**Mechanism:** first kick settles retriable → `unmarkWarmCoverage` releases the row and records the id in `failedCoverageMarks` → `finish()`'s collect pass (:17174-81) or the kick's own late settle (:16567-70, :16627-30) mints `+1` via `_mintWarmReKick` → the warm is then discarded (menu warm adopted into a wave-N save via the :16868 gate; `game:startFailed` :14538; navigate-away :14530; ruleset mismatch :16859) → `warm.building = false` (:16993) releases the residency owner pin so the warm's GLB records become evictable → the in-flight re-kick settles `'completed'` → `keepCovered` keeps `+1` → `covered(id)=1` with `kickClaims=0`. The deferred lane's fresh filter (`:17629`, `covered <= reKickClaims`) now excludes the archetype for the rest of the run. If its records are evicted, the first live spawn pays the in-round compose + program link the warm exists to pre-pay — the exact pop-in class this lane guards. Re-kick mints cannot fire post-discard (`!warm.root.parent` guard :17067), so only already-minted claims are affected.

**Fix sketch:** keep covered only while the warm lives — `releaseClaim(swarmWarmOutcomeClaims(settled) && warm.building === true)` at :17107 (or stamp `warm.discarded` in `_discardEarlyCrucibleWarm` and consult it). Alternative: make the discard/teardown loops decrement re-kick-minted rows — the launch-lane analog of the deferred lane's `retryMintCounts`/`retryReleasedCounts` accounting (:17719-31) — but the `warm.building` gate is one line and degrades to a conservative re-warm when a claimed settle lands after the settle arm drains.

**Effort:** S · **Magic-frame impact:** M (one archetype's first spawn pays compose+link inside a presented round; requires a discard racing an in-flight re-kick plus record eviction) · **Risk:** L (failure direction is over-warm, never under-warm).

### 2. `unmarkBeginCoverage`/`_discardEarlyCrucibleWarm` decrement the live ledger field, not `warm.coveredMap` — cross-run decrement window

**Evidence:** `unmarkBeginCoverage` (:16442-56) reads `this._swarmWarmCoveredEnemyIds` — the live field — while its sibling `unmarkWarmCoverage` (:16404) correctly reads `warm.coveredMap`, the captured map whose contract is documented at :16396-99. `_discardEarlyCrucibleWarm` (:16997-17004) shares the live-field read. `run:ended` nulls the field (:15224) and the next run re-mints it (:16391, :17566).

**Mechanism:** a warm's `buildExemplars` continuation outlives `run:ended` — its `paceIfDue`/`vf.build` awaits survive root detach (the loop iterates a detached root fine). A late throw lands in the outer catch (:16669-72) or the promise catch (:16681-84) → `teardownWarm` → `unmarkBeginCoverage`. Post-`run:ended` the field is null → the `:16443` guard correctly skips. But once run 2's map is minted, a still-alive run-1 teardown decrements run-2's rows for run-1's `coveredEnemyIds` — under-counting run-2's coverage so its deferred lane over-warms (self-healing) or eats a co-claimant's row. `_discardEarlyCrucibleWarm` is same-run-equivalent today because `run:ended` also nulls `_earlyCrucibleWarm` (:15222) — the divergence is latent there, live in `unmarkBeginCoverage`.

**Fix sketch:** decrement `warm.coveredMap || this._swarmWarmCoveredEnemyIds` at :16451-53 and :17001-03 — one line each, matching the deferred lane's captured-map contract (:17655-59).

**Effort:** S · **Magic-frame impact:** L-M (needs a warm's async build to fail late across a run boundary; consequence is ledger corruption that self-heals via re-warm) · **Risk:** L.

### 3. Nit — launch lane blanket-marks `launchEligibility` before spec resolution

**Evidence:** :16392 marks every `swarmEligibleEnemyIds(waveBase)` id up front; the deferred lane resolves specs first and marks only `markedEnemyIds` (:17633-53), with the comment at :17634-36 documenting the failure class ("a declared id with no spec would mint a covered mark, get no kick and no settle — a coverage lie that blocks every later dwell's retry").

**Mechanism:** safe today only via the `swarmCatalogIssues()` startup gate (`src/data/swarmMode.js:630` — roster + boss-package ids ⊆ `ENEMY_TYPES`, asserted empty in `test/swarm-brood-bosses.test.mjs:141` and gated at `src/systems/survivalWave.js:104`). `swarmRosterEnemyDefs` (`src/render/partsLibrary.js:13025-41`) silently drops eligible ids missing from `ENEMY_TYPES` — a catalog hole lands a mark with no kick and no settle for the whole run. The deferred lane is hardened because its domain is wider (plan-declared ids, `takeEnemyId` :17603-11); the launch lane's identical exposure is held only by the gate.

**Fix sketch:** mark post-resolution — build `launchEligibility ∩ spec.data.lootTableId` like `markedEnemyIds` (:17638-44) and unmark the residual diff at mint. **Effort:** S · **Impact:** L (requires a catalog defect the startup gate is designed to catch) · **Risk:** L.

### 4. Nit — adopt gate fails open on non-integer wave fields

**Evidence:** :16860-62 — `staged.swarmScoped === true && Number.isInteger(staged.waveBase) && Number.isInteger(state.run.wave) && staged.waveBase !== state.run.wave` → discard. A non-integer on either side falls through to adopt (:16869-72). All mint sites stamp `waveBase` (:16377-82), so a waveless record only exists via hot-reload or a future mint path — but a restore whose `run.wave` is not yet integer at `scenePrepared` would adopt a wave-1-scoped warm into a wave-N run, recreating the under-warm the wave-axis fix targets (and the deferred lane then skips the under-warmed ids — coverage lie, not just over-warm).

**Fix sketch:** fail closed — when `staged.swarmScoped === true`, discard unless both fields are integers AND equal. **Effort:** S · **Impact:** L (unverified whether `run.wave` can be non-integer at `scenePrepared` — flagged as a verification gap, not observed) · **Risk:** L.
