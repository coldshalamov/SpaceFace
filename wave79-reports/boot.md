### F1 — Cook's census→bucket→unit-construction stretch is now the launch path's largest atomic block — unsliced under loading AND under flight recooks

- **Evidence**: `src/render/renderer.js:13067` `collectInstancePoolCompileRootsAndSubjects(scene)` (one whole-scene traverse — the code's own comment at `:13066` sizes it ~21k nodes, `latePipelineAdmission.js:189-211`), then `:13087-13116` the `enclosingCompileRoot` memoized ancestor walk over every census subject, then `:13127-13129` `uniqueAdmissionUnits(cookCompileSubjects.concat(sceneCompileSubjects), { skipReadyMaterial })` with a `renderer.properties.get` + `currentProgram` probe per unique material (`openingGpuAdmission.js:255-263,281-283`). The only bound is the outer `cookDeadlineMs`, consulted between steps — `cookOverBudget()` gates `sceneCompileSubjects` (`:13117-19`) but the census walk, bucket pass, and dedupe all run regardless.
- **Mechanism**: under `mode==='loading'` this is a single large JS block inside the shell window — the cohort the paced legs exist to spread lands as one lump between yields. Under a same-sector recook while `mode==='flight'` (the case `materialAlreadyLinked` exists for, `:13120-22`) it is a real presented-frame stall — the wallet consults W78 added never see it because the stretch precedes the only gated yield site in the block. Estimated tens-of-ms on a populated sector (walk + ancestor chains + ~subject×material probes).
- **Fix sketch**: pace the stretch on the same ledger contract the warm census uses — a chunked census generator (or a `paceIfDue`-style elapsed>4ms check inside the traverse callback's node counter) debits `notePacedFrameSpend` and yields; then move bucketing + `uniqueAdmissionUnits` inside `admitOpeningUnitsAcrossSlices`' already-sliced issue loop (dedupe/probe per subject under the 16ms window), or simply wrap the whole stretch in a `paceCensusSlice` twin at subject-run boundaries. Order and output stay identical — the walk is read-only and DFS order is already the bucketing contract.
- **Effort** M · **Magic-frame impact** M (presented-frame hitch on flight recooks) / L under loading · **Risk** M — must preserve DFS order, the `[root]` drawable-less fallback, `collectCompileSubjects` fallback for unreachable roots, and subject-once semantics; verify subject multiset identity on a seeded scene.

### F5 — Loading-minted 16ms slicers never consult or debit the ledger — a cook finishing under flight spends invisibly to the wallet

- **Evidence**: `rockPoolYield` `:13156-58`, `touchYield` `:12708`, `yieldBuffers` `:12778`/`:14143` — all `state.mode==='loading' ? createSlicedYield(base,{sliceMs:16}) : base`, minted once at leg start. `createSlicedYield` (`pipelineReadiness.js:133-151`) consults only its private window — no `pacedFrameSpend` read, no `notePacedFrameSpend` write. - **Mechanism**: a cook minted under loading that crosses the flight transition keeps its 16ms windows — still paced (no wedge), but its spend never enters the wallet, so flight-gated sibling slicers read the frame as unspent and stack their own windows on top. - **Effort** S · **Magic-frame impact** L (over-budget frames only when a load straddles the transition) · **Risk** L — additive consult on an existing paced shape.

**(c) `enclosingCompileRoot` bucketing is deterministic; perRootSubjects insertion order cannot leak into commit order.** Each subject resolves its *nearest* compile-root ancestor (`:13089-13101` — first `compileRootSet` hit wins; memo back-fills every chain node to the same hit), so a subject is claimed by exactly one bucket — two sibling roots cannot both claim it, and a nested compile root's subjects bucket under the inner root (matching `flatMap(collectCompileSubjects)` membership). **(d) Ready-probe staleness — one-sided hole, F4.** Consumers of the ready bit: only the `programSubjects` exclusion (`:283-87`) — enumerate: `materialCount` report-only, `geometrySubjects` independent (`:289-92`). No re-probe at issue; ready→evicted skips compile → links at first draw (rare). Unready→linked is signature-deduped, benign.

**(e) Mode flip mid-cook cannot wedge or un-pace.** `compileSubjectsAcrossPresents` keeps its own `spent >= budgetMs` window independent of `shouldYield` (`compilePresentSlice.js:65-67`); `createSlicedYield` keeps its private window across flips; `paceIfDue`/deferred/census consults are ungated so they pace in every mode. The W78 consults read `state.mode` per call — a flight→loading flip drops only the union term (private windows persist); loading→flight activates them mid-leg (the designed W78 behavior). Menu cooks never mint the flight gate and pace on private windows + raw yields — strictly conservative. The spend-visibility asymmetry the flip leaves is F5.
