- **Mechanism.** The arm was already scheduled (`:22867-22869`) but runs post-present (`armCallbackAfterPresent`, `compilePresentSlice.js`); the checked sync runs inside `syncEntityViews` in the next presented frame, so the live restore lands first — the restored casters draw depth in that frame's shadow refresh while their depth-variant programs were never linked → a cold program-link burst inside the presented frame, on the fattest roots (parked roots are precisely the over-cap/undrawable cohort). ### F2 — Coverage unmarks decrement the live `_swarmWarmCoveredEnemyIds` instead of the warm's captured `coveredMap` — cross-run claim theft, over-warm direction

- **Evidence.** The documented contract (wave-70/W62 lineage, reaffirmed in the deferred lane's comment at `:17704-17710`) is that every unmark releases through the *captured* map so a re-minted ledger can't strip a later owner's claims: `unmarkWarmCoverage` uses `warm.coveredMap` + `failedCoverageMarks` (`:16401-16411`), `_warmSwarmDeferredRoster` uses its own captured `coveredMap` + `unmarked` (`:17704-17732`), `_mintWarmReKick` uses `warm.coveredMap` (`:17065`). Two sites violate it: `unmarkBeginCoverage` (`:16442-16456`) decrements `this._swarmWarmCoveredEnemyIds` directly — the *live* map, which `run:ended` nulls (`:15224`) and a later `_beginCrucibleBoundedRosterWarm` re-mints (`:16391`); and `_discardEarlyCrucibleWarm` (`:16997-17006`) does the same live decrement via `this._swarmWarmCoveredEnemyIds`.
- **Mechanism.** Begin-fail unmark or early-warm discard firing after a wave turnover decrements entries in a *different* run's ledger — claims the new warm just minted for its own exemplars get stolen → the deferred lane sees "not covered" → re-warms exemplars already building → extra warm work inside a dwell (armory budget, presented frames). Over-warm only — never a cold link — but it silently breaks the ledger's ownership invariant.
- **Fix sketch.** Route both sites through the captured map: `unmarkBeginCoverage` already captures `warm.coveredMap`/`warm.coveredEnemyIds` — use them (guarded by `failedCoverageMarks` like `unmarkWarmCoverage`); `_discardEarlyCrucibleWarm` should decrement via `warm.coveredMap`/`warm.coveredEnemyIds` on the warm object it holds.
- **Effort** S · **Magic-frame impact** L (bounded extra warm work in a dwell; never pops late) · **Risk** L — captured-map release is strictly narrower than live-map decrement.

### F3 — Launch warm marks `launchEligibility` coverage *before* spec resolution — an unresolvable declared id mints a permanent claim that skips every future warm attempt

- **Evidence.** `_beginCrucibleBoundedRosterWarm` mints `covered.set(id, +1)` for every `launchEligibility` id at `:16391-16392`, ahead of `swarmRosterEnemyDefs` resolution — the deferred lane deliberately does the opposite: `swarmRosterShipExemplarSpecs` resolves first and only then stamps ("A declared id with no spec would mint a covered mark that every later retry consults as already warm", `:17633-17649`). `swarmCatalogIssues`/`swarmMode.js` validate catalog↔ENEMY_TYPES, but a spec can also drop at `swarmRosterShipExemplarSpecs` (`partsLibrary.js:12993-13020` filter) or later mount-fail — the launch mint already counted it.
- **Mechanism.** If an eligible id produces no spec (catalog drift, ENEMY_TYPES gap), the permanent `covered.set` survives (no unmark on the not-covered path — unmarks only release *marked* ids via `warm.coveredEnemyIds` which only gets the marked set). Deferred lane and later waves then treat the id as warm forever → when that archetype actually fields in-round, it takes the cold compose+link path inside the presented frame. Latent — needs a coverage lie to ship; the audit seams exist to catch the class.
- **Fix sketch.** Move the `covered.set` loop after `swarmRosterShipExemplarSpecs`/`swarmRosterEnemyDefs` resolution and mark only ids that produced specs — the same resolve-before-mark order the deferred lane already uses.
- **Effort** S · **Magic-frame impact** L (latent; H if a bad catalog row ever ships — skipped warm → in-round cold link) · **Risk** L.
