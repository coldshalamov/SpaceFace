## Findings (ranked)

### F1 — Defer-cap storm cliff: synchronized per-row streaks exhaust in the same pass and stack N forced Box3 walks into one presented frame

- **Evidence**: `src/render/visualCullRadius.js:145-161` (over-budget key-moved branch serves `known * DRAWN_CULL_STALE_SERVE_BIAS` only while `drawnCullDefers <= 3`, then falls through to the walk), `:164-171` (cadence-expiry branch, same per-row streak), `:158`/`:165` (streak is per-mesh `data.drawnCullDefers`), `:172-173` (the fall-through walk increments `_passRemeasureCount` but is no longer gated by it), `renderer.js:23844` (`resetDrawnCullPassBudget` per syncEntityViews pass).
- **Mechanism**: every row's `drawnCullDefers` starts at 0 at the same mass re-key event — an authored-admission wave flipping `authoredAssetState`/`compositionId` across a fleet (the machinery this lane covers) or a fleet-wide `wholeShipLodActiveLevel` descent. For three consecutive over-budget passes every row serves stale×1.15 while only the 4/walk fresh budget is paid. On the fourth pass every storm row hits `defers > 3` simultaneously — the streaks were minted together so they expire together — and each consult falls through to `setFromObject` regardless of how many walks already ran this pass. ~(N−12) fat subtree walks land inside one syncEntityViews pass: the W104 "N fat walks inside the busiest pass" the defer was built to eliminate is not removed, only delayed three frames and made perfectly synchronized. A shared per-pass defer budget desynchronizes at the cost of paying walks earlier (same total); a jittered cap desynchronizes while preserving the transient-window intent the cap exists for (a passing window frees the budget before most streaks would have tripped).
- **Fix sketch**: mint each row's streak cap jittered by mesh identity — e.g. `cap = 2 + ((mesh.id | 0) & 3)` instead of the constant 3 — so storm rows exhaust across four pass-groups rather than one; or add a shared `_passDeferCount` reset beside `resetDrawnCullPassBudget()` so only the first D consults serve stale and the rest walk early (spreads the same total work across earlier passes, no cliff).
- **Effort** S · **magic-frame impact** H (single presented-frame spike exactly during the admission burst the defer guards) · **Risk** L — serve/walk semantics unchanged; only the exhaustion schedule moves. The jitter variant preserves the legal-direction bound (bounded stale-serve streaks still exist per row).

### F2 — Warm-lane backlog escalation is inert under sustained live-lane pressure (W105-F4 leftover-inheritance interaction)

- **Evidence**: `renderer.js:2319-2320` (warm lane budget = `Math.max(0, DESPAWN_DISPOSE_BUDGET_MS − (now() − liveLaneStarted))`), `:2087-2088` (`backlog > 32 → budgetMs *= 2` — doubles the *inherited* leftover), `:2093-2097` (paced-wallet skip + `DESPAWN_DISPOSE_LEDGER_MAX_SKIPS` = 2), `:2100`/`2132` (`deadline = startedAt + budgetMs`; loop breaks past it — ~1 Steps slice on a ~0 budget).
- **Mechanism**: the axis asks whether the inherited-budget path can starve the warm lane's aging or invert lane priority. Verified it cannot: `_warmDisposeLedgerSkips` is an independent counter — a permanently spent wallet still forces a drain every ≤3 service calls (aging cannot starve), and the live lane always drains first inside `serviceRenderMeshResidency` (no priority inversion). The residual is that the backlog escalator now multiplies the inherited leftover, not the 2 ms base: under a sustained live-corpse stream the leftover is ~0, `×2` stays ~0, so a forced warm drain pays ~1 iterator slice (~512 nodes) per ≤3 calls regardless of backlog depth — the deep-backlog case the escalator exists for is exactly the one it no longer reaches. A ~60-root roster/warm release is ~300+ slices → ~10-15 s of spent-wallet frames to fully reclaim: hidden trees keep GL buffers and unsettled `sfDespawnNoted` receiver-tally rows pinned far past the despawn moment (shadow maps stay conservatively on; heap headroom stays committed).
- **Fix sketch**: escalate off the lane's own base when the backlog is deep — e.g. warm lane uses `Math.max(inherited, backlog > 32 ? DESPAWN_DISPOSE_BUDGET_MS : 0)` or a flat ~0.5-1 ms floor once its ledger cap trips with deep backlog — preserving W105-F4's two-lane ceiling under shallow backlogs while letting the escalator reach the deep case it was written for.
- **Effort** S · **magic-frame impact** M (GL retention + conservatively-on shadows; no direct pop — warm corpses are invisible) · **Risk** L — changes bounds only inside the already-forced drain path.

### F3 — Merged spec-map consume forgoes payload hoisting: a late emit's hulls warm behind the first emit's 3-family exemplar tail (serial-equivalent, but a missed win)

- **Evidence**: `renderer.js:18550-18563` (merged consume iterates `specQueue` in Map insertion order; `mergedExemplars` = union of each row's full concat deduped by `seenExemplarIds` + `_rosterPrewarmIds`/`_meshes` skip), `:18452-18462` (each row's `exemplarSpecs` = `specs.concat(wreck, combat, asteroid)` — payloads lead within the concat), `:18529-18535` (`list = emit.exemplarSpecs`, so the merged order drives the drain), `:18564-18565` (`emit.specs = mergedSpecs` feeds only the weapon pass at `:18705-18712`), `:18550-18551` (delete-during-iterate: `specQueue.has(spec.id) → continue` keeps first-insert position — first-emit-first preserved).
- **Mechanism**: merged order ≈ `[emit1 payloads…, all 3-family exemplars, emit2 payloads…, emit3 payloads…]` — the family tail dedupes into the first queued row's concat position, so a later emit's front-row hull sits behind ~60 ambient exemplar builds. Enumerating the axis: this is **serial-equivalent** (a queued emit would have waited behind the in-flight drain's whole tail anyway) — no regression, and Map insertion order does preserve first-emit-first for payloads. But each payload spec already owns its own queue row, so `mergedSpecs` *is* the cross-emit payload set: hoisting it ahead of the family tail would let a front-row wave hull from a late emit warm strictly sooner than serial draining ever allowed. A wave materializing ~0.5-1 s after its emit can still draw before its warm slot clears the tail → cold `vf.build` + `requestAuthoredUpgrade` inside the round, the exact pop-in the cohort exists to prevent. Weapon warm position is unchanged (runs after the exemplar list either way).
- **Fix sketch**: `emit.exemplarSpecs = mergedSpecs.concat(mergedExemplars.filter(e => !mergedIdSet.has(e.id)))` — payloads globally first, deduped families after; `seenExemplarIds` semantics unchanged, coverage identical, ordering strictly dominates the serial baseline for warm-beats-draw.
- **Effort** S · **magic-frame impact** M · **Risk** L — ordering only; the mounted set is unchanged.
- **Sub-note**: `specQueue.has(spec.id) → continue` (`:18504`) runs *before* the covered-hull `newWeapon` check (`:18505-18516`) — a same-id spec re-emitted with a different loadout while still queued is dropped before its weapons can be scanned (narrow edge: same id + varying loadout). L.

### F4 — `_applyFrameOriginRebase`: Steps-ification adjudicated illegal; memoization inapplicable; selective translate is the only legal slice (W105-F5 revisit, per lane axis)

- **Evidence**: `renderer.js:23711-23751` (O(`_meshes`) `position +=` + `matrixAutoUpdate === false → updateMatrix()`, `_hazardVisuals` translate, `_contactShadowPool.records` x/z shift, `translateAsteroidInstancePool`, cam/vfx reproject), `:25293-25295` (fires on `rebase.changed` inside syncEntityViews, before the slot sync).
- **Mechanism/verdict**: the frame-facing rows must translate atomically — a partially-rebased mesh set presents mixed origins in one frame (visible scatter = the pop this machinery prevents), so Steps-ification is contract-illegal for `_meshes`, hazards, the instance pool, and cam/vfx. Memoization is inapplicable — every frame-local row genuinely moves by δ. The legal slice: rows re-seated from galactic every sync (position absolutely rewritten by the seat path after the rebase runs) don't need the `+=` — the walk could skip them under a reliable seat-dynamic marker, leaving only mount-frozen/static roots (already paying `updateMatrix`). The contact-record shift is correctness-neutral but strictly cheaper than the slot re-upload it prevents — keep synchronous.
- **Effort** M (the marker must be exact — a wrongly-skipped static row renders displaced by δ) · **magic-frame impact** L-M (cost = rebase frequency × O(_meshes); dense sectors worst, rare event otherwise) · **Risk** M.
