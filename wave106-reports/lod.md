## Ranked findings

### F1 — Recount resume-verify misses same-length reorders into the consumed prefix (under-count)

**Evidence:** `src/render/shadowReceiverTally.js:120-186` — the resume pass catches a moved open-chain child via `children[parentFrame.idx] !== f.node` → `indexOf` → gap seed `[idx, shifted)` (`:135-141`) plus a *prefix* seed `[0, min(shifted, idx))` — but the prefix seed is gated on `parentFrame.node.children.length > kidCount` (`:142-153`). A **same-length** reorder — remove-at-k + insert-at-i nets zero — leaves `children.length === kidCount`, so the prefix seed never fires. Live mutation sites producing exactly this shape: `restoreObjectHome` (`renderer.js:6069-6070`, called from ~9 staging/prepass restore sites: `:9711`, `:9969`, `:11089`, `:11926`, `:13625`, `:13994`, `:15273`, `:16335`, `:27410`), `openingGpuAdmission.js:720-721` (parked-item restore), `bloom.js:806-807` (forced-render home restore), `partsLibrary.js:5097-5098` (`splice(indexOf(prepass),1)` + `unshift` — this instance is benign: the moved leaf has `receiveShadow=false`, but it proves the class fires on live scene scope).

**Mechanism.** Concrete trace: open chain child at `idx`, an *unvisited* subtree at `k > idx` splice-moved to `0 < i ≤ idx` (unshift, or `restoreObjectHome` restoring to an earlier index). The remove at `k` leaves the chain child at `idx`; the insert at `i` pushes it to `idx+1` → detection fires → `shifted = idx+1` → the gap seed covers `children[idx]` — the *consumed* row that slid right — while the moved unvisited subtree sits at `i < idx`, inside the consumed span, never pushed. `children.length` is unchanged → the prefix seed doesn't fire → the subtree is silently skipped → `receivers` under-counts. Consumers gate on `count > 0 || dirty` (`renderer.js:24855`, `:25396`): a skipped span holding all receivers settles `count` at 0 and drops the whole shadow pass; partial skips skew the `Math.max(1, count)` sizing at `:25423`. Silent reorders emit no shadow notes, so the wrong count persists until an unrelated `markDirty` — sticky, not a flicker. This is the one remaining non-conservative direction in the file: W105-F3's fix covered growth, this is the same-length residue.

**Fix sketch.** Fire the prefix seed on *any* detected shift, not just growth — i.e. drop the `children.length > kidCount` gate (the seed is already `openSet`-filtered and only ever re-walks consumed rows: bounded over-count, the legal direction). To also cover a swap that lands an unvisited row deeper than `idx` while leaving the chain child unmoved, stamp each frame's predecessor identity (`lastChild = children[idx-1]` at push) and prefix-seed when it drifts. Both variants keep the "never under" invariant; the second catches the free-floating swap no in-repo site currently produces.

**Effort:** S (a few lines + comment). **Impact:** M — narrow trigger (a silent reorder under the open chain during a paced recount suspend), but the payoff is a sticky under-counted receiver tally — the exact class the recount machinery exists to exclude. **Risk:** low — converts a skip into a bounded re-walk; over-count direction unchanged.

### F2 — No per-walk seed budget: silent churn re-seeds the consumed prefix every resume

**Evidence:** `shadowReceiverTally.js:164-186` — seeded pushes charge `sinceYield` (slice-fair per resume) but carry no cumulative cap; `openSet` only excludes currently-open ancestors, so every seeded row re-pushes and re-walks its *entire* subtree regardless of how many times it already walked.

**Mechanism.** While a pending recount sits suspended under a parent whose `children` churn on every suspend (splice-seat/restore cycles during admission storms are the realistic producer), each resume re-seeds up to `min(shifted, idx)` consumed rows. A seed at a *high* ancestor re-walks whole sibling subtrees — worst case a scene-level reorder under an open `scene` frame re-pushes earlier sector roots, each a ~10⁴-node re-walk, per resume. Baseline cost is O(scene); the churned walk pays O(resumes × consumed-width × subtree). Two effects, both legal-direction: (a) settle latency — `dirty` stays set and the stale count serves longer, arbitrarily stretched while churn continues; (b) the final stamp inflates — re-visited receivers re-count, over-reporting toward conservative-on. Self-heals on quiesce or on a `dirtySeq` bump (supersede ≤ `RECOUNT_SUPERSEDE_CAP=4`), so the blast radius is latency + count inflation, never starvation or under-serve.

**Fix sketch.** Per-walk `seededTotal` counter; past ~4× `nodesPerSlice` (2048), `iter.return()` and re-mint — the supersede machinery already owns that path, so this is a counter + one bail clause, not new machinery. (A per-resume cap is wrong-shaped: the resume is already slice-charged; it's the *cumulative* re-walk that's unbounded.)

**Effort:** S-M. **Impact:** L+ — requires sustained silent reorder churn overlapping a suspended recount; bounded harm, conservative direction. **Risk:** low — abandon-and-remint is already exercised.

### F3 — Inline `unfreezeHiddenSubtreeMatrices` on re-unbind of a bound-queued row

**Evidence:** `renderer.js:22024-22029` — `owedBoundRestore && disposeBound !== true → unfreezeHiddenSubtreeMatrices(mesh)` runs inline, uncapped. The bound queue tier right above (`:22015-22022`, `UNBIND_HIDDEN_RESTORE_INLINE_PER_PASS = 2` at `:916`) exists precisely to cap this class — but only covers the *first* unbind.

**Mechanism.** The trigger sequence: live unbind past the inline budget → bound-queued restore pushed → mesh re-bound and re-unbound before the drain mints → the second unbind's stamp-clear kills the queue entry → the owed restore finalizes **inline**, a full ~2×O(subtree) walk inside the sweep frame. Per-call unbounded: a bind/unbind churn cycle across sweeps pays K whole-subtree restores (packaged hulls ~1-3k nodes) inside one presented pass — the atomic class the freeze lanes exist to amortize.

**Fix sketch.** Re-queue through `_pendingHiddenUnfreeze` with `sfHiddenUnfreezeBound` re-stamped instead of the inline call — the queue entry is already detach/visible-exempt under the bound tier and restores before any real reuse, which is all the contract needs. (Must not ride `_queueHiddenSubtreeUnfreeze` — it early-outs on `sfHiddenFrozen !== true`, which is fine here since the frozen flag was cleared above; pushing the same entry shape as the first bound push is sufficient.)

**Effort:** S. **Impact:** L — the re-unbind-inside-drain-window sequence is rare; each occurrence is bounded per mesh but uncapped per call. **Risk:** low-moderate — the restore-before-reuse ordering must be preserved; the queue path already enforces it.

**(b) Prefix-rescan repeat cost — worst-case re-push volume, and whether a cap is needed.** Per resume: the shift detector fires only when the open-chain child moved (`children[idx] !== f.node`); seeds ≤ `shifted` rows via gap+prefix. Each seeded row re-walks its whole subtree (`openSet` excludes only open ancestors — visited rows re-count, over-count legal). Per-resume work is slice-charged (`sinceYield` counts indexOf + pushes, yields mid-seed) — so a single resume can't burst. The *cumulative* volume is the gap: sustained churn re-seeds per resume with no per-walk bound → O(resumes × width × subtree) total — see F2. The detector itself has the under-count hole — see F1 (same-length reorder) — and a fully-airtight version also wants predecessor-drift detection for free-floating swaps.

**(c) Flap-epoch reach — can a stale `sfHiddenFlapSeq` delay a first freeze mint past its savings point?** No — unreachable. Both queue paths stamp `sfHiddenFlapSeq = <that lane's queuedSeq>` in the same breath (`:21548-21549`, `:21687-21688`), so for any row *in* a queue, `flapSeq === queuedSeq` and `Math.max(lastShow, queuedSeq, flapSeq)` is dominated by the row's own queue date — the flap stamp can never be *newer* than the queue stamp on a live entry. The only path retaining an *older* flapSeq — the freeze-queue early-out on `sfHiddenFrozen` (`:21524-21540`), which deletes the unfreeze stamps but leaves `flapSeq` — applies to a row that isn't queueing at all (still frozen; nothing to mint). Re-queues always restamp; unbind clears (`:21984`). Dwell bound is `HIDDEN_FREEZE_FLAP_DWELL = 3` view-sync passes, always finite. Quantified savings: a freeze mint costs ~4 subtree visits and saves ~1 compose-visit per hidden frame — a root must stay culled ≥3 passes to mint at all, so the dwell is exactly the hysteresis the design intends; no row can be dwell-starved past ~6 passes of continuous cull. **Clean — no residual.**
