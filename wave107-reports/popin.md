## Findings (ranked)

### F1 — Post-cap forced walks bypass the per-pass remeasure budget; the jitter spreads them into ~4 synchronized stacks instead of eliminating them

**Evidence:** `src/render/visualCullRadius.js:144-163` — the key-moved serve path only runs when over budget; `:160-161` increments `data.drawnCullDefers` and serves `known * DRAWN_CULL_STALE_SERVE_BIAS` while `defers <= (2 + (mesh.id & 3))`; `:162` — "Past the cap (or nothing honest to serve): fall through and pay the walk" — falls to `:174-175`, `_passRemeasureCount += 1; _drawnCullBox.setFromObject(mesh)` with **no second budget check**. The pass budget (`resetDrawnCullPassBudget` at `renderer.js:24368`, `DRAWN_CULL_REMEASURE_PER_PASS = 4`) gates only the serve-vs-walk decision, never walk execution.

**Mechanism.** A mass re-key of N rows in one admission wave (fresh `compositionId`/`authoredAssetState` on authored landing, `wholeShipLodActiveLevel` flip across a fleet, interior `childCount` grafts — all key inputs per `:96-104`) has every row consulting every pass (visible loop `renderer.js:24579`, hidden loop `:24471`, bind path `:22368`). While over budget each consult defers once per pass; on pass `cap+1` the whole `2+0` cohort (~N/4 by mesh-id parity) falls through and pays O(subtree) walks in one pass — repeated on the next three passes by the cap-3/4/5 cohorts. Worst case ≈ N/4 + 4 fat-subtree walks per presented frame for ~4 consecutive passes, inside exactly the storm the machinery exists for. (A never-measured row — `known === 0` — always walks immediately regardless of storm state; documented at `:142-143` and inherent: nothing honest to serve. `primeDrawnCullStamps` covers authored-commit mints; unprimed mass mints still stack N walks in pass 1.)

**Fix sketch.** Route post-cap walks through a per-pass-budgeted force-remeasure FIFO: on `defers > cap`, push `{mesh, lruKey}` onto `_drawnCullForceRemeasure` (dedup per defer-epoch) and keep serving `known * 1.15` while queued; drain ≤K entries/pass (charge `K` against `_passRemeasureCount`), walking then writing the record. Staleness bound becomes `cap + ceil(queue/K)` passes — still a hard bound, direction-identical to today's defer. Queued rows whose mesh unbinds/disposes must drop (id/mesh-liveness check at drain). Never-measured rows keep the immediate walk.

**Effort:** S-M. **Impact:** M-H — replicates ~1/4 of the W106-F1 cliff per pass for 4 passes (~tens of ms spread across the storm window on fat authored hulls); strictly additive over the current state. **Risk:** L-M — same stale-serve contract, longer bound; the queue's liveness bookkeeping is the only new edge.

### F2 — Floored warm-lane drain pays a full `DESPAWN_DISPOSE_BUDGET_MS` inside an already-spent presented frame

**Evidence:** `src/render/renderer.js:2112-2116` — `if (backlog > 32) budgetMs = Math.max(budgetMs * 2, DESPAWN_DISPOSE_BUDGET_MS)`; `:2341-2348` — warm lane receives `Math.max(0, DESPAWN_DISPOSE_BUDGET_MS - liveLaneSpend)`; `:2121-2126` — per-lane ledger skip ≤ 2 then forced drain regardless of wallet.

**Mechanism.** The W106 floor fixed the ~0-budget starvation (deep warm backlog draining ~1 slice per forced call). But the floor ignores the paced wallet: when the live lane already spent its 4 ms escalation (or the frame simply ran hot), a forced warm call still pays up to the full floored 2 ms inside the same presented pass — every ~3rd service call per lane (`_DESPAWN_DISPOSE_LEDGER_MAX_SKIPS = 2`). Both lanes deep → summed worst-case ≈ 4 ms live + 2 ms warm = ~6 ms teardown in one presented beat, vs ~4 ms + ε before the floor. Ordering is not inverted — live always drains first (`:2342` before `:2347`) — this is a bounded summed-spend residue, not priority inversion. Ledger counters bound per-lane cadence, but nothing bounds the *cross-lane* total on forced frames.

**Fix sketch.** Floor against paced headroom rather than the constant: `budgetMs = Math.max(budgetMs * 2, Math.min(DESPAWN_DISPOSE_BUDGET_MS, Math.max(sliceMs, PACED_FRAME_BUDGET_MS - pacedFrameSpend())))` — keeps forced progress ≈4-8× the old single-slice rate while capping summed spend near the frame wallet.

**Effort:** S. **Impact:** L-M — bounded +1.5-2 ms on ~every 3rd frame only while both lanes are deep; most acute exactly during mass-despawn waves that also stress the frame. **Risk:** L — purely a budget-floor computation change.

### F3 — Mid-drain arrivals still wait behind the in-flight exemplar tail (payload hoist only runs at consume boundaries)

**Effort:** M. **Impact:** L-M — removes up to ~one drain cycle of latency for mid-drain arrivals; only visible when a wave lands inside a live drain. **Risk:** M — mid-iteration splice must keep `seenExemplarIds`-style dedup and witness-count semantics for the spliced payloads.

## Lane answers

**(a) Jittered-cap residue.** The serve side is correct: cap 2-5 spreads stale-serve expiry across ~4 pass-groups, and the clamp keeps serving only measured history (`known > 0`). The walk side is the residue — the post-cap fall-through at `:162` runs `setFromObject` unconditionally with no budget check, so each jitter group stacks ~N/4 walks inside one pass. The per-pass budget *should* gate the walk side — via a paced force-remeasure FIFO that keeps the stale serve while queued (legal: the same over-serve direction the cap already sanctions, bound `cap + ceil(queue/K)` passes) — and never-measured rows keep the immediate walk as the only honest answer. → F1.

**(b) Warm-lane floor inversion.** No ordering inversion: the live lane always drains first and hands warm the remainder (`:2341-2348`); the escalation clause is the only new spend. The ledger-skip counters bound each lane's forced cadence (≤2 skips) but nothing bounds the summed per-pass spend across both lanes on forced frames — worst ~6 ms (4 live escalated + 2 warm floored) vs ~4 ms + ε pre-floor. The floor could consult the paced wallet's headroom while preserving forced progress. → F2.

**(c) Payload hoist order.** Verified unchanged for correctness: two equal-priority emits merge as `[all payloads in queue order] + [exemplar union deduped by id]` — a different interleave than the pre-hoist union but strictly better for warm-beats-wave semantics (payloads are the named hulls; the union tail is family exemplars). The weapon pass reads `mergedSpecs` — queue-insertion order preserved; `compilePipelines` is one shared closure (`:18938`) so `mergedCompile`'s last-non-null rule is benign today. A front-row wave can still sit behind a *later* emit's exemplar tail — but only while the current drain is in flight (queue consumed between emit cycles, not mid-drain). → F3.

**(d) Remaining un-budgeted walks.** Ranked: F4-d1 clearance re-key walks (fat moving structural rows, per-frame query) > F4-d2 un-sliced urgent residency batch (count-unbounded merged pass) > F4-d3 motion-pad first-mint consult.
