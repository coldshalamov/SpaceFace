## Ranked findings

### 1. `preCountRoot` through the stepped lane can never satisfy its own contract — a suspended walk returns `false`, the swap seam falls back to counting a half-rewritten subtree, and the receiver tally drifts silently (hunt c)

Evidence:
- `src/render/renderer.js:9251-9254` — `onAuthoredAssetSwap` calls `this._syncShadowCasterPolicyChecked(target, lodLevel, entity, root ? { preCountRoot: root } : null)` then `this._noteShadowMeshAdded?.(root, swapPolicy ? swapPolicy.preReceiverCount : null)` — the pre-rewrite receiver count is consumed synchronously from the return value.
- `src/render/renderer.js:25030-25035` — `{preCountRoot}` rides `{...syncOpts, ...extra}` into `driveShadowPolicySteps`; a mid-walk return is `null → changed === false`, so the checked sync returns `false` and `swapPolicy.preReceiverCount` is `undefined`.
- `src/render/renderer.js:25020/:25095-25096` and `:26930-26940` — `receiverOut = { receiverDelta: 0 }`; `preReceiverCount` is copied into `opts.out` only in the `step.done` branch and only when `slot.out.preReceiverCount !== undefined`; `finish` is the sole writer (`src/render/shadowCasterPolicy.js:329-333`).
- `src/render/renderer.js:25771-25777` — `_noteShadowMeshAdded(root, null)` falls through to `tally.noteAdded(root)`; `src/render/shadowReceiverTally.js:36-38` — `noteAdded` counts `receiveShadow === true` over the subtree **at call time** (mid-rewrite flags), and `count` clamps at 0 so the error's sign is hidden.
- Second sub-mechanism: the abandon sig (`renderer.js:26921`, `allowCast|lodLevel|walkRootIsRoot`) ignores `preCountRoot` — a walk parked by an ordinary sync (minted without it) resumed under the swap call finishes with `slot.out.preReceiverCount === undefined` → nothing delivered → `noteAdded` counts the *post*-rewrite subtree. The count is wrong in both directions: mid-rewrite on a suspend, post-rewrite on a mismatched-mint finish.

Mechanism: pre-W92 this seam took the atomic `syncShadowCasterPolicy` and got an exact pre-rewrite count in the same synchronous call. Under the stepped lane the caller's synchronous contract is unsatisfiable — the fallback `noteAdded` measures a subtree whose `receiveShadow` flips are partially applied, so `_shadowReceiverCount` under-counts by the applied-prefix delta (and over/under-counts on the resume-without-mint case). The tally comment (`renderer.js:25766-25770`) spells out the consequence: an under-count reaching 0 freezes shadow-map refreshes — a fully drawn scene, stale depth map — until an unrelated `markDirty`/recount heals it, since `noteAdded`/`noteDelta` never set `dirty`.

Fix sketch: in `_syncShadowCasterPolicyChecked`, route calls carrying `extra.preCountRoot` to the atomic `syncShadowCasterPolicy` branch (deleting the parked slot exactly as the withhold branch does). The seam's value is needed on return — pacing is fundamentally incompatible with a synchronous out-param. ~3 lines; restores exact pre-W92 behavior on a rare seam (authored asset swaps). `syncPackagedBodyShadowPolicy` (`:11274-11280`) already takes the atomic branch via `syncScope` — this is the only remaining `preCountRoot` caller routed through the stepped twin.

Effort S · magic-frame impact M · risk L (the atomic path is the pre-W92 path; worst case is the pre-existing one-shot traverse on an authored swap, bounded by the same 8-per-pass traverse cap that already gates it).

### 2. Abandoned stepped walks leak their prefix's `receiverDelta` — and `lodLevel` in the abandon sig makes abandons common at band edges (hunt b)

Evidence:
- `src/render/renderer.js:26921-26928` — `sig = ${opts.allowCast===false?0:1}|${lodLevel||''}|${walkRoot===root?1:0}`; on mismatch `parkedMap.delete(root); slot = null` — `slot.out` (the walker's accumulated `{receiverDelta}` since mint) is dropped.
- `src/render/shadowCasterPolicy.js:263-267` — `receiverDelta` accumulates per visited node in the walker closure; delivery is only via `finish` → `slot.out` → `opts.out` in the drive's `step.done` branch (`renderer.js:26934-26940`). Flags written by the abandoned prefix persist on the meshes; their delta never reaches the tally.
- `src/render/shadowCasterPolicy.js:264-265` — `noteReceiver` counts `(object.receiveShadow===true)!==next`, so the reminted walk measures zero for nodes the abandoned prefix already flipped → delivered delta under-reports applied flips by exactly the abandoned prefix's net delta → same silent under-count/freeze class as finding 1.
- `src/render/shadowCasterPolicy.js:279-328` — `visit()` never reads `lodLevel`; the verdict is `allowCast && opaqueReceiver` plus visibility/userData gates. `lodLevel` only feeds the `state.lodLevel` bookkeeping stamp in `finish` (`:336`) and the mint-time early-out (`:250`). Embedding it in the abandon sig is over-strict: a mid-walk LOD flip discards provably identical work.
- Oscillation case: a fat root straddling a visible-LOD band re-syncs every frame (dirty latch stays set — `finish` never ran); each sync sees `lodLevel` different from the parked walk's mint → abandon+remint → the walk can never complete while the level flips → ≤4ms/frame of pure prefix burn plus one leaked delta per abandon.

Mechanism: two separable defects at one site — (i) every abandon of a walk that wrote ≥1 receiver flip silently loses that prefix's tally contribution; (ii) the sig's `lodLevel` term is verdict-neutral, so the most common mid-walk option change (LOD churn at band edges under camera motion) buys abandonment for zero semantic gain and can starve completion on oscillating roots.

Fix sketch: (i) carry the abandoned `slot.out.receiverDelta` onto the reminted slot (`slot.carriedDelta`) and add it into the delivered total in the `step.done` branch — `finish` *assigns* `out.receiverDelta` (`shadowCasterPolicy.js:331`), so a plain `opts.out` transfer would be overwritten; carrying on the slot delivers the prefix's flips exactly once through whichever call completes the walk. (ii) Drop `lodLevel` from the sig and re-stamp `state.lodLevel` from the live level at walk end (pass the current `lodLevel` into the drive per call, stamp in `finish` or the done-branch) — sound because verdicts are lod-invariant.

Effort S for (i), M for both · magic-frame impact M · risk M ((i) is mechanical; (ii) changes which walks abandon — keep the `allowCast`/`walkRoot` terms as-is).

### 3. The visible-pass stepped leg consults `pacedFrameSpend()` but never debits it — resumed/minted walks burn up to ~4ms·(roots resumed) invisible to the frame ledger (hunt a/d adjacency)

Evidence:
- `src/render/renderer.js:25028-25035` — `policyDeadlineAt = policyNow() + 4`; the drive's loop break at `:26907` is `now() >= deadline || pacedFrameSpend() >= PACED_FRAME_BUDGET_MS` — it reads the shared wallet mid-walk.
- No `notePacedFrameSpend` anywhere on this path: `syncEntityViews` (`:22382-23135`) debits nothing, and neither `prepareFrame` call site (`:23346`, `:23753`) debits it. The arm's restore leg *does* debit (`:25604`, `notePacedFrameSpend(armNow() - armStartedAt)`) — the presented-pass leg is the unmetered half.
- `src/render/decodeTaskBudget.js:84-107` — the ledger is a sum of explicit debits keyed to the rAF epoch; unreported wall time reads as zero spend. ~60 other slicers in the file debit their elapsed.
- `hadParkedWalk` bypasses `traverseDeferred`, so resumed-walk count per pass is unbounded by `SHADOW_ROOT_SYNC_PASS_CAP = 8` — K parked roots resumed in one pass pay ≤4K ms inside the presented sync.

Mechanism: the ledger exists so a busy frame doesn't carry the *sum* of every slicer's budget (`decodeTaskBudget.js:36-44`). A frame where policy legs precede the other paced drains (env-rebind drain inside `serviceRenderMeshResidency` at `:2144`, gltf compile/parse drains, residency slices) leaves the wallet at ~0 for every later slicer → each stacks its own 4ms on top → exactly the stacking failure the ledger prevents elsewhere. One resumed root is 4ms; a dirty-burst frame resuming several (hold-freeze catch-up, mass band-entry) multiplies it — unmetered, inside the presented pass.

Fix sketch: wrap the drive call — `const policyStartedAt = policyNow();` before `driveShadowPolicySteps` at `:25031`, `notePacedFrameSpend(policyNow() - policyStartedAt)` after (mirroring the arm's `:25604` pattern). One call-site change; the drive's mid-walk consult at `:26907` is already correct and stays.

Effort S · magic-frame impact M · risk L.
