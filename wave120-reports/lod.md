## Ranked findings

### F1 — Bolus-sector lights bypass the pool-light contract AND the census hook (cross-lane: hitch + stale-sig cold link)
- **Evidence**: `src/render/bolusView.js:127-139` mounts `BOLUS_LANTERN_SHAFTS.length` PointLights into a group on `renderer.scene` (`group` added at `:138`); `:28-29` sets `view.group.visible = inside` and `view.lights[i].visible = inside` every sync. `src/render/marrowCone.js:47-53` mounts a SpotLight (+target) into `renderer.scene`; `syncMarrowCone` flips `spot.visible = inside`. Neither file calls `noteShadowCensusLightMutation`. Both syncs run per frame from `renderer.js:27996` (`tryPresentedCall('bolus-view')`) and the marrow sync.
- **Mechanism**: every Bolus-sector enter/exit flips the rendered light census by N point lights + 1 spot light. three bakes `numPointLights`/`numSpotLights` into every material's program key (`vendor/three.module.js:7901-7903, 8035-8044`) → mass synchronous relink inside the next presented frame — the "2026-07 recompile storm" the pool discipline exists to kill (`vfx.js:15138-15140`, `weaponLights.js:4-6` keep counts constant for exactly this). Worse, the epoch never bumps: `_shadowCensusMemo` keeps serving the pre-flip sig as fresh, so every census consult — `cleanRootCensusDrift`, `collectServeLive`, the parked drift prefilter, the arm's verdict/leftover/rescue compares — decides against a light set that no longer exists; depth marks certify variants three will re-key, so band-1 casters draw "staged" marks while the real programs never linked → cold links across the cohort at the next shadow refresh. And when some unrelated mutation finally bumps the epoch, the entire cohort pays the W119-bounded mass re-collect anyway — the unwitnessed drift buys nothing.
- **Fix sketch**: pool discipline — keep both light sets permanently mounted and visible, dim via intensity only (no count churn, no relink, no census flip); at minimum call `noteShadowCensusLightMutation()` on the visible-flip boundary and pre-warm the new-count program variants inside the mount. Optionally fold the Bolus shafts into `syncVisiblePointLightBudget`'s compile-time stand-in census so the variants pre-link.
- **Effort S-M · Magic-frame impact H · Risk M** (intensity-ramp reads slightly different from the authored visibility cut; keeping `.visible` flips + census note + prewarm is the behavior-identical variant).

### F2 — Leftover eval accepts the dead-epoch serve as a staging witness (cold link, unsigned arms)
- **Evidence**: `renderer.js:30760-30774`. `leftoverSig = lightSig != null ? lightSig : this._shadowCensusForFrame()`; only the *additional* live serve is freshness-gated (30767-30770). When the arm runs unsigned (`lightSig` null — "routine on every sector enter", comment 30347-30356) and the memo serves the dead epoch while `pendingIter` runs, `leftoverSigs = [staleServe]`. The eval runs synchronously at 30775-30790 — before the deferred leg lands any marks — so a cache-path mesh (unstagedByRoot populated via `entry.unstagedCache` at 30416-30452 with empty `collectSigs`) whose `sfDepthMark.l === staleServe` reads "marked" → excluded from `leftoverByRoot` → the restore loop (30799+) releases the withhold → the mesh draws with a dead-census depth variant inside the next presented shadow refresh. The comment at 30761-30766 states "a dead-sig match is not live-census staging evidence" — the code uses it as a witness anyway.
- **Mechanism**: cold link in presented frame, bounded by the deferred leg's completion (typically a few presents); fires on sector-enter arms that run unsigned under a pending census mint.
- **Fix sketch**: freshness-gate the base witness like the live one — when `lightSig == null` and the memo isn't fresh, serve no witness (`leftoverSigs = []`) so every mesh counts leftover and the root requeues (fail-closed). One-line shape: `const leftoverSig = lightSig != null ? lightSig : (leftoverLiveSig)` i.e. drop the raw serve.
- **Effort S · Impact M-H · Risk low**.

### F3 — Census flip drains through per-root drift detects instead of one bulk re-stage (bounded churn)
- **Evidence**: per `(b)` enumeration — `renderer.js:29286-29360` (per-root collectGate + cap), `29976-30310` (arm: ≤32/arm, ~48ms cadence, paced skips), `30799-30886` (per-root restore traverses).
- **Mechanism**: a light-set flip (sources enumerated in (b)) queues every band-1 root: each pays a subtree flag collect + per-mesh flag writes + an arm ceremony slot; beyond cap-8 the rest over-cover whole-subtree and wait for the paced drain — a mass shadow blink scaled by cohort size. The work itself (re-stage under the new census) is mandatory; the residual is the N-way bookkeeping shape.
- **Fix sketch**: flip-triggered bulk re-stage — at `noteShadowCensusLightMutation` sites (or on memo miss), mint the new sig first and drive ONE stepped `collectUnstagedShadowCastersFlag` over `scene.children` feeding a single staging leg; withhold only the not-yet-staged subset. Same total work, one census-shaped pass instead of N subtree passes, and the blink window shrinks to the leg duration.
- **Effort M · Impact M · Risk M**.

### F4 — Band-0→1 promotion pays a second collect on the next eval
- **Evidence**: `renderer.js:29286-29289` — the promotion eval opens `collectGate` via `band !== 1 ? !queued`; a clean empty collect lands `unstaged=[]` but the stamp at 29366 requires `band === 1`, so `stampedCollectEpoch` stays -1 → next eval `cleanRootCensusDrift` fires → second full subtree flag collect.

- **Fix sketch**: stamp `STAGE_COLLECT_EPOCH_KEY` (NOT `STAGE_SELF_DIRTY_KEY`) on any completed unscoped collect regardless of band — the collect genuinely evaluated the whole subtree under the live epoch; band-0 gate (`!queued`) doesn't consult the epoch stamp so no gate semantics change.
- **Effort S · Impact L · Risk low**.
