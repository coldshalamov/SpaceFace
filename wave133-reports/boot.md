# wave133-reports/boot.md — boot-loading lane

Audited `devin/1791504143-perf-w120` @ `dffceb385` (W132 landed: `766f6d954` boot 7/7, `d131b4182` popin 4/4). Read-only audit; no app launch; SwiftShader box — CPU-side numbers are node24 micro-benchmarks on a synthesized save-shaped envelope, per this lane's evidence convention.

**saturated: false** — two material residual costs remain: the 180 ms settle fill re-pays the full synchronous `JSON.parse` that the armed spec resolves in the worker ~20 ms later anyway, and a synchronous multi-MB `localStorage.getItem` still runs on pick/arm tasks in three places.

## Findings (ranked by evidence × impact)

### F1 · The settle fill pays the sync parse the wave moved off the pick task — while its own spec arm parses the same bytes in the worker ~20 ms later (hunts a+b) — MECHANISM_VERIFIED + measured, impact M

Evidence: `saveLoad.js:813` — `fillSlotData` runs `unwrapSaveData(JSON.parse(entry.raw))` synchronously inside the `_SLOT_DATA_FILL_MS = 180` (`:806`) timer task (`scheduleSlotDataFill` `:819-830`). The same pick already armed the spec: `_select` emits `save:loadSpeculationTarget` at `:1205-1209` → `speculateLoadPrepare` (`saveSystem.js:2594`) → `_armSpeculativePrepare` parks `spec.dispatch()` for `SPEC_ARM_DEBOUNCE_MS = 200` (`:179`, `:2561-2575`). So per settled occupied pick: at t+180 ms the main thread parses the envelope (~12-14 ms measured for a 2 MB envelope on this box; W132 measured 15-32 ms at 2.2 MB); at t+200 ms the arm posts the same bytes to the worker, which parses them again — and the `save:envelopeSpecPrepared` fan-in's memo write (`saveLoad.js:1017`, `if (!entry.data)`) is then a no-op because the fill already set `entry.data`. Net: every settled pick pays a ~15-30 ms main-thread stall the spec machinery was built to absorb, plus a wasted duplicate worker parse per pick.

Mechanism: the fill was written for the no-spec world; once the arm exists for the same (slot, sig), the fill's sync parse is strictly dominated work — the emit delivers `prepared.data` for free.

Fix sketch: in `fillSlotData`, consult the live spec covering this pick (e.g. a `sys.speculativeCovers(slot, sig)` accessor over `_speculativeContinuePrepare`) — on a hit call `spec.dispatch()` (it flushes the parked timer and is identity-guarded) and return; the emit fills the memo and re-renders (already `refs.selected === slot`-gated). Keep the existing sync `JSON.parse` as the fallback when no covering arm exists (Worker absent, arm superseded or failed). Optionally lift the fill deadline just past the arm's (~210 ms) so the emit wins deterministically.

Effort S · Impact M (one ~15-30 ms stall per settle during dwell; the pick task itself is already clean — this is the settle task, not per crossed row) · Risk L — the emit path, staleness re-checks and re-render gate already exist; the sync fallback preserves today's behavior when the arm can't serve.

### F2 · The pick task still materializes multi-MB bytes: `readSlotSaveData`'s own `getItem`, plus three raw-less paths that re-pay it on emit/arm tasks (hunts a+c) — MECHANISM_VERIFIED, impact L-M

Evidence:

- `saveLoad.js:787` — a memo miss runs `localStorage.getItem(LS_PREFIX + slot)` synchronously on the pick task (`readSlotSaveData` ← `_renderStage` ← `_select`). W132 removed the parse from the pick; the DOMString materialization stayed — for a multi-MB save that is a multi-ms copy on every first-pick-per-slot during a filmstrip scrub. The raw is consumed only by (a) the speculation emit's `picked.raw` handoff (`:1207`) and (b) the fill's parse — both already off the pick task.
- `saveSystem.js:2607` — `speculateLoadPrepare`'s fallback `localStorage.getItem` runs on the calling task whenever `provided.raw` is unusable: pause's `{slot:'quick'}` emit (`pause.js:1155`), gameOver's `{slot: model.loadLatestSlot}` (`gameOver.js:829`), and Save/Load re-picks of spec-minted memo entries (`raw:null` — minted at `saveLoad.js:1016-1017` without raw; a re-pick after the arm was superseded re-reads the whole blob on the pick task).
- Bounded: `_select` emits unconditionally including empty slots, but the null `getItem` → `!raw` early return (`saveSystem.js:2610`) keeps those cheap.

Fix sketch (two cooperating halves): (i) `readSlotSaveData` mints `{sig, slot, raw:null, data:null}` without reading storage — `sig` is `saveStoreSignature()`, already O(1); `fillSlotData` materializes `entry.raw` inside its own deferred task when it must fall back to the sync parse. (ii) `speculateLoadPrepare` stops materializing `raw` at arm time: mint the arm `{slot}`-only and read `localStorage.getItem` inside the parked dispatch/timer task, deriving `spec.sig` there — the emit's generation re-check (`saveSystem.js:2548-2553`) already rejects a store that moved mid-arm. Same observed behavior; zero bytes cross the pick/pause-open task. Cheapest variant that keeps most of the win: leave the pick-side getItem (the memo makes it once-per-slot per screen-open) and only move the `speculateLoadPrepare` fallback read into dispatch.

Effort S-M · Impact L-M (multi-ms DOMString copy per first-pick-per-slot and per raw-less arm; once per slot, not per row) · Risk L-M — the arm's sig mint moves to dispatch; the emit-side generation and identity guards already cover staleness.

### F3 · Nit: spec-fan-in memo mints bypass the LRU trim (hunt a) — MECHANISM_VERIFIED, impact L

`saveLoad.js:1016-1017` mints `{sig, slot, raw:null, data}` into `_slotDataMemo` without the `while (size > _SLOT_DATA_MEMO_MAX)` eviction `readSlotSaveData` runs (`:792-794`). A re-mint after eviction can grow the map to 7 — bounded and harmless; fold the trim into the fan-in or share a `_memoSet` helper. Effort S · Impact L · Risk none.

### F4 · Nit: `_attachProfileToExport`'s `"profile"` substring check over-trips to the parse fallback (hunt c) — MECHANISM_VERIFIED, impact L

`saveSystem.js:7353-7357` — any `"profile"` substring anywhere in the envelope (e.g. inside pilot/story text) forces the full `JSON.parse`+`JSON.stringify` round-trip the splice was added to avoid (~15-30 ms parse + comparable stringify per 2.2 MB on this box). The splice covers object roots; the fallback is over-conservative, not incorrect — output stays right either way. A tighter check (top-level key only) would need a shallow parse — probably not worth it. Effort S · Impact L (export click only, rare trigger) · Risk none.

## Scanned clean / non-findings

- **(a) specPrepared fan-in contract — clean apart from F1/F3.** `unwrapSaveData(payload.data)` guards malformed payloads (`saveLoad.js:1012`); `typeof slot !== 'string'` early-out; the memo write is `!entry.data`-gated so stale data can't masquerade — `entry.sig` is re-stamped only alongside the data write (`:1017`), and a stale entry keeps its old sig so the next `readSlotSaveData` misses and re-reads rather than serving old bytes.
- **(b) 180 ms window — clean apart from F1.** Pick→click inside the window: stage data is optional for load (consume uses its own prepare, never `_slotDataMemo`); `load()`/`loadAsync` flush `spec.dispatch()` so the arm's in-flight worker parse isn't lost. Pick→exit mid-window: the timer is cleared in `onHide`/`dispose` before any dead-memo write is reachable, and `fillSlotData` is synchronous so dispose cannot interleave. Rapid cross-slot scrubs: a fill for an old slot is re-render-guarded by `refs.selected === slot` (`:815`) — it can't clobber the new pick's stage; the trailing debounce leaves only the settled slot pending.
- **(c) remaining synchronous legs — the rest are bounded.** Thumbnails: `img.decoding = 'async'` + dataUrl from card meta (`saveLoad.js:1123-1131`) — off the critical path. Import: FileReader async → sliced lane, byte gate band-gated. Export: blob mint is an O(1) `URL.createObjectURL`; revoke rides `setTimeout(…, 30000)` (`:1548-1552`); `_finishExportJsonAsync` serializes through slices (`saveSystem.js:7280+`). `listSlotsIndexCards` is O(index keys) and `_scheduleSlotIndexValidation` yields before walking (`:2343+`, `:2384+`). `deleteSlot` writes the index directly (W131-verified). The remaining multi-MB sync legs are F1's fill parse and F2's getItems — reported.
- **(d) disarm contract — closed.** Every exit path runs `onHide`; mode re-checks guard both the timer dispatch and the emit. Pause/gameOver arms whose screens exit mid-park are dropped by the timer's mode re-check before any clone/parse posts.

## Measurement notes

CPU-side node24 micro-benchmark on this box (SwiftShader; the app was not launched): `JSON.parse` of a synthesized 2.0 MB save-shaped envelope = **12-14 ms per call** (8292 entity records; consistent with W132's 15-32 ms at 2.2 MB on a realistic mix). `localStorage.getItem` cost is not measurable under node (no DOM backend); F2's impact is stated as a mechanism — a multi-MB string materialization on the pick task — sized by the campaign's standing multi-MB-per-slot premise.
