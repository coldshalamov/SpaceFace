## Ranked findings

### F1 — Zero-step wallet floor on the presented bind/pack drains; deterministic pack starvation behind any multi-pass bind
- **Evidence:** `src/render/renderer.js:26950` — `if (pacedFrameSpend() >= PACED_FRAME_BUDGET_MS) break;` sits at the *top* of the `_presentationRebindIter` drain loop, before any `iter.next()`. `renderer.js:27035` — identical loop-top gate on the `_fencePackPending` drive. Every sibling metered lane steps at least once before consulting the wallet, and the codebase documents that contract in words at `renderer.js:3210-3212` ("The check sits post-step so every frame still advances ≥1 pass"): reconcile (step 3200→check 3214), residency poll (3264→3278), resident reattach (2614→2630), arrival roster (3043→3058), arrival reserve (3110→3134), protected first-flight (2421→2444), hold-exempt degrade (3655→3672), cache lease (3017→3027), hidden-freeze queue (`visited > 0` floor, 22730), and the GLTF compile drain's `GLTF_COMPILE_MAX_SKIPPED_FRAMES = 2` aging escape (`decodeTaskBudget.js:369-386`).
- **Mechanism:** Two compounding defects. (a) *Deterministic cascade:* the rebind/spawned drain debits its own elapsed via `notePacedFrameSpend` at 26977-26979 *before* the pack drive at 27011+ runs in the same pass — so any pass where bind work consumes ≥4 ms leaves the pack's loop-top gate already spent, and the pack makes **zero** progress that pass. A multi-pass rebind (fat `_meshes` census — exactly the first-publication / sector-remap case the drain's own comment at 26941-26943 anticipates) starves the pack for its entire duration: `packPresentationWorldToFence` never steps, the snapshot keeps serving the pre-pack tick, and presented poses lag the sim for the whole bind window — i.e. frozen world motion on the first presented frames. (b) *Sustained-spend wedge:* any paced debiter earlier in the same epoch — resumed `scheduler.yield`/`setTimeout(0)` continuations of flight-gated boot tails (`debitGate: () => state.mode === 'flight'` joins the wallet exactly at the transition), GLTF compile drain continuations, deferred-admission flushes — can spend the 4 ms before `prepareFrame` reaches the drain. The zero-floor gate then parks the leg indefinitely: wallet parking is not a fault, so it never touches `FaultRetries`, never trips the ~1 s degrade, and never escalates to the once-per-epoch sync twin — the durable latches (`_openingRebindOwed`, `_openingSpawnedBindPending`) stay armed while no leg can ever run. That is the leak-surface answer to (a): the only state where an armed latch's leg provably cannot run is a starved wallet, and there is no floor.
- **Fix sketch:** Move the consult post-step on both loops (mirror `reconcileSliceStart`/`pollSliceStart`), or add a bounded `ledgerSkips`-style aging escape (the dispose lane's `ledgerSkips < 2` pattern at 2239-2246) that debits the forced wallet on the escape frame. Same for the pack drive; the pack additionally wants the wallet consult evaluated *before* minting a fresh `pendingPack` (27016) so a spent pass doesn't churn mint/supersede (27003-27007) without ever stepping.
- **Effort:** S · **Magic-frame impact:** H · **Risk:** L-M (re-adds ≤ one step to an already-spent pass — the contract every sibling lane already accepts)

### F2 — Opening publish tail runs 13 sites unguarded; a persistent site fault silently nullifies the whole post-fault tail on every pass
- **Evidence:** `_publishOpeningFirstPictureSteps` `renderer.js:26469` (`publishActivityFrame`), 26478 (`cam.follow`), 26482 (`yield* syncEntityViewsSteps` — internally belted, ok), 26484-26486 (`state.render.prepareOpeningVfxFrame` → `_publishOpeningPersistentVfx`, vfx.js:2008-2018: `_syncFrameMembrane` + `_updateEnergy(0)` + `_updateFieldGeometry(0)` — opening-only), 26489 (`updateMatrixWorldSteps` forced compose — stepped, ok), 26492-26495 (pool band: `syncContactShadowPool`, `ensureShipAuxPoolCapacityForFrame` — opening-only, `tickShieldShellClock`, `syncShipAuxPools`), 26501 (`_syncAuthoredInstanceSubmission`), 26503-26524 (shadow band: `_syncShadowMapEnabled`, `_syncKeyLightShadowFrustum`, `_updateShadowFollow`, `scheduleRealtimeShadowRefresh`, `prepareActiveShadowCamera`, `_syncAsteroidInstanceSubmission`). In `prepareFrame` the same work sits behind `tryPresentedCall` with per-site fallbacks (27137-27281, 15 sites — the brief's "11" has grown).
- **Mechanism:** Answering the brief's (b) enumeration directly: every one of the 13 can fault (plain method calls — e.g. `_syncAsteroidInstanceSubmission` → `syncAsteroidInstancePool` + `_syncWorldPresentationTableMeshes` whole-field walk when `field.dirtyPoseIds` is absent, 26307-26316). The fault path: `iter.next()` throws → `drivePublishFirstPicture` catch (26656-26667) closes the iter, re-mints once, and on a second throw degrades via `runCookSyncTwin('opening-first-picture-publish', ..., true)` — which swallows the fault internally and returns **`true`**. So a transient fault costs two stepped re-mints replaying the entire leg chain plus one full atomic sync-twin run; a *persistent* fault at site *k* means the pass reports success while sites *k*..*n* never run on any of the ≤8 settle passes — e.g. an asteroid-submission throw leaves asteroids un-instanced in the frozen first picture and they pop in on the first unheld flight frame, which is precisely the defect class the opening barrier exists to prevent. A fault does **not** reject the boot: only the early `return false` paths (context loss at 26472) and settle-envelope throws propagate, and the caller catches those into `firstPictureError` (14070-14086, degraded continue). The silent-degrade shape also means the failure is invisible to `noteLaneFault`/the epoch-latched warn pattern the quarantine uses.
- **Fix sketch:** Wrap the tail's call sites in `tryPresentedCall(this, '<label>', ..., <fallback>)` inside the generator, mirroring the presented-frame fallbacks (`active-shadow-camera` → `this._activeShadowCamera`, keylight/shadow-follow/refresh → `false`, rest → void); the two opening-only sites get labels `opening-vfx-frame` and `ship-aux-capacity`.
- **Effort:** S · **Magic-frame impact:** M (conditional on a site faulting — but that fault class is exactly what W109 built the quarantine for) · **Risk:** L

### F3 — `_openingSpawnedBindPending` re-mint + chain growth while armed; concat has no dedupe
- **Evidence:** `renderer.js:26921-26938` — the spawned mint is an `else if` reached whenever the rebind-mint condition fails (parked iter + no arm edge, or `rebindFaulted`). Each such pass mints a fresh `spawnedIter` and calls `_chainPresentationBindIters(spawnedIter, this._presentationRebindIter)` (23574-23577), prepending a link — the already-chained copy is not closed or deduped. `_openingSpawnedBindPending` clears only inside the leg on completion (26932-26933), so while the drain can't finish the spawned leg (wallet starvation per F1, or simply a >1-pass drain), the chain deepens by one link per presented pass and every chained copy re-walks the full `pendingList` — O(k·list) dead steps plus retained iterators. Compounds with the concat at 26430-26433 and 26860-26863, which appends `announced` slices with no dedupe across repeated consumes while a leg is parked.
- **Mechanism:** The boot window is where this bites: if `prepareOpeningFirstPicture` aborts mid-publish (its `finally` at 26801-26812 clears `_openingFirstPicturePrepared` and the activity frame but deliberately leaves the latches), the pending list can carry the whole spawn set into the first presented frames, where F1's starvation then grows the chain. In steady flight the spawned sets are smaller, so impact is dominated by the transition case.
- **Fix sketch:** Gate the else-if on "no spawned leg already in flight" (e.g. a `_openingSpawnedBindActive` flag cleared with the pending list, or by inspecting the chain head), and dedupe `concat` via a Set of pending slots (or `new Set(pendingList)` at leg mint).
- **Effort:** S · **Magic-frame impact:** M-L · **Risk:** L

### F4 — Quarantine-adjacent bare calls in the presented tail
- **Evidence:** `renderer.js:27143` `serviceRenderMeshResidency(this, frameDt)`; 27212 `liveShadowCastRadius(this.state)`; 27222-27224 `_updateSectorPostTransition(frameDt)`, `_updateSectorPaletteTransition(frameDt)`, `_bgTime` integrate — all outside `tryPresentedCall`.
- **Mechanism:** A machinery fault in any of them propagates out of `prepareFrame` to the `renderUpdatePhase` catch (`renderError`), which drops the whole frame — the blast radius the row quarantine and `tryPresentedCall` exist to remove. The residency service's inner lanes self-catch, but the outer call does not; the two transition ticks iterate per-sector transition state and are real throw candidates.
- **Fix sketch:** Wrap each in `tryPresentedCall` — transitions → `void` fallback, `liveShadowCastRadius` → last `_frameShadowCastRadius` (or a conservative constant), residency → `void`.
- **Effort:** S · **Magic-frame impact:** L-M · **Risk:** L
