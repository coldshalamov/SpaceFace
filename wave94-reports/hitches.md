# wave94 audit — in-flight-hitches

HEAD audited: `33e18718a` on `devin/1791064509-perf-w60` (wave-93 tip; carries W60–W93).

saturated: false

W93's three landings verify clean — the pass-scoped policy wallet, the env-drain debit/ledger, and the wasVisible doom gates all behave as designed (regression notes below). Three residuals remain on presented-frame pacing seams: the wallet's per-root min-slice cost is additive across roots (and over-cover verdicts mint uncounted atomic traverses), the env drain's done-heads skip the deadline check entirely where the despawn sibling checks after every head, and the parked-root drift compare re-mints a whole-scene census walk every frame a lightSig-carrying park is evaluated.

## Findings (ranked)

### F1 — Spent pass wallet still pays ≥1 stepped slice per dirty/parked root; fresh mints pay slice-1 too; parked resumes are cap-exempt — K roots stack K×≤256 node visits per presented frame

**Evidence.** `_policyPassDeadlineAt` mints once per collectSeq roll (`src/render/renderer.js:24917-28`) and feeds `policyDeadlineAt` (:25053-54) — the wallet itself works. But `driveShadowPolicySteps` runs `iter.next()` **before** the deadline check: `const step = slot.iter.next()` at :27010, `deadlineFn() === true → return null` at :27024 — every parked root resumed in a pass takes its full slice (≤256 node visits, `shadowCasterPolicy.js:391` `visited>=256 → yield`) even with the wallet already spent. Fresh mints do the same: the non-atomic path mints a fresh `syncShadowCasterPolicySteps` generator and drives it immediately (:25055-61), paying slice-1 regardless of `policyDeadlineAt`. Parked resumes are additionally exempt from `SHADOW_ROOT_SYNC_PASS_CAP=8`: `hadParkedWalk` short-circuits at :25031-36 before the `traverseDeferred` check, and `_shadowRootSyncPassCount` only increments on the non-parked mint path (:25037-39).

**Mechanism.** Presented-frame policy cost = min(wallet spend, 4ms) + K×≤256 visits, where K = #roots evaluated this pass that are parked or freshly dirty. K scales with the same bursts the wallet was meant to bound (`invalidateShadowCasterPolicy` sites: attach storms, LOD cascades, census re-signs — partsLibrary.js:3342/:4280/:9169/:9201/:9455, renderer.js:9248/:10700/:11268/:25074/:25691/:25731). A parked root survives to completion across frames — a 10k-node authored subtree holds ~40 passes at 256 visits/pass, paying a slice on every presented frame it spans. The pass's only unbounded-by-count term: **over-cover verdicts mint atomic traverses without ever collecting** — `overCovered` (:24930-52) → `syncOpts = {...opts, allowCast:false}` (:24978-82) → the atomic `syncShadowCasterPolicy` whole-subtree walk (O(subtree ≤ ~10k) each), counted nowhere; every dirty root past the collect cap pays one, contra the comment's "verdicts are bounded by the same collect cap" (:25015-19 — that bound holds only for withhold verdicts, which required a collect). No starvation — min-1 preserves liveness and park order is Map order — but the wallet does not bound total per-frame policy spend.

**Fix sketch.** Two bounded moves, either alone or together: (1) evaluate `deadlineFn()` once before minting a fresh slot when the wallet is spent — park the root unpaid so it re-enters next pass under the fresh wallet (leave parked-resume min-1 intact). (2) Count verdict traverses against the pass — leave excess roots dirty for the next pass (fail-open on `castShadow=true`, quality-preserving); over-cover keeps the atomic doctrine but joins the count.

**Effort:** S–M. **Magic-frame impact:** M (K×~0.1-0.3ms additive exactly during mass-verdict windows; worst case unbounded via over-cover count). **Risk:** M — slice-1 deferral changes first-touch latency for fresh roots; verdict counting changes which roots apply castShadow=false in-pass (fail-open is quality-preserving but changes frame-to-frame flag sets).

### F2 — Env-drain done-heads bypass the deadline check: `step.done → continue` skips budget evaluation entirely; the despawn sibling checks after every head

**Evidence.** `drainSceneEnvRebindQueue` (:26947-74): the entry gate ages the ledger correctly (`pacedFrameSpend() >= PACED_FRAME_BUDGET_MS && skips < 2 → skips++ return`, :26952-56) and mints `deadline = startedAt + 4` (:26959). Inside the while loop, `iter.next()` at :26962 then `if (step.done) { queue.shift(); disposeTarget.dispose(); continue; }` (:26963-68) — **the `continue` jumps over the budget check** `now() >= deadline || pacedFrameSpend() >= PACED_FRAME_BUDGET_MS → break` at :26970-72, which only evaluates on non-done steps. The sibling `drainDespawnDisposeQueue` evaluates `now() > deadline` at the bottom of every iteration including done-heads (:2027 `if (drained >= limit || now() > deadline) break;` runs after the iterDone block) — asymmetry confirmed. `disposeTarget.dispose()` inside the skipped window is the GL-facing call the wallet exists to pace.

**Mechanism.** A queue of K entries whose iterators all complete this call drains all K plus K dispose calls with zero budget evaluation — cost unbounded by wall-clock, bounded only by queue depth (the queue mints one entry per env re-bake; a chained bake storm stacks several). The non-done case breaks correctly, and the aging floor's forced drain still pays ≥1 slice at full ledger by design (min-1 doctrine holds). The defect is narrow — only the done-head hop is unbounded — but disposing a texture-heavy env target is exactly the presented-frame cost the wallet exists to bound.

**Fix sketch.** Evaluate the deadline/wallet check at the top of each loop iteration (or drop the early `continue` so the done path falls through to the shared check), matching the despawn lane's check-after-every-head shape.

**Effort:** S. **Magic-frame impact:** L–M (needs a queue of completing entries in one call; unbounded in pathological bake storms). **Risk:** L — a hoist only; ≥1-slice liveness is already guaranteed by the outer entry gate.

### F3 — Verdict-parked roots carrying a lightSig re-mint a whole-scene census traverse every presented frame they're evaluated; the seq-keyed memo expires per frame by design

**Evidence.** In `_syncShadowCasterPolicyChecked`, the release chain `parkedEntry && parkedEntry.lightSig != null && parkedEntry.lightSig !== this._shadowCensusForFrame()` (:24834-35) calls the census for every evaluation of a lightSig-carrying verdict park. `_shadowCensusForFrame` memoizes on `{seq, epoch, scene}` (:25141-52) where `seq = _viewSyncSeq` bumps once per `syncEntityViews` — i.e., per presented frame (:22398) — so the first compare each frame pays `lightCensusSignature(scene)` (`shadowDepthAdmission.js:395-413`): a whole-scene `traverse` (isLight check on every node, ~16k visits) plus a per-light ancestor-visible walk and fog key. Park entries minted at :24869-80 carry `lightSig` forward (:24872-73) and persist until release; the cheap compares sit *after* it in the else-if chain — oqX cell compare (:24837-43) only fires when lightSig is null, denied-castable (:24844-50) later still — so the sig walk is not short-circuited for lightSig-carrying parks. The allowCast===false keep-verdict re-keys the record to the live census (:24853-66), but only once the sig already drifted; matching sigs pay the walk again next frame.

**Mechanism.** While any verdict-parked entry carrying a lightSig exists and its row is evaluated — visible ship/station/place rows call `_syncShadowCasterPolicyChecked` every frame (:22684-90) — every presented frame mints one whole-scene traverse, ≈0.3-0.7ms/frame recurring for the park's whole residency (recheck backstop 96-128 passes ≈ 1.6-2s at 60fps; denied parks can live longer). The compare exists to release parks early on light churn; the one-frame staleness bound is conservative because unnoted light mutations can't be ruled out.

**Fix sketch.** Either (a) key the memo on `_shadowCensusEpoch` alone, after enumerating unnoted light add/remove paths (`noteShadowCensusLightMutation` already covers dispose heldLight :27092, castShadow flips, `_syncShadowMapEnabled` — the rest need a census), or (b) piggyback the sig compare on the existing `parkedEntry.recheck` cadence (:24885-97 — check every ~96-128 passes instead of every frame). (a) preserves release latency; (b) is near-zero risk with bounded savings.

**Effort:** M (a: unnoted-mutation census) / S (b). **Magic-frame impact:** M — recurring ~0.3-0.7ms/frame precisely during park-residency windows, i.e. the frames the pacing machinery is already working hardest. **Risk:** M for (a) — a stale sig means late release, which is correctness-preserving; L for (b).

## Lane task enumeration

**(a) Pass-wallet starvation / min-1-slice residual** — reported as F1. No hard starvation: `iter.next()` before the deadline check preserves ≥1 slice per call (the doctrine), park order is Map insertion order, `hadParkedWalk` resumes before the cap. The residual is additive cost, not starvation.

**(b) Env-drain aging-floor forced drain vs inner paced check** — aging floor verified (full ledger → `skips=0` → drains ≥1 slice by design, :26957). The done-head bypass inside the loop is F2.

**(c) hiddenSlots consumption vs wasVisible gate (visible→invisible→doomed mid-window)** — VERIFIED CONSISTENT. `visible` is written only by `setVisibility` (marks minted on every 1↔0 transition, presentationWorld.js:1096-1105) and by doom mints (:986-88, :1008-11). A slot flipped visible→invisible mid-window passed through setVisibility — its mesh hidden and mark consumed in that pass — so the later doom mint reads `wasVisible=0` and correctly mints doomed=1+visible=0 with no mark: the slot is already outside the visible set and can never enter `hiddenSlots` (`exactVisible` fails doomed rows, presentationQueries.js:128-52; a respawn push clears doom atomically, :948). The dense sweep reads `world.entityRefs[slot]` directly and its `resident.alive === false → continue` handles recycled ids (:1001-13) consistently with the liveOccupant guard (:979-81). No mark leak either direction.

**(d) liveEntities.get cost in the doom loop under mass-destroy storms** — `state.entities` is a plain Map passed from presentationPublisher.js:130-37; one `Map.get(hiddenId)` per doomed id per partial feed ≈ 40-80ns on int keys. A 200-id destroy storm adds ~10-20µs against the per-id work already paid (byId.get, column reads, markDirtyBits). `liveEntities === undefined → liveOccupant === undefined → doom proceeds` — same as pre-guard behavior. Noise; no mechanism.

**(e) Remaining whole-scene/subtree walks on presented paths** (ranked by worst-case node count):
1. `lightCensusSignature` ~16k nodes — once per collect-bearing frame, plus per frame during verdict-park residency (F3).
2. Atomic verdict traverses O(subtree ≤ ~10k) each — withhold verdicts collect-bounded (≤8), over-cover verdicts uncounted (F1); deliberately atomic per the cold-link doctrine.
3. `needsAtomicOut` attach-event walks O(subtree) — LOD swap (:9256), packaged graft (:11283); event-bounded, not wallet-bounded.
4. `countShadowReceivers(root)` via unmeasured `_noteShadowMeshAdded/Removed` (:25810-23) — O(attached subtree) per unmeasured site (:8069-78, :9659-60, :10381/:10410, :14183/:14234, :16054, :17700/:17790/:17813/:17874/:18097, :18248/:18789/:19602/:20062, :18671/:18703); measured sites use preCountRoot (:9258) / countShadowReceivers out-params (:20005).
5. `scene.updateMatrixWorld()` (:26200) — once per presented frame; vendored sfMatrixFrozen prune + matrixWorldNeedsUpdate skips bound it to the dirty set. Documented basecost.
6. Stepped slices — ≤256 visits per call per root (F1 residual).
7. `guard.hide(scene)` traverseVisible — amortized (documented W93 (e)).
8. `disposeObject` per corpse — inside the paced despawn/retained queues.
9. `scanPresentedDrawables` per mount — O(mounted subtree) per event; dirty-gated pool scans are not tree walks.
