## Ranked findings

### F-1 — `traverseDeferred` starves `preCountRoot` callers: the 8-cap inverts into an unbounded atomic count walk

- **Evidence:** renderer.js:25032-36 — `traverseDeferred` requires `!scopedSync && !skipTraverseOnDrift && !hadParkedWalk && syncOpts.allowCast !== false && _shadowRootSyncPassCount >= SHADOW_ROOT_SYNC_PASS_CAP`; `needsAtomicOut` (`extra.preCountRoot`) is only consulted at :25045, *after* the defer gate, so a deferred preCountRoot call skips both lanes. Defer returns `changed === false` (:25132-36). The sole un-scoped caller is `onAuthoredAssetSwap` at :9256-59 (`{ preCountRoot: root }`, no `syncScope` — the packaged caller at :11281 passes `syncScope` and can never defer). On `swapPolicy === false` it calls `_noteShadowMeshAdded(root, null)` → tally `noteAdded` → `countShadowReceivers(root)`, an unbounded `root.traverse` (renderer.js:25810-14; shadowReceiverTally.js:9-25).
- **Mechanism:** once a presented pass has spent 8 fresh traverses (station/fleet commit storms, sector entry re-dirities), the 9th+ authored swap's checked sync defers; the swap seam then pays `countShadowReceivers` — the same O(subtree) atomic walk the cap exists to bound — *inside the presented pass*, and the deferred stepped walk still mints next pass because the root stays dirty via the :9253 invalidate. Protection inverts: strictly more atomic work than letting the traverse run, plus a second walk later. The tally stays correct (the fallback re-measures the same as-mounted flags) — pure work inversion, no correctness defect. Player sees: a hitch on multi-swap commits — the exact frames the cap was built for.
- **Fix sketch:** exempt `needsAtomicOut` from `traverseDeferred` (hoist it above the gate — the comment at :25043-45 already states the doctrine: "a caller needing a synchronous out-param can't wait"). Stronger variant that also closes the rest of residual (a): keep the stepped lane and satisfy the out-param directly — `out.preReceiverCount = countShadowReceivers(extra.preCountRoot)` evaluated before the walk mints — O(graft) instead of O(root); every swap then paces under the wallet and the cap, and no caller ever needs the atomic branch for its out-param.
- **Effort:** S. **Magic-frame impact:** M. **Risk:** low — variant one is a gate change on an already-exercised path; variant two preserves the pre-rewrite count semantics since the scoped count runs before `visit` touches the graft's flags.

### F-2 — Withhold-verdict traverses run atomic outside both bounds (residual e, confirmed)

- **Evidence:** renderer.js:24983 / :24985 / :25003 / :25008 — four `syncOpts = { ...opts, allowCast: false }` mints (overCover, `band!==1 && queued`, band-1 withheld-cache-miss, queued catch-all); :25035 excludes `allowCast === false` from `traverseDeferred`; :25064-89 — the atomic else-branch calls `syncShadowCasterPolicy(syncScope)`, a whole-subtree traverse that neither `_shadowRootSyncPassCount` nor `_policyPassDeadlineAt` bounds. The comment at :25018-19 ("verdicts are bounded by the same collect cap") only covers verdicts whose collect actually ran; the `queued` catch-alls mint verdicts with *no* collect (collectGate at :24909-12 is closed for `band!==1 && queued`, and `band===1 && selfDirty` skips it too).
- **Mechanism:** concrete trigger: `_stageShadowDepthOnSettingEnable` (:25664+) — when the click-time collect outruns `toggleBudget` mid-root, `queueOverCover` takes the in-flight root plus *every unvisited scene sibling* (:25694-25704), each `invalidateShadowCasterPolicy`'d (:25730). The next presented pass pays one atomic whole-subtree traverse per queued root (band-0 roots via :24984; band-1 roots with no withheld cache via :25000-03). Same stacking shape on a census re-sign (`parkedReleaseOnDrift` mass releases, :24834-52) or a sector-entry dirty burst. Per-root bounded per dirty generation by the walker's early-out, but the class is uncapped and un-walleted — the same O(subtree) work the stepped lane exists to pace. Player sees: a single-frame O(N×subtree) spike on a shadows ON flip or a light-census re-sign in a busy sector.
- **Fix sketch:** the cold-link-critical writes already land synchronously (`withheldMeshes` per-mesh `castShadow=false` at :25092-95; settings-flip per-mesh writes at :25761). Route the remainder — whole-tree cast=false on staged meshes, receiver/canopy writes, band stamps — through `driveShadowPolicySteps` under the existing deny sig (`0|1`; the carriedDelta machinery already chains abandoned prefixes). Alternatively mint the band/pose stamps synchronously and pace only the flag walk. Either way a suspended deny walk must keep the root dirty and must never let a presented refresh see a half-applied verdict.
- **Effort:** M. **Magic-frame impact:** M (burst-shaped: rare triggers, large spike when they land). **Risk:** M — verdict atomicity is cold-link doctrine; the split has to keep withhold-before-present ordering provable.

### F-3 — `_policyStepsParked` hygiene gaps (minor)

- `_sweepDetachedDepthStageRoots` (:25196-25208) reaps `_pendingDepthStageRoots` / `_parkedDepthStageRoots` / `_withheldDepthCasters` but not `_policyStepsParked` — a root detached via a path that skips both `_unbindPresentationMesh` (:20639) and owner teardown (:20864) pins its suspended iterator (a stack of node refs) until unbind. Bounded ref-pin leak, no correctness gap: `state.dirty` stays set since `finish` never ran, so a re-attached root re-syncs through the dirty latch — though its resumed iterator still walks the pre-detach snapshot before that dirty pass (a snapshot missing anything grafted while detached gets corrected by the *next* dirty generation, since `finish` stamps `dirtySeq > seqAtMint`). Add a `this._policyStepsParked.delete(root)` to the sweep. **Effort S. Impact L.**
- Parked resume order is Map insertion (park) order, not glass proximity: within a pass's shared 4ms wallet an off-glass resume can run ahead of a just-parked on-glass walk — the on-glass root's flags land a pass later. Bounded by the ≥1-slice-per-call floor (:27009-24). A glass-first reorder (e.g. iterate park order but resume on-glass keys first) would shave a frame of shadow-policy lag under wallet pressure. **Effort S. Impact L.**
