## Findings (ranked)

### F1 — `updateMatrixWorldSteps` lost the `sfMatrixFrozen` prune on unforced drives

- evidence: `src/render/staticChildMatrices.js:168-173` pushes every child regardless of cleanliness vs the vendored twin's per-child skip `if (!force && child.matrixWorldNeedsUpdate === false && child.userData.sfMatrixFrozen === true) continue;` at `vendor/three.module.js:139-140`.
- mechanism: the stepped twin is output-correct — under `entryForce=false` a clean frozen node recomputes nothing (`matrixAutoUpdate===false` skips `updateMatrix()`, flag false + entryForce false skips the world multiply). But it *visits* every node: the only unforced drive, the second compose in `_publishOpeningFirstPictureSteps` (`src/render/renderer.js:22971`), now pays a full-scene DFS per settle pass (≤8 + final passes per publish) instead of the pruned walk the vendored twin gave. On a dressed opening scene (~10–50k nodes) that is ~0.5–3ms of pointer-chase per pass, paced across yields but still wall time inside the load→first-picture seam.
- fix sketch: add the same skip at push time — `if (!childForce && child.matrixWorldNeedsUpdate === false && child.userData && child.userData.sfMatrixFrozen === true) continue;` — inside the children loop at :168, before both the overridden-child delegation (:171) and the stack push (:172). Identical output to both twins (a frozen subtree with a dirty descendant still descends — the flag check precedes the frozen check, same as vendored).
- effort: S. magic-frame impact: M (bounded to opening settle passes today; protects every future unforced drive). risk: low — the skip condition is copied verbatim from the sibling the twin was proven against.

### F2 — packaged commit leg-1 runs one un-paced O(nodeCount) span

- evidence: `src/render/visualFactory.js:4254-4286` — inside a single `.then` microtask: `record.renderPackage.createInstance(...)` (:4254) → `tagsByName` map build (:4266-4269) → `instance.planNodes` visible-flag walk (:4270-4277) → `packaged.add(packageRoot)` (:4278) → `bindInstanceMotion(packageRoot, record.motionBank)` (:4280). First yield is :4287.
- mechanism: `createInstance` (`src/render/renderPackageLoader.js:800-874`) is a flat `for (i < entries.length)` loop of `entry.source.clone(false)` + `objects[parentIndex].add(object)` per node, then three small Map builds. Bounded by `plan.nodeCount`, but not by wall time: a banked hulk/station package (~1–3k plan nodes) lands ~2–8ms of clone+walk atomically. `bindInstanceMotion` → `bindAuthoredMotion` is already O(N+B) (one `collectNodesByNameMap` walk), so leg-1 is two whole-subtree passes plus the clone loop, all before the first `yieldToBrowser`. The continuation can resume adjacent to a presented frame and hold the main thread for the full span.
- fix sketch: a `createInstanceSteps` generator yielding per-stride (512–1024) over the plan loop — `objects[]` is index-addressed so the stride boundary is free; keep the Map materialisation in the final span or a second stride block. Fold the `planNodes` visible-flag walk into the same drive (it iterates `planNodes` directly), and leave `bindInstanceMotion` atomic (O(N+B) single pass becomes the next-largest residue after pacing — optional Steps twin if a future wave wants it). `attachPackagedBody` is already async and already drives `driveLeg`; `createInstance` failure paths must keep `releaseOwner('render-package-instance-create-failed')` on throw.
- effort: M. magic-frame impact: M (one mid-flight commit = one visible slice for banked packages; banked is the minority path — most packages take the flat-primitive leg). risk: medium — residency/owner release parity on error and the `createNode` contract must be preserved; a partial instance across yields is only reachable inside this leg, no foreign readers.

### F3 — `rebuildSourceIds` narrowing can strand a write-once pose stale past publish

- evidence: `src/core/presentationJournal.js:253-279` (`prepareRecord`) and `:390-399` (`recordCoalescible`) — the foreign-write/suspension flags fire only when `kind === 'destroy' || entityId === 0 || !rebuildSourceIds || !rebuildSourceIds.has(entityId)`.
- mechanism: during a stepped `rebuildFromSteps` (:530-603), a transform write to an entity that IS in `rebuildSourceIds` no longer flags `rebuildInvalidatedDuringSteps` — by design, since the collect re-reads live state. The residual gap is timing: a write landing *after* the collect read that row but *before* publish is not flagged, so the rebuilt row carries the pre-write pose; if the entity then never writes again (a one-shot teleport/seat), the journal keeps the stale pose indefinitely — presentation stand-ins draw the old position until any unrelated record for that entity arrives. Self-healing whenever a later record lands; the wedge is only the write-once-then-silent case inside a rebuild window.
- fix sketch: track reads-at-collect per source id and flag invalidation on a write that lands after its row was read (dirty-on-read-set membership), or cheap post-publish re-compare of the written-while-collecting set before clearing `rebuildInProgress`. Keeps the W85 suppression win for the common concurrent-write storm; only re-flags the narrow post-read gap.
- effort: S. magic-frame impact: L (stale stand-in pose for a never-moving entity; no pop-in, no hitch). risk: medium — re-opening any flag scope re-imports the rebuild-storm class the narrowing killed; must stay membership-gated.

### F4 (residual) — `canonicalizeObjectSurfaceProgramKeys` still an un-paced traverse in the post-freeze microtask

- evidence: `src/render/visualFactory.js:4355` — `canonicalizeObjectSurfaceProgramKeys(packaged)` runs synchronously between `driveLeg(freezeStaticChildMatricesSteps)` (:4349) and the next `yieldToBrowser` (:4357). `illustratedSurface.js:180-196` = `root.traverse` over the packaged subtree with a per-node material check + `customProgramCacheKey` closure mint on changed surfaces.
- mechanism: W85 moved it off the atomic mount tail (correct) but it remains an O(subtree) microtask slice. Per-node cost is small (~100–300ns), so ~2k nodes ≈ <1ms — bounded, low worst-case.
- fix sketch: optional Steps twin / fold into the freeze leg's existing strides (the freeze walk already visits the same order). effort S. magic-frame impact L. risk low.
- residual note: this sits in the class W80 already documented as "residual bounded atomic spans" — listed here only because it shares a subtree with the paced legs and folding it in is nearly free.

### F5 (residual) — mount tail's two whole-subtree walks are deliberately atomic; bound stands

- evidence: `src/render/visualFactory.js:4413-4427` — `hideProceduralChildren(root)` (walks the OLD procedural subtree) + `root.add(packaged)` + `packagedShadowSync` → `_syncShadowCasterPolicyChecked(root, ...)` (`src/render/renderer.js:24353`) whose unconditional tail is `syncShadowCasterPolicy(root, ...)` (:24510) — a traverse over root+packaged (~largest single walk in the tail, packaged-scale node count).
