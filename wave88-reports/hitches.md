## 2. Ranked findings

### F1 — suspended journal rebuild still clears + re-allocates + re-dirties the whole presentation world per tick-advanced present — impact H, effort M

- Evidence: `src/render/presentationPublisher.js:106-114` (`fallbackFromState` calls `world.rebuildFromEntities(sharedCollect || aliveEntities(state))` whenever `completedTickCount > 0`), `src/render/presentationWorld.js:790-830` (`rebuildFromEntities` → `clear()` retires every slot, then `allocateEntity`/`allocateRecord` per entity — and `allocateRecord` at :566 marks `PRESENTATION_DIRTY.TRANSFORM`, `bindMesh` at :725 re-marks BINDING|TRANSFORM|VISIBILITY), `src/core/presentationRunner.js:813-872` (`rebuildCollectedEntities` stashed only on completed stepped collect).
- Mechanism: during exactly the window hitches hurt most — a stepped journal rebuild suspended across presents (post-jump, restore, authored-upgrade bursts) — every presented frame that saw ≥1 completed tick pays O(E) slot retire + O(E) allocate + O(E) pose writes, and re-dirties every slot so the next `syncEntityViews` re-poses and recomposes the full mounted set (the W86-era measurement: ~500 mounts, ~13k subtree matrix writes) *again per present*. The shared collect (W87) removed the O(E) collect walk but left the O(E) world churn and the full dirty blast radius.
- What the player sees: while the stepped rebuild is suspended — i.e. while the frame is already tight — each present re-pays the full mount/pose cost, stretching the hitch over every tick-advanced frame until the rebuild completes.
- Fix sketch: diff-apply against `sharedCollect` — retire slots whose entityId is absent from the collect, `allocateEntity` only for ids not in `byId`, and for retained rows call `writeEntityPose`/`refreshVisibleEntity`-shaped compare-then-write so dirty marks land only on changed slots (the quiet-skip machinery at `presentationWorld.js:748-784` already has the compare shape). The collect array is one stable object per publish, so the diff is pointer-compares plus deltas; generation stamps already guard staleness.
- Risk: medium — the diff must reproduce rebuild semantics for generation/retire ordering (retired-then-recycled ids, ledger rows). `clear()` also resets `asteroidDirty`/grid bookkeeping the diff must keep consistent.
