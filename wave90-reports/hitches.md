## Findings (ranked)

### 1. Stale `_despawnDisposeIter` survives queue resets — the next enqueued corpse is consumed without being torn down

- **Evidence:** `src/render/renderer.js:17436-17442` (destroy flush) and `:20823-20828` (`clearAllMeshes`) both do `queue.length = 0; _despawnDisposeHead = 0` but never null `owner._despawnDisposeIter`. The paced drain (`:1963-2000`) adopts `owner._despawnDisposeIter` at the head **before** checking which corpse it was minted for (`let iter = owner._despawnDisposeIter; if (!iter && m) iter = ...disposeObjectSteps(m)`). The drain's own reset at `:1992-1993` does null it — the two outer resets don't.
- **Mechanism:** the drain parks mid-corpse on the deadline (a fat packaged hull is ~1-3k nodes). If `destroy()` or `clearAllMeshes()` runs before the next paced drain — a sector jump is exactly when a despawn backlog is pending — the reset loop disposes the parked corpse synchronously but leaves the suspended generator alive. The next corpse enqueued (queue[0], head 0) drives the OLD iterator: its remaining stack nodes get their hooks double-fired (releaseAuthoredAssetResidency / detachAuthoredMotion / releaseOwnerInstances / geometry+material dispose all ran once in the sync flush), and when it returns `done` the drain does `head++` — the new corpse is marked drained while never torn down at all. Leaked tree holds its geometry/material buffers and, worse, `releaseOwnerInstances` never runs — borrowed instance slots pin their chunk for the session.
- **Fix sketch:** one line at each reset site — `this._despawnDisposeIter = null` (the suspended generator holds no resources; dropping it is the whole fix). Defense in depth: stamp `iter._corpse = m` at mint and have the drain re-mint when `queue[_despawnDisposeHead] !== iter._corpse`.
- **Effort:** S. **Magic-frame impact:** M (rare trigger — parked corpse + sector clear inside one frame — but each occurrence pins a ~1-3k-node tree plus pool slots for the session and double-fires residency releases). **Risk:** low; pure bookkeeping, no contract surface.

### 2. `packPresentationWorldToFence` rewrites every active row on every tick-advanced or journal-applied present

- **Evidence:** `src/render/snapshotFence.js:282-325`; driven at `src/render/renderer.js:23551-23564` when `_snapshotSourceTick !== completedTick || packCount === 0 || publication.rebuilt || publication.applied > 0` — i.e. effectively every presented frame in a live sector.
- **Mechanism:** the pack walks all `active` slots (thousands in dense sectors) doing ~15 field reads + sin/cos (or yawSin/yawCos cache reads) + a `Map.set` + ~16 typed-array writes + `setLean` per row — including the large static majority (stations, idle ships, far asteroids) whose packed bytes are identical to the previous tick's. This is the largest unconditional per-present span left on the flight path after W89.
- **Fix sketch:** dirty-column pack. `world.dirtyMasks`/`dirtySlots` already mark TRANSFORM|VISUAL-dirty rows per apply; for clean slots, copy the previous fence buffer's packed row verbatim via `snapshotIndexOf(previous, entityId)` (O(1) `indexByEntityId` Map, `snapshotFence.js:190-200`). Compacted write order and the `count`/`indexByEntityId` invariants are preserved; the copy replaces field reads + trig with typed-array reads of known-good bytes. Deeper variant — slot-stable fence indices plus read-fallback to the previous pack on index miss — elides the copies entirely but changes every consumer's read contract.
- **Effort:** M. **Magic-frame impact:** M (worst presented ticks in dense sectors; ~0.2-0.5 ms class). **Risk:** M — a write path that mutates pose without dirty-flagging leaves stale fence columns; correctness rides the same journal dirty machinery `updateFromEntities` already trusts, but every pose writer must honor the mask.

### 3. Destroyed-but-uncollected entities keep drawing through the suspended-rebuild window

- **Evidence:** `src/render/presentationWorld.js:843-846` (`retireSuppressed` keeps byId rows alive); `src/core/presentationRunner.js:783-794` (doomed-collect covers only `suppressedDestroys ∩ collectedIds`); collect legs pace at `JOURNAL_REBUILD_COLLECT_MS=4`, publish at 512 rows/present.
- **Mechanism:** during a stepped journal rebuild, an entity destroyed mid-suspension and not yet collected holds its stale row — `syncEntityViews` keeps pose-applying and drawing the dead ship for the remaining ~1-8 presents (a 4k-row rebuild at the 512-row publish cadence). Both a lingering-visual artifact (a dead hull persisting ~130 ms) and wasted apply cost per suspended present.
- **Fix sketch:** the journal already knows the doomed ids — plumb `suppressedDestroyIds` into the publisher's `{retire:false}` call as a hide-set so `updateFromEntities` marks uncollected doomed rows hidden (a bit-flag write, cleared when the publish retire frees the slot). Generation-stamp the mark so an id respawned inside the window can't inherit the hide.
- **Effort:** S. **Magic-frame impact:** L-M (bounded window, but dead hulls persisting across presents sits squarely on the nothing-wrong-on-the-presented-frame bar). **Risk:** low-moderate — the hide is advisory and the publish retire runs regardless; must be generation-guarded.

### 4. Retire walk allocates `[...byId.keys()]` on every call that has absents

- **Evidence:** `src/render/presentationWorld.js:893-895` — on `retainedHits !== byId.size`, spreads every byId key into a fresh array, then re-looks-up each slot.
- **Mechanism:** during destroy storms — exactly when absents are routine — each fallback/sync update allocates an O(byId.size) array and walks Map keys inside the presented apply. Sustained churn makes this per-present alloc + hash-iteration recurring.
- **Fix sketch:** scan the dense slot arrays instead: `for slot of world.activeSlots → if world.alive[slot] === 1 && lastSeenSeq[slot] !== seq → collect world.entityIds[slot]` then retire the collected ids. Zero alloc, cache-friendly typed-array scan, resolves slot→id via the `entityIds` column the fence pack already reads at `snapshotFence.js:304`.
- **Effort:** S. **Magic-frame impact:** L. **Risk:** low — retire mutates byId so the absent-id scratch list is required (absents are the minority, so the scratch stays small).

## Hunt notes — residuals (a)-(e)

**(a) Rebase-invalidated transform caches — enumerated clean for in-flight paths.** Contact-shadow records translate in place (~:22170s); the asteroid pool is translated (:22180); `_meshes` roots shift by construction; `_hazardVisuals` shift inline; camera and VFX reproject (`cam.reprojectFrame`; `vfxReprojectFrame` vfx.js:2686 covers gas/rupture/particles/sprites/trails/lights/beams/massline/apex/ribbons); engineTrailSurfaces.js:823 `reproject` shifts stored trail samples; opaqueMaterialBatch (~190-200) compares `matrixHash` against the source chunk arrays so it inherits coverage; ship-aux/shield pools and chunk-spawned pools live under entity roots (covered by the root shift); broodPresentation and parallaxLayers recompute per frame (no stale cache). Remaining uncovered: killcamStage instanced pools (rare; bolt/flash targets recompose from live entity transforms each frame → self-corrects within a frame), asteroidInteriorPreview's separate scene (not in flight), precompile/programCanon probes (not presented). No wholesale-invalidation residual worth a wave item.

**(b) lastSeenSeq wrap — closed, no mechanism.** `updateSeq = (updateSeq+1)>>>0`; on hitting 0 it re-mints to 1 AND `lastSeenSeq.fill(0)` runs in the same call — every stale stamp is zeroed before seq can repeat any prior value, so a colliding stamp cannot exist: a slot's stamp can equal a post-wrap seq only if written post-wrap. Collision window is zero; the ~4.29B `updateFromEntities` calls needed to reach it are unreachable anyway (~1.3 years of continuous 100 Hz calls).

**(c) `{retire:false}` retained-stale-row costs, ranked:** (1) destroyed-but-uncollected rows keep drawing — finding #3; (2) stale rows still pay pose-apply + visible-flag compare in `syncEntityViews` — O(doomed rows) per present, bounded by the ~1-8-present window; (3) mesh bindings held — the corpse mesh stays bound and holds its pool slots until publish retires it — same bounded window. Versus the atomic fallback it replaced (a whole-entities collect + clear/realloc inside ONE presented frame — the W88 regression this fixed): strictly better. Finding #3 is the only residual worth acting on.

**(d) Parked corpse vs bind races — recheck coverage enumerated.** `m.parent != null` is re-checked on every while-iteration at the queue head before iterator adoption (:1963-1968); the drain is the queue's only consumer (FIFO via head), so a remount between drain passes is always caught at the next head check; roots aren't pool-recycled, so the remount window is narrow and the abandon is correct. The one gap in recheck coverage is the reset-side adoption — finding #1. Residual worth noting but not a wave item: hooks already fired on a remounted corpse (releaseOwnerInstances, detachAuthoredMotion, residency release, geometry/material dispose) aren't reversed — a re-bound zombie keeps its shape while its GPU buffers lazily re-upload on first draw (one-time link/upload hitch; self-heals). Optional hygiene: stamp `__despawnAborted` on abandon so `_bindPresentationMesh` can re-arm payload hooks — S effort, L impact, only worth it if remount-mid-teardown shows in a profile.
