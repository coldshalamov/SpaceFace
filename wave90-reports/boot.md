## Ranked findings

### BOOT-F1 — `_killDepthStageSession` is dead code: `this._depthStageSession` is never assigned, so every designed session-close point silently no-ops

- **Evidence:** `src/render/renderer.js:25381-25387` — `_killDepthStageSession()` reads `this._depthStageSession`, a field with zero assignments anywhere under `src/`. Its only occurrences are these two lines. Call sites: drain-empty close at `renderer.js:24969` (`_queueShadowDepthStage` pump), arm-scheduler empty-pending close at `renderer.js:25373`, and shadow-disable at `renderer.js:25571` (`_syncShadowMapEnabled` OFF path). The real session lives in module-private `_depthStageSessions` (WeakMap, `src/render/shadowDepthAdmission.js:538`; written at `:692`, deleted at `:660`,`:672`,`:117`) — unreachable from the renderer.
- **Mechanism:** the staging session outlives every designed close point: the staging scene (cloned key light + target clone + ≤10 light clones), the per-session diagnostic Sets — including `drawnDepthObjects` holding live Object3D refs (F5) — and all mint bookkeeping persist until sig/epoch drift at a subsequent drive (`shadowDepthAdmission.js:669-672`), a `censusStale` abort (`:657-663`), or renderer teardown (`:113-118` via `disposeRendererOwnedResources` 8734). On the OFF→drain-empty path the dead hook was the only intended release, so a shadow-disable mid-drain leaves a parked session whose clone set quietly diverges from live state (compounds with F2 — a long-parked stale-ortho session is re-admitted verbatim at the next drive since the sig/epoch still match). Bounded memory + stale-pose retention; no wrong-sig marking (the reuse gate re-checks the freshly minted sig).
- **Fix sketch:** export a `closeHeldDepthStageSession(renderer)` from `shadowDepthAdmission.js` that performs the `:113-117` close+delete on the WeakMap entry (without touching the shared scratch/override material), and have `_killDepthStageSession()` call it — the renderer-side field is the wrong handle; the module owns the only session reference.
- **Effort:** S. **Magic-frame impact:** M (its own cost is small; it widens F2's staleness window by unbounding session lifetime). **Risk:** low — close() is already the designed contract; drift close would simply happen earlier.

### BOOT-F2 — staged key-light pose + shadow ortho freeze at session mint while the live light re-seats every frame; reuse spans unbounded player/sector drift

- **Evidence:** `admissionKeyLight` syncs the clone's transform + target + `shadow.camera` once per call (`shadowDepthAdmission.js:55-111`) and is invoked only inside `createShadowDepthStagingSession` (`:752`). The reuse gate (`:590-592`) accepts on `sig === lightSigOverride && epoch === shadowCensusEpoch()` alone — `lightCensusSignature` (`:374-398`) keys only `type:layersMask:castShadow` per light plus fog class, so pose/frustum drift never invalidates. Live side: `_keyLight.position.set`/`target.position.set` commit per quantized follow-key change (`renderer.js:24596-24599`), and `_syncKeyLightShadowFrustum` re-derives the ortho extent from per-sector radius (`renderer.js:25604-25618`, driven at `:23240` and `:23672`).
- **Mechanism:** slice renders run under the mint-era ortho. A caster inside the live shadow volume but outside the stale one never draws into the slice's depth pass → `markCastersDepthStaged` marks only drawn casters (`shadowDepthAdmission.js:498-525`, gated on `drawnDepthObjects` membership at `:516`) → the caster stays unmarked → remains withheld → parks undrawable (transient dark casters) or is force-released un-staged — a cold depth-program link in a presented frame, the exact brick this machinery exists to prevent. Park release on live-target cell drift (`renderer.js:24700-24709`) re-stages through the same stale-ortho session → park/recheck churn on a moving player. Session lifetime is now per-drain (or longer, per F1), so divergence grows with session age, not with a single drive. Non-key staged clones' pose is irrelevant: they never cast (`staged.castShadow` forced only on the key light) — only counts enter program keys — so the stale-pose surface is exactly the key light.
- **Fix sketch:** re-sync `stagedKeyLight` + `staged.target` + `stagedKeyLight.shadow.camera` inside `slice()` per drive (~10 field copies + `updateProjectionMatrix`; trivially cheap against the render itself), or fold the quantized follow cell + `_shadowOrthoExtent` into the session reuse key so drift re-mints instead of reusing. The re-sync is smaller and keeps the reuse win.
- **Effort:** S. **Magic-frame impact:** M-H (first-flight/post-jump withhold classes are the boot lane's own dark-pop surface). **Risk:** low — same objects, same marks; only coverage freshness changes. Contract-safe (render-side only).

### BOOT-F3 — `_releaseSurvivalRosterPrewarm` pays a sync `disposeObject` loop over the whole warm roster inside the `run:ended` emit

- **Evidence:** `renderer.js:19981-20015` — `for (const root of roots) { … if (!disposePreparedAuthoredBoundary(root)) disposeObject(root); }` with no slicing; callers are `onBus('run:ended')` (`renderer.js:16878`) and renderer destroy (`:8644`). `run:ended` emits through `_commitRun` (`src/systems/runSession.js:186`), so the handler's teardown runs inline inside that emit task.
- **Mechanism:** roster warm roots are whole composed ship trees kept hidden as next-wave admission subjects — hundreds of nodes each, roster sized by wave planning. The run-end → results/death-screen boundary pays a multi-root atomic tree teardown inside the emit: the same defect class W89's `disposeObjectSteps` closed for corpses, landed on the boundary where the shell is presenting end-of-run content. Player-visible as a freeze at survival run end.
- **Fix sketch:** enqueue the released roots onto `_despawnDisposeQueue` (the parked per-corpse iterator already exists and its per-node yield is exactly the needed granule), or drive `disposeObjectSteps(root)` per root inside a paced drain; keep the detach/`_noteShadowMeshRemoved` leg immediate.
- **Effort:** S-M. **Magic-frame impact:** M. **Risk:** low — roots are already detached and hidden; queue order is unaffected.

### BOOT-F4 — detached-boundary-owner release disposes each owner atomically inside the stepped walk

- **Evidence:** `renderer.js:20771-20786` — the `for (const owner of released)` loop `yield`s per owner but each turn runs `disposePreparedAuthoredBoundary(owner) || disposeObject(owner)` — a whole-subtree atomic traverse (`disposeObject` body at `:26622-26671`).
- **Mechanism:** the yield granule is owners, not nodes. A fat packaged boundary owner (authored place body, ~1–3k nodes) pays its entire dispose inside one step — the residual of the same class the W89 per-corpse parked iterator closed in `drainDespawnDisposeQueue`.
- **Fix sketch:** drive `disposeObjectSteps(owner)` here with the same per-128-node yield (the generator twin already exists and owns all hooks via `disposeObjectNode`), or route released owners through `_despawnDisposeQueue`.
- **Effort:** S. **Magic-frame impact:** L-M (release sweeps run during settle churn; a fat owner still lands inside one slice). **Risk:** low.

### BOOT-F5 — `drawnDepthObjects` pins live Object3D refs for the held session's whole lifetime; only `.size` is ever read

- **Evidence:** `shadowDepthAdmission.js:798` `const drawnDepthObjects = new Set();` accumulated per draw at `:857`; consumed only as `drawnDepthObjects.size` in `close()` at `:936`.
- **Mechanism:** every staged caster's JS object stays strongly referenced for the session's lifetime — with session reuse (and F1's dead close) a corpse'd mesh staged early in the drain cannot GC its JS-side tree until the session dies. GL resources are already released by the dispose paths; the pin is JS-heap only and bounded by staged-caster count — small but unneeded in machinery designed to live across presents.
- **Fix sketch:** replace the Set with a counter (per-slice `sliceDrawn` at `:843`/`855` already dedupes within a slice; if cross-slice dedupe of the count is ever needed, store uuids).
- **Effort:** S. **Magic-frame impact:** L. **Risk:** trivial.

## Lane hunt disposition

- **(a) session-lifetime drift classes.** Sig terms are `type:layersMask:castShadow` per rendered light (ancestor-visibility aware) + fog class (`lightCensusSignature`, `shadowDepthAdmission.js:374-398`). Enumerated non-sig drifts: light intensity/color/distance/decay/angle/penumbra params, light pose, fog color/density mutations — none enter depth-variant or programCacheKey terms, so all are correctly non-invalidating. Membership drift is covered: runtime light adds/removes are unreachable outside the noted sites — authored packages reject light nodes (`assertRigidPlanNode`, `renderPackageLoader.js:631`; `assetLoader.js:1510`), all live lights are init-pooled (weapon pool `weaponLights.js` ×2, event pool `vfx.js` `_initEventLights`, overhead `flightOverheadPresentation.js` — every one minted `visible=true`, `castShadow=false`, never re-minted), and every add/remove/flip path calls `noteShadowCensusLightMutation` (`shadowDepthAdmission.js:408`, noted at `renderer.js:25565/25599/25654`, `:26689/26711`, `weaponLights.js:108`, `flightOverheadPresentation.js:61`, `precompile.js:180/198`). Fog class never swaps (single `FogExp2` minted `renderer.js:9141`). **A stale session cannot mark casters under a sig queries never re-hit:** marks are stamped with `markLightSig`, and the reuse gate (`:590-592`) pins it to a `lightSigOverride` minted fresh each drive (`renderer.js:25050`); signature terms cover every class queries actually distinguish. All residual drift fails open (extra re-mint or unmarked casters), never wrong-marked. The one un-noted drift that does matter is pose — F2.
- **(b) mint-time clone staleness.** Only `stagedKeyLight` matters: non-key clones don't cast and contribute only type-count terms to program keys — pose-invariant by construction. The key clone's `shadow.camera` + position/target decide which casters draw into each slice; frozen at mint while the live rig re-seats per quantized cell + per-sector ortho extent → F2.
- **(c) staging accumulation.** Bounded. Per-slice caster reparents restore in `finally` (`staging.remove(root)` `shadowDepthAdmission.js:~922-926`); permanent staging children are one key clone + its target clone + ≤10 pooled light clones (light clones skipped when `options.stagedLights` supplies them but re-pushed each mint — `staging.clear()` in `close()` bounds it). `updateMatrixWorld(true)` at mint walks ~a dozen nodes; per-slice matrix work is O(staged cohort), not O(scene).
- **(d) remaining atomic drains inside shell-visible frames, ranked by rows.** (1) `_releaseSurvivalRosterPrewarm` — roster-sized × full-tree, inside `run:ended` emit → F3. (2) detached-owner release — per-owner-tree atomic inside a stepped walk → F4. (3) `_updateHazardVisuals` (`renderer.js:22910-22922`) — bounded small set, below report threshold. Verified already-paced drains (not residual): opening leftover-mesh sweep yields per 8ms (`:12563-12576`), jump departing sweep rides `providerSliceDue` (`:15085-15100`), `drainDespawnDisposeQueue` per-corpse iterator (`:1958-1995`), `settleRebuildBridges` `visitBound` (`:2063-2095`), `_flushMeshReleasePending` O(pending×5) map probes (`:20505-20514`). Deliberately sync teardown paths (`clearAllMeshes`, `disposeRendererOwnedResources`, context-loss catalog) run on boundaries where sync teardown is the documented contract — not reported.
- **(e) scratch-target churn.** Non-issue: `_admissionScratchTarget` is a module-global 8×8 RT minted lazily once per context lifetime (`shadowDepthAdmission.js:9-15`), shared across all sessions, disposed+nulled in `disposeAdmissionShadowResources` (`:133-135`) reached at renderer teardown (`:8734` region via `disposeRendererOwnedResources`). No per-session mint. Context loss does not call it, but three re-initializes render-target GL lazily against the post-restore properties map — same contract the rest of the owned-RT machinery relies on.
