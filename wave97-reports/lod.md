## 2. Ranked findings

### F1 — Denied-park release clause fires every eval; each cycle pays an uncapped atomic withhold traverse

- **Evidence:** `src/render/renderer.js:25137-25144` (`parkedEntry.denied === true && opts.allowCast === true → parkedRelease`); park mint `25876-25884` (`denied: true` on the settle-time denied park, `castBand` stamped from `shadowCasterBand`); keep-verdict re-key preserves `denied` only under `opts.allowCast === false` (`25153-25185`); release side-effects `25187-25191`; withhold-again path `25286-25303`; `withholdCoverageKnown`/`traverseDeferred` gates `25349-25358`.
- **Mechanism:** Denied parks are minted (25876) only on roots that had unstaged casters — i.e. roots that were castable at mint, so `opts.allowCast === true` is the norm, not the flip. The clause therefore fires tautologically on every eval of an in-band denied park: `parkedMap.delete` + withheld-cache delete + `sfDepthUndrawableCycles` delete (25187-25191) → `queued` stays true → `cached === undefined` → `syncOpts.allowCast=false` (25303) → a withhold verdict whose coverage is unknown (`withheldDepthCasters` was just cleared) → `traverseDeferred` cannot fire → **one atomic O(subtree) traverse inside the presented pass, every drain cycle, for every denied root**. The stamped recheck backoff (`recheckCycles` doubling to 8× at 25095-25102) is dead code for this population — the release never waits for it. W92's intent ("a denied root that turned castable changes no stored term") is real, but only for the keep-verdict population: parks re-keyed under `allowCast === false` (25153-25184) that later drift back. For them the clause fires exactly once, correctly. For mint-time-castable parks it fires forever. The correct exit path — `parked && unstaged.length === 0` release at 25271-25277 after the arm finishes staging — already exists and needs no clause.
- **Fix sketch:** Stamp the mint-time context on the park record (`deniedAllowCast = opts.allowCast` at 25876; the 25153 keep path already implies `false`), and gate the clause on `parkedEntry.denied === true && opts.allowCast === true && parkedEntry.deniedAllowCast !== true`. In-band denied parks then wait for arm progress (empty re-collect at 25271), recheck expiry, or a genuine drift release; the flip case keeps its fast release. Alternative with the same shape: drop the clause entirely and let re-keyed out-of-ortho parks ride the `oqX/oqZ` drift release — loses the non-ortho uncastable→castable fast path, so prefer the context stamp.
- **Effort:** S. **Magic-frame impact:** H — under sustained arm saturation (exactly when presented frames are busiest) every denied root re-pays a whole-subtree traverse + collect bookkeeping per drain cycle. **Risk:** M — the clause was deliberately added in W92; the fix must preserve the genuine flip release for re-keyed parks and keep `denied` semantics on the re-key path.

### F2 — Uncovered withholds run an atomic O(subtree) traverse past the pass cap; the only contract-preserving bound is a stepped walk plus a one-frame refresh hold

- **Evidence:** `renderer.js:25344-25358` (`withholdCoverageKnown` gates `traverseDeferred`; uncovered = `allowCast===false && withheldMeshes==null && !cache.has(root)` → forced atomic); stepped lane restricted to `allowCast !== false` verdicts (25365); `syncShadowCasterPolicySteps`/`makeShadowPolicyWalker` shared iterator exists (`src/render/shadowCasterPolicy.js` ~283-364); parked mid-walk ownership already tracked (`hadParkedWalk`, 25332); depth-pass gating precedent: `shadowMapActive`/`needsUpdate` already hold map work when the receiver tally is zero (26252-26258).
- **Mechanism:** The cap `SHADOW_ROOT_SYNC_PASS_CAP` defers only when withhold coverage is already known. On a genuinely uncovered withhold (queued band-1 root whose withheld cache was consumed/stripped — the 25286-25303 path), deferring would leave unstaged casters drawing cold-linked depth variants, so the traverse pays O(dirty subtree) atomically in the presented frame. Deferred by W96.
- **Enumerated alternatives:**
  - **A (recommended): stepped withhold + hold the refresh.** Mint the withhold as a `syncShadowCasterPolicySteps` walk writing `castShadow=false` as it visits, and suppress `key.shadow.needsUpdate` (the map refresh) until the walk finishes. Same-pass semantic preserved at the draw level — no unlinked variant can present because the depth refresh itself is held — while the flag write paces across frames under the existing `_policyPassDeadlineAt` wallet. The held refresh re-presents the previous map contents for one bounded window, identical in kind to what parked subtrees already tolerate. Per-root caster rosters (the arm already materializes `deferMeshes` sets at 25888) could drive the stepped write list directly, shrinking the walk's constant.
  - **B (rejected alone, useful inside A): coverage recording from the over-covered collect.** When the subset collect over-covers (`overCovered`, 25278), it has already walked part of the subtree — persisting the visited set into the withheld cache lets a later resume skip it. But unvisited casters still draw cold unless the refresh is held, so B alone cannot close the pass; it only accelerates A.
  - **C (rejected): root-level withhold consulted by the depth draw.** `castShadow` flags are the only skip predicate WebGLShadowMap honors; there is no subtree-skip hook in `projectObject`, and `layers` masks are per-object (flipping a subtree's mask is the same O(subtree) walk). Would need a scene-proxy around `shadowMap.render` — fragile, touches the color/depth shared traversal.
  - **D (rejected): eager generic depth-variant warm at attach.** Turns the withhold into a no-op by pre-linking every in-band mesh's depth variant at mount — i.e. paying the compile the deferred arm exists to defer. Violates the belt's purpose, not its letter.
- **Fix sketch:** Route `syncOpts.allowCast === false` uncovered verdicts to the stepped walker with a `holdDepthRefresh` flag on the renderer; clear the hold when the parked walk completes or abandons (abandon → `_markShadowReceiversDirty`-style recount + immediate sync withhold on next eval, preserving the cold-link belt).
- **Effort:** M. **Impact:** M — rare path (needs a denied/queued in-band root with consumed cache past the cap) but worst-case is the largest subtree in the frame. **Risk:** M-H — refresh-hold interacts with `shadowMapActive`/rebind seams; keep a hard one-frame bound on the hold and re-verify shadow behavior on boundary teardowns mid-hold.

### F3 — `disposePreparedSectorBoundary` re-invocation double-subtracts the shadow-receiver tally; also: sync-path `settled` is stamped unconditionally

- **Evidence:** `renderer.js:8073-8103` — no once-guard on the record; `disposeBoundaryObject` walks the subtree with a **fresh** `boundaryDisposeMeasure` minted per call (10429); `disposeObjectNode` clears `castShadow` but never `receiveShadow` (~27417+), so a second completed walk recounts the same N receivers and `markShadowReceiversDirty` settles them again via `noteDelta(-N)` (10492-10494). Partial/abandoned walks are safe (settled=false → `_markShadowReceiversDirty` recount, 10496). Sync fallback stamps `settled = true` unconditionally (10450) even if `disposeObject` returned false.
- **Mechanism:** A second `disposePreparedSectorBoundary` on the same record — reachable after the journal throws an `AggregateError` at 8098 (binding flags cleared only on success at 8100-8101) and a caller retries — settles `-N` a second time. `_shadowReceiverTally` under-counts; `count` clamps at 0 but the internal count stays wrong until an unrelated full recount (`_markShadowReceiversDirty` callers) heals it — meanwhile `shadowMapActive` gating can freeze map refresh. Impact is bounded because a *successful* first call still leaves `receiveShadow` set and the recount paths are numerous; the lasting corruption needs the double-settle without an intervening dirty mark — exactly what the retry sequence produces since the retried call's own `markShadowReceiversDirty` settles the stale count, not a recount.
- **Fix sketch:** Idempotency stamp on the record (`record.disposedAt`/`_disposed`) early-returned at 8076, or clear `receiveShadow` inside `disposeObjectNode` so re-walks count zero — the former is narrower and safer. Also make the sync fallback mirror the real result: `boundaryDisposeMeasure.settled = (settled === true)` at 10450 instead of unconditional true.
- **Effort:** S. **Impact:** L-M — needs a retry-after-error path; when it lands it stalls shadow refresh rather than wrong pixels. **Risk:** L.

### F4 — `_initEventLights` mounts 6 live PointLights with no census-epoch bump (latent seam)

- **Evidence:** `src/render/vfx.js:14939-14970` — `_initEventLights` runs `this._scene.add(l)` six times, no `noteShadowCensusLightMutation` anywhere in vfx.js (contrast: weaponLights.js:41, flightOverheadPresentation.js:32, and the mounted-pool dispose bumps). Deferred re-attach path exists (`update()` 12130: `_initPools(); _subscribeOnce()` under `!this._scene`).
- **Mechanism:** The memo's freshness contract relies on mount order, not notification: the pool mounts during `_initPools` before the first `_shadowCensusForFrame` mint, so the sig is correct today. Any reorder — an early census read during boot, or a future re-init while `_scene` is live (which would also double-mount the lights — `_initEventLights` re-adds unconditionally) — serves a stale signature for the rest of the run. The sig misses are silent: held sessions keep reusing a census that predates the lights.
- **Fix sketch:** One line: `noteShadowCensusLightMutation()` after the mount loop (and a defensive once-guard on the pool so a re-init removes rather than doubles the lights). Also cheap: assert in `_initEventLights` that `this._lights` is empty before adding.
- **Effort:** S. **Impact:** L today (masked by ordering), M as a latent hazard — census memo spans the whole run. **Risk:** L.

### F5 — Enumerated residuals of the castBand release clause ordering (prompt area b)

- **Late-by-one is confirmed but bounded:** `state.castBand` is written inside `finish()` (`shadowCasterPolicy.js:364`) *after* the renderer's release check reads `shadowCasterBand(root)`, so the band clause fires one sync late by construction. Not a defect on its own: the flip itself forces the traverse that writes the band; the next eval releases. Bounded to one extra sync.
- **Band-1-minted park self-release: YES, once.** A park minted while the stamped band is 1 (over-cap abort park, 25747) that later takes a withhold-again sync gets stamped `castBand=0` by that sync's own `finish()` — the *park's own withhold* creates the band delta the clause then treats as a regime change (25145-25152) → one spurious PLAIN release + re-collect, after which the re-minted park stamps 0 and the clause goes quiet. Self-limiting to one churn cycle per park; still worth folding into the F1 fix (compare against mint-context, not post-withhold stamps).
- **Band regime changes needing early-unpark:** `oqX/oqZ` drift release already covers ortho-cell moves; `dirtySeq` covers LOD/invalidate; `lightSigEpoch` covers census changes. The one uncovered regime term is `opts.allowCast` itself (hysteresis can flip the band on position with no dirtySeq bump — that's the intended job of the denied/band clauses). No additional term identified.
- **Effort:** folded into F1. **Impact:** L-M. **Risk:** L — note the audit surface here overlaps F1; do not land a separate band-clause change that re-tautologizes.
