## 2. Findings (ranked)

### F1 — Deferred `_initPools` can mount the 6 visible event PointLights onto a live mid-flight scene with no `noteShadowCensusLightMutation` bump
- **Evidence:** `src/render/vfx.js:14938–14955` — `_initEventLights` loops `this._scene.add(l)` for `EVENT_LIGHT_POOL_SIZE = 6` (vfx.js:422) visible-forever PointLights; no census bump anywhere in vfx.js (grep: symbol absent — needs a new import). Deferred call site: vfx.js:12128–12132 (`if (!this._scene) { ... }` inside `update()`; the `_initPools()` + `_subscribeOnce()` call is at :12130) — inside `update()`: `if (!this._scene) { if (state.render.scene) { this._initPools(); this._subscribeOnce(); } ... }`. `_initPools` early-returns `if (!scene) { this._scene = null; return; }` (vfx.js ~:2160), so when vfx.init ran before `state.render.scene` existed, the pool mounts lazily mid-flight on the first update that sees a scene.
- **Mechanism:** `lightCensusSignature` (shadowDepthAdmission.js:401–436) counts every visible `isLight` — the six mounts are a real signature mutation, but the epoch never bumps. `_shadowCensusForFrame` (renderer.js:25515–25525) keeps serving the pre-mount sig; the parked-entry lightSig compare (renderer.js:25122–25129) is prefilted on `lightSigEpoch !== shadowCensusEpoch()`, so the drift-release can never fire on this change — parked roots wait out the recheck backstop (up to ~16 s escalated) instead of re-verifying. Larger seam: when the deferred path does fire mid-flight, six `visible` PointLights appear after lit programs linked — `numPointLights` is baked into program keys, so the next presented render re-links every lit material inside the presented pass (the exact "bloom brick" class the W-pinned-flags contract exists to prevent). The unready guard hides still-linking drawables but the link work itself stalls the frame. The event lights are NOT in `_vfxOwnerRoots` (vfx.js ~:2056–2140), so the perf-isolation path does not touch them — the only live seam is the deferred `_initPools`.
- **Fix sketch:** `import { noteShadowCensusLightMutation } from './shadowDepthAdmission.js'` at the top of vfx.js and call it once after the `_initEventLights` mount loop (one bump for the batch — the mounts are observed atomically by the next census read anyway). For the deferred path, additionally consider deferring the whole `_initPools` to a post-present arm when `update()` is the caller — the comment at vfx.js:12130 marks the seam "defensive", and if it fires in real runs the program rekey is the hitch; if it truly never fires post-boot the epoch bump alone suffices.
- **Effort S** (the bump; M if deferring `_initPools`). **Magic-frame impact M** — conditional on the deferred path ever firing after programs link; the census staleness alone is L (bounded by recheck backstop). **Risk low** — the bump only opens a release window the machinery already handles.

### F2 — Whole-scene receiver recount can still land inside a presented frame on dirty-marked frames
- **Evidence:** `_syncShadowMapEnabled` (renderer.js:26220) runs every presented frame (renderer.js:24068); on `_shadowReceiversDirty || tally.dirty` it pays `this._shadowReceiverTally.resolve(this.scene, {force})` (26239) → `recount` = `scene.traverse` (shadowReceiverTally.js:51–60), or the raw fallback `this.scene.traverse` at 26248 when no tally. Dirty sources that mark without a measured delta: `_markShadowReceiversDirty` at 21205 (mass mesh clear — amortized, fine), 16436 (settings flip — necessary), unsettled `boundaryDisposeMeasure` fallback at 10486–10497/10500, and unmeasured `_noteShadowMeshAdded/Removed` helpers at 8110/8118 (`countShadowReceivers(root)` subtree walks — bounded but synchronous).
- **Mechanism:** any unmeasured teardown mark converts the next presented frame's `_syncShadowMapEnabled` into an O(scene) traverse (~whole-graph DFS, tens of thousands of nodes in a dressed sector) inside the pass. Abandoned/sector-churn teardowns can chain dirty marks across several consecutive presented frames.
- **Fix sketch:** the count only gates `shadowMapActive` (refresh scheduling), and flags are pinned, so a ~one-frame stale count is safe: serve the last count and drive `recount` via a chunked twin across timer gaps (settled → publish, matching the `boundaryDisposeMeasure` pattern this lane already uses), or thread measured receivers through the remaining unmeasured marks (the 10496 fallback already knows `measure.receivers` when the walk completed — the unmeasured marks at 8110/8118 are the real gap).
- **Effort M.** **Impact M** (rare frames, but multi-ms each when they land). **Risk medium** — a lagged count could briefly hold `shadowMapActive` on a zero-receiver scene; bounded to one wasted map render.

### F3 — `scene.updateMatrixWorld()` still walks the live spine atomically every presented frame
- **Evidence:** renderer.js:26588 — `_renderPostRoute` calls `scene.updateMatrixWorld()` unforced before every presented dispatch (comment at 26583–26587 documents the design). Vendor prune: `vendor/three.module.js:139–140` skips `sfMatrixFrozen` subtrees on clean frames. Freeze coverage: `staticChildMatrices.js:59–145` (`freezeStaticChildMatrices`, `freezeStaticTransformRoot`, `freezeStaticTransformRootMarked`); pre-freeze cost quoted in-tree at renderer.js:20233 ("~11 ms a frame" on the owner's iGPU before the freeze machinery).
- **Mechanism:** this is the residual *after* the freeze waves, not a regression — what remains is the live spine: every posed entity root (matrixAutoUpdate true), all lights/cameras/animated nodes, vfx pool roots, plus O(degree) flag checks on frozen children of every visited parent. Worst case ≈ total non-frozen node count — likely the largest single atomic JS walk left on the presented path. This is enumerated per hunt item (e); I flag it here because it is the top residual and has a conceivable path.
- **Fix sketch:** replace the whole-scene compose with a dirty-branch walk — since `scene.matrixWorldAutoUpdate` is already false, the compose exists only to propagate parent writes: collect pose-writing roots into a per-frame dirty set (the write paths already funnel through known pose APIs) and call `updateMatrixWorld` on just those roots. Or freeze pool roots whose local transforms are written via explicit `updateMatrix()` and never compose. Either is surgery on the transform pipeline.
- **Effort L.** **Impact M** (every frame, but the frozen-out share is already the bulk of scene mass). **Risk medium-high** — a missed dirty branch renders stale matrices; correctness is load-bearing.
