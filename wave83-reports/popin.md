## Findings (ranked)

### F1 — A never-settling launch-lane re-kick pins `covered` + `kickClaims` forever: per-archetype coverage lie, guaranteed pop-in at live spawn (fresh)

- Mint: `src/render/renderer.js:18289-18293` — `_mintWarmReKick` writes `covered+1` on `warm.coveredMap` and `claims+1` on `_swarmWarmReKickClaims` before dispatching `reKick(1)`. `entry.reKicked = true` (`:18287`) makes it one-strike.
- Release: only inside the kick's own settle at `:18317-18324` — `releaseClaim(swarmWarmOutcomeClaims(settled) && warm.building === true)`. Both decrements ride that `.then`; there is no timeout on the kick promise itself.
- The launch warm's settle deadline (`_armCrucibleWarmBuildingSettle`, `:18245-18262`) clears `warm.building`/`root.userData.warmBuilding` at `warm.settleDeadlineAt` while legs run detached — it does NOT release coverage or claim pins for attachments that never settled.
- Consume: the deferred warm's fresh filter (`_warmSwarmDeferredRoster`, `:18844-18846`) admits a row only when `covered <= reKickClaims`. A wedged kick (decode request whose promise never resolves — the same class the W9-hitches stale-delivery guard drops at the worker boundary) leaves `covered=1, claims=1`: `1 <= 1` → the archetype is filtered out of every later dwell's `fresh` set for the rest of the run.
- Mechanism: that archetype's next live spawn has no warm decode waiting — it pays the glass-admission decode in-frame = the pop-in this machinery exists to kill. Self-limiting (one archetype per wedged promise) but silent.
- The deferred lane already handles the identical case correctly: at the settle deadline, `timedOut` rows read per-kick results from `pendingAttachmentResults` (`:19186-19191`) and release non-claimed coverage via `unmarkEnemy` — a never-settled kick has no recorded result → `swarmWarmOutcomeClaims(undefined)` is false → released. The launch-lane shared mint has no equivalent.
- Fix sketch: mirror the deferred lane — per-kick `pendingAttachmentResults`-style record at `_mintWarmReKick` dispatch, plus a sweep at `warm.settleDeadlineAt` (inside `_armCrucibleWarmBuildingSettle`'s terminal `.then`, or the existing 30 s `WARM_BUILDING_SETTLE_DEADLINE_MS` path) that releases `kickClaims`/`covered` pins for kicks with no recorded settle. Cheaper variant: wrap `reKickResult` in `Promise.race([it, timeout → {status:'warm-kick-timeout'}])` before pushing to `pendingAttachments`, so the existing settle handler always fires `releaseClaim(false)` (timeout is unclaimed → errs toward re-warm, the safe direction).
- Effort S–M | magic-frame impact M (rare trigger; consequence is a real per-archetype in-round pop-in) | risk L (every release direction here is already the safe direction).
