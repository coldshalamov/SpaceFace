### F1 — `_drainProtectedFirstFlightBuildsSteps` repartition still truncates at the mint head: rows appended while the repartition is parked are dropped with their `queuedIds` stamps surviving — terminal burial for exempt (rescue/on-glass) builds during the first-flight hold

- **Evidence.** `src/render/renderer.js:20880-20926`: `const queue = this._meshBuildQueue` + `const head = this._meshBuildQueueHead | 0` mint at `:20885-20886`; `const tail = queue.slice(head)` snapshots `[head, mintLength)` at `:20903`; the eval loop yields per 256 rows (`:20907-20914`); write-back `queue.length = head` at `:20922` truncates to the **mint-time** head and pushes `hoisted`/`remainder` at `:20923-20924`. The repartition only runs while `holdFirstFlightStreaming` holds (`:2145-2171`), where the exempt-enqueue iterator `enqueueHoldExemptMeshBuildsSliced(owner, 4)` (`:2164`, parked `_holdExemptEnqueueIter`) minted on the same 100 ms beat appends to the live queue while the parked drain (`owner._protectedFirstFlightDrainIter`, `:1901-1923`, driven ≤4 ms per pump) is suspended. `enqueueMeshBuildCandidate` dedupes on `_meshBuildQueuedIds`, cleared only at `clearAllMeshes`.
- **Mechanism.** An append landing while the repartition is parked sits at an index ≥ the mint `queue.length`; the `queue.slice(head)` snapshot predates it, so it is in neither `hoisted` nor `remainder`; `queue.length = head` then pushes only the snapshot — the appended row is truncated out of the array while its `queuedIds` stamp persists, so the next collect beat's `enqueueMeshBuildCandidate` refuses it. During the ~20 s hold this is terminal for the epoch: the dropped rows are exactly the exempt cohort (rescue actors, explicit focus, on-glass rows) the hold path exists to build first — a permanent missing-body hole. This is the identical stale-head-burial class W82 F1 fixed in `hoistDeadlineGlassMeshBuildsSteps` (live-head re-anchor + `queuedIds` filter + inline v=2 re-eval at `:3185-3202`); this sibling repartition got W82's debit instrumentation but not the anchor rewrite, and it additionally lacks the stamp filter the rehoist got at `:20826`.
- **Fix sketch.** Mirror the hoist fix: re-read `liveHead`/`liveQueue` at write-back, truncate at `liveHead` not `head`, skip rows no longer in `_meshBuildQueuedIds`, and let post-snapshot appends pass through untouched (they already sit past the snapshot tail — truncating only `[liveHead, liveLength)` preserves them if the truncation reads live length first; safest form: rebuild `queue.splice(liveHead, queue.length - liveHead, ...partitionedStamped)`). Effort S.
- **Effort** S · **Magic-frame impact** H — the buried rows are the on-glass-deadline cohort the hold exists to serve; failure mode is a permanent hole, strictly worse than a stand-in · **Risk** low — ordering-only machinery, same pattern as the landed W82 fix.

### F2 — `rockSurfaceLibraryReady.then` reskin window: the live `_meshes` reskin runs first but the compile legs never cover live roots — a presented frame inside the window draws a just-reskinned rock holding a never-compiled interned PBR material

- **Evidence.** `src/render/renderer.js:9384-9486`. Reskin loop over `this._meshes.values()` with per-32 `await yieldToBrowser()` at `:9393-9396`, then `_rosterPrewarmRoots` at `:9400-9403`. Compile legs cover only `parallaxLayers.activeGroups()` (`:9406-9409`), `_rosterPrewarmRoots` (`:9424-9427`), and `poolCompileRoots` (`:9451-9454`) — the live rock roots reskinned at `:9394` are never compiled in the continuation. `upgradeBareRockMaterials` assigns interned `astMaterial(typeId, def, tint, variant)` PBR materials (`visualFactory.js:2411-2426`) — minted fresh at reskin time (bare→PBR swap means no `currentProgram` exists on them yet). The unready-drawable guard (`bloom.js:1333-1392`) only fires when a scan triggers — program-set growth, scene-child change, mounted roots, or `pendingSubjects.size > 0` (`:1240-1290`); a material object swap on existing visible meshes produces none of those in a quiet window (steady-state early return `:1248-1250`).
- **Mechanism.** The continuation yields between legs — presented frames interleave. A frame landing after the reskin loop but before the compile legs draws live rocks whose new interned PBR material has no linked program: either three.js links it synchronously inside the presented frame (cold link + texture upload — the brick class the admission machinery exists to prevent), or, if some unrelated pending subject armed the scan that frame, the per-material guard hides the rocks → they blip out until linked. Pre-W82 this whole block ran in one atomic microtask; pacing introduced the interleaveable window. The window is bounded (the compile legs are a few yields away — ~2-6 presented frames), and every reskinned family is later covered because the interned materials are shared — but the first draws inside the window pay the family's cold link / pop-out.
- **Fix sketch.** Reorder legs so interned PBR materials link before live meshes hold them: run the `_rosterPrewarmRoots` reskin **first**, compile the prewarm roots (they now carry the same interned PBR materials the live reskin will assign — program key + shared textures warm globally), then reskin `_meshes`, then keep the remaining legs. Alternatively mark reskinned live roots `pipelinesPending` until the compile legs land (heavier — hides real models; prefer the reorder). Effort S.
- **Effort** S · **Magic-frame impact** M — a bounded mid-flight window of cold links or blip-outs on every live bare rock; probability real whenever the surface library resolves after first playable (the documented slow-decode case this continuation exists for) · **Risk** low-M — the reorder changes which reskin count feeds the `count > 0` compile gate; split the gate (compile when either reskin produced work) to keep leg coverage identical.

### F3 — `parkedRelease` on light-sig / ortho-cell drift bypasses the collect gate: a band-1 parked root falls through every withhold branch to a live `allowCast` restore on stale-marked meshes — cold depth link inside the next presented shadow refresh

- **Evidence.** `src/render/renderer.js:23723-23737`: `parkedRelease` fires on `dirtySeq > parkedEntry.seq` **or** `parkedEntry.lightSig !== this._shadowCensusForFrame()` (`:23725-23726`) **or** ortho-cell drift via `oqX/oqZ` (`:23727-23731`); the release deletes the park record, the `_withheldDepthCasters` cache, and `sfDepthUndrawableCycles` — no invalidate, no re-queue. Then `parked=false`/`queued=pending-only` (`:23738-23739`), `selfDirty` holds (the arm stamped `STAGE_SELF_DIRTY_KEY = dirtySeq` at `:24277` for the leftover-park class minted at `:24250-24264`), `collectGate` at `:23769-23771` stays closed for band-1 (`dirtySeq > stampedSeq && dirtySeq > 0` fails — no dirty bump landed), and the else-if chain (`:23833-23858`) requires `queued` or a cache — both false → falls to the live `syncShadowCasterPolicy` at `:23859-23869`.
- **Mechanism.** The `dirtySeq`-bump release is safe (the new generation re-opens the band-1 collect gate → collect → withhold+requeue). The sig/ortho releases are not: under a drifted light census every mark is stale (`mark.l !== newSig` → `casterDepthMarkCurrent` false → unstaged), and an ortho drift can make an off-ortho "undrawable leftover" drawable — the exact population the park/recheck machinery exists to re-offer. The contrast that proves the hole: the `parkedRecheck` expiry path re-collects through the gate (withhold+requeue on stale marks); the drift releases delete the withheld state and fall through to live restore, and nothing ever re-queues the root afterward (clean band-1, selfDirty, not pending, not parked → gate closed permanently until an unrelated dirty). - **Fix sketch.** Fold non-dirty releases into the collect: when `parkedRelease` fires on `lightSig`/`oqX`/`oqZ` (not the dirtySeq compare), set a flag that ORs into `collectGate` (equivalent to forcing `parkedRecheck = true` for this pass) so the same sync re-collects under the live census — stale meshes re-enter the withhold+requeue path instead of live restore. The withheld-cache delete is fine to keep (the collect re-derives under the new sig); only the gate must open. Effort S.
- **Effort** S · **Magic-frame impact** M-H — recurring trigger (the ortho cell drifts every half-extent of player travel) × leftover-park population; each occurrence risks the in-frame depth-program link this machinery exists to eliminate. Likelihood gated by how many leftover-park roots carry drift-drawable meshes (genuinely undrawable-forever meshes harmlessly gain a flag that never draws) · **Risk** low — one extra bounded collect on an already-rare path, under the existing per-pass node/collect caps.

### F4 — Stale-array write-backs + consumed-re-add duplication across the mint→suspend→write windows (ordering degraded, never corrupt)

- **Evidence.** Three sites capture `this._meshBuildQueue` by reference at mint: hoist write-back (`:3132`, `:3189-3202`), `_reconcileMeshResidencySteps` rehoist (`:20803`, writes `:20839-20841`), protected repartition (`:20885`, `:20922-20924`). The drain epilogue compaction `queue = queue.slice(head); head = 0` (`:21332-21334`) replaces the array — a suspension that spans it leaves write-backs mutating a detached array. Rehoist/repartition scans also classify a consumed-then-re-added id at both its stale slot and its tail append (the `queuedIds` stamp survives both).
- **Mechanism.** Post-compaction write-backs land on the dead array: the repartition/reorder is silently lost (ordering heuristic only — the live array keeps every pending id, no loss of work). A consumed-then-re-added row enters the write-back twice → duplicate queue entries → drained twice (second pass skipped by `alreadyServed`/`_meshes.has` at `:21149`) → wasted dequeue budget, self-correcting. Re-added rows can also leap ahead of later rows via their stale slot — a small ordering violation vs the tail-append contract.
- **Fix sketch.** Re-read `this._meshBuildQueue`/`_meshBuildQueueHead` at each write-back and bail when the reference changed (the order is advisory; a lost repartition costs nothing real). Dedupe the write-back against the stale-slot identity if it still passes the stamp (a per-call `Set` of written ids is cheap at these sizes). Effort S.
- **Effort** S · **Magic-frame impact** L — worst case is lost ordering freshness and occasional wasted dequeue slots; no id loss, no corruption · **Risk** low.

### F5 — Refused-start `return 0` skips the terminal hoist segment's debit (paced-ledger undercount)

- **Evidence.** `driveHoist` posts `notePacedFrameSpend(now() - segStartedAtMs)` per **suspended** segment and re-mints (`:20999-21008`); on `hoistStep.done` it returns without posting the segment from the last resume to completion. The prologue gate's refused path `if (!(yield* driveHoist(this))) return 0;` (`:21016`) then bypasses the epilogue debit (`:21336-21338`). Under the inline sync drain the same gap exists but sums identically — the missing debit is only the terminal segment either way.
- **Mechanism.** A refused-start drain that paid a hoist tail-scan (up to one 256-row slice plus the O(tail) write-back) posts nothing for that segment onto a frame that was already over budget — the ledger reads the frame as cheaper than it was, weakening the very signal (`pacedFrameSpend`) the late-present gate consults. Bounded to one hoist segment per refused call.
- **Fix sketch.** Debit before the early return (`notePacedFrameSpend(now() - segStartedAtMs)` ahead of `return 0`), or post the terminal segment inside `driveHoist` on `done`. Effort trivial.
- **Effort** S (one line) · **Magic-frame impact** L — accounting-only; never changes what is drawn · **Risk** none.

## Lane hunts

**(a) Checked-sync branch end-state enumeration — can a still-unstaged queued root reach a live `allowCast` restore?** Enumerated every terminal branch of `_syncShadowCasterPolicyChecked` (`:23712-23913`):

- `unstaged.length > 0` → live sync + per-mesh withhold + cache union + invalidate/stamp + re-queue (`:23816-23896`) — withheld.
- `parked && unstaged === []` → park release → live sync — **legal**: the collect proved every caster mark-current (`:23820-23826`).
- `overCovered` (cap or node-budget abort) → whole-subtree withhold + re-queue with preserved scale (`:23827-23832`, `:23897-23905`) — withheld.
- `band !== 1 && queued` → withhold (`:23833-23834`) — withheld.
- `band === 1 && selfDirty && queued && cache-hit` → re-stamp cached flags, `return false` (`:23835-23848`) — withheld.
- `band === 1 && selfDirty && queued && cache-miss` → withhold (`:23849-23852`) — withheld.
- `queued` catch-all → withhold (`:23853-23858`) — withheld.
- Non-queued → live sync — legal gates only: band-1 needs `dirtySeq > stampedSeq` (a real dirty) to collect, else it trusts the stamped generation; band<1 non-queued collects every promote (`!queued` opens the gate); a non-queued root with `dirtySeq === 0 && stampedSeq === -1` (never invalidated) skips the collect — sound only under the documented invariant that every subtree attach/detach bumps `dirtySeq` via an invalidate seam (`:23841-23843` comment; seams enumerated: authored swap `:8930`, packaged graft `syncPackagedBodyShadowPolicy` `:10891`, partsLibrary `swapTo` on `shadowTreeChanged` `:9001-9007` + stale-root cleanup `:8969-8975`, the withhold's own stamp `:23889`, OFF→ON re-arm `:24447`/`:24487`, admission-start withhold `:10323`; retained-root visible-flips need no bump because the collector ignores visibility and the withheld set/marks already cover those meshes; living-hull attaches are all `transparent: true` — never castable).

Arm race: the arm is synchronous within `armCallbackAfterPresent`; pending entries are deleted at slice build (`:24035`) and every unrestored member is re-queued in `finally` (`:24339-24352`) including mid-slice throws — no slice member can interleave a sync while held, and leftovers re-prove marks via `casterDepthMarkCurrent(mesh, lightSig)` before any restore (`:24190-24199`). **The one gate that leaks: `parkedRelease` on lightSig/ortho drift — finding F3.**

**(b) Parked recheck earning scaled budgets — does the scale persist into the next park, and is growth bounded?** Yes and yes. `depthNodeScale` rides the park record (`:24102`, `:24263`), is carried into re-queues via `preserved` (`:23893-23895`, `:23902-23904`, `:24505-24508`) and merges `{...preserved, ...pending.get(root)}` so a live pending entry's scale wins (`:23940-23945`); re-parking re-mints from `entry.depthNodeScale`. Escalation is `min(8, ×2)` per over-cover (`:24106`); recheck cadence is `(96 + stamp%32) × min(8, 2^(cycles−1))` — bounded ~96→1024 syncs (`:24095`, `:24254`); `sfDepthUndrawableCycles` clears on release/restore/detach. One accounting wrinkle, not a defect: a scaled recheck spends `SHADOW_DEPTH_PASS_NODE_CAP × scale` from a **fresh per-root wallet** that never debits the shared `_depthCollectNodesLeft` (`:23790-23799`) — intentional (the base budget would over-cover every scaled root) but it means several coincident scaled rechecks can stack up to N_parked × 8×4096 nodes of collect inside one presented-frame sync, outside the nominal per-pass cap. Bounded, staggered by `stamp%32`, worth knowing.

**(c) Stepped drains' yield-per-row under mid-row mutation — can a row double-process or skip?** `_drainMeshBuildQueueSteps` row loop (`:21080-21328`): the yield sits only at the loop top (`:21082`); each row is atomic peek (`:21102-21105`) → deadline/budget/slice consults (`:21108-21144`) → dequeue (`_meshBuildQueueHead++` + `queuedIds.delete`, `:21145-21147`) → verdict/build/mount (`:21148-21327`). No yield can interleave peek↔dequeue.
