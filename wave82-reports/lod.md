### F1 — `hoistDeadlineGlassMeshBuildsSteps` anchors its rewrite at the mint-time head: mid-scan consumption or enqueue buries the deadline-glass rows it just promoted — terminal in-epoch invisibility for the highest-priority builds

- **Evidence.** `hoistDeadlineGlassMeshBuildsSteps` (`src/render/renderer.js:3069-3136`): `const head = owner._meshBuildQueueHead | 0` minted once at `:3072`; the verdict scan iterates `for (let i = head; i < queue.length; i++)` yielding every 256 rows (`:3092-3097`); the rewrite then truncates at the **stale** mint head — `queue.length = head` — and pushes `hoisted` then `remainder` (`:3120-3131`). Consume is `id = this._meshBuildQueue[this._meshBuildQueueHead++]` + `_meshBuildQueuedIds.delete(id)` (`:20886-20888`), and concurrent drains run under a suspended hoist: `owner._drainPendingMeshBuilds()` fires at every pump tail — reconcile path `:2284`, poll path `:2327`, drain path `:2330` — and the cook lane's `drainIter` (`drainMeshBuildsBehindShell` `:11473-11533`) resumes across awaits. Enqueues also append mid-scan (`_holdExemptEnqueueIter` `:2777`, `enqueueMissingMeshBuildsSteps` `:20284`). Re-enqueue is stamped out by `queuedIds.has(id)` at `enqueueMeshBuildCandidate` `:936`; `queuedIds` is only cleared wholesale at `clearAllMeshes` (`:20051` region), never by queue reset/reset-slice (`:21070-21076`).
- **Mechanism.** A hoist scan suspends only when the tail exceeds 256 rows — exactly the deadline-glass-buried-behind-backlog case it exists for. While suspended, a pump-tail drain consumes C rows (live head → H0+C) and/or enqueues append. At rewrite: `queue.length = H0` truncates everything past the stale head (dropping freshly-appended rows while their `queuedIds` stamps survive → never re-queued, never built), then the pushed partition lands starting at index H0 — the first C pushed entries sit **below the live head** and are unreachable forever. Because `hoisted` is pushed first, the buried rows are the deadline-glass builds — entities already crossing onto the glass — and they stay stamped in `_meshBuildQueuedIds`, so `enqueueMeshBuildCandidate` returns false for them forever after. The drain's own epilogue never rescues them: `head >= length` reset or `head > 64` compaction (`:21070-21076`) drops them from the array while the stamps persist — burial is terminal for the epoch. Consumed rows do get repacked as ghost entries (already `queuedIds`-deleted → `alreadyServed` skip at `:20890` — wasted dequeue only). This is the same repack-under-live-head defect class as the W81-found drain-epilogue issue, in the second hoist site the wave-82 prompt called out.
- **Fix sketch.** At the rewrite, re-read `const liveHead = owner._meshBuildQueueHead | 0`; set `queue.length = liveHead` (not `head`), and filter both pushes through `owner._meshBuildQueuedIds.has(id)` — consumed ids drop out, appended ids (added below the scan floor are impossible since appends land ≥ old length, but truncating them is the bug) stay; simplest correct form: rebuild `tail = queue.slice(liveHead)` first, partition that, then `queue.length = liveHead; queue.push(...partitioned)`. Effort S.
- **Effort** S · **Magic-frame impact** H — the buried rows are specifically the on-glass-deadline entities; the failure is a permanent hole where a body should be, strictly worse than a stand-in · **Risk** low — ordering-only machinery, but the fix must not reintroduce the over-cover partition for already-consumed rows.

Fresh-appended rows during the scan also get repartitioned (their ids keep stamps — ordering-only). - **Fix sketch.** Guard the repack: capture `const liveHead = this._meshBuildQueueHead` at write time and partition only `pendingBuilds.slice(liveHead)` rows still stamped in `_meshBuildQueuedIds`; skip indices below liveHead. Rows are not lost — `queue`/`head` persist — but the designed "suspend and continue" behavior silently degrades to "suspend and abandon"; under sustained saturation the build tail drains at fresh-mint cadence, not the slice clock's intent. - **Fix sketch.** Re-stamp `startedAtMs = now()` inside the `drainBeat !== drainBeatSeen` block (`:20836-20842`) — the whole-call clock becomes per-resume like every other term there; the paced ledger already bounds genuine overspend. Effort S.

### F4 — Released-boundary teardown loop has no final liveness re-check: a boundary re-attached between its `releaseOwner` visit and its teardown turn gets disposed live
