# docs/ — Agent Notes

> Scope: `docs/` and all descendants. Root `AGENTS.md` still applies. Start at
> [`README.md`](./README.md); do not sweep the entire tree for an ordinary feature task.

## What belongs here

- Engineering navigation and troubleshooting: `MODULE_MAP.md`, `COMMON_BUGS.md`,
  `VALIDATION_WORKFLOW.md`.
- Agent orientation and behavior: `ORIENTATION.md` (repo map / reading ladder), `AGENT_OPERATIONS.md`
  (working agreement in full), `AGENT_LESSONS.md` (owner preferences, verified facts).
- Agent policy and context routing: `POLICY_MANIFEST.md`, `SEARCH_CONTEXT.md`.
- Generated code projections: `EVENT_ROUTING.md`, `SYSTEM_REGISTRY.md`.
- Narrow technical contracts and acceptance records: `Spec/`.
- Setting, story, and content source material: `worldbuilding/`.
- Historical integration evidence: `handoffs/`.

Whole-program status belongs in `design/program/`, architectural decisions in repo-root
`ARCHITECTURE.md` or `design/adr/`, and product/system plans in the relevant `design/` suite.

## Truth and maintenance rules

- Verify code claims against the working tree; do not copy line numbers, counts, or completion claims
  from an old handoff.
- `EVENT_ROUTING.md` and `SYSTEM_REGISTRY.md` are generated by `npm run build:indexes`. Never patch
  either file manually.
- Treat `handoffs/`, `Spec/MASTER_MAKEOVER_PLAN.md`, and review iterations as evidence/history unless
  a current authority explicitly activates them.
- A future plan may remain valuable when code does not exist. Label it as future or partial; do not
  convert absence into permission to delete the design.
- Link to one canonical source instead of duplicating policy or status prose.
- For new files, run `git add -N <file>` immediately. Preserve unrelated dirty-tree work.

## Verification

- Check changed Markdown links resolve.
- Run `git diff --check -- docs/`.
- After source event/registry changes, run `npm run build:indexes` and review the generated diff.
