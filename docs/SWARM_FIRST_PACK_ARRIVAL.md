# Training: first-pack arrival

Reconciled against `31a011002036e625c971d315f8da08a7a32687ee`.

Ordinary Swarm keeps its immediate horde. Only a plan carrying the existing explicit Training
`openingLesson` arms scout coaching and held-pack presentation; this patch does not select that plan.

The existing materialization receipt adds generation-stamped actor IDs and scheduled package
identity. Release intent is silent. The first actual admitted held body triggers one arrival cue
with its archetype and actual compass bearing. Refusals, stale occupants, foreign packages, and
ordinary/later waves cannot claim arrival. Fortify's existing gate/source-gate/ingress receipt is
preserved: scheduled identity uses the source gate, direction uses the actual body's position.

The same cue can include an untaught counter rather than compete with a separate higher-priority
hint. Existing objective priority, five-line budget, spawn timing and combat authority remain intact.

Focused tests: `test/swarm-pack-arrival.test.mjs` executes current dispatch/release, announcer,
compass and voice-queue logic with explicit materialization/runtime ports. This is not a browser,
native full-encounter or audio acceptance claim.

The current production node-safe manifest includes both wave and announcer owners, so identity
validation occurs together inside the authoritative worker before presentation crosses the wire.
The focused suite also imports the real event bridge and structured-clones generated admission and
voice payloads, verifying no depth rejection or loss of actor IDs/generations. This does not boot
the browser worker itself.
