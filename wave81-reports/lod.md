### F1 — `rebuildShipMesh` remount gap: the old boundary disposes in-emit and the new mesh has no stand-in and no keep-drawing bridge — non-protected hulls pop out for the whole admission window; protected roots draw the unlinked mesh raw in-frame

- **Evidence.** `rebuildShipMesh` (`src/render/renderer.js:20476-20531`): `scene.remove(old)` + `_despawnDisposeQueue.push(old)` at `:20485-20493` inside the same emit that builds the replacement — the outgoing hull stops drawing immediately. The new mesh mounts `scene.add(m)` at `:20514`, then `geometryPending` is stamped at `:20519` only when `hasUnresidentGeometry(m)` (`:20516-20518`), and `_liveGeometryAdmissions.enqueue(e, m)` queues it (`:20521`). `shouldSubmitEntityMesh` (`src/render/entityMeshVisibility.js:35`) holds `geometryPending` roots invisible — the hull is **gone from frame** until the lane resolves: ambient drain cadence on success, `MAX_ADMISSION_RETRIES=4` × `RETRY_COOLDOWN_MS=4000` reopen loop on failure (`src/render/liveGeometryAdmission.js:36-47,250-256`). Protected roots (`isPlayer`/`forceRender`/`neverCull` — `entityMeshVisibility.js:63-65`) return `true` at `:21` **before** `pipelinesPending` (`:27`), `authoredPending` (`:32`), and `geometryPending` (`:35`) — a protected rebuild submits the same frame with its color program unlinked (`compileObjectPipelines` at `:20524` is a discarded `void` promise on the serial lane) and its geometry unuploaded — the in-frame link + vertex upload the latches exist to kill, plus a withheld-then-armed depth path the checked sync handles but the color pass does not. Emit sites reachable mid-flight: loadout/hull recompute `src/systems/ships.js:1990` (any entity incl. player), player `recomputeActiveShip` `ships.js:2315`, priority-courier service `src/systems/traffic.js:3644`. The `ship:appearanceChanged` → `rebuildShipMesh` handler is at `renderer.js:14773-14780`. The `!m` early-return at `:20497` shares the same hole: old disposed, nothing mounted — the entity stays meshless until the next reconcile re-enqueues.
- **Mechanism.** Mid-flight `appearanceChanged` minting unresident geometry (first-seen loadout/weapon/tier combination — cached combos re-stamp resident and draw clean): non-protected hull vanishes at the emit's next present and re-pops when the admission lane resolves — a pop-out → pop-in pair inside the magic frame, the exact "nothing pops into existence late" class. Protected roots take the opposite defect: draw immediately raw, paying the link+upload inside the presented frame. The pool solved this identical class with the `retiring` keep-drawing bridge (`asteroidInstancePool.js:864-874`, OWNER note `:856-861` — "growing a bucket used to dispose the drawing batch on the spot … every rock of that kind vanished together and came back"); `materializeBoundaryResolvingMarker` (`visualOverrides.js:441`) exists for the authored-admission family but is never staged on the rebuild path.
- **Fix sketch.** Mirror the pool bridge: park the outgoing boundary in a `rebuilding` slot that keeps drawing its last committed state until the replacement clears `geometryPending`/`pipelinesPending` (then dispose through the existing despawn queue); bounded like `RETIRING_BATCH_MAX_SYNCS`. Alternative: stage `materializeBoundaryResolvingMarker` for the admission window — smaller change but visually swaps a real hull for a stand-in, which the bridge avoids entirely. Either must route the failure path (`!m` or exhausted retries) the same way.
- **Effort** M · **Magic-frame impact** M (narrow trigger — mid-flight appearance changes with unseen geometry — but a true pop-out/in or in-frame link when it fires) · **Risk** M — keeping the old boundary drawable defers the visual update and must not outlive a second rebuild or sector flip (park on epoch + bookkeeping clear like the depth-stage parked sweep).

### F2 — `extra` option spread can clobber the withhold verdicts' `allowCast:false` — latent seam, no current caller exploits it

- **Evidence.** `renderer.js:22964-22966`: `syncShadowCasterPolicy(root, lodLevel, { ...syncOpts, ...(extra || {}), out: receiverOut })` — `out` is forced after the spread but `allowCast` is not; every branch the queue-time withhold lands on (`overCovered` `:22937`, `band!==1&&queued` `:22938`, band-1 self-dirty cache-miss `:22957`, catch-all `:22962`) writes `syncOpts.allowCast = false` **before** `extra` merges. All current `extra` callers pass only `{ preCountRoot }` (`:8653` onAuthoredAssetSwap, `:10582` packaged commit); `syncShadowCasterPolicy` itself reads only `allowCast`/`preCountRoot`/`out` (`src/render/shadowCasterPolicy.js:245-323`).
- **Mechanism.** A future call site passing `extra = { allowCast: true }` (natural for a caller wanting to force a restore) silently defeats the entire withhold contract — a still-queued unstaged root reaches live `allowCast` and links its depth variant inside the presented shadow refresh. Not a live bug; a one-field-typo-shaped hole in the gate this lane's correctness rests on.
- **Fix sketch.** Apply `allowCast:false` after the extra spread whenever a withhold verdict fired (reorder to `{ ...syncOpts, ...(extra || {}), ...(syncOpts.allowCast === false ? { allowCast: false } : {}), out }`), or strip `allowCast` from `extra` at function head.
- **Effort** S · **Magic-frame impact** L (contract hardening — prevents re-opening the cold depth-link class) · **Risk** none.

### F3 — Retiring-pool bridge force-releases at 300 syncs while the replacement still sits `pipelinesPending` — the whole rock family blinks exactly when the admission lane is wedged

- **Evidence.** `settleRetiringBucketMesh` (`src/render/asteroidInstancePool.js:508-518`): `if (nextPending && retiring.frames < RETIRING_BATCH_MAX_SYNCS) return true;` — at the cap the retiring batch is disposed unconditionally (`:515-516`) even while `next.userData.pipelinesPending === true`, so bloom's unready-drawable hide (`entityMeshVisibility.js:27`) keeps the replacement submitted-but-hidden → every record of that bucket family vanishes until the lane clears. The bridge exists precisely because "every rock of that kind vanished together and came back" (`:856-861`).
- **Mechanism.** A genuinely wedged or starved admission (queue pressure, repeated urgent-flip churn) turns the failsafe into the defect it prevents — a family-wide blink ~5 s in. Deliberate bound (a never-settling replacement can't pin a zombie batch forever), so the residual is the cap's blindness: it releases on elapsed syncs regardless of whether the replacement is actually admitted vs. merely pending.
- **Fix sketch.** At cap, re-request/re-kick the pending admission rather than releasing blind (the lane already dedupes), or extend the bridge while `nextPending` holds and the pending admission is still live — keeping the failsafe for a truly dead lane (e.g. retry-exhausted).
- **Effort** S · **Magic-frame impact** L-M (bounded blink of one instanced family under wedge; rare) · **Risk** M — must still guarantee eventual release so a dead admission can't pin retired geometry forever.
