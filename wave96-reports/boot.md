## Findings (ranked)

### B1 — `lateRoots` literal pays two atomic whole-scene traverses inside one un-paced cook leg

- evidence: `src/render/renderer.js:13940-13955` — the non-warm `lateRoots` array literal evaluates `collectLateAdmittedCompileRoots(this._meshes, openingSubjects)` (:13952) and `cookPoolCompileRoots()` (:13953) in a single synchronous expression. The lazy memo's first mint at :13891-13893 runs `collectInstancePoolCompileRoots(scene)` — a whole-scene traverse (`src/render/latePipelineAdmission.js:220-237`; the Steps twin's own comment at :270-276 cites the walk as "~21k-node traverse"). `collectLateAdmittedCompileRoots` (:46-64) traverses every `_meshes` root's subtree — the full entity forest.
- mechanism: the literal sits between `paceCookStretch()` boundaries with no yield inside — ~2× ~21k node-visits land as one main-thread block inside `cookLiveSceneGpu` while the loading shell is the only presented surface. The shell's rAF animation freezes for the block: exactly the frozen-loading-screen class this lane hunts. The paced per-root loop at :13985-13989 only starts after the literal resolves.
- fix sketch: drive `collectInstancePoolCompileRootsAndSubjectsSteps(scene, 256)` under `paceCookStretch()` ahead of the literal — the seal path already does exactly this at :13095-13111 — and derive both `poolRoots` and the late-entity list from that one stepped walk. `collectLateAdmissionCensus` (:15393-15420) already implements the mesh-subtree derivation (meshRootSet + ancestor test) that replaces `collectLateAdmittedCompileRoots`'s per-root re-traversal; factor or inline it. Keep the sync branch as the Steps-less fallback.
- effort: M | magic-frame impact: M | risk: low — same predicates and walk order; pure restructure with a sync fallback.

### B2 — `_shadowCensusForFrame` serves the pre-mutation sig for the rest of the seq

- evidence: `src/render/renderer.js:25327-25349` — `epoch` latches at the first call per `_viewSyncSeq` (:25334-25340); the memo hit-test at :25342 compares `memo.epoch === epoch` against the LATCHED value, so a call after `noteShadowCensusLightMutation()` re-enters the pre-mutation memo. Mutation sites that can only bump the raw epoch: `src/render/precompile.js:180/:198/:876/:880/:911/:918` (stand-in PointLight mounts/removals), `renderer.js:27301/:27323` (`disposeObjectNode` light teardown — its own comment at :27299-27301 says "same-seq census memos minted before this teardown would serve the stale sig" — the intent the latch defeats; module-level functions cannot reach `this._shadowCensusMemo`). Renderer-internal sites that DO clear the memo: :25888, :26051, :26084. Doctrine comment at `src/render/shadowDepthAdmission.js:426-429` claims the bump means "a same-seq memo can't serve the pre-mutation signature" — true for the session layer (`heldSession`/`censusStale` at :620/:639/:716 check the RAW epoch), false for the renderer memo.
- mechanism: a light mutation mid-seq — `syncVisiblePointLightBudget` at :15330 runs inside `runPostOpeningPipelines`' own legs — leaves every same-seq consumer reading sig E while the live light set is E+1: park-entry `lightSig` mints (~:25560/:25687), the collect gate's `collectUnstagedShadowCastersFlag` (:25085, :25901), arm-drain verdicts (:25440+). Bad direction: a mark minted under sig E reads "current" after the census became E+1 → the mesh's depth-stage verdict is carried under the wrong light set for the remainder of the seq (≤1 presented pass), self-healing at the next latch. Conservative direction: post-mutation marks read stale → extra withholds. Bounded: `_viewSyncSeq` bumps once per `syncEntityViews` (:22526), so the window never crosses seqs.
- fix sketch: read `shadowCensusEpoch()` fresh each call (O(1)) and key `_shadowCensusMemo` on `{seq, scene, rawEpoch}` — the memo still serves all same-epoch same-seq reads; the first call after a bump re-mints once lazily. Honest trade-off: the latch exists for pass-internal verdict consistency (:25330-25333), but a mid-seq mutation means the world already changed — serving sig E is consistency with a dead world. If pass-internal consistency is judged load-bearing, the narrower fix is to fail-closed on the raw-epoch pair (`lightSigEpoch` is already stamped beside every `lightSig` at the park literals) rather than serving the stale sig.
- effort: S (memo key) | magic-frame impact: L-M | risk: low-medium — the latch is deliberate, so the fix needs a pass over every `lightSig` consumer for consistency-vs-freshness assumptions.

### B3 — sync `lightCensusSignature(scene)` mints inside presented-frame legs

- evidence: `renderer.js:15656` (`const depthLightSig = lightCensusSignature(scene)` — minted once per `driveDepthCompile` call), :15661-15662 (`freshDepthLightSig()` re-mints on every stale retry, up to 4), :566-567 (`driveCompileShadowDepthPipelines` re-mints `lightSigOverride` per drift retry inside the arm's microtask). Each mint = one scene.traverse of ~21k nodes (`src/render/shadowDepthAdmission.js:401+`).
- mechanism: each call is an atomic whole-scene walk inside an otherwise-paced leg — paced around, not within; ~1-3 ms paid per drive call × per drift retry inside the loading shell's frame budget.
- fix sketch: consume `this._shadowCensusForFrame()` when its raw epoch matches `shadowCensusEpoch()` — the memo IS `lightCensusSignature(scene)` output (:25345). Requires B2's raw-epoch memo key to stay honest post-mutation (without it the memo may serve stale — exactly what these sites must not accept). Fallback: a `lightCensusSignatureSteps` twin driven in the paced legs.
- effort: S-M | magic-frame impact: L-M | risk: low — reuse only when raw epochs match; drift must still force a fresh mint.

### B4 — `collectCompileSubjects(root)` atomic per root inside paced loops

### B5 — superseded-cook warm roots stay in `_rosterPrewarmRoots` after scene removal

- evidence: push sites :14272/:14324; inner finally at :14740-14745 `scene.remove`s the root but never splices the list (splice precedent at :18909-18915); consumers that then walk a detached root: rescan candidates :15767, sweeps :9741/:9829/:18364 (some legs filter `root.parent` — :13260 — not all).

- effort: S | magic-frame impact: L | risk: none.

### B6 — `disposeObject` sync leg in non-flight modes

## Lane residual hunt (a)–(e)

**(a) `postSupersededResult` consumers — CLEAN.** The tail `{skipped:true, superseded:true, queued, sector:sectorResult, lateRoots:0, depth:{skipped:true, reason:'epoch-superseded'}}` is minted only when `postSuperseded()` (passEpoch !== live enterSerial) fires — checked before AND after every `postPace()` yield (:15376-15384) and inside every rescan leg (census bail :15406, `subjectsForCompileRoots`, `dedupeLateSubjects`, unstaged collect :15734/:15811, `driveDepthCompile`). `preparePostOpeningPipelines` (:15840-15859): the released stamp lands ONLY under `passEpoch === live enterSerial && !_postOpeningRescanRequested` (:15826-15829) — a superseded tail never stamps released, so every later caller mints a fresh full pass. `_postOpeningPipelinesInFlight` clears on settle (:15857-15858 `inFlight.then(clear, clear)`) — nothing joins a resolved-superseded promise; in-flight joiners arm `_postOpeningRescanRequested` and force a re-sweep before release. Verdict: retry-next-epoch is preserved by construction.

**(b) `precollectedCasting` staleness — bounded one-pass miss, self-healing, not a defect.** `casting` is the leaf list minted once at drive entry (`options.precollectedCasting || (yield* collectPotentialShadowCastSubjectsSteps(subjects))`, shadowDepthAdmission.js ~:607); the reparent/mark stage iterates that frozen list — a caster attaching mid-drive inside an already-collected root subtree is NOT walked by the reparent stage (verified: `session.slice`/`sliceSteps` consume `casting`, not the live tree). The unattested caster stays un-marked → the next collect gate flags it via `collectUnstagedShadowCastersFlag` (:25085) → withhold/arm covers it → shadow arrives a pass late with no cold link. Re-collecting mid-drive would invalidate the slice's reparent set — the current design is correct.

**(c) epoch latch staleness — REAL → B2.** Window is remainder-of-seq, NOT multi-seq: `_viewSyncSeq` bumps once per `syncEntityViews` (:22526); a cook suspended across seqs sees a fresh latch each new seq. Within the mutation's own seq, latched epoch + memo serve the stale sig to all same-seq consumers; the pass's own `syncVisiblePointLightBudget` mutation (:15330) is the canonical trigger. See B2 for mechanism, fix, and the in-tree doctrine contradiction.

**(d) `cookStale`/`cookSuperseded` re-drive — CLEAN: full re-cook, no corrupt carry-over.** Every sector:enter mints a NEW invocation (`_liveSectorCookGeneration++` at :14827; entry arm :17084-17085 → `prepareLiveSectorAfterJump`); the superseded invocation returns `cookSuperseded`; the newest runs the whole body — full re-cook, not resume. `liveSectorGpuAdmission` is re-set per entry (:14819) and the cook's outer finally is generation-gated (`if (!cookStale())` at :15299) — a stale invocation cannot strip the live cook's latches. Temp roots are removed in an inner finally even on a superseded return (:14740-14745 — "belongs to this invocation even when the live owner changed"); only the `_rosterPrewarmRoots` entry survives (→ B5). Minted warm state (programs, buffers, marks) is content-keyed — survives as valid warm work. Root-keyed bookkeeping (`_withheldDepthCasters`, `_parkedDepthStageRoots`, `_pendingDepthStageRoots`) re-derives under the new census via the raw-epoch prefilter; stale-sector roots reap at teardown seams. `_pendingPostOpeningSector` is consumed by whichever pass reads it first (:15326-15327) — a superseded read costs only the next pass's `sectorResult.sectorId` diagnostic. `jumpLedger` is per-invocation (:14832). Verdict: partial bucket/minted state does not misbehave into the re-cook; B5 is the sole residue.
